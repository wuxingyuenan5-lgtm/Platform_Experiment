> 状态：历史部署参考。当前Platform开发应优先使用根目录脚本与`docs/codex/current-state.md`。

## 适用范围

本文件仅描述`projects/risk-control`旧Go/MySQL兼容服务曾使用的基础依赖：

- Go 1.20或更高版本；
- MySQL 8.0；
- Node.js与pnpm，用于构建前端；
- Nginx；
- systemd；
- 可选的Redis和Docker工具。

当前原生部署权威入口仍需以`deploy/README.md`和`deploy/install-native.sh`为准，并在执行前完成Legacy L0外部服务器与数据核验。

## MySQL安全配置

创建数据库和最小权限用户时必须现场生成随机密码，不得复制文档中的固定示例：

```bash
openssl rand -hex 32
```

示意SQL：

```sql
CREATE DATABASE IF NOT EXISTS risk_control
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'risk_app'@'127.0.0.1'
  IDENTIFIED BY '替换为现场生成的随机密码';
GRANT ALL PRIVILEGES ON risk_control.* TO 'risk_app'@'127.0.0.1';
FLUSH PRIVILEGES;
```

要求：

- MySQL仅监听本机或受控内网；
- 不向公网开放3306；
- 凭据保存在`/etc/variable-global/*.env`等受限文件中，权限应为0600；
- 不在Git、文档、日志、截图或命令历史中保存真实值；
- 已在历史文档出现过的凭据必须轮换，不能继续使用。

## 服务账户与目录

旧原生部署使用受限系统用户和目录：

```bash
sudo adduser --system --group --shell /usr/sbin/nologin variable-global
sudo install -d -o variable-global -g variable-global -m 0750 /var/lib/variable-global
sudo install -d -m 0700 /etc/variable-global
```

不要为服务账户授予sudo权限。

## 网络边界

建议只开放：

- 22：SSH，且应限制来源；
- 80：仅用于首次跳转或验收；
- 443：正式HTTPS。

以下端口不得直接暴露公网：

- 3306：MySQL；
- 6379：Redis；
- 8080：Legacy Auth Service；
- 8082：Legacy Data Service。
