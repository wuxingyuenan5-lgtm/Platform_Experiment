# Platform Experiment 0.9.1 启动说明

> 集成分支：`release/0.9.1-user-system`  
> 基线：最新上传的 `main`  
> 状态：用户系统已接入 0.9.1 集成分支，未合并 `main`

## 一、服务边界

```text
admin-risk                 前端，默认端口 4373
platform-backend           Platform API 与浏览器用户系统，默认端口 8000
execution-runtime          执行运行时，默认端口 8100
legacy auth-service        旧兼容服务，默认端口 8080
legacy data-service        旧兼容服务，默认端口 8082
```

0.9.1 保留最新版 `main` 中的对冲基金看板、跨所价差、资金费执行、Runtime 与启动脚本改动，同时把浏览器用户身份权威统一到 `platform-backend`：

```text
platform-backend/app/user_*.py
platform-backend/app/member_holding_*.py
```

旧 Go `auth-service` 和 `data-service` 仅用于尚未迁移的兼容页面，不再是新用户、权限、Session 或会员持仓的权威来源。

浏览器 CEO Session 不等于 API Key `admin`，不能绕过 LiveTradingSession、Kill Switch、对账、绝对限额或 Runtime Live Gate。

## 二、推荐开发启动

用户系统与主要平台页面使用三个终端：

```text
1. platform-backend：8000
2. execution-runtime：8100（只在执行与实时状态功能需要时启动）
3. admin-risk：4373
```

也可以在仓库根目录使用现有统一启动脚本：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev-platform.ps1
```

## 三、Platform Backend

首次安装：

```bash
cd platform-backend
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'
cp .env.example .env
```

Windows PowerShell：

```powershell
cd platform-backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

开发环境关键配置：

```text
VG_ENVIRONMENT=development
VG_DATABASE_PATH=./data/platform.db
VG_RUNTIME_BASE_URL=http://127.0.0.1:8100
VG_CORS_ORIGINS=http://127.0.0.1:4373,http://localhost:4373
VG_AUTH_MODE=development
VG_BROWSER_SESSIONS_ENABLED=true
VG_LIVE_TRADING_ENABLED=false
```

启动：

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

检查：

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/api/v1/ops/schema-migrations
```

## 五、前端

```bash
cd admin-risk
HUSKY=0 pnpm install --frozen-lockfile
pnpm dev
```

访问：

```text
http://127.0.0.1:4373/
```

前端使用固定端口 4373。端口被占用时应先释放端口，不应静默切换后继续使用旧 CORS 配置。

主要代理：

```text
/api/v1   → http://127.0.0.1:8000
```

用户系统通过同源 `/api/v1` 使用 HttpOnly `vg_session` Cookie。CSRF 只保存在前端内存，不写入 localStorage、sessionStorage 或持久化 Pinia。

## 六、用户与权限

公开注册只允许：

```text
employee  员工，需要部门
member    会员，需要会员类型
```

固定业务角色：

```text
ceo
tech_lead
employee
member
```

用户系统支持：

- 注册、登录、退出、近期重新认证；
- 个人资料、头像、密码和设备 Session；
- 用户搜索、筛选、审批、角色和状态管理；
- 管理员运营备注；
- 会员本人持仓、基金 NAV、资产估值与收益展示；
- 修改密码、角色或状态后的旧 Session 失效。

## 七、会员持仓

会员持仓是客户报告读模型，不是正式财务账本、申赎结算事实、交易账户余额或风险限额输入。

浏览器人工维护来源固定为：

```text
manual_admin
```

所有份额、净值、市值与收益使用 Decimal 字符串语义。NAV 缺失显示 unavailable，过期显示 stale，不伪造为 0。
