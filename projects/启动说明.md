# Platform Experiment 启动说明

> 版本：0.9.0  
> 用户系统分支：`feature/issue-117-user-system`  
> 本文描述当前 canonical 本地启动路径。旧 Go 服务只为尚未迁移的页面提供可选兼容能力，不再是浏览器用户身份权威。

## 一、当前服务边界

```text
admin-risk                 前端，默认端口 4373
platform-backend           Platform API 与浏览器用户系统，默认端口 8000
execution-runtime          执行运行时，默认端口 8100；仅相关功能需要
legacy auth-service        旧兼容服务，默认端口 8080；用户系统主流程不依赖
legacy data-service        旧兼容服务，默认端口 8082；仅未迁移账户页面可能依赖
```

浏览器用户、密码、Cookie Session、权限、用户管理、个人账号和会员持仓的权威实现位于：

```text
platform-backend/app/user_*.py
platform-backend/app/member_holding_*.py
```

真实交易自动化仍使用 API Key、LiveTradingSession、Kill Switch、对账和 Runtime Live Gate。浏览器 CEO Session 不能替代这些闸门。

## 二、推荐启动顺序

用户系统开发只需要两个终端：

```text
1. 启动 platform-backend，端口 8000
2. 启动 admin-risk，端口 4373
```

需要查看执行、交易或 Runtime 状态时，再单独启动 `execution-runtime`。只有访问尚未迁移的旧账户数据页面时，才需要旧 8080/8082 服务。

## 三、首次准备 Platform Backend

进入目录：

```bash
cd platform-backend
```

创建并激活 Python 3.12 虚拟环境。Windows PowerShell 示例：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
```

Linux/macOS 示例：

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev]'
```

复制环境变量模板：

```bash
cp .env.example .env
```

Windows PowerShell：

```powershell
Copy-Item .env.example .env
```

默认开发配置包含：

```text
VG_ENVIRONMENT=development
VG_DATABASE_PATH=./data/platform.db
VG_CORS_ORIGINS=http://127.0.0.1:4373,http://localhost:4373
VG_AUTH_MODE=development
VG_BROWSER_SESSIONS_ENABLED=true
VG_LIVE_TRADING_ENABLED=false
```

不要把真实 API Key、密码、Session、CSRF Token 或重置凭证写入 `.env.example`、Git、日志或 Markdown。生产 API Key 配置只保存 Token SHA-256，原始值由受控秘密管理方式提供。

## 四、启动 Platform Backend

```bash
cd platform-backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

健康检查：

```bash
curl http://127.0.0.1:8000/health
```

Schema migration 状态：

```bash
curl http://127.0.0.1:8000/api/v1/ops/schema-migrations
```

该状态接口受现有认证边界控制；在不同环境下按配置提供相应凭证。

## 五、创建初始 CEO

数据库中没有 active CEO 时，使用交互命令创建第一名 CEO：

```bash
cd platform-backend
python -m app.user_cli create-ceo
```

命令通过 `getpass` 输入密码，不显示、不回显、不写入命令行历史。系统没有默认 CEO、默认密码或可提交的临时密码。

若数据库已经存在 active CEO，命令会拒绝再次创建。后续 CEO 或技术负责人账号必须由已有 CEO 在用户管理页面创建。

## 六、启动前端

进入前端目录：

```bash
cd admin-risk
```

安装依赖：

```bash
HUSKY=0 pnpm install --frozen-lockfile
```

开发启动：

```bash
pnpm dev
```

固定访问地址：

```text
http://127.0.0.1:4373/
```

`vite.config.ts` 使用 `strictPort: true`。4373 被占用时不会静默切换端口，应先停止占用进程或显式修改前端端口与后端 `VG_CORS_ORIGINS`。

## 七、前端代理关系

```text
/api/v1       → http://127.0.0.1:8000   canonical Platform API 和用户系统
/api/auth     → http://127.0.0.1:8080   旧兼容服务，仅未迁移页面
/api/data     → http://127.0.0.1:8082   旧兼容服务，仅未迁移页面
```

用户系统页面只使用同源 `/api/v1`：

```text
登录、注册、退出、近期再认证
个人资料、头像、密码、登录设备
用户列表、审批、角色、状态、重置凭证、强制退出
会员本人持仓、CEO 持仓与基金单位净值维护
```

浏览器管理 HttpOnly `vg_session` Cookie。CSRF Token 只保存在当前前端内存，不写入 localStorage、sessionStorage 或持久化 Pinia。

## 八、登录与注册流程

公开注册仅允许：

```text
employee  员工申请，需要部门
member    会员申请，需要会员类型
```

注册后状态为 `pending`，不能立即登录。CEO 或有权限的技术负责人审核普通账号；CEO/技术负责人不能通过公开注册获得。

固定业务角色：

```text
ceo
tech_lead
employee
member
```

API-Key 角色是另一命名空间：

```text
viewer
researcher
trader
risk_officer
operations
admin
```

API-Key `admin` 的 wildcard 不等同浏览器 CEO。浏览器 CEO 使用显式业务权限，不能借此提交 Live 交易或修改 API-Key-only 核心风险闸门。

## 九、个人账号与 Session

canonical 个人账号入口：

```text
/account/index
```

旧 `/risk/profile` 仅隐藏重定向到新入口。

默认 Session 安全参数：

```text
绝对有效期        12 小时
空闲有效期        30 分钟
近期再认证窗口    10 分钟
最大活动设备数    5
```

密码、角色和生命周期变化会使旧 Session 失效。用户系统请求收到 401 后，前端清除内存 CSRF，并在下一次路由判断时回到登录状态。

## 十、会员持仓说明

会员持仓是客户报告读模型，不是：

```text
正式财务账本
申购赎回或结算事实
交易账户余额
策略 NAV
Position / PnL / FinancialFact
风险限额或执行输入
```

持仓与单位净值使用后端 Decimal 和 canonical decimal string。缺失 NAV 保持不可用，不显示为 0；过期 NAV 显式标记 stale。

浏览器人工维护来源固定为：

```text
manual_admin
```

`migration` 和 `external_import` 仅为未来专用导入器预留，浏览器 API 不能伪装这些来源。

## 十一、可选旧服务

旧 auth-service 8080 和 data-service 8082 仍保留在仓库中，供尚未迁移的页面兼容使用。它们不是新用户系统的身份、权限或持仓权威。

不要使用旧服务中的固定 JWT、默认密码或前端本地 Token 方案作为新实现参考。是否迁移或删除旧服务必须另开独立 Issue，并先确认是否存在真实用户或客户数据。

## 十二、常用排查命令

查看前端端口：

```bash
ss -ltnp 'sport = :4373'
```

查看 Platform Backend：

```bash
ss -ltnp 'sport = :8000'
```

查看 Runtime：

```bash
ss -ltnp 'sport = :8100'
```

查看相关进程：

```bash
ps -ef | grep -E 'uvicorn|vite|pnpm|execution-runtime' | grep -v grep
```

Windows PowerShell：

```powershell
Get-NetTCPConnection -LocalPort 4373,8000,8100 -ErrorAction SilentlyContinue
```

停止前台服务使用 `Ctrl + C`。不要使用 `Ctrl + Z` 代替停止进程。

## 十四、生产部署前置条件

生产部署前必须确认：

- HTTPS 终止和 Secure Cookie；
- 前端与 `/api/v1` 同源反向代理；
- 精确 Origin、Cookie、CSRF 和 CORS 配置；
- Platform SQLite、头像目录和代理配置备份；
- Migration 5/6 升级与恢复演练；
- 公开认证接口的反向代理分布式限流；
- API Key 与浏览器 Session 边界未混淆；
- 全量 CI、Secret Scan 和 Version Consistency 通过；
- Platform 与 Runtime Live Write 仍按受控流程保持关闭或单独验收。
