# Legacy Risk-Control MySQL Schema参考

> 状态：历史数据结构参考，不是当前Platform数据库权威。  
> 禁止在本文保存真实数据库凭据、默认管理员密码或可直接使用的密码哈希。

## 数据安全声明

旧文档曾包含固定数据库密码、默认管理员弱密码和MD5示例。这些值必须视为已泄露，不得继续使用。

恢复或迁移旧MySQL前必须：

1. 轮换数据库用户密码；
2. 轮换JWT Secret与账户加密密钥；
3. 禁用或重置全部历史默认管理员；
4. 检查Git历史、备份、服务器环境文件和命令历史；
5. 完成数据库备份与恢复抽检；
6. 不使用MD5、SHA-1或明文保存用户密码。

## 仓库当前实际Schema Owner

旧Go服务通过运行时`EnsureSchema`维护MySQL：

- Auth：`projects/risk-control/auth-service/internal/repository/mysql/user_repo.go`；
- Data：`projects/risk-control/data-service/internal/repository/mysql/repository.go`。

真实服务器Schema可能与当前源码不同，必须通过只读`information_schema`审计确认。

## 已知核心表

### `users`

可能包含：

- 用户名与密码哈希；
- 角色和部门；
- 申请角色、审批状态与审批信息；
- 创建和更新时间。

Auth与Data Service都包含`users`建表逻辑，但字段版本不完全一致。迁移前必须比较实际列、枚举、默认值和历史数据。

### `user_sessions`

可能包含旧数据库Session、用户ID、IP、User-Agent和过期时间。

### `accounts`

可能包含：

- 账户名称、类型和地址；
- 初始资本、所有者和状态；
- 加密API Key与API Secret；
- 父账户和兼容标志。

### `assets`

可能包含：

- 总资产和可用资金；
- Bybit仓位JSON；
- 数据来源、快照类型和更新时间；
- 历史净值快照。

### 历史规划表

旧设计文档还规划过`orders`、`risk_rules`和`risk_logs`。当前Go Data Service未证明仍创建或使用这些表，必须以服务器实际Schema与查询日志为准。

## 只读Schema检查

在服务器上执行时，不输出密码或密钥列内容：

```sql
SELECT TABLE_NAME, TABLE_ROWS, CREATE_TIME, UPDATE_TIME
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'risk_control'
ORDER BY TABLE_NAME;

SELECT TABLE_NAME, COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_DEFAULT
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'risk_control'
ORDER BY TABLE_NAME, ORDINAL_POSITION;

SELECT TABLE_NAME, INDEX_NAME, COLUMN_NAME, NON_UNIQUE
FROM information_schema.STATISTICS
WHERE TABLE_SCHEMA = 'risk_control'
ORDER BY TABLE_NAME, INDEX_NAME, SEQ_IN_INDEX;
```

敏感列只检查是否存在值，不导出明文：

```sql
SELECT
  COUNT(*) AS account_count,
  SUM(api_key_encrypted IS NOT NULL AND api_key_encrypted <> '') AS api_key_rows,
  SUM(api_secret_encrypted IS NOT NULL AND api_secret_encrypted <> '') AS api_secret_rows
FROM risk_control.accounts;
```

## 用户迁移原则

旧Go用户不能直接复制到当前Platform用户系统：

- 角色模型不同；
- Session模型不同；
- 密码哈希算法、参数和来源需要确认；
- 审批、状态、部门和会员语义需要映射；
- 迁移必须保留审计记录并强制用户重置密码。

禁止通过插入固定管理员、复用旧密码或直接写当前Platform数据库来完成迁移。

## 处置边界

在以下条件满足前，不得删除`risk_control`数据库或Legacy目录：

- 数据库备份可恢复；
- 表结构、行数、最近写入和数据Owner已确认；
- 用户、账户、加密凭据和净值历史已完成迁移/保留决策；
- 所有Legacy前端消费者已迁移；
- 停机和回滚方案经所有者批准。
