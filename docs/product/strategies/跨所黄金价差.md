# 跨所黄金价差

## 目标

围绕 Bybit `XAUTUSDT` 与当前真实 MT5 `XAUUSD.s` 的既定黄金组合，完成研究、指令、两腿受控执行、配平、敞口、订单成交、费用、PnL、NAV、恢复和对账闭环。

相似的黄金 Symbol 不代表相同合约。数量换算必须显式使用各 Venue 的合约乘数、最小数量、步长、tick、币种、交易时段和费用语义。

## 当前业务合同

- Owner 明确指定方向和业务数量；系统不自动扩大标的或规模。
- 一个业务指令最多创建一个 ExecutionBatch，两腿共享稳定的关联身份。
- Platform API 负责编排、风险、账本和对账；Venue SDK 与订单副作用只在 Execution Runtime。
- ACK 不等于 Fill；成交事实来自标准化外部结果和恢复查询。
- 每条腿的累计成交、换算后等价数量和剩余暴露必须独立记录。
- Bybit 与 MT5 只有同时具备当前动作所需的可执行状态时，价差才可参与正常开平仓和自动止盈止损。单腿休市或受限时继续展示价差并监控仓位、保证金和爆仓风险，不触发正常交易。

## 账户资金与仓位展示

- 风控栏把 Bybit 与 MT5 的数据状态合并为一个策略级状态；任一侧异常显示对应问题，双侧异常同时显示。单个 Bybit 或 MT5 账户的单边净敞口不单独展示，Cross 净敞口只对两侧合并后的标的数量判断配平状态。
- Bybit 与 MT5 的杠杆率、爆仓价和账户浮盈亏按指标对齐显示，单边资金利用率置于末行；风控栏不展示账户权限或持仓价值。
- 仓位分布保留环形图和表格，持仓价值按原币展示；MT5 腿按账户报告币种 USD 读取，不再把 USD 与 USDT 拆成两套仓位。黄金标的数量使用 `oz`，多头和空头分别显示，不能重复计算或从一侧推导另一侧。
- Cross 的净敞口和配平状态使用 Bybit、MT5 各自实时读取的仓位行合并计算；一侧读取失败时不得用另一侧数据补齐或覆盖。

## 损益与总资产统计时段

- 跨所策略每日盈亏与策略损益默认只采用 Bybit、MT5 同时开市且报价有效的估值。MT5 周末、节假日及日内休市期间暂停更新，显示有效估值时间；日历标记“休市”，不是零收益。
- 恢复开市后与上次有效开市估值直接比较，不使用休市单边浮亏作为基线，避免虚假回补收益。真实价差变化、已实现成交、手续费、资金费和库存费不会被抹除；暂停期间的真实费用在恢复统计时纳入。
- 全账户总资产图提供“过滤 MT5 休市”和“7×24 小时”按钮，默认前者。过滤模式的回撤从过滤后的权益序列重算，并继续剔除真实资金进出；缺少时段证据或估值时明确留空。
- 账户资金、账户权益、保证金、仓位与风控继续实时展示。本规则仅用于跨所策略，不改变资费或其他策略的统计方式，也不改变账户原始流水与交易执行规则。

## 执行与恢复

- 开仓执行模板在执行方式上方同时展示 Bybit 与 MT5 的真实账户净值和可用资金；数据直接来自双边权威账户风险快照，读取失败时显示不可用，不使用页面默认值或 mock。
- 交易规则区保留原有五行简表。交易时间显示 MT5 服务器时区的周一至周五开市窗口；夏冬令时、周末、节假日及临时维护由 Runtime 的时段配置和日期覆盖反映。Bybit 默认使用 `Bybit/MT5`（UTC+2，按 3 月第二个周日到 11 月第一个周日切换 UTC+3），不能用北京时间或 `Europe/Athens` 的切换日期替代。当前 `00:00-23:00` 服务器窗口对应北京时间每日 04:00-05:00（UTC+3，夏令时）或 05:00-06:00（UTC+2，冬令时）休市。开收盘前后可配置的 N 分钟只暂停后台自动止盈止损，页面显示“开收盘前后 N 分钟不自动交易”，人工开平仓仍可自行下达；完整休市显示“休市”并阻止正常双腿执行。没有真实值的字段显示 `—`，Seed 和 Fixture 不能冒充真实规则。
- 重复提交、并发、重启和断线不能创建第二个业务意图。
- 修改、撤单重挂和恢复动作不得突破原指令累计成交上限。
- 限价价差执行保留“追逐限价”和“触发后市价”选择。追逐限价使用 Bybit 原生 Chase；开平仓与 TP/SL 可设置允许不利偏移，单边不可交易时不触发新交易。终止余单并核清实际成交后，按可精确换算的数量执行 MT5 市价对冲；结果未知不重复下单。执行与恢复细则见跨所执行合同。
- 任一腿结果未知时进入 `result_unknown`，停止新副作用并执行查询、对账或人工接管。
- 部分成交需要显式展示已配平量、未配平量和当前风险，不能用批次最终状态掩盖腿级事实。
- Fill、Deal、Commission、Swap、Funding、FX 和合约换算必须保持来源与时间语义。

## 双边资金划转

- “移动双边资金”必须从平台内真实完成 `bybit-live-main` 与其 MT5/TradFi 账户之间的资金划转；跳转 Bybit 官网由 Owner 手工操作不属于该功能验收通过。
- 当前尚无经过验证、可审计且适合服务器长期部署的正式写入能力，因此该功能必须保持不可提交；辅助记录、余额预约、官网链接或 Owner 手工划转都不能呈现为自动划转成功。
- 只有正式接口与账户绑定经过核实、真实账户 readiness 成立，并在逐项 Owner 授权下通过最小真实写入验收后，才能启用。不得以浏览器自动化、未公开网页接口或网页登录会话作为长期生产集成。
- 启用后，每次请求必须具有稳定业务身份和明确的源、目标逻辑账户。只有权威转账身份与双边余额共同确认终态才算完成；结果未知、查询不可用或单边变化时继续 fail closed，并保留账户级资源约束直至对账或人工接管。

## 明确不包含

- 自动寻找更多黄金 Venue 或 Symbol。
- 自动决定仓位、阈值或扩大资金规模。
- 海内外价差、CTP 或国内期货执行。
- 无人值守 Live 交易。
- 用 Fake Gateway 或样例数据证明真实外部闭环。

## 完成证据

- Bybit 与 MT5 的标的身份、合约规格和数量换算经过核实。
- 两腿订单、成交、费用、持仓和外部身份可以稳定关联。
- 断线、重复、乱序、部分成交和结果未知场景 fail closed。
- 关闭后残余敞口、费用、PnL 和账户事实完成对账。
- 每个外部连接或真实写入步骤均有单独 Owner 授权；本地验收不能替代外部证据。
