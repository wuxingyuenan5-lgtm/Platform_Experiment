# 资金费率套利

## 目标

在同一 Bybit 账户内，由 Owner 明确指定永续与现货标的及数量，建立永续空头与现货多头的受控资金费率组合，并完整记录执行、持仓、费用、Funding、PnL、NAV 与对账事实。

本策略不是自动选币、自动调仓或无人值守交易系统。

## 当前业务合同

- Owner 明确指定账户、永续标的、现货标的、方向和数量。
- 支持同时持有多个已明确指定的 pair，但每个业务指令身份独立。
- 开仓和关闭均复用受限两腿执行、幂等、账本、对账和恢复基础。
- 当前顺序为永续腿优先；只有新近证明的永续累计成交增量，才允许对应比例的现货增量。
- 至少需要一笔可核实的 Funding Settlement 才能证明资金费率闭环，不得用预测费率替代真实结算。

## 执行与恢复

- 每个 Owner 指令最多创建一个 ExecutionBatch。
- 永续腿采用有界 PostOnly Chase；修改或撤单重挂仍属于同一批次和原始数量上限。
- 重复事件不能重复触发现货腿。
- 到期或达到 Chase 边界后取消剩余量；取消或成交状态未知时停止后续副作用。
- 任何腿的累计成交、未配平暴露、费用和外部订单身份都必须可查询、可恢复和可对账。

当前本地测试参数是 15 秒总 Chase TTL、1 秒评估间隔、最多 5 次修改或撤单重挂、至少一个 tick 的价格变化后才允许修改。这些是可配置的 Owner 批准测试参数，不是交易所事实或永久生产默认值。

## 明确不包含

- 自动发现或筛选标的。
- 自动决定仓位、资金分配或再平衡。
- 反向 Carry。
- 跨交易所资金费率套利。
- 长期开启 Live Write 或无人值守运行。
- 外部客户资金或多人基金运营。

## 完成证据

- 指令、批次、订单、成交、持仓、费用、Funding 和 PnL 身份可串联。
- 部分成交、重复、乱序、断线和重启不产生超量或重复现货成交。
- 至少一笔真实 Funding Settlement 经过账户账本核实。
- 关闭后两腿结果、残余敞口、费用和收益完成对账。
- 每个外部连接或真实写入步骤均有单独 Owner 授权；代码和本地测试本身不构成授权。
