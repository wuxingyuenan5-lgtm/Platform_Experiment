# 资金费率套利

## 目标

在同一 Bybit 账户内，由 Owner 明确指定永续与现货标的及数量，建立永续空头与现货多头的受控资金费率组合，并完整记录执行、持仓、费用、Funding、PnL、NAV 与对账事实。

本策略不是自动选币、自动调仓或无人值守交易系统。

## 当前业务合同

- Owner 明确指定账户、永续标的、现货标的、方向和数量。
- 支持同时持有多个已明确指定的 pair，但每个业务指令身份独立。
- 支持开仓、指定组合全部平仓和部分平仓；平仓可输入数量或选择 25% / 50% / 75% / 100%，按交易所步长向下取整，不能超过该组合可平数量。
- 开仓和平仓均支持市价、限价 FOK 和挂单追价，复用两腿执行、幂等、账本、对账和恢复基础。
- 当前顺序为永续腿优先；只有新近证明的永续累计成交增量，才允许对应比例的现货增量。
- 新开仓输入为现货毛买入数量；按当前确认的 0.1% 买入基础币手续费计算净到账，永续数量为净到账按永续步进向下取整。两腿分别校验最小数量及金额，取整后不够永续最小下单量时不创建指令。确认页展示毛数量、预计净到账、永续数量和剩余净敞口；不足一个永续步进的正向现货余量保留并显示，不自动补交易。
- 实际成交后按原生手续费币种核对净持币。现货卖出手续费以收到的 USDT 支付，不再从可卖 BTC 重复扣除；永续 USDT 手续费计入成本。旧组手续费未配平进入本策略异常区，保留仓位供 Owner 手动平仓，不自动改写或修正旧订单。
- 至少需要一笔可核实的 Funding Settlement 才能证明资金费率闭环，不得用预测费率替代真实结算。

## 执行与恢复

- 每个 Owner 指令最多创建一个 ExecutionBatch。
- 市价：永续腿只提交一次市价委托，现货随已核实的实际成交量执行；未确认结果不重发。
- 限价 FOK：Owner 指定永续价格，永续必须终态精确全成交后才释放现货市价腿。零成交的明确拒绝或撤销结束为失败；异常部分成交停止后续对冲并要求核对。
- 挂单追价：永续采用有界 PostOnly Chase；修改或撤单重挂仍属于同一批次和原始数量上限。
- 限价约束永续腿；现货对冲为市价成交，不承诺组合总价差。
- 平仓永续腿为 reduce-only；现货数量按原组实际净到账、手续费币种及剩余可平数量计算，缺失费用或余额证据时不提交。
- 行情、合约规格与下单使用同一活动账户绑定：实盘使用 primary，模拟使用 local_test。真实合约数量步长、最小数量和价格 tick 在计划创建时读取并冻结。
- 第一笔委托前检查永续及现货两种市场的交易权限和规格；实盘委托按当前原生数量规则校验，不能被本地旧精度误拒绝。
- 重复事件不能重复触发现货腿。
- 到期或达到 Chase 边界后取消剩余量；取消或成交状态未知时停止后续副作用。
- 任何腿的累计成交、未配平暴露、费用和外部订单身份都必须可查询、可恢复和可对账。
- 执行状态变化后同步刷新持仓事实，包括人工处理和结果未知；持仓表分别显示剩余可平与未配平数量，不能用已对冲数量冒充单腿成交。已经成交一条腿的故障单保留原指令及预约，不自动重开或自动补单。
- Owner 通过风险处置平掉故障仓位后，只有全部剩余仓位已核实归零，指令才结束为失败并进入历史，同时释放预约；原始成交和故障原因保留可追溯记录。重复处置不能再次平仓。
- 提交超时只按原幂等身份查询；明确失败后解除草稿锁定，旧指令不自动重试。零成交失败保留在执行历史，不计作活动持仓；未知结果仍保留预约并阻止重提。

当前本地测试参数是 15 秒总 Chase TTL、1 秒评估间隔、最多 5 次修改或撤单重挂、至少一个 tick 的价格变化后才允许修改。这些是可配置的 Owner 批准测试参数，不是交易所事实或永久生产默认值。

## 明确不包含

- 自动发现或筛选标的。
- 自动决定仓位、资金分配或再平衡。
- 反向 Carry。
- 跨交易所资金费率套利。
- 长期开启 Live Write 或无人值守运行。
- 外部客户资金或多人基金运营。

## 完成证据

- 指令、批次、订单、成交、持仓、费用、Funding 和 PnL 身份可串联。
- 部分成交、重复、乱序、断线和重启不产生超量或重复现货成交。
- 至少一笔真实 Funding Settlement 经过账户账本核实。
- 关闭后两腿结果、残余敞口、费用和收益完成对账。
- 每个外部连接或真实写入步骤均有单独 Owner 授权；代码和本地测试本身不构成授权。
