# 产品总入口

Variable-Global 当前不是单一页面项目，而是一组围绕交易研究和执行管理的工作台。产品文档先按模块管理，不急着合并成长篇 PRD。

## 产品口径

- 前端页面首先服务“高频使用的交易/投研工作流”。
- 页面里不要出现解释实现的文字，例如 Backend、Runtime、Gateway 这类内部概念，除非当前页面就是技术运维视图。
- 策略管理页应展示策略表现、账户资金、订单和风险状态，不展示调试面板。
- 执行相关能力要和模拟/实盘边界清楚分开。

## 用户、权限和数据范围

当前浏览器用户系统采用四类固定业务角色；角色只是权限集合的输入，不是前端自行决定的安全边界。

| 角色 | 当前产品范围 | 明确禁止 |
|---|---|---|
| CEO | 全部用户管理、注册审批、敏感字段、会员持仓和审计 | 查看原密码；停用或降级最后一个有效 CEO |
| 技术负责人 | 会员和员工管理、账号支持、技术与运行信息 | 修改 CEO 或其他技术负责人；默认修改会员持仓或执行真实交易 |
| 员工 | 被授权业务页面和用户只读视图 | 用户写操作、系统级配置和真实交易 |
| 会员 | 本人资料、会话设备和本人基金持仓 | 其他用户、内部组织、风控、运行监控和交易管理 |

授权必须分别判断页面访问、数据读取、敏感字段、业务操作和资源范围；未知或无法判断的高风险请求默认拒绝。前端隐藏按钮不是授权，后端必须从受信任 Principal 解析权限与数据范围。Browser Session 不能替代 API Key 或 LiveTradingSession，审批也不能替代执行权限、风险检查或数据范围。

第一阶段正式范围包括同源登录、服务端 Session、CSRF/Origin、即时撤销、用户管理、会员持仓读模型和敏感操作审计。社交登录、企业 SSO、自定义角色编辑器、用户硬删除、申购赎回清算和浏览器 Live 认证重设计不属于当前范围。未来研究、交易、策略、风险、数据和系统管理职责若需细分，应通过集中 Capability 与 Data Scope 扩展，不在页面中新增隐式角色。
