# 风险管理

风险管理是账户、资产、权限、审计、运行和交易风险的内部管理入口。它展示并控制风险，但不替代各领域的业务事实 Owner。

## 用户结果

- 查看账户、资产、敞口、风险状态和异常。
- 管理受权限约束的用户、角色、会话和审批。
- 查看运行状态、审计记录、对账差异和人工处理事项。
- 在授权范围内执行 Kill Switch、确认或修正流程。

## 当前范围

- 风险详情与敞口。
- Funding 与 Cross 的策略管理「账户资金」页提供执行风控设置：显示默认/专属配置，可确认修改腿间最长时间、余差名义上限、失败处置以及策略 Kill Switch。现有权限控制写入；配置只对新批次生效，已有批次保留冻结参数，回执丢失沿原请求核对。策略阻断不自动平仓，也不替代全局及账户开关。
- 账户、资产、资金与财务视图。
- 数据和服务状态。
- 风控详情下方设「数据审计」子页，覆盖平台业务数据库、研究数据与归档，以及 Runtime 自有存储的只读状态；不是对冲看板专属工具。
- 数据审计由后端每 5 分钟运行，检查断更、采集缺口、必需指标缺失、归档丢失与数据库完整性；页面读取持久结果。页头提醒入口跨页面显示异常数量，点击进入检查证据和异常/恢复记录。
- 同一问题合并为一个持久告警；确实检查恢复才关闭，复发重新打开。审计结果超过 15 分钟未更新或 API 不可读取，前端显式提示不能确认当前健康。
- 行情源状态为 receiving/received/up_to_date 也必须验证接收时间；Bybit 聚合订阅状态由具体现货/线性子流覆盖，避免把无独立时间戳的容器状态当作生产故障。未知状态不算通过。检查项消失或停用不是恢复证据，保留未复核问题，旧证据不累计发现次数。页面展示可取得的数据日期、更新时间和时限，检查通过数量不代表全库逐条验证。
- 用户、权限、会话、审计和个人账号。
- 对账差异、消息和人工处理入口。

## 边界

- 会员不可见且后端拒绝内部风险管理资源；员工默认只读。
- 前端按钮、菜单和路由不能替代后端授权。
- Kill Switch、LiveTradingSession、审批、数据范围和执行权限相互独立。
- 监控视图不把缺失、陈旧或估算数据显示为正常零值。
- 风险页面不直接持有 Venue 凭据或执行订单。
- 审计不自动改写、补造或清理业务事实，不触发交易或行情重采。事件驱动表没有新增不等于故障；外链、停用采集和旧归档与持续生产数据区分。
- 覆盖清单和未验证项必须公开：A 股全A成交与百亿股历史按本平台缓存的独立新浪交易日历检查，日历每 7 日刷新，获取失败保留旧值但覆盖过期/刷新超时提醒；其他市场暂不宣称完整的交易日覆盖。新表/新数据集未配置规则会提醒。深度检查超出时间预算标为未验证，不宣称整库正常。服务完全离线时站内提醒无法主动外送，不代表已有独立外部告警设施。
- 数据审计异常只进入监控与处置，不作为所有策略共用的实盘总闸。交易准入按策略、绑定账户、场所和标的检查所需行情/交易能力：A 股研究数据故障不得阻断 Cross 或 Funding；Funding 只依赖其 Bybit 账户和现货/永续两腿，Cross 必须同时满足 Bybit 与 MT5 两腿条件；单账户故障只阻断依赖该账户的交易。全局 Live Write 与全局 Kill Switch 仍是明确的人工总闸，账户级/策略级 Kill Switch 仅作用于对应范围。

## 最小验收

- 直接 URL、菜单和 API 使用一致的 Capability 语义。
- 关键风险数值保持 Decimal、币种、单位和带时区时间戳。
- 高风险操作具有明确确认、审计和失败关闭行为。
- 数据缺失、过期、权限不足和系统错误可以被用户区分。
