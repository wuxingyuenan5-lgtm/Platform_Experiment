# 策略

策略模块把研究、执行准备、受控交易、账户事实、订单成交、持仓、PnL、NAV、风险和复盘连接成一个闭环。“交易平台”是执行视角，“策略管理”是运行与结果视角，不再分别维护两套产品定义。

## 用户结果

- 判断一个策略为什么值得关注以及当前是否具备执行条件。
- 在明确模式、账户、标的和数量后提交受控业务意图。
- 查询命令、批次、订单、成交、持仓、费用、PnL、NAV 和对账结果。
- 对异常、部分成交、断线和结果未知进行人工接管与复盘。

## 当前范围

- 资金费率套利和跨所黄金价差两条优先闭环。
- 研究、Simulation、只读账户事实和 Live 模式明确分离。
- 稳定 Strategy、Account、Instruction、ExecutionBatch、Order、Fill、Position、PnL、NAV、Risk 和 Reconciliation 身份。
- 只读策略账户可以展示经验证的账户事实，但不能提交、改单或撤单。

## 执行边界

- 一个 Owner 指令最多产生一个执行批次。
- 累计外部成交不得超过指令数量；重复、并发、重启和断线不能产生新业务意图。
- ACK 不等于 Fill；`result_unknown` 必须停止副作用并进入查询、对账或人工处理。
- Frontend 和 Platform API 不直接调用 Venue SDK。
- Live Write 默认关闭，每个真实写入步骤需要单独授权。

## 最小验收

- 研究上下文可以进入执行准备，但不会自动变成订单。
- 账户、订单、成交、持仓和收益具有稳定身份、币种、单位和时间语义。
- 部分成交、重复事件、乱序、断线和恢复不会产生超量或重复成交。
- 用户可以辨识 `sample`、只读外部事实、Simulation 和 Live。
- 结果未知、对账差异或安全门禁失败时系统 fail closed。
