# 策略

策略模块把研究、执行准备、受控交易、账户事实、订单成交、持仓、PnL、NAV、风险和复盘连接成一个闭环。“交易平台”是执行视角，“策略管理”是运行与结果视角，不再分别维护两套产品定义。

## 用户结果

- 判断一个策略为什么值得关注以及当前是否具备执行条件。
- 在明确模式、账户、标的和数量后提交受控业务意图。
- 查询命令、批次、订单、成交、持仓、费用、PnL、NAV 和对账结果。
- 对异常、部分成交、断线和结果未知进行人工接管与复盘。

## 当前范围

- 资金费率套利和跨所黄金价差两条优先闭环，由平台 CEO 账户直接下达指令；完整覆盖确认、执行反馈、持仓、平仓、部分平仓、止盈止损、异常恢复和结果核对。
- 抄底、短线交易员 WW、短线交易员 BL 为只读账户监控；绑定后展示账户资金、持仓、订单、成交和费用，未绑定时明确空态。
- 本轮完善策略管理损益、资金分类与费用记录；共享账户总资产不作为每个策略独立资金重复累计，预测费率不作为结算收入。
- Funding 与 Cross 的订单、成交和结算按其页面提交的服务端策略指令归属；共享账户不改变策略归属，无法确认归属的流水保留待核对。
- Funding 和 Cross 的异常卡片各自只接收本策略指令所属的异常组，并在策略管理和对应执行子页显示；没有异常时整张卡片隐藏。正常持仓也按开单策略的指令与组合归属读取；即使共用账户且交易同一品种，Funding 与 Cross 的订单、成交、持仓及异常也不得互相混入，不得用品种过滤代替策略归属。Funding 展示现货实际净持币、永续剩余量和净敞口，并复用已有单组平仓或失败批次风险处置入口。
- 保留 Funding 原有资费收益、基差收益、现货附加收益、现货借贷成本、持仓损益、累计交易成本、执行偏差，以及 Cross 原有 XAUT/XAU 价差、永续/现货价差、USDT/USD 偏离、腿间持仓、库存费、资费、累计交易成本、执行偏差分类。细分算法分步完善，未接通的数值显示缺失、曲线留空，不展示重复的“待计算”备注；订单成交和原生结算持续保留。
- 收益曲线提供周度、日度、1H、5min 时间精度，默认日度；按实际时间记录展示，不补造缺失的分钟历史。
- USDT、USDC 和实际持有的 USD 分币种展示；多币种资产的 USD 汇总仍为估值口径，界面保留 USD 币种但不附加“折合 USD”字样。MT5 现金及结算使用其账户报告币种，不能从 XAUUSD 合约名称推定为 USD 现金。
- Cross 执行区支持读取和受控调整 Bybit 当前合约杠杆、查看账户保证金占用；Funding 执行页保留行情、开仓资金、交易规则、指令、持仓和执行记录，合并重复信息。
- Cross 将误下双腿组合、单腿成交及未完成平仓单独放入“异常订单与待处理仓位”，展示各腿已平和剩余数量、MT5 Ticket、失败原因与针对该项的平仓入口。异常项不进入正常组合总览或正常列表的一键全平；未知结果先核对原订单。已完成的腿不得因处理异常而重新提交。
- 海内外价差暂停开发；行情分析暂不纳入本轮。
- 研究、Simulation、只读账户事实和 Live 模式明确分离。
- 稳定 Strategy、Account、Instruction、ExecutionBatch、Order、Fill、Position、PnL、NAV、Risk 和 Reconciliation 身份。
- 只读策略账户可以展示经验证的账户事实，但不能提交、改单或撤单。

## 账户资金与损益展示

- 账户资金概览仅展示标题和金额，不展示“最近同步成功”“交易保证金额度”等卡片备注。全账户总资产排在统一交易账户权益前面；资金状态和异常在风控区域单独呈现。
- 策略管理页默认先展示“账户资金”，再展示“策略损益”。每日盈亏日历和仓位分布归入账户资金区，策略损益区聚焦损益曲线与损益细分。
- 账户快照中断或过期时须在页面轮询发现后显示告警；后台持续重试读取；本地只读服务由独立看护进程受控恢复，策略页显示同步、退出监控和服务看护告警，页面提供刷新状态入口，并保留最近成功快照及其时间。
- Cross 概览顺序：BYBIT-LIVE-001 全账户总资产、BYBIT-LIVE-001 统一交易账户权益、MT5-LIVE-001 交易账户权益、BYBIT-LIVE-001 可用保证金、MT5-LIVE-001 可用保证金、BYBIT-LIVE-001 维持保证金；不展示 MT5 维持保证金卡片。
- Cross 策略损益的每日盈亏按该策略绑定的 Bybit 与 MT5 两条腿合并展示；同一 UTC 日期、同一币种时合计两腿盈亏并按两腿期初权益计算收益率。缺一条腿或币种不一致时该日收益率显示不可用，不把 Funding 或其他策略的订单归入 Cross。
- 资金结构观察仅展示已有的资金账户、统一交易账户、TradFi / MT5、理财，按此顺序排列；不展开子分类、Alpha 或币种余额。展示精简不改变后台资产记录、总资产计算或可交易余额。
- 统一交易账户的资金主曲线显示全账户总资产，标题、摘要、图例和历史取值一致；普通交易账户仍显示交易账户权益。历史缺失不以交易权益补齐，字段语义见 [API 合同](../../contracts/API.md)。
- 损益页不展示“按已记录成交与结算计算”“分类保留，明细算法待接入”等常规备注，也不展示按账户列出的“成交与结算”明细卡片；实际数据异常仍保留。
- Cross 执行区每个账户的可用资金与保证金占用并列显示；Bybit 杠杆输入默认 50x，当前值独立回读。默认输入不触发修改，写入与确认边界见 [跨所执行合同](../../contracts/CROSS_SPREAD_EXECUTION.md#71-bybit-杠杆与保证金占用)。

## 正常交易权限

2026-09-09 Owner 确认：Cross/Funding 按常规交易运行。CEO 登录后可以在已绑定交易账户上开仓、加仓、部分平仓或全平，不需要早期测试会话、临时审批窗口、固定一盎司/名义额度、单组持仓限制或验收专用策略/品种白名单。监控账户仍只读。

真实账户权限、余额/保证金、Venue 数量规格、紧急停止、幂等防重、累计成交不超指令、对账与未知结果保护继续有效。账户范围和安全总开关由明确运营设置决定；AI 不因修改权限代码获得代为下单或恢复既有自动退出计划的授权。

## 执行边界

- 一个 Owner 指令最多产生一个执行批次。
- 累计外部成交不得超过指令数量；重复、并发、重启和断线不能产生新业务意图。
- ACK 不等于 Fill；`result_unknown` 必须停止副作用并进入查询、对账或人工处理。
- Frontend 和 Platform API 不直接调用 Venue SDK。
- Live Write 默认关闭，每个真实写入步骤需要单独授权。

## 最小验收

订单信息在跨所价差、资金费率、抄底和短线等策略间共用列表、筛选与详情组件。按当前持仓、开平记录、逐笔成交和委托明细组织；开平记录按可证明的指令/批次归组，监控订单保留自身身份。列表直接展示开平、买卖、场所、数量单位和状态，完整编号及时间依据收进可展开详情；没有可靠开平依据时标为待核对。日期筛选和显示统一使用北京时间，异常原始时间不能冒充确定的成交时刻。

- 研究上下文可以进入执行准备，但不会自动变成订单。
- 账户、订单、成交、持仓和收益具有稳定身份、币种、单位和时间语义。
- 部分成交、重复事件、乱序、断线和恢复不会产生超量或重复成交。
- 用户可以辨识 `sample`、只读外部事实、Simulation 和 Live。
- 结果未知、对账差异或安全门禁失败时系统 fail closed。
