## Objective

## Required Design

- Reuse `execution_batches`; do not add a queue, event bus, service, new database table or distributed-lock dependency.
- After catalog/binding and Kill Switch admission, but before creating any leg `TradeCommand`, acquire a SQLite write transaction (`BEGIN IMMEDIATE` or an equivalently proven atomic repository operation).
- Inside that transaction, idempotent replay of the same key and matching payload returns the existing batch and creates no new intent.
- A different instruction is rejected while any batch in any strategy has status `pending`, `executing`, `partially_executed` or `manual_intervention`.
- `manual_intervention` and any batch whose external disposition is unknown retain the lease. Restart or process loss cannot release it because persisted database state is authoritative.
- Only proven terminal batch states release admission for a later instruction. This task must not invent automatic timeout release or infer terminal state from missing in-memory work.
- The winning claim inserts one batch and its legs atomically. A rejected competitor creates no batch, leg, `TradeCommand`, order or Runtime command.
- Risk-reduction `TradeCommand` paths remain available through their established idempotent risk workflow; this task serializes new strategy open/close batches and must not weaken Kill Switch or emergency risk contraction.

## Acceptance

- TDD evidence proves two concurrent different idempotency keys cannot both create batches; exactly one persisted batch wins and the loser returns a fail-closed conflict.
- Same-key/same-payload replay returns the original batch even while it holds the global lease; same-key/different-payload remains `409`.
- A persisted unresolved batch blocks a new instruction after application restart; `manual_intervention` and result-unknown disposition remain blocking.
- Proven terminal `hedged` or definitive `failed` state permits the next instruction without mutating historical facts.
- Tests prove rejection occurs before leg commands/orders/Runtime effects and applies across different strategy keys and open/close directions.
- Existing cross-spread lifecycle, execution-risk, idempotency and live-safety tests pass; no `platform-web` path changes.
- Ruff, Pyright, `git diff --check`, version, structure and documentation checks pass. Repository-wide Pack budget failures remain reported, not misrepresented.
- Critical independent acceptance reviews an immutable commit range.
