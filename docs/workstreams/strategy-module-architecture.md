# 策略模块架构工作流

整理日期：2026-10-29。最近直接策略验收依据为10月2日的本地加载与Owner登录后只读页面结果；后续研究存储变化由[研究阶段](strategy-market-research.md)接续。此处不缓存当前账户、持仓、命令数量或Live Write状态。

## 范围与当前结果

保留Web、模块化单体API与独立Runtime，以现有执行内核修复Funding/Cross、账户观测、财务归属和本地生命周期。没有选定替换OMS；历史第二版方案只作参考，不能覆盖当前合同或已复现的事实。

| 工作线 | 已有结果 | 剩余验收 |
|---|---|---|
| 指令与恢复 | Funding计划和预约原子持久后由后台runner推进，同幂等键只回读。原平仓剩余现货恢复使用原身份，已有恢复子单只核对。异常HTTP、非JSON、迟到ACK、落库失败及适配器异常均保留未知/认领，冲突命令拒绝重派 | 新的真实开平仓、单腿失败恢复和重启后的场所经济结果，仍需逐项授权与原生证据 |
| Cross与风控 | 按真实策略定义控制权限，首腿前核对原生MT5 Ticket、方向数量及Bybit组净额。场所手工平仓只有在双边新鲜完整、空仓且原生成交/未决检查通过后才关闭计划，原失败凭据保留 | 不以预检通过或历史空仓证明当前可交易；两策略专属风险阈值尚未由Owner按账户规模确定，不能擅改默认风险偏好 |
| 账户与财务 | 后台只读同步和管理投影已持久化；账户收益与策略收益分离，资金费仅按订单关联/正式归属，不凭历史唯一标的推断。日历按北京时间选点，缺失日终不补造，月/年汇总显示不完整 | 全部原生成交、费用、Swap、资金费与日终估值未全覆盖；共享UTA/TradFi资产不得重复加总，监控投影不能代替正式会计 |
| 自动退出 | Funding价差退出配置、修订/抢占/原指令关联已实现并经隔离浏览器验证；Cross退出遵循MT5休市/边界和双腿可执行性限制 | 没有本轮创建或启用真实退出计划；实盘自动退出、实际成交及Funding结算经济验收未完成 |
| 性能与页面 | 目录复用、在途请求合并、精确幂等键查询、账户查询索引及后台读模型已加载；策略切页、Funding本金预览及实时行情经Owner登录后核对。旧草稿只在原键明确不存在时解除，查询失败继续锁定 | 仍有冷启动/尾延迟尖峰与历史不可达样本；短时健康和局部页面验证不等于长期正常交易完成 |
| 本地生命周期 | 原dev-platform入口、watchdog、supervisor和pulse受管恢复已有本地证据；MT5由固定Worker经SDK一次连接，后台窗口隐藏、失败退避，服务日志由子进程持有 | 真正连续运行、断网、整机重启与完整浏览器重连仍待验证；Live Write开启时后端中断保护不得改为自动重启 |

## 验证边界

- 已有定向隔离API→Runtime开平仓、部分成交、Chase、并发、未知结果、权限与恢复回归，以及本机服务和只读页面证据；fake Runtime与合成账户不证明真实交易完成。
- 10月1日Owner场所端平仓与当时权限恢复是历史事实；10月2日只读恢复时双层Live Write关闭。后续权限、账户与仓位必须重新查询，历史记录不授予新交易权限。
- 原版本22至后续迁移的备份/恢复事实各按当时证据保留；当前存储与迁移见[数据库文档](../database/README.md)，不从本阶段的历史版本推断当前库。
- Funding/Cross数量、手续费、报价与时间语义不同，保持各自合同；不为统一界面或框架强行合并执行流程。
