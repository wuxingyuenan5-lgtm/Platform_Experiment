## 1. 目的

Bybit 与 MT5 的模拟环境不能完整复现实盘账户、成交、Funding、Swap、券商终端和网络行为，因此最终验收采用真实账户、小资金和最小仓位。

本手册把“小资金实盘测试”定义为受控运营验收：

```text
只读实盘
→ 历史与账户风险核对
→ 影子对账
→ 1 oz 人工监督写入
→ 失败处置与 Kill Switch
→ 日终对账
```

任何阶段失败，立即回退只读模式。工程 CI 不能代替真实账户验收。

## 2. 不可突破的底线

- 实盘 Runtime 与 Simulation 使用不同数据库、Journal、Account ID 和凭证引用。
- 实盘凭证不进入代码、Git、Markdown、日志、截图或聊天记录。
- Platform Live Write、Runtime Live Write 和自动退出监控默认关闭。
- Platform Kill Switch 与 Runtime Write Gate 必须同时放行。
- Account、StrategyInstance 和 Symbol 必须位于精确 allowlist。
- ACK 不等于 Fill；`result_unknown` 不得触发重复业务意图。
- 查询失败不能解释为空仓、零余额、零订单或没有历史。
- 外部 Order、Fill/Deal 和 Position 身份必须可追溯。
- 未完成日终对账前，不增加资金、数量、品种、并发或自动化频率。

## 3. 当前临时验收限制

以下是第一轮真实账户验收的临时限制，不是最终产品上限：

| 临时限制 | 当前值 | 目的 |
|---|---:|---|
| 单次跨所价差数量 | 不超过 `1 troy ounce` | 限制最坏单腿敞口 |
| Runtime 实际写入 | Bybit 与 MT5 按实时合约乘数换算后不超过 `1 oz` | 防止绕过 Platform 放大仓位 |
| 活动生命周期 | 最多一个非 `closed` Exit Plan | 避免 Ticket 和退出计划混淆 |
| 已有仓位、未决 Batch 或人工介入 | 禁止新开仓 | 防止叠加未知风险 |
| 执行模式 | Market Open/Close；价差阈值触发 Market Close | Limit 执行尚未完成 |
| 合约规格 | 每次写入前读取 Venue 当前规格 | Seed 不作为实盘依据 |
| 开仓后 | 两边真实 Position 必须匹配 | Batch 状态不能代替外部证据 |
| 平仓后 | 两边目标 Position 必须归零 | Close 返回不能代替归零证据 |
| MT5 明确失败 | 仅允许一次幂等 Bybit `reduceOnly` 回滚 | 收缩第一腿敞口 |
| MT5 结果未知 | 禁止自动回滚和盲目重试 | 避免双倍或反向敞口 |
| Live Write 默认 | Platform=false，Runtime=false | 合并代码不等于授权 |
| 自动退出监控默认 | false | 主机验收前不自动产生写入 |

### 永久安全原则

未来即使放宽 1 oz 或单生命周期限制，也必须永久保留：

- ACK/Fill 分离。
- `result_unknown` 不盲目重试。
- Platform 与 Runtime 独立写入门禁。
- Bybit Close 使用 `reduceOnly` 和明确 `positionIdx`。
- MT5 Close 使用真实 Position Ticket。
- 合约规格、权限、持仓和账户风险读取失败时 fail-closed。
- 凭证隔离与日志脱敏。
- 临时限制只能经独立 Issue、任务包、PR 和运营证据复审。

## 5. 阶段 1：只读实盘与历史证据

保持所有写入门禁关闭。

GET /venue/instruments/{symbol}?accountId=...
GET /venue/account-risk?accountId=...

### 5.2 当前订单与历史订单

```http
GET /venue/orders?accountId=...&symbol=...&limit=50
GET /venue/orders/{externalOrderId}
GET /venue/order-history?accountId=...&symbol=...&startTime=...&endTime=...&scope=active&limit=50
GET /venue/order-history?accountId=...&symbol=...&startTime=...&endTime=...&scope=closed&limit=50&cursor=...
```

验收：

- [ ] Runtime 启动前、人工创建或 Route 丢失后的订单仍可读取。
- [ ] 无 Platform Route 的订单标记 `external_only`，不伪造完整映射。
- [ ] 活动订单与历史订单分开解释。
- [ ] 单次历史窗口不超过七天，单页不超过 100 条。
- [ ] Bybit 使用 Venue Cursor 续页。
- [ ] MT5 在固定时间窗口内使用确定性 Offset 续页。
- [ ] ACK、部分成交、成交、撤销和拒绝状态可区分。
- [ ] Requested、Filled、Remaining Quantity 可解释。
- [ ] `reduceOnly`、`positionIdx`/Position Ticket、TIF、拒绝/撤销原因按 Venue 能力展示。

### 5.3 成交与 Deal 历史

```http
GET /venue/fills?accountId=...
GET /venue/fill-history?accountId=...&symbol=...&startTime=...&endTime=...&limit=50&cursor=...
```

验收：

- [ ] Bybit `execId` 是 Fill 身份。
- [ ] MT5 Order Ticket、Deal Ticket 和 Position Ticket 不互相冒充。
- [ ] MT5 市价单主要返回 Deal Ticket 时，可恢复对应 Order Ticket。
- [ ] Fee、Commission、Funding 和 Swap 的币种及符号可解释。

### 5.4 强平与账户保证金风险

Bybit 必须核对：

- [ ] `totalEquity`、可用余额、总初始保证金、总维持保证金。
- [ ] Account IM/MM Rate。
- [ ] Position Mark Price、Break-even Price、IM/MM 和 PnL。
- [ ] 交易所返回有限 `liqPrice` 时，与 Bybit 原生界面一致。
- [ ] 未返回有限 `liqPrice` 时显示 `null / venue_not_finite`，不得显示 0 或本地估算。

MT5 必须核对：

- [ ] Balance、Equity、Profit、Margin、Free Margin、Margin Level。
- [ ] `margin_so_call`、`margin_so_so` 和 `margin_so_mode` 与 Terminal/Broker 设置一致。
- [ ] 单仓强平价显示“MT5 API 不提供”，不得生成本地估算值。
- [ ] Position 当前价、浮盈亏、Swap、TP 和 SL 可读取。

### 5.5 Platform 聚合面板

```http
GET /api/v1/trading/cross-spread/observability?historyHours=24&limit=20
```

验收：

- [ ] Bybit 与 MT5 的 Account Risk、Position、Active Order、Recent Order、Recent Fill 分区显示。
- [ ] 某一区块失败时仅该区块标记 `unavailable`，其余区块仍可使用。
- [ ] `unavailable` 不得显示为健康的 0 或空列表。
- [ ] 24 小时、3 天和7天历史范围可以切换。
- [ ] 面板没有下单、撤单或修改持仓按钮。
- [ ] 市价生命周期数量默认值为 `1 oz`。

只有阶段 1 全部通过，才进入影子核对。

## 6. 阶段 2：影子核对

仍保持写入关闭，执行：

```http
POST /api/v1/ops/venue-reconciliation/runs
POST /api/v1/ops/live-economic-events/import
```

核对：

- External Order/Fill/Deal 与 Platform Order/Fill。
- Venue Position 与 Formal Position。
- Venue Balance/Account Risk 与 Formal NAV 输入。
- Funding、Swap、Fee 与 FinancialFact。
- 重复导入不重复改变 Position、PnL 或 Fact Count。

验收：

- [ ] 多个核对周期无未解释差异。
- [ ] `result_unknown` 可通过 Venue Query 恢复。
- [ ] 外部冲突生成 Reconciliation Difference，不无痕覆盖。
- [ ] Formal Position/PnL 可从不可变事实重建。

## 7. 阶段 3：1 oz 人工监督写入

只有阶段 0–2 完成，才允许在单次人工监督窗口中开启写入。

开启前记录：负责人、时间窗口、Account、StrategyInstance、Symbol、方向、Market 类型、单笔/单日限额、Kill Switch 操作人、Bybit 回滚和 MT5 人工平仓路径。

顺序：

1. 再次读取实时规格、权限、账户风险和现有仓位。
2. 确认目标 Symbol 无已有持仓和活动生命周期。
3. 提交不超过 1 oz 的 Bybit Market 第一腿。
4. 只有 Bybit 终态成交后，按实际成交量精确换算 MT5 手数。
5. 查询 Bybit Fill、MT5 Deal 和两边 Position。
6. 只有外部仓位完全匹配才创建 Exit Plan。
7. 人工 Market Close 或受控 TP/SL 触发一次 Market Close。
8. 两边真实仓位归零后才标记 `closed`。
9. 导入 FinancialFact 并完成 Formal PnL/NAV 重建。
10. 测试 Kill Switch。
11. 关闭两层 Live Write，将名义金额上限恢复为零。

## 8. 双腿失败处置验收

必须演练：

- 第一腿 ACK 但未确认成交：不得提交第二腿。
- 第一腿终态部分成交：只对冲实际成交量。
- 第一腿成交、第二腿明确拒绝：一次幂等 Bybit `reduceOnly` 回滚。
- 第二腿超时或 `result_unknown`：禁止自动回滚和盲重试，人工接管。
- Bybit 可用而 MT5 不可用。
- MT5 Deal 已发生但本地事件丢失。
- Runtime/Terminal 重启、Route Store 丢失和网络中断。
- 处置命令重复提交。

最终必须进入明确状态：撤销未成交腿、平掉已成交腿、替代对冲完成，或带责任人的人工敞口接管。不能停留在无后续动作的 `manual_intervention`。

## 9. 日终验收

每个实盘测试日核对：Order、Fill/Deal、Position、Balance/Equity、Account Risk、Funding、Swap、Fee/Commission、FinancialFact、Formal PnL、Formal NAV。

差异至少分类：`missing_local`、`missing_external`、`quantity_mismatch`、`price_mismatch`、`currency_mismatch`、`status_mismatch`。每个差异记录责任人、原因、处置和关闭时间。

## 10. 临时限制解除条件

只有 Issue #39 连续记录以下证据，才允许创建“临时实盘限制复审”Issue：

1. 当前/历史订单、Fill/Deal、Position 和 Account Risk 多次读取成功。
2. Runtime/Terminal 重启与 Route Store 丢失后仍能恢复外部状态。
3. 多次双向 1 oz 开平仓及外部仓位核对成功。
4. Bybit 回滚、MT5 `result_unknown`、断网和超时演练无重复仓位。
5. TP/SL 原子 Claim 与 exactly-once Market Close 通过。
6. 多个真实交易日无未解释 EOD Difference。
7. Kill Switch、备份恢复和人工接管通过。
8. 认证、RBAC、双人审批和生产密钥托管落地。

解除流程：

- 不得直接改环境变量静默提高限制。
- 必须独立 Issue、任务包、分支和 PR。
- 每项限制分别标记 `retain`、`relax` 或 `remove`。
- 每次只放宽一个明确维度。
- 放宽后重新执行最小规模验收和 EOD 对账。
- ACK/Fill、未知结果不盲重试、双层写门禁、精确平仓身份和凭证隔离不得删除。

项目已设置条件提醒：只有上述证据成熟时，才提醒负责人进行限制复审。
