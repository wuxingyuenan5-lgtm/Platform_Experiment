## 1. 目的

Bybit 与 MT5 的模拟环境不能完整复现实盘账户、成交、Funding、Swap、券商终端、Private WebSocket 和网络行为，因此最终验收采用真实账户、小资金和最小仓位。

```text
只读实盘
→ 历史、合约规格与账户风险核对
→ 影子对账
→ 1 oz Market 人工监督写入
→ 1 oz FOK 人工监督写入
→ TP/SL Market/FOK
→ PostOnly Chase
→ 失败处置与 Kill Switch
→ 日终对账
```

任何阶段失败，立即回退只读模式。工程 CI 不能代替真实账户验收。

## 2. 不可突破的底线

- 实盘 Runtime 与 Simulation 使用不同数据库、Journal、Account ID 和凭证引用。
- 实盘凭证不进入代码、Git、Markdown、日志、截图或聊天记录。
- Platform Live Write、Runtime Live Write、Exit Monitor 和 PostOnly Chase 默认关闭。
- Platform Kill Switch 与 Runtime Write Gate 必须同时放行。
- Account、StrategyInstance 和 Symbol 必须位于精确 Allowlist。
- ACK 不等于 Fill；`result_unknown` 不得触发重复业务意图。
- 查询失败不能解释为空仓、零余额、零订单或没有历史。
- 外部 Order、Execution/Deal 和 Position 身份必须可追溯。
- FOK 零成交、部分成交和未知结果必须使用不同状态语义。
- PostOnly 重复事件、断线、序列异常和撤单/成交竞态必须 fail-closed。
- 未完成日终对账前，不增加资金、数量、品种、并发或自动化频率。

## 3. 当前临时验收限制

| 临时限制 | 当前值 | 目的 |
|---|---:|---|
| 单次跨所价差数量 | 不超过 `1 troy ounce` | 限制最坏单腿敞口 |
| Runtime 实际写入 | 按实时合约乘数换算后不超过 `1 oz` | 防止绕过 Platform 放大仓位 |
| 活动生命周期 | 最多一个非 `closed` Exit Plan | 避免 Ticket 和计划混淆 |
| 已有仓位、未决 Batch 或人工介入 | 禁止新开仓 | 防止叠加未知风险 |
| 人工执行模式 | Market、FOK；PostOnly 仅在专门监督阶段临时启用 | 分阶段验证 |
| 自动退出 | 保存独立 TP/SL Market/Limit 与 FOK/PostOnly 策略 | 监控仍默认关闭 |
| FOK/PostOnly 对冲预留 | 默认 `0`，实盘证据后显式配置非负值 | 不伪造 MT5 滑点保护 |
| PostOnly Runtime 开关 | 默认 `false` | 私有流验收前不启用 |
| 合约规格 | 每次写入前读取 Venue 规格并与 Platform Contract 核对 | Seed 不能代替实盘证据 |
| 开仓后 | 两边真实 Position 必须匹配 | Batch 状态不能代替外部证据 |
| 平仓后 | 两边目标 Position 必须归零 | Close 返回不能代替归零证据 |
| MT5 明确失败 | 仅允许一次幂等 Bybit `reduceOnly` 回滚 | 收缩第一腿敞口 |
| MT5 结果未知 | 禁止自动回滚和盲目重试 | 避免双倍或反向敞口 |
| Live Write 默认 | Platform=false，Runtime=false | 合并代码不等于授权 |

永久保留：ACK/Fill 分离、未知结果不盲重试、双层写入门禁、价差 Limit 不静默回退、Bybit Reduce-only/Position Index、MT5 Position Ticket、凭证隔离与日志脱敏。

## 7. 阶段 3：1 oz Market 人工监督写入

1. 再次读取规格、权限、风险和现有仓位。
2. 确认无已有仓位、未决 Batch 和活动生命周期。
3. 提交不超过 1 oz 的 Bybit Market 第一腿。
4. 只有终态成交后，按实际 Fill 换算 MT5。
5. 外部仓位完全匹配后才创建 Exit Plan。
6. 人工 Market Close，并分别监督一次 TP/SL Market Close。
7. 双边归零后才标记 `closed`。
8. 测试 Kill Switch，关闭写入并完成 EOD。

Market 双向 Open/Close 通过后才进入 FOK。

## 8. 阶段 4：1 oz FOK 人工监督写入

记录限制价差、双边 Bid/Ask、可成交价差、真实 Tick、Reserve、Raw Price 和 Tick-rounded Price。

### 8.1 全成交

- Bybit 原生订单必须为 `Limit + FOK`。
- 只有终态且累计量等于请求量时，才允许 Platform Fill 和 MT5 Deal。
- MT5 数量按实际 Fill 和真实 Contract Size/Step 换算。
- Close 核对 Reduce-only、Position Index 和 Position Ticket。

### 8.2 零成交

- Bybit 终态取消且累计量为零。
- 不生成 Fill，不提交 MT5。
- Open 不创建 Exit Plan。
- Close 恢复原计划为 `active`。

### 8.3 异常结果

部分成交、数量不一致、超时或未知可通过受控 Stub/网络演练验证，不要求用真钱主动制造。

- [ ] 不生成可驱动 MT5 的正常 Fill。
- [ ] 不自动提交 MT5。
- [ ] 不把异常解释为零成交。
- [ ] Batch/Exit Plan 进入对账或人工介入。
- [ ] 原业务意图不自动重试。

## 9. 阶段 5：TP/SL 执行方式

在自动 Exit Monitor 保持关闭时，先人工调用 Evaluate；随后仅在单独监督窗口临时开启监控。

- [ ] Exit Plan 保存 TP/SL 独立 Execution Mode 和 Limit Strategy。
- [ ] Market、FOK 均复用同一 Close Action。
- [ ] 自动 Limit 使用原子 Claim 的 `triggerSpread`。
- [ ] 下单前行情失效或干净零成交可以释放 Claim。
- [ ] 部分成交、提交后超时或未知结果不能释放 Claim。
- [ ] 不静默回退到其他执行方式。
- [ ] 测试结束恢复 Exit Monitor=false。

## 10. 阶段 6：PostOnly Chase

仅在前述阶段全部通过后进入，并严格按照 `V6-PostOnly-Chase-受控验收补充.md`。

核心要求：

- PostOnly 默认关闭，仅在监督窗口显式开启。
- Private Order/Execution 是主状态源。
- TTL、最小改单 Tick、最大 Mutation、Cooldown 有界。
- Amend 失败后先 Cancel，终态确认后才 Repost。
- 重复 Execution 不重复累计。
- 私有流断线、序列/身份异常或 REST 不一致停止 Chase。
- 只有去重累计量精确等于请求量才放行 MT5。
- 部分成交保持显式残余敞口，不自动 MT5。

## 11. 双腿失败处置

必须演练：

- Market ACK 未确认：不得提交第二腿。
- Market 终态部分成交：只对冲实际成交量。
- FOK 零成交：不得提交第二腿；Close 恢复 `active`。
- FOK 部分/不一致：不提交第二腿，人工介入。
- PostOnly Partial/Disconnect/Race：停止 Chase，不提交 MT5，终态对账。
- 第一腿成交、第二腿明确拒绝：一次幂等 Bybit Reduce-only 回滚。
- 第二腿超时或未知：禁止自动回滚和盲重试。
- Runtime/Terminal 重启、Route Store 丢失和网络中断。

最终必须进入明确状态：撤销未成交腿、平掉已成交腿、替代对冲完成，或带责任人的人工敞口接管。

## 12. 日终验收

每个实盘测试日核对 Order、Execution/Deal、Position、Balance/Risk、Funding、Swap、Fee/Commission、FinancialFact、Formal PnL/NAV。

Limit/PostOnly 额外核对 Strategy/TIF、目标与可成交价差、Bybit 硬边界、Requested/Filled/Remaining、子订单身份、是否只有精确全成才出现 MT5 Deal。

Difference 至少分类：`missing_local`、`missing_external`、`quantity_mismatch`、`price_mismatch`、`currency_mismatch`、`status_mismatch`，并记录责任人和关闭时间。
