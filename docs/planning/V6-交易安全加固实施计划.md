## 1. 总目标

```text
交易输入可验证
+
命令、事实和处置幂等
+
结果未知可恢复
+
金融事实可重建
+
双腿风险可处置
+
真实 Venue 可查询
+
实盘写入可限制、可关闭、可追溯
+
日终差异、SLA 和扩大实盘门禁可审计
+
代码、测试、文档和 CI 全程留痕
```

Bybit 与 MT5 采用真实账户接入，并优先使用小资金、最小允许仓位完成运营验收。但自动实盘写入默认关闭；真实账户存在和工程 CI 通过都不等于自动实盘获批。

## 4. Phase 4D：实盘日终对账与运营门禁

### 4D-1 时间和身份

- Business Date、IANA Timezone、Valuation Time、Due At 显式。
- StrategyInstance + Account 为报告范围。
- Idempotency Key 与自然身份双重约束。
- 同一身份载荷冲突返回 409。

### 4D-2 日终编排

固定顺序：

1. 对业务日期窗口订单和历史未终结订单执行 Venue Reconcile。
2. 导入外部 Position 与 Balance。
3. 导入 Funding、Swap、Commission 和 Fee。
4. 从 FinancialFact 重建 Formal Position/PnL。
5. 在统一 Valuation Time 生成 Formal NAV。
6. 汇总 Difference、Skipped Event、Missing Account、Incomplete PnL 和运行错误。
7. 生成不可变 EOD Report。

### 4D-3 报告与 SLA

报告状态：

- `complete`
- `completed_with_differences`
- `partial`
- `failed`

SLA：

- `pending`
- `met`
- `breached`
- `overdue`

外部失败不得生成虚假 complete、空仓、零余额或零差异。

### 4D-4 Scale Gate

- 默认 `blocked`。
- 只有 clean report 进入 `eligible_for_review`。
- 人工复核不可变。
- `approved_same_limits` 只允许继续当前小资金和当前限额。
- Open Difference 和 Accepted Difference 均阻断扩大实盘。
- Skipped Event、Missing Account、Incomplete PnL 或 errors 均阻断扩大实盘。

## 5. 真实账户运营验收

依赖真实账户、小资金和人工监督，不能由 CI 代替：

- [ ] Bybit 真实账户只读核对。
- [ ] MT5 真实账户只读核对。
- [ ] 使用最小允许仓位完成下单、撤单、成交、查询和事实导入。
- [ ] 每个测试日形成 EOD Report。
- [ ] 连续多个真实日终周期无未解释差异。
- [ ] Kill Switch、断网、Runtime 重启和 `result_unknown` 演练。
- [ ] 测试后 Write Gate、Notional Limit 和临时 allowlist 强制复位。

运营验收前保持 `liveWriteEnabled=false`。即使通过，也只能进入独立扩大规模评审，不自动提高限额。

## 6. 当前明确限制

- 真实凭证和账户配置未提交仓库，也不得提交。
- CI 不接触真实账户，无法替代运营验收。
- WebSocket 持续状态流尚未替代主动查询。
- 认证、RBAC、双人审批和生产密钥托管尚未完成。
- 告警、备份、恢复演练和生产级调度仍需补齐。
- EOD Report 不自动修改真实仓位或解决差异。
