## 3. Phase 1 实施内容

### 3.1 订单安全校验

订单进入 Runtime 前必须完成：

- 账户必须存在。
- 账户状态必须为 `active`。
- 凭证引用只能保存为 `secret://...` 引用，不能保存真实密钥。
- 标的必须存在。
- 标的必须存在 ContractSpecification。
- 数量必须满足最小下单量和数量步长。
- 限价必须满足价格步长。
- Live 账户仍受全局 `live_trading_enabled=false` 门禁保护。

任何信息无法确认时一律拒绝，不允许默认放行。

### 3.2 Runtime 幂等

旧流程：

```text
先查询 command 是否存在
→ 再写入 command
→ 再调用 Gateway
```

存在并发竞态。

新流程：

```text
INSERT OR IGNORE 原子抢占 command_id
→ 只有成功插入者允许调用 Gateway
→ 重复调用读取已持久化事件
→ 首次调用仍执行中时返回 409，不重复执行
```

### 3.3 CI 与工程环境

GitHub Actions 覆盖：

- `main`。
- `hardening/**`。
- 所有面向 `main` 的 Pull Request。

检查项：

- Platform Backend：Phase 1 Ruff Gate + 全量 Ruff 债务盘点 + Pytest。
- Execution Runtime：Phase 1 Ruff Gate + 全量 Ruff 债务盘点 + Pytest。
- Frontend：冻结锁文件安装、策略范围 Type Check、Production Build。

本批次同时修复了三项工程环境问题：

1. Runtime 将 Windows 专属 `MetaTrader5` 与 Crypto Gateway 依赖拆为可选依赖，Linux CI 只安装核心运行时与测试依赖。
2. 前端统一使用 `pnpm@9.15.9`，与 lockfile v9 对齐；CI 设置 `HUSKY=0`，避免子目录工作区找不到 `.git` 时安装失败。
3. TypeScript 补充 `/@/* -> src/*` 路径映射，使 Vite 别名和 `vue-tsc` 使用同一口径。
