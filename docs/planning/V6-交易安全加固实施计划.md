## 3. Phase 1：交易安全底线

已完成：

- 未知账户、停用账户、未知标的和缺失 ContractSpecification 全部 fail-closed。
- 数量满足最小下单量和数量步长，限价满足价格步长。
- 凭证只保存 `secret://...` 引用。
- Live 受全局 `live_trading_enabled=false` 门禁保护。
- Runtime 原子抢占 command，重复 command 不产生第二次外部副作用。
- Backend、Runtime、Frontend 的测试、类型检查和生产构建纳入 CI。

验收：`Platform CI run 29983926790`，全部通过。

## 4. Phase 2：命令入口与结果恢复

已完成：

1. 单腿交易统一通过 `TradeCommand + idempotencyKey`。
2. ExecutionBatch 每条腿生成独立 TradeCommand。
3. Batch 强制提供 `strategyInstanceId` 与 `idempotencyKey`。
4. TradeCommand 校验 Strategy、Account Binding、Account、Instrument 和 ContractSpecification。
5. `/trading/orders` 只保留为 deprecated 兼容入口。
6. `result_unknown` 从 Runtime Journal 恢复，不重新下单。
7. Fill event 重放不会重复更新 Position 和 PnL。
8. 前端从 Backend Catalog 动态获取策略、账户、绑定与标的。
9. 同一幂等键复用不同载荷时返回 409。
10. 权威 Markdown 变化纳入 CI 触发范围。

验收：`Platform CI run 29986397987`，Backend、Runtime、Frontend 全部通过。

详细记录：`V6-Phase2-命令入口与结果恢复.md`。

## 5. Phase 3：金融事实与正式账务

已完成，代码发布提交为 `77bf4223c2059d5a56fc08a2d49214351c396abc`：

1. 新增不可变 FinancialFact，支持 Order、Fill／Deal、Funding、Swap、Fee、Balance、Position 和 FX。
2. 客户端幂等键与外部事实身份双重去重；相同身份不同载荷返回 409。
3. Quantity Unit、Settlement Currency 和 Contract Multiplier 由后端 Catalog 快照确定。
4. Formal Position、Formal PnL 可以从事实完整重建。
5. PnL 分项保存 Trading、Funding、Swap、Fee、FX 和 Total。
6. 非基础币种缺失 FX 时标记 incomplete，不按 1:1 静默换算。
7. Formal NAV 对全部 active binding 账户使用同一 valuationTime。
8. NAV 返回账户覆盖数和 missingAccountIds，不把缺失账户当作零。
9. 已加入资费套利 PnL 与多账户 NAV 金样本。
10. 事实入库、投影重建和 NAV 创建均写入 AuditEvent。

## 6. 当前明确限制

- 只有 Fake Gateway 具备完整下单闭环。
- Bybit/MT5 尚未形成真实 Demo 下单、撤单、查单和事实自动导入链路。
- `result_unknown` 当前只从 Runtime Journal 恢复，尚未主动查询外部 Venue。
- 旧 `/pnl` 与 `/nav-snapshots` 仍是工程兼容口径；正式核对使用 `formal-*`。
- 外部账单解析和逐笔账单核对尚未完成。
- 双腿失败后尚无自动反向平仓、替代对冲和 Kill Switch。
- 应用层认证、RBAC、双人审批和生产密钥托管尚未落地。

因此，禁止将当前版本解释为可实盘版本。

## 7. Phase 4 入口

Phase 4 聚焦执行风险和 Demo 闭环：

1. Bybit Demo 与 MT5 Demo 正式适配器。
2. 主动查单、查成交、查仓位和事实自动导入。
3. 双腿最大间隔、残留敞口阈值和自动处置。
4. Kill Switch、人工接管和操作审计。
5. 日终订单、成交、持仓、余额与 Formal PnL/NAV 对账。
6. 断网、超时、Runtime 重启和单腿失败演练。
