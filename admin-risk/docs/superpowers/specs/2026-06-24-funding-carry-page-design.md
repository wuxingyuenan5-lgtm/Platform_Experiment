# Funding Carry Page Design

## Goal

将“资金费率套利”研究页正式并入最新版平台 `admin-risk`，挂载到现有 `Strategy` 菜单体系下，保持平台既有白底后台风格，并保留抽象点线结构图区作为视觉锚点。

## Confirmed Scope

- 仅做单一交易所内的现货多头 + 永续空头资金费率套利研究页。
- 首期覆盖交易所：Binance、OKX、Bybit。
- 首期覆盖币种：BTC、ETH、SOL、DOGE、XRP、XAUT。
- 优先做“单币深度研究页”，即先有标的，再判断是否值得做。
- 当前版本不接数据库，不下沉执行系统，不复刻待执行 / 已执行任务表。
- 当前版本允许使用 mock 数据承载页面展示，后续通过适配层替换成真实接口。

## UI Direction

页面必须遵循当前平台的视觉语言，而不是旧版深色终端样式：

- 白色 / 米白主背景
- 低饱和金色与墨绿色点缀
- 圆角卡片、轻阴影、大留白
- 结构上参考用户给定平台截图
- 抽象结构图区保留，但不在图中混入解释性业务文字

## Information Architecture

### 1. 页面入口

挂载到：

- `策略 / 资金费率套利`

不替换现有 `交易平台` 与 `策略管理`，而是在 `strategy` 模块下新增独立子路由。

### 2. 页面骨架

页面由五层组成：

1. 页面头部  
   显示研究定位、说明文案、当前选中交易所 / 币种 / 视角。

2. 交易所与币种切换层  
   - 交易所：Binance / OKX / Bybit
   - 币种：BTC / ETH / SOL / DOGE / XRP / XAUT

3. 总览层  
   - 左：当前交易所下的币种资金费率快照
   - 右：账户净值、保证金余额、24h carry、累计收益、净 carry、稳定度评分等摘要卡

4. 结构图区  
   保留抽象点线图，仅承担结构与气质表达，不承载业务标签。

5. 单币深度层  
   以选中币种为中心展示：
   - 期现价差 / 资金费率 / 借贷利率视角切换
   - 核心结论卡
   - 收益拆解
   - 稳定性 / 容量 / 执行提示
   - 执行 Memo

## Component Boundaries

页面必须可拆可换，避免“大页写死”。

- `index.vue`  
  仅负责状态编排与模块装配。

- `FundingDeskTabs.vue`  
  负责交易所切换。

- `FundingSymbolList.vue`  
  负责币种快照列表。

- `FundingSummaryCards.vue`  
  负责顶部摘要指标卡。

- `FundingStructureHero.vue`  
  负责抽象结构图区。

- `FundingDetailPanel.vue`  
  负责单币深度研究主体，包括结论、拆解、风险、容量、执行提示。

- `types.ts`  
  统一定义类型。

- `mock/data.ts`  
  统一管理展示数据，后续可由接口适配层替换。

## Data Model

当前版本采用“展示数据层”和“页面消费层”分离：

- 页面只消费标准化后的对象
- 页面内不硬编码分散数据
- 后续接真实接口时，只需替换 `mock/data.ts` 或新增 adapter，不重写组件

核心数据维度包括：

- 交易所级账户摘要
- 币种级资金费率快照
- 币种级研究结论
- 收益拆解表
- 风险 / 容量 / 执行说明

## Error Handling

- 若交易所不存在，回退到 Binance。
- 若币种不存在，回退到当前交易所的首个币种。
- 若字段缺失，卡片显示 `--`，而不是报错或空白错位。

## Verification

交付前至少验证：

- 路由可进入
- 页面可渲染
- 交易所切换正常
- 币种切换正常
- 视角 tab 切换正常
- TypeScript 检查通过

## Out Of Scope

- 数据库建模
- 真实交易接口
- 下单与成交回报
- 风控引擎
- 任务流转表
