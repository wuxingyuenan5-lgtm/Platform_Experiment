# `<模块或子板块名称>`：详细需求

状态：`draft／active`  
产品基线：Platform V5  
架构版本：Platform V6 或讨论版本  
适用分支：`refactor/frontend-architecture-v6`  
文档层级：一级模块／二级模块／子板块需求  
主责产品模块：`<一级模块>`  
依赖定位文档：`<路径>`

## 1. 文档定位

说明本文：

- 定义什么。
- 不定义什么。
- 依赖哪些上级需求、策略文档和架构文档。
- 与其他相邻文档如何分工。

## 2. 产品定位

回答：

- 该模块服务什么用户任务。
- 为什么属于当前一级模块。
- 在平台中的独特价值是什么。
- 与相邻模块的核心区别是什么。

## 3. 目标用户与权限

至少列出：

- 目标用户类型。
- 页面访问能力。
- 数据读取能力。
- 敏感字段能力。
- 操作能力。
- 审批或确认能力。
- 导入、导出和正式发布能力。

引用统一角色和数据范围文档，不在每个模块发明新权限模型。

## 4. 核心用户问题

使用用户能够理解的问题表达，例如：

- 用户进入页面后需要判断什么？
- 用户需要比较什么？
- 用户需要完成什么操作？
- 用户如何发现异常？
- 用户如何进入下一步？

每个核心功能都应对应至少一个用户问题。

## 5. 产品范围

### 5.1 必须包含

列出正式产品能力。

### 5.2 可以扩展

列出未来可能支持但当前未确认的能力。

### 5.3 明确不包含

列出容易被误放入本模块的能力，并说明正确归属。

## 6. 信息架构

描述：

- 页面或主要视角。
- 页面之间的层级。
- 固定区块。
- 可配置区块。
- 详情、抽屉、弹窗和工作流入口。
- 不适用内容如何隐藏，而不是显示虚构零值。

## 7. 路由与上下文

至少说明：

- 路由语义。
- 可恢复主上下文。
- StrategyId、accountId、instrumentId 等稳定 ID。
- 时间、币种和筛选。
- 页面刷新和深链接。
- 切换模块、视角或对象时哪些上下文保留、重置或重新查询。

## 8. 功能需求

按用户任务逐项描述。

每项功能至少包含：

- 功能目标。
- 输入。
- 处理规则。
- 输出。
- 可执行动作。
- 权限。
- 状态。
- 异常。
- 验收。

推荐格式：

### 8.x `<功能名称>`

#### 用户目标

#### 前置条件

#### 输入和筛选

#### 展示内容

#### 操作

#### 服务端规则

#### 异常和降级

#### 验收标准

## 9. 数据需求

### 9.1 数据对象

列出正式业务对象，不直接列数据库表或 Mock 字段。

### 9.2 字段语义

关键字段至少明确：

- 名称。
- 业务含义。
- 类型。
- 单位。
- 币种。
- 精度。
- 是否可空。
- 来源。
- 时间。
- 是否估算。
- 是否敏感。

### 9.3 数据来源

区分：

- 权威领域事实。
- 外部数据源。
- Backend Read Model。
- 人工维护。
- 导入数据。
- 派生指标。

### 9.4 数据时间和质量

至少包括：

- sourceTime。
- receivedAt。
- 数据截止时间。
- 修订时间。
- DataQualityState。
- 延迟、缺失、冲突和部分可用。

### 9.5 数据权威

说明：

- 谁写入。
- 谁只读。
- 谁组合查询。
- 哪些结果可以重建。
- 哪些原始事实不可覆盖。

## 10. Query、Command 与 Event

### Query

列出页面和流程所需主要查询。

### Command

列出正式写入和业务操作。

### Event

列出页面实时更新、跨模块协作和审计需要的事件。

不得用 Query 接口执行写入，也不得把前端事件当领域事件。

## 11. 状态与生命周期

必须区分：

- 请求状态。
- 数据质量状态。
- 业务对象状态。
- 权限和交易许可。
- 审批状态。
- 对账状态。
- 任务或运行状态。

公共状态引用唯一状态文档；模块只补充专项状态和映射。

## 12. 权限、审批与审计

至少说明：

- 所需 Capability。
- Data Scope。
- 敏感字段。
- 高风险动作。
- ApprovalPolicy。
- 操作日志和审计字段。
- 前端禁用和后端拒绝的关系。

## 13. 异常、空数据与降级

至少覆盖：

- Loading。
- Empty。
- Delayed／Stale。
- Partial。
- Conflict。
- Error。
- Permission Denied。
- Read Only。
- Degraded。
- Result Unknown，适用时。

说明每种状态：

- 用户看到什么。
- 能做什么。
- 不能做什么。
- 如何恢复。

## 14. 跨模块关系

使用表格说明：

| 相关模块 | 读取内容 | 发起内容 | 数据权威 | 跳转上下文 |
|---|---|---|---|---|

不得仅写“与其他模块联动”，必须明确对象和方向。

## 15. 非功能要求

引用全局非功能要求，并补充模块专项要求：

- 性能。
- 数据新鲜度。
- 可用性。
- 安全。
- 审计。
- 可恢复性。
- 导出和报表。
- 桌面和移动端。
- 大数据量和分页。

## 16. 前端要求

只写产品和架构要求，不写当前具体文件：

- Module Shell。
- Page Orchestrator。
- Repository／Adapter。
- Domain Model／View Model。
- 本地状态和服务端状态。
- 路由恢复。
- 共享组件。

## 17. 后端与数据依赖

说明：

- 主责领域。
- 依赖领域。
- Read Model。
- 外部数据和 Gateway。
- 是否需要异步任务。
- 是否需要事件、对账和恢复。

不在需求文档中锁死数据库、中间件和部署产品，除非已经形成 ADR。

## 18. 报表、导入与导出

按模块适用性说明：

- 可导出内容。
- 文件格式。
- 数据范围。
- 数据截止时间。
- 版本。
- 正式与临时结果。
- 导入校验、错误和修正。

## 19. 数据安全与隐私

说明：

- 敏感级别。
- 脱敏要求。
- 前端展示范围。
- 导出限制。
- 日志限制。
- AI 使用限制。
- 保存和删除要求。

## 20. 验收标准

验收应可测试，至少包括：

- 用户任务完成。
- 范围与边界正确。
- 权限正确。
- 数据来源和质量可见。
- 异常和降级正确。
- 路由和刷新可恢复。
- 跨模块不产生第二套事实。
- 关键 Query、Command 和 Event 语义正确。
- 非功能要求达到目标或具有明确差异说明。

## 21. 未决事项

只列真正未确认的内容：

- 业务规则。
- 数据来源。
- 权限。
- 技术决策。
- 依赖。

未决事项不得在正文中伪装为已确认结论。

- [ ] 数据对象、来源、时间和质量明确。
