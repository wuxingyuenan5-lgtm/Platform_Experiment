# 一级模块定位总表

状态：`active`  
产品基线：Platform V5  
架构版本：Platform V6  
适用分支：`refactor/frontend-architecture-v6`  
文档层级：产品架构

## 1. 文档定位

本文档是平台一级产品模块、核心职责和模块文档完整性的总入口。

一级模块按照用户任务和产品入口划分；前端目录、后端领域、数据库表、Gateway 或隐藏路由不改变产品层级。产品归属、技术领域和数据权威必须分别判断，详细映射参见 `docs/architecture/module-ownership-matrix.md`。

## 2. 一级产品架构

平台固定包含六个一级模块：

1. 首页。
2. 对冲基金看板。
3. 新闻日历与理财。
4. 策略。
5. 风险管理。
6. 金融AI分析。

| 一级模块 | 核心定位 | 主要子板块 |
|---|---|---|
| 首页 | 品牌入口、少量关键摘要和核心业务导航 | 品牌主视觉、市场摘要、模块入口、重要状态提示 |
| 对冲基金看板 | 宏观、资产类别和跨市场变量研究，以及研究工具聚合 | 宏观、商品、加密、美股、A 股、全球、交易工具 |
| 新闻日历与理财 | 事件、新闻摘要和理财机会信息的整理与筛选 | 宏观日历、新闻整理、理财信息 |
| 策略 | 具体投资策略的分析、平台执行、结果统计和复盘 | 交易平台、策略管理 |
| 风险管理 | 风险及平台内部管理能力的集中产品入口 | 风控详情、账户与资产、财务与资金、数据与服务监控、报表、审计、用户与权限、个人账号、系统设置、消息通知 |
| 金融AI分析 | 对授权研究信息和业务数据进行归纳、问答、情景推演和结构化输出 | 研究问答、信息归纳、情景推演、策略 Memo、分析任务与结果 |

## 3. 模块边界

### 3.1 首页

只负责品牌、摘要和导航，不建设第二套研究、策略、风险或管理工作台。

### 3.2 对冲基金看板

负责结构化研究与研究工具入口，不提供正式交易主操作，不承担策略长期绩效管理。

### 3.3 新闻日历与理财

负责内容与日历信息整理，不将新闻方向标签直接解释为交易信号，也不代替用户执行申购或资金操作。

### 3.4 策略

固定包含：

- 交易平台：行情分析和交易执行，只覆盖资费套利、跨所价差、海内外价差。
- 策略管理：策略损益、账户资金和订单信息，覆盖全部六类纳管策略。

交易平台负责当前分析与执行工作流；策略管理负责实际结果查询、统计、核对和复盘。

### 3.5 风险管理

风险管理是产品导航容器，不是一个吞并 Account、IAM、Audit、Reporting、Configuration 等全部后端能力的巨大 Risk 技术模块。

各子板块的数据权威和技术领域以职责矩阵为准。例如账户主档属于 Account，用户权限属于 IAM，审计记录属于 Audit，风险规则与风险事件属于 Risk。

### 3.6 金融AI分析

负责分析任务和可追溯输出，不拥有原始行情、新闻、订单、损益和风险事实；AI 结果不能直接成为正式交易指令、风险处置或最终投资结论。

## 4. 跨模块协作原则

- 首页通过 Backend Read Model 展示少量摘要，不复制源模块事实。
- 对冲基金看板消费 Research Data，并可只读展示部分 Execution Market Data。
- 新闻日历与理财消费 Content and Calendar Data。
- 交易平台通过 Platform API 查询行情、账户、风险和交易许可，并提交 TradeCommand。
- 策略管理通过 Read Model 查询 PnL、Account、Position、Order、Fill、Reconciliation 和 Data Quality 结果。
- 风险管理读取权威业务事实并维护风险规则、判断、事件和处置。
- 金融AI分析只读取授权数据并保留来源、时间和不确定性。

页面之间不得互相复制和同步第二套订单、账户、持仓、损益或风险状态。

## 6. 产品文档与实现记录边界

模块定位和需求文档只定义：

- 用户任务。
- 产品范围。
- 页面和信息架构。
- 权限与交互。
- 数据语义和质量要求。
- 跨模块边界。
- 非功能要求和验收标准。

具体 Vue 文件、Mock 位置、已完成代码、文件过大等实现情况不属于产品定义，应进入审计、版本说明或实施盘点文档。

## 7. 验收标准

- 产品入口仅包含六个一级模块。
- 正式名称统一使用“金融AI分析”。
- 每个一级模块均有定位和需求文档。
- 策略的两个二级模块均有独立定位和需求文档。
- 页面归属不会被误认为后端领域和数据权威。
- 同一核心业务事实不存在多个冲突写入入口。
- 模块间通过权威领域数据、Query、Command 和 Event 协作，而不是前端页面相互复制状态。
