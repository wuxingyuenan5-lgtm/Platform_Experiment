# 首页：需求文档

状态：`active`  
产品基线：Platform V5  
架构版本：Platform V6  
适用分支：`refactor/frontend-architecture-v6`  
文档层级：一级产品模块需求

模块定位依据：`docs/modules/首页-模块定位.md`

## 1. 文档定位

本文档定义首页的产品范围、信息结构、数据要求、权限、交互、非功能要求和验收标准。

首页是平台品牌入口、少量关键摘要和核心模块导航页，不承担任何业务模块的完整工作流。

## 2. 产品目标

首页应帮助用户：

1. 快速理解平台定位。
2. 查看少量高优先级市场或平台摘要。
3. 进入六个一级模块中的授权入口。
4. 识别需要立即关注的重要状态。
5. 在不加载完整业务页面的情况下完成初步导航。

## 3. 核心用户

- 首次进入平台的用户。
- 日常需要快速跳转的用户。
- 投资、研究和管理观察人员。
- 具有不同模块权限的数据范围用户。

## 4. 信息架构

首页按以下顺序组织：

1. 品牌主视觉与平台定位。
2. 主要模块入口。
3. 少量跨资产市场摘要。
4. 重要风险、任务或数据状态提示，适用时。
5. 辅助说明与版本信息，适用时。

首页不得演变为完整经营驾驶舱或第二套风险、策略和研究总览。

## 5. 模块入口

可配置入口包括：

- 对冲基金看板。
- 新闻日历与理财。
- 策略。
- 风险管理。
- 金融AI分析。

首页本身已经是当前一级入口，不重复设置“首页入口”。

规则：

- 入口必须与正式路由一致。
- 无页面访问权限的入口按照产品规则隐藏或禁用并说明原因。
- 不因新增普通页面自动增加首页卡片。
- 入口排序和文案由首页配置管理，不在多个组件重复定义。

## 6. 市场摘要

市场摘要只展示少量高价值指标，例如主要资产价格、涨跌、风险指标或宏观变量摘要。

每项摘要至少表达：

- 指标名称。
- 当前值与单位。
- 方向或变化。
- 数据时间。
- 数据来源或来源类型。
- 数据质量状态。
- 目标模块跳转，适用时。

市场摘要通过 Backend Read Model 或稳定 Query 获取，不拥有 Execution Market Data 或 Research Data 的权威事实。

## 7. 重要状态提示

首页可以展示有限提示：

- 关键风险阻断或风险事件数量。
- 交易或数据服务不可用。
- 待处理审批或人工任务。
- 高优先级消息。

规则：

- 只展示摘要和跳转。
- 不在首页完成风险处置、审批决定或交易操作。
- 状态来源必须为权威服务或 Read Model。
- 无权限用户不得看到敏感账户、策略和事件详情。

## 8. 数据与状态

首页展示数据应包含：

- `dataTime` 或业务时间。
- `source`。
- `qualityStatus`。
- `isEstimated`，适用时。
- `lastUpdated`。

页面应区分：

- 加载中。
- 刷新中。
- 空数据。
- 延迟或失效。
- 部分数据。
- 查询失败。

不得使用静态示例数据冒充实时数据。

## 9. 交互要求

- 核心入口在首屏可识别。
- 市场摘要支持跳转至相应研究模块，适用时。
- 页面刷新后不依赖大量本地业务状态恢复。
- 外部链接明确标识跳转目标。
- 概念设计文字不应长期作为正式用户文案。

## 10. 权限与安全

- 首页入口根据页面访问能力和数据范围展示。
- 首页不保存长期有效敏感凭证。
- 首页摘要不暴露未授权账户、策略、订单和审计信息。
- 前端隐藏入口不能替代后端 Query 权限校验。

## 11. 非功能要求

- 桌面端首屏层级清晰。
- 核心入口和摘要在常用分辨率下无需页面级横向滚动。
- 单个摘要源失败不得导致首页整体白屏。
- 页面应支持区块级错误边界和降级。
- 不因动画和高饱和视觉干扰信息阅读。

## 12. 明确不负责

- 完整研究图表和工具目录。
- 新闻和理财完整列表。
- 交易参数和正式下单。
- 策略损益、账户资金和订单管理。
- 风险规则、审批和风险处置。
- AI 分析任务执行。
- 系统级管理主操作。

## 13. 验收标准

- 首页清楚表达平台定位。
- 用户可以进入所有授权一级模块。
- 风险管理是否进入首页由配置和权限明确控制，不再被遗漏。
- 摘要具有数据时间、来源和质量状态。
- 首页不形成第二套业务事实或管理入口。
- 加载、空数据、延迟和错误状态完整。
- 页面不包含正式交易、风险处置和系统管理主操作。
