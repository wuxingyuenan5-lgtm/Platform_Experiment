# 策略管理：模块定位

状态：`active`  
适用基线：Platform V5

## 1. 模块定位

策略管理是面向全部纳管策略的结果统计、资金观察、订单查询和复盘工作台。

它既管理通过交易平台执行的策略，也管理不通过交易平台下单、但需要被统一统计和监督的策略。

当前纳管策略包括：

- 资费套利。
- 跨所价差。
- 海内外价差。
- 抄底。
- 短线交易员 L。
- 短线交易员 W。

其中抄底及两个短线交易策略当前不进入交易平台，但必须进入策略管理。这是既定业务规则。

## 2. 核心用户

- 策略负责人。
- 投资管理人员。
- 负责资金和风险观察的人员。
- 需要查询订单、成交和执行记录的管理人员。

## 3. 核心任务

用户进入策略管理后，需要完成：

1. 选择需要查看的策略。
2. 判断策略整体表现和当前状态。
3. 查看收益、成本和风险归因。
4. 查看策略相关账户的资金使用、安全状态和效率。
5. 查询当前持仓、历史订单、成交和执行记录。
6. 对异常表现或异常执行进行穿透和复盘。

## 4. 固定页面结构

### 4.1 策略损益

回答：

- 策略赚了多少钱？
- 收益来自哪里？
- 成本和损失来自哪里？
- 当前收益是否伴随明显风险或执行偏差？

主要内容：

- 损益总览。
- 日度收益和净值曲线。
- 损益归因。
- 损益细分表。
- 损益细分曲线。
- 策略腿或标的贡献。
- 必要的执行偏差和风险补充。

### 4.2 账户资金

回答：

- 策略当前使用了多少资金？
- 可用资金、保证金和资金占用如何？
- 账户当前是否存在明显风险？
- 净值、回撤和资金效率如何变化？

主要内容：

- 账户总览。
- 可用资金和资金占用。
- 保证金和风险占用。
- 双端或多端账户对照。
- 资金效率。
- 净值和回撤曲线。
- 当前适用的基础风险指标和风险状态。

策略管理负责展示账户和策略风险状态，不负责定义全局风险规则。

平台处于初创阶段时，风险能力采用轻量、渐进式建设：

- 初期先覆盖关键指标、明显异常和基础限制。
- 不要求一开始建立大量复杂或过严规则。
- 风险阈值、限制和执行标准应根据真实交易、回撤、资金占用和异常记录逐步测试与校准。
- 已验证的规则再由风险管理形成正式口径，策略管理负责读取和展示。

### 4.3 订单信息

回答：

- 当前持有什么？
- 历史上执行了哪些订单？
- 每条腿和每次成交的实际结果是什么？
- 是否存在失败、撤单、部分成交或人工干预？

主要内容：

- 当前持仓。
- 历史订单。
- 成交记录。
- 执行记录。
- 时间筛选。
- 订单状态筛选。
- 分页和总数。

订单信息页是主要查询和复盘入口，不承担实时下单主操作。

## 6. 模块主责的查询和管理视图

策略管理是以下内容的主要查询、统计和复盘入口：

- 策略统计口径。
- 策略损益和归因结果。
- 策略净值和回撤。
- 策略相关账户资金视图。
- 完整持仓查询。
- 历史订单查询。
- 成交记录。
- 执行记录。
- 策略管理视角下的风险状态。

这些内容描述前端模块职责，不代表订单、成交、持仓、账户等底层数据只属于策略管理页面。

实时交易指令不由本模块发起。

## 7. 明确负责

- 所有纳管策略的统一统计入口。
- 策略损益、账户资金和订单信息三类固定页面。
- 平台执行策略和非平台执行策略的统一结果管理。
- 策略间一致的基础展示框架。
- 各策略特有的损益、资金、订单和风险字段。
- 历史查询、筛选、分页和穿透。
- 已确认风险指标和风险状态的展示。

## 8. 明确不负责

- 实时行情机会判断。
- 正式下单、改单和撤单主操作。
- 双腿实时执行和配平。
- 完整宏观和资产类别研究。
- 全局风险规则、阈值和处置标准的最终维护。
- 用户、权限和系统配置。

## 9. 与其他模块的关系

### 交易平台

交易平台负责执行过程；策略管理负责实际结果的统计、查询、归档和复盘。

### 非平台执行来源

抄底、短线交易员 L 和短线交易员 W 即使不经过交易平台，也必须使用统一策略 ID 和统一管理结构进入策略管理。

### 风险管理

策略管理向风险管理提供损益、资金、持仓、订单和异常记录，并读取已确认的风险规则和状态。

初期风险规则可以较少、较宽松，但必须保留记录和复盘能力，以便后续根据真实数据逐步形成可执行标准。

### 账户与资产子板块

账户与资产子板块负责账户主档和平台级账户信息；策略管理展示与具体策略相关的账户资金视图。

## 10. 验收标准

- 策略管理展示 `management.enabled = true` 的全部六类策略。
- 抄底和两个短线策略不因未进入交易平台而缺失。
- 每类策略都具备损益、资金和订单三类管理能力。
- 策略管理不提供正式实时下单入口。
- 同一策略在不同 Mock、页面和组件中使用同一个策略 ID。
- 订单、成交和执行记录可以进行统一筛选和穿透。
- 风险展示保持轻量可用，并支持后续根据真实数据逐步校准规则。
