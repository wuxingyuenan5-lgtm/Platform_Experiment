# 策略管理：模块定位

状态：`active`  
适用基线：Platform V5

## 1. 模块定位

策略管理是面向全部纳管策略的结果统计、资金观察、订单归档和复盘工作台。

它既管理通过交易平台执行的策略，也管理不通过交易平台下单、但需要被统一统计和监督的策略。

当前纳管策略包括：

- 资费套利。
- 跨所价差。
- 海内外价差。
- 抄底。
- 短线交易员 L。
- 短线交易员 W。

其中抄底及两个短线交易策略当前不进入交易平台，但必须进入策略管理。这是既定业务规则。

## 2. 核心用户

- 策略负责人。
- 投资管理人员。
- 负责资金和风险观察的人员。
- 需要查询订单、成交和执行记录的管理人员。

## 3. 核心任务

用户进入策略管理后，需要完成：

1. 选择需要查看的策略。
2. 判断策略整体表现和当前状态。
3. 查看收益、成本和风险归因。
4. 查看策略相关账户的资金安全和使用效率。
5. 查询当前持仓、历史订单、成交和执行记录。
6. 对异常表现或异常执行进行穿透和追溯。

## 4. 固定页面结构

策略管理固定分为：

### 4.1 策略损益

回答：

- 策略赚了多少钱？
- 收益来自哪里？
- 成本和损失来自哪里？
- 当前收益是否伴随异常风险或执行偏差？

主要内容：

- 损益总览。
- 日度收益和净值曲线。
- 损益归因。
- 损益细分表。
- 损益细分曲线。
- 策略腿或标的贡献。
- 必要的执行偏差和风险补充。

### 4.2 账户资金

回答：

- 策略当前使用了多少资金？
- 账户是否安全？
- 资金占用和效率如何？
- 净值和回撤如何变化？

主要内容：

- 账户总览。
- 可用资金和资金占用。
- 保证金和风险占用。
- 双端或多端账户对照。
- 资金效率。
- 净值和回撤曲线。
- 策略特有风控规则。

### 4.3 订单信息

回答：

- 当前持有什么？
- 历史上执行了哪些订单？
- 每条腿和每次成交的实际结果是什么？
- 是否存在失败、撤单、部分成交或人工干预？

主要内容：

- 当前持仓。
- 历史订单。
- 成交记录。
- 执行记录。
- 时间筛选。
- 订单状态筛选。
- 分页和总数。

订单信息页是档案和穿透查询页面，不承担实时下单主操作。

## 5. 策略范围

| 策略 | 策略损益 | 账户资金 | 订单信息 | 是否通过交易平台下单 |
|---|---:|---:|---:|---:|
| 资费套利 | 有 | 有 | 有 | 是 |
| 跨所价差 | 有 | 有 | 有 | 是 |
| 海内外价差 | 有 | 有 | 有 | 是 |
| 抄底 | 有 | 有 | 有 | 否 |
| 短线交易员 L | 有 | 有 | 有 | 否 |
| 短线交易员 W | 有 | 有 | 有 | 否 |

## 6. 模块拥有的业务对象

策略管理主要拥有：

- 策略统计口径。
- 策略损益和归因结果。
- 策略净值和回撤。
- 策略相关账户资金视图。
- 完整持仓档案。
- 历史订单档案。
- 成交记录。
- 执行记录。
- 策略管理视角下的风险状态。

实时交易指令不由本模块拥有。

## 7. 明确负责的内容

- 所有纳管策略的统一统计入口。
- 策略损益、资金和订单三类固定管理页面。
- 平台执行策略和外部执行策略的统一结果管理。
- 策略间一致的基础展示框架。
- 各策略特有的损益、资金、订单和风险字段。
- 历史查询、筛选、分页和穿透。

## 8. 明确不负责的内容

- 实时行情机会判断。
- 正式下单和改单撤单主操作。
- 双腿实时执行和配平。
- 完整宏观和资产类别研究。
- 全局风险规则的制定和维护。
- 用户、权限和系统配置。

## 9. 与其他模块的关系

### 交易平台

输入：通过平台执行的策略产生的订单、成交、持仓和执行结果。  
边界：交易平台负责执行过程，策略管理负责结果归档、统计和复盘。

### 非平台执行来源

输入：抄底、短线交易员 L 和短线交易员 W 的策略结果。  
边界：即使不经过交易平台，也必须以统一策略 ID 和统一管理结构进入策略管理。

### 风控相关模块

输入：风险规则和告警结果。  
输出：策略损益、资金、持仓和订单数据，为风险判断提供依据。

## 10. 当前 V5 实现状态

已实现：

- 六类策略切换。
- 策略损益、账户资金和订单信息三页结构。
- 策略损益总览、归因和曲线。
- 账户资金、风险、净值和回撤相关组件。
- 当前持仓、历史订单、成交和执行记录。
- 日期、状态和分页筛选。

待完善：

- 统一策略注册表。
- 各 Mock 文件统一使用策略 ID 类型。
- 模块级需求和策略级需求文档。
- 组件职责进一步拆分。
- 非平台执行策略的数据接入方式，本轮暂不考虑后端实现。

## 11. 验收标准

- 策略管理展示注册表中 `management.enabled = true` 的全部策略。
- 抄底和两个短线交易策略不因未进入交易平台而缺失。
- 每类策略都具备损益、资金和订单三类管理能力。
- 策略管理不提供正式实时下单入口。
- 同一策略在不同 Mock、页面和组件中使用同一个策略 ID。
- 订单、成交和执行记录可以进行统一筛选和穿透。
