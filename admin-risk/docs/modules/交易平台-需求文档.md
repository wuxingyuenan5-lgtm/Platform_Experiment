# 交易平台：需求文档

状态：`active`  
产品基线：Platform V5  
架构版本：Platform V6  
适用分支：`refactor/frontend-architecture-v6`  
文档层级：二级产品模块需求

模块定位依据：`docs/modules/交易平台-模块定位.md`

## 1. 文档定位

本文档定义交易平台的产品范围、信息架构、分析与执行流程、权限、运行上下文、数据、状态、异常、交互和验收标准。

交易平台是策略模块中的交易前分析与交易执行工作台，不承担完整市场研究、长期策略绩效、账户主档、公司财务、用户权限和全局风险规则管理。

## 2. 产品目标

交易平台应支持用户完成：

1. 选择策略实例、市场、标的和账户。
2. 观察市场状态并识别机会。
3. 评估价差、费率、历史位置、成本、收益和风险。
4. 配置两条交易腿的方向、数量、价格和订单类型。
5. 确认部署环境、交易模式和交易能力。
6. 完成前端字段校验和服务端执行前校验。
7. 提交具有幂等标识的 TradeCommand。
8. 跟踪 ExecutionBatch、LegInstruction、Order 和 Fill。
9. 识别部分成交、结果未知、执行配平偏差和未对冲暴露。
10. 在权限范围内执行撤单、补单、配平、终止或人工处理。
11. 通过后端权威事实供策略管理查询和复盘。

## 3. 策略范围

| 策略 | StrategyId | 行情分析 | 交易执行 | 当前结构 |
|---|---|---:|---:|---|
| 资费套利 | `funding` | 有 | 有 | 现货腿 + 永续腿 |
| 跨所价差 | `crossSpread` | 有 | 有 | 两个交易场所或市场的双腿结构 |
| 海内外价差 | `domesticOverseas` | 有 | 有 | 国内腿 + 海外腿，包含汇率因素 |

以下策略不进入交易平台：

- 抄底。
- 短线交易员 L。
- 短线交易员 W。

策略名称、ID、排序和产品能力由统一策略注册表和能力矩阵维护，不在页面中重复定义。

## 4. 用户、权限与数据范围

### 4.1 用户类型

- 研究和交易人员。
- 策略负责人。
- 只读观察人员。
- 异常处理和授权操作人员。

### 4.2 操作能力

至少区分：

- `strategy.platform.read`。
- `strategy.execution.prepare`。
- `strategy.execution.submit`。
- `strategy.execution.cancel`。
- `strategy.execution.close`。
- `strategy.execution.rebalance`。
- `strategy.execution.override`。
- `strategy.execution.manualResolve`。

页面访问权限、操作能力、数据范围、RiskDecision、TradingPermissionState 和 ApprovalPolicy 分别判断。

无提交权限的用户可以按产品规则查看执行上下文，但正式动作必须隐藏或禁用并显示原因。前端控制不能替代后端最终校验。

## 5. 运行上下文

页面持续表达：

- DeploymentEnvironment：development、testing、staging、production。
- TradingMode：demo、simulation、paper、live。
- TradingPermissionState：disabled、read_only、enabled、blocked。
- 当前 StrategyInstance。
- 当前账户和数据范围。
- Gateway、执行服务和行情质量。

规则：

- `production` 不等于 `live`。
- Demo、Simulation、Paper 和 Live 使用清晰不混淆的文案。
- 运行上下文未知时禁止正式交易。
- 页面不得通过 URL query 或本地常量决定 Live 能力。
- Live 动作需要服务端综合权限、风险、账户、Gateway、服务和行情质量判断。

## 6. 信息架构与路由

交易平台具有两个主要切换维度：

1. 策略。
2. 视角：行情分析、交易执行。

推荐路由语义：

```text
/strategy/platform?strategy=funding&view=analysis
/strategy/platform?strategy=crossSpread&view=execution
```

规则：

- StrategyId 必须有效且 `platform.enabled = true`。
- 非法参数回退至安全默认值并修正 URL。
- 切换策略默认进入目标策略的行情分析。
- 同一策略内从分析进入执行时可以传递稳定、兼容的市场上下文。
- 未提交交易参数不跨策略继承。
- 离开存在未提交参数的执行页前提示确认。

## 7. 行情分析

### 7.1 页面目标

用于回答：

- 当前是否存在交易机会。
- 机会处于何种历史位置。
- 收益是否覆盖成本和风险。
- 应选择哪些场所、标的、合约或市场组合。

### 7.2 页面结构

1. 策略、市场和数据上下文。
2. 当前机会摘要。
3. 核心价格、价差或费率图表。
4. 历史分位和统计分析。
5. 市场结构、期限结构或跨市场对比。
6. 成本、预计收益和风险补充。

具体区块由对应策略文档定义；不适用内容不显示空白卡片。

### 7.3 通用筛选

根据策略能力支持：

- 交易所、市场或交易场景。
- 标的和合约。
- 主腿和对冲腿。
- 时间精度。
- 统计区间和日期范围。
- 计价币种。
- 策略特有条件。

图表、指标和表格使用同一分析上下文。

### 7.4 数据要求

- 指标具有名称、单位、口径和时间。
- 报价具有 sourceTime、receivedAt 和 QuoteStatus。
- 研究指标具有数据截止时间、来源和 DataQualityStatus。
- 估算值明确标记。
- 延迟、失效、缺失、冲突和计算失败明确展示。
- 行情分析不提供正式下单主操作。

## 8. 交易执行

### 8.1 标准业务链路

```text
前端准备 TradeIntent
→ 提交 TradeCommand
→ 后端校验权限、数据范围、运行上下文、参数、风险、审批和幂等
→ 创建 ExecutionBatch
→ 创建 LegInstruction
→ Gateway 提交 Order
→ 接收 Order 回报与 Fill
→ 更新 Position、ExecutionBalanceStatus 和 ExposureStatus
→ 完成、异常、结果未知或人工处理
```

前端不得分别提交两张权威订单后自行拼接为双腿批次。

### 8.2 执行前状态区

必须展示：

- DeploymentEnvironment 和 TradingMode。
- TradingPermissionState 和禁用原因。
- 最新报价、时间和质量。
- Gateway 和执行服务状态。
- 账户、余额和保证金摘要。
- RiskDecision、限制和 GlobalTradingBlock。
- 当前是否需要 ApprovalGrant。

### 8.3 交易参数

根据策略支持：

- 开仓、平仓或调整。
- 两腿角色和买卖方向。
- 账户和交易场所。
- 标的和合约。
- 订单类型。
- 委托价格和数量。
- 目标名义价值或比例。
- 滑点、限价偏移和价格保护参数。

未提交参数属于页面本地状态，不是后端业务事实。

### 8.4 执行影响预估

提交前至少展示：

- 两腿目标数量和名义价值。
- 目标配平关系。
- 预计手续费和滑点。
- 预计持仓或资金成本。
- 预计毛收益和净收益。
- 执行后资金占用和保证金变化。
- 主要风险和敏感假设。
- 计算时间、币种和是否估算。

预计值不得与实际 PnLResult 混用。

### 8.5 前端校验

至少校验：

- 必填字段。
- 基本格式和数值范围。
- 数量大于零。
- 两腿方向和结构基本一致。
- 页面上下文完整。

前端校验只改善体验，不能代替服务端权限、账户、合约规则、风险和幂等校验。

### 8.6 服务端执行前校验

至少包括：

- 身份、能力和数据范围。
- DeploymentEnvironment、TradingMode 和交易许可。
- StrategyInstance 和 StrategyAccountBinding。
- Instrument 和 ContractSpecification。
- QuoteStatus 和必要数据质量。
- Account、BalanceSnapshot 和 MarginSnapshot。
- RiskDecision 和 GlobalTradingBlock。
- ApprovalGrant，适用时。
- `idempotencyKey` 和对象版本。

### 8.7 提交确认

正式提交前显示：

- 策略和策略实例。
- 运行环境和交易模式。
- 交易动作。
- 两腿账户、市场、标的和方向。
- 数量、价格和订单类型。
- 目标配平关系。
- 预计收益、成本、资金和风险。
- 限制、审批和数据质量提示。

### 8.8 命令请求

正式命令至少具有：

- `requestId`。
- `idempotencyKey`。
- 客户端时间。
- 目标 StrategyInstance。
- TradeIntent 参数。
- `approvalGrantId`，适用时。

操作人、权限、数据范围和运行上下文由受信任会话确定，不接受前端伪造。

## 9. 命令与执行反馈

### 9.1 TradeCommand

TradeCommand 只表达命令是否收到、校验、拒绝、受理或结果未知。

`accepted` 不表示订单已提交、成交或执行完成。

### 9.2 ExecutionBatch

ExecutionBatch 表达双腿执行的实际进度、异常和人工处理。

### 9.3 Order 与 Fill

- 每条腿可以产生一张或多张订单。
- 一张订单可以产生多笔 Fill。
- 撤单不删除已经发生的 Fill。
- 外部状态映射为平台状态并保留原始值。

### 9.4 配平与暴露

分别展示：

- ExecutionBalanceStatus。
- ExposureStatus。
- 目标关系。
- 实际成交关系。
- 容忍范围。
- 暴露数量、名义价值和持续时间。

## 10. 状态唯一来源

交易平台涉及：

- QuoteStatus。
- DataQualityStatus。
- TradingPermissionState。
- TradeCommandStatus。
- ExecutionBatchStatus。
- OrderStatus。
- ExecutionBalanceStatus。
- ExposureStatus。
- RiskStatus。
- GatewayStatus。

完整状态码和生命周期统一引用 `docs/architecture/domain/status-enums-and-lifecycles.md`，本文件不维护重复清单。

## 11. 异常和人工处理

至少识别：

- 报价过期或冲突。
- Gateway 或执行服务不可用。
- 命令拒绝。
- 命令或执行结果未知。
- 订单被拒绝或状态未知。
- 单腿成交和另一腿失败。
- 两腿部分成交。
- 配平超出容忍范围。
- 汇率或多腿暴露。
- 保证金或可用资金不足。
- 风险状态在执行中变化。
- 用户主动中止。

异常区域展示：

- 发生时间和原因码。
- 关联 TradeCommand、ExecutionBatch、LegInstruction、Order 和 Fill。
- 当前配平、暴露和风险。
- 已执行动作和允许动作。
- 操作人、备注、审批和审计信息。

`result_unknown` 不得直接当作失败后使用新幂等键重下。

## 12. 实时事件与恢复

实时推送可以包括：

- QuoteUpdated。
- TradeCommandAccepted 或拒绝结果。
- ExecutionBatchCreated／StatusChanged。
- OrderAcknowledged／PartiallyFilled 等订单事件。
- FillReceived。
- ExecutionBalanceStatusChanged。
- ExposureStatusChanged。
- RiskDecisionChanged。
- GatewayDisconnected。

断线恢复：

1. 标记实时数据可能过期。
2. 重新连接和认证。
3. 恢复订阅。
4. Query 当前 TradeCommand、ExecutionBatch、Order、Fill、Account、Position、Exposure 和 Risk。
5. 用权威快照覆盖本地状态。
6. 恢复操作能力。

恢复完成前禁止重复提交同一命令。

## 13. 策略差异

| 策略 | 行情分析重点 | 执行重点 | 业务口径来源 |
|---|---|---|---|
| 资费套利 | 资金费率、综合基差、多交易所机会和收益持续性 | 现货腿与永续腿、资金费影响和名义价值配平 | `docs/strategies/资费套利.md` |
| 跨所价差 | 跨市场价差、历史分位、区间统计和市场结构 | 两市场报价、目标价差、双腿比例和执行偏差 | `docs/strategies/跨所价差.md` |
| 海内外价差 | 内外盘换算、汇率、价差分位和持仓成本 | 国内腿、海外腿、汇率影响和双账户资金 | `docs/strategies/海内外价差.md` |

海内外价差当前正式口径以黄金为主；其他标的需在换算、合约和损益口径确认后启用。

## 14. 数据与数值要求

核心关联 ID：

- `strategyId`。
- `strategyInstanceId`。
- `tradeCommandId`。
- `executionBatchId`。
- `legInstructionId`。
- `orderId`。
- `executionId`。
- `accountId`。
- `instrumentId`。

时间至少区分 occurredAt、sourceTime、receivedAt、calculatedAt 和 updatedAt。

金额、价格、数量、比例和汇率明确：

- 原始数值。
- 币种和单位。
- 合约乘数。
- 精度。
- 汇率来源和时间。
- 预计或实际属性。

正式金融计算避免依赖 JavaScript 浮点数。

## 15. UI 与交互

遵循：

- `docs/design/platform-ui-guidelines.md`
- `docs/architecture/shared-ui-governance.md`

特有要求：

- 策略切换和分析／执行切换使用不同视觉层级。
- 页面持续显示运行上下文。
- 正式、普通和危险操作具有明确层级。
- 同一区域最多一个主要交易动作。
- 两腿参数、订单、成交、配平和暴露保持视觉关联。
- 禁用动作显示明确原因。
- 加载、空数据、延迟、错误、结果未知和人工处理状态完整。

## 16. 跨模块关系

- 对冲基金看板提供研究背景和数据。
- 新闻日历与理财提供事件提醒。
- 策略管理查询后端实际结果，不接收页面复制对象。
- 风险管理维护规则、事件、限制和审批入口。
- 账户与资产维护 Account 主档；Strategy 维护绑定。
- 金融AI分析可以读取授权材料，不修改执行事实。

## 17. 非功能要求

- 桌面交易工作台优先。
- 前端断线不终止后台执行。
- Command 具有幂等和可追踪上下文。
- 高频行情渲染不能阻塞订单和风险事件。
- 页面和服务重启后可恢复未完成批次。
- 关键动作和人工处理可审计。
- Demo、Simulation、Paper 和 Live 清晰隔离。

## 18. 验收标准

### 范围

- 只展示三类平台执行策略。
- 非平台执行策略无空交易页面。

### 行情分析

- 统一市场、标的、时间、币种和数据上下文。
- 指标具有来源、口径、时间和质量。
- 不提供正式下单主操作。

### 交易执行

- 完整展示运行上下文、参数、预估、校验和确认。
- TradeCommand 与 ExecutionBatch 分开。
- 双腿执行由后端批次组织。
- 幂等、审批和服务端校验有效。
- 部分成交、结果未知、未配平和人工处理可表达。

### 数据和状态

- 状态统一引用公共枚举。
- 订单、成交、配平、暴露和风险使用独立维度。
- 核心对象通过稳定 ID 关联。
- 页面能够通过 Query 恢复权威状态。

### UI

- 正式交易、普通操作和危险操作层级明确。
- 两腿参数和结果保持视觉关联。
- 禁用原因、数据质量和交易模式清晰可见。
