# 交易平台：需求文档

状态：`active`  
适用基线：Platform V5  
模块定位依据：`docs/modules/交易平台-模块定位.md`

## 1. 文档目的

本文档定义交易平台在当前前端阶段的产品需求、页面职责和验收口径。

本轮不涉及：

- 后端服务设计。
- 数据库设计。
- 实时行情和交易接口接入。
- 抄底、短线交易员 L、短线交易员 W 的平台下单。

交易平台当前仅覆盖：

- 资费套利。
- 跨所价差。
- 海内外价差。

## 2. 模块目标

交易平台应帮助用户完成一条完整但边界清晰的盘中工作流：

1. 选择策略和交易上下文。
2. 在行情分析页判断是否存在机会。
3. 查看与交易决策直接相关的市场结构、统计和成本。
4. 进入交易执行页确认参数和风险。
5. 提交交易指令。
6. 查看成交、配平、暴露和执行反馈。

交易平台不是完整研究中心，也不是盘后绩效管理模块。

## 3. 用户角色

### 3.1 交易人员

主要任务：

- 观察机会。
- 设置交易参数。
- 执行开仓、平仓和调整。
- 处理单腿暴露和执行异常。

### 3.2 策略负责人

主要任务：

- 复核交易逻辑。
- 确认机会和风险是否满足策略要求。
- 查看当前持仓、配平和执行状态。

### 3.3 管理观察人员

主要任务：

- 查看当前策略运行和执行概况。
- 不默认拥有正式下单权限。

权限控制属于后续系统能力，本轮仅保留角色差异的产品边界。

## 4. 策略范围和能力

| 策略 | 行情分析 | 交易执行 | 核心结构 |
|---|---:|---:|---|
| 资费套利 | 有 | 有 | 现货腿 + 永续腿 |
| 跨所价差 | 有 | 有 | 两个不同市场或交易场所的对冲腿 |
| 海内外价差 | 有 | 有 | 国内腿 + 海外腿，附带汇率因素 |
| 抄底 | 无 | 无 | 不通过本平台执行 |
| 短线交易员 L | 无 | 无 | 不通过本平台执行 |
| 短线交易员 W | 无 | 无 | 不通过本平台执行 |

策略范围应由统一策略注册表控制，不在多个页面重复维护。

## 5. 信息架构

交易平台固定采用两层切换：

### 5.1 策略切换

固定展示：

- 资费。
- 跨所价差。
- 海内外价差。

### 5.2 工作模式切换

固定展示：

- 行情分析。
- 交易执行。

页面切换要求：

- 切换策略时默认回到行情分析。
- 当前策略、交易所、标的、时间精度等上下文应尽量保持一致。
- 不支持的组合不得显示空白执行页，应由策略能力配置决定是否展示。

## 6. 行情分析页通用需求

### 6.1 页面目标

行情分析页回答：

- 当前是否存在机会？
- 当前机会处于什么历史位置？
- 收益是否能够覆盖成本和潜在风险？
- 应选择哪个交易所、标的、合约或市场组合？

### 6.2 通用组成

每个策略的行情分析页可以从以下区块中按需组合：

1. 策略上下文筛选区。
2. 当前市场状态或机会摘要。
3. 核心主图。
4. 历史分位和统计分析。
5. 市场结构或期限结构。
6. 多交易所或多市场对比。
7. 策略特有补充研究区。

### 6.3 通用筛选条件

按策略需要提供：

- 交易所或交易场景。
- 标的。
- 主腿和对冲腿。
- 时间精度。
- 统计区间。
- 开始和结束日期。

筛选条件应在页面顶部或图表工具栏集中展示，不应分散在多个无关卡片中。

### 6.4 通用交互要求

- 筛选条件改变后，相关卡片和图表应使用同一分析上下文。
- 图表应具备悬浮提示。
- 长时间序列应支持缩放或时间区间选择。
- 表格应具备清晰单位和口径。
- 刷新按钮仅表达刷新行为，不承担参数确认。
- 行情分析页不得出现正式下单主按钮。

## 7. 交易执行页通用需求

### 7.1 页面目标

交易执行页回答：

- 当前是否允许执行？
- 应交易哪些腿、方向和数量？
- 预计收益、成本和风险是多少？
- 指令是否提交、成交和配平？
- 是否存在单腿暴露或其他异常？

### 7.2 通用组成

每个策略的交易执行页应从以下区块中按需组合：

1. 执行前状态区。
2. 市场报价和必要镜像信息。
3. 执行参数区。
4. 收益、成本和风险预估区。
5. 双腿或多腿配平区。
6. 当前执行订单区。
7. 当前持仓摘要。
8. 执行反馈和异常提示。

### 7.3 参数要求

按策略需要支持：

- 开仓、平仓或调整。
- 买卖方向。
- 账户或交易所。
- 标的或合约。
- 订单类型。
- 价格。
- 数量。
- 两腿比例。
- 滑点或价格保护参数。
- 必要的风险限制提示。

本轮只定义前端字段和交互，不定义真实订单接口。

### 7.4 执行状态

前端状态至少应能够表达：

- 待确认。
- 已提交。
- 部分成交。
- 全部成交。
- 已撤单。
- 执行失败。
- 单腿暴露。
- 已配平。
- 需要人工处理。

不同策略应复用统一状态语义，不应自行创造含义重复的状态名称。

## 8. 资费套利需求

### 8.1 行情分析

必须支持：

- 交易所切换。
- BTC、ETH 等标的切换。
- 当前资金费率。
- 历史资金费率曲线和分位。
- 现货与永续价差。
- 多交易所机会对比。
- 时间精度和统计区间切换。
- 当前机会的收益、成本和持续性判断信息。

### 8.2 交易执行

必须支持：

- 现货腿和永续腿参数。
- 两腿方向和数量。
- 预计资金费收益。
- 基差影响。
- 手续费和其他执行成本。
- 配平状态。
- 单腿暴露提示。
- 当前订单和持仓摘要。

### 8.3 明确边界

- 行情分析页不承担正式下单。
- 执行页只保留必要费率和基差信息，不复制完整研究图表。

## 9. 跨所价差需求

### 9.1 行情分析

必须支持：

- 主交易所切换。
- 主腿和对冲腿选择。
- 当前价差。
- 价差主图。
- 历史分位。
- 区间统计。
- 季节性或周期性分析。
- 必要的期限结构和机会分析。

### 9.2 交易执行

必须支持：

- 两个市场报价。
- 目标价差和当前价差。
- 双腿方向、价格和数量。
- 两腿比例与名义价值配平。
- 预计收益、手续费、滑点和资金成本。
- 当前持仓和两腿暴露。
- 执行反馈和人工处理入口。

### 9.3 明确边界

- 不将海内外汇率因素强行加入通用跨所价差模型。
- 跨所价差和海内外价差可以共享执行骨架，但保持独立业务口径。

## 10. 海内外价差需求

### 10.1 行情分析

必须支持：

- 金、银、铜等标的切换。
- 国内标的和海外标的选择。
- 内外盘换算关系。
- 汇率因子。
- 当前价差及历史走势。
- 区间分位和统计。
- 期限结构、库存费或年化分析。
- 实时价差列表。

### 10.2 交易执行

必须支持：

- 国内腿和海外腿参数。
- 汇率影响和换算价格。
- 双账户资金变化预估。
- 双腿方向、数量和配平。
- 预计手续费、资金成本和汇率影响。
- 执行后持仓和账户摘要。
- 单腿风险和汇率风险提示。

### 10.3 明确边界

- 行情分析中的汇率研究只保留与该策略直接相关的部分。
- 完整宏观汇率研究仍属于其他研究模块。

## 11. 通用视觉与组件要求

交易平台继续使用 V5 已建立的统一主题和页签基座。

应优先复用：

- `CompactSegmentTabs`。
- `strategy-theme.less` 中的主题变量。
- 统一按钮、输入框、选择器和卡片层级。

后续共享组件建议按真实复用需求逐步形成：

- 页面工具栏。
- 筛选栏。
- 指标卡片。
- 图表卡片。
- 状态标签。
- 数据表格。
- 执行反馈组件。

不要求本阶段立即完成组件重构。

## 12. 状态与异常展示

页面必须区分：

- 正常状态。
- 等待状态。
- 风险状态。
- 失败状态。
- 无数据状态。
- 数据或组件加载异常。

禁止使用只有颜色、没有文字含义的状态表达。

## 13. 当前前端数据约束

在后端接入前：

- 可以继续使用 Mock 数据。
- Mock 数据必须按统一策略 ID 组织。
- 页面不得将同一指标在多个组件内重复硬编码为不同值。
- 单位、币种和时间口径必须在数据结构或展示层明确。
- 前端演示数据不得被文档表述为真实业务数据。

## 14. 与其他模块的接口边界

### 14.1 对冲基金看板

交易平台可以引用与当前策略直接相关的研究结论或工具，但不复制完整研究看板。

### 14.2 策略管理

交易平台产生：

- 当前订单。
- 成交结果。
- 持仓结果。
- 执行记录。

策略管理负责长期归档、统计和复盘。

### 14.3 风控相关模块

交易平台读取并展示风险限制结果，执行前应能够表达允许、限制或禁止状态。

交易平台不拥有全局风险规则。

## 15. 非功能要求

- 页面切换不得出现明显布局跳变。
- 主要交互在常用桌面分辨率下无需横向滚动，超宽表格除外。
- 大型图表和工作台组件应具备独立错误边界或降级提示。
- 新增策略不得通过复制整个模块入口实现。
- 策略范围应由统一注册表决定。
- 当前阶段不为了未来后端提前引入复杂状态管理和接口层级。

## 16. 验收标准

### 16.1 架构验收

- 交易平台只展示三类平台执行策略。
- 策略名称和能力来自统一策略注册表。
- 模块入口只负责路由、页签和页面装配。
- 行情分析与交易执行职责清晰。

### 16.2 产品验收

- 三类策略均具备完整的行情分析页面。
- 三类策略均具备完整的交易执行页面。
- 行情分析页不出现正式下单主操作。
- 交易执行页具备参数、预估、状态和反馈四类信息。
- 关键指标具有明确名称、单位和统计口径。

### 16.3 前端验收

- 现有 V5 页面功能和主要交互不退化。
- 页签、卡片、按钮、输入控件遵循统一视觉基座。
- Mock 数据使用统一策略 ID。
- 页面具备空状态和异常状态。
