# 对冲基金看板：模块定位

状态：`active`  
适用基线：Platform V5

## 1. 模块定位

对冲基金看板是面向宏观、资产类别和跨市场变量的研究、观察和工具聚合模块。

它负责回答“市场发生了什么、关键变量如何传导、哪些研究工具可以继续深入”，不承担具体策略的正式下单、长期绩效管理和全局风险处置。

## 2. 当前固定栏目

- 宏观。
- 商品。
- 加密。
- 美股。
- A 股。
- 全球。
- 交易工具。

交易工具当前包含：

- 宏观工具。
- 股市工具。
- 加密工具。
- 金属工具。
- 量化工具。
- 综合工具。

本次不改变上述路由结构。

## 3. 核心用户

- 研究人员。
- 策略负责人。
- 需要观察跨资产变量的交易人员。
- 需要快速进入外部研究工具的用户。

## 4. 核心任务

用户进入后应能够：

1. 选择研究资产类别或市场范围。
2. 查看关键变量、图表、表格和市场快照。
3. 理解变量之间的相对关系和可能传导路径。
4. 跳转到对应的外部研究工具。
5. 将研究结论带入交易平台或策略判断，而不是在本模块直接下单。

## 5. 模块拥有的业务对象

- 研究分类和研究模块配置。
- 看板区块和图表配置。
- 市场快照和研究型指标展示。
- 本地图表或 TradingView 组件配置。
- 交易工具目录及其分类映射。
- 外部研究来源链接。

## 6. 明确负责的内容

- 宏观和跨资产研究看板。
- 商品、加密、美股、A 股和全球市场观察。
- 研究图表、市场快照和统计信息。
- 与研究分类对应的工具目录。
- 图表错误边界和外部来源入口。

## 7. 明确不负责的内容

- 具体策略正式下单。
- 完整交易执行面板。
- 策略损益和账户资金统计。
- 完整订单档案。
- 全局风险规则和处置。
- 新闻内容的长期整理和发布。

## 8. 看板与交易工具的关系

- 看板负责展示研究内容。
- 交易工具负责提供外部研究入口。
- 宏观、商品和加密看板可以在下方直接挂接对应工具目录。
- 工具目录的数据源以 `docs/trading-tools-bookmarks-review.md` 为主，通过同步脚本生成前端数据。
- 工具内容修改应优先修改 Markdown 源文档，不直接编辑生成文件。

## 9. 与其他模块的关系

### 交易平台

对冲基金看板提供研究背景；交易平台负责具体策略机会判断和执行。看板不得复制正式下单面板。

### 新闻日历与理财

新闻日历提供事件和新闻输入；看板可以引用研究结果，但不重复维护新闻列表。

### 金融 AI 分析

金融 AI 可以基于看板变量进行摘要和情景推演；看板本身仍保持结构化研究展示。

## 10. 当前 V5 实现状态

已实现：

- 六类看板路由。
- 统一顶部页签。
- 本地图表与 TradingView 图表混合渲染。
- 图表错误边界。
- 宏观、商品、加密下挂接交易工具目录。
- 交易工具 Markdown 自动同步机制。

当前技术债务：

- `hedgeBoard/index.vue` 文件过大，同时承担页面编排、图表渲染、数据和交互逻辑。
- 部分市场快照和图表数据硬编码在页面中。
- 不同看板的视觉和布局仍存在差异。
- 图表计算、区间拖动和页面结构耦合。

这些问题后续可在本地逐步拆分，本阶段只确定模块边界。

## 11. 后续前端治理要求

- 每个看板区块应具备明确研究目的。
- 图表配置、数据和页面编排逐步分离。
- 工具目录继续保持单一 Markdown 数据源。
- 不新增无决策价值的说明文字。
- 不把交易工具链接复制到多个不同数据文件。
- 不因复用交易平台组件而把正式交易操作带入看板。

## 12. 验收标准

- 六类看板和交易工具路由保持不变。
- 每个栏目具备清晰研究范围。
- 看板与交易工具关系明确。
- 看板不承担正式下单和策略管理。
- 工具目录可以由唯一 Markdown 源文件同步生成。
- 后续拆分大型页面时不改变现有产品结构。
