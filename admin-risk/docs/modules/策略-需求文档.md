## 1. 文档定位

本文定义策略一级模块的共同产品规则、策略范围、统一身份、运行上下文、二级模块协作、公共对象、权限、数据质量、异常处理和验收标准。

策略一级模块固定包含：

1. 交易平台。
2. 策略管理。

详细功能分别以以下文档为准：

- `交易平台-需求文档.md`。
- `策略管理-需求文档.md`。

各策略的交易结构、计算公式、损益归因、特有风险和数据来源以 `docs/strategies/` 下对应策略文档为准。一级模块和二级模块不得自行重新定义策略专属口径。

## 2. 产品定位

策略模块是平台将研究背景、交易执行、外部执行数据、账户资金、损益结果、风险状态和复盘材料连接起来的业务工作区。

它应形成以下闭环：

```text
研究与市场背景
→ 策略机会分析
→ 交易准备与执行，适用时
→ Order／Fill／Position 等实际事实
→ EconomicEvent 与 PnLResult
→ 策略管理查询、核对和复盘
→ 风险、报表和金融AI分析的授权读取
```

策略模块不承担：

- 全平台宏观与资产研究体系。
- Account、IAM、Risk、Audit、Reporting 的完整后台管理。
- 公司财务总账和经营资金管理。
- 外部交易系统凭证和 Gateway 运维主入口。
- 金融AI分析任务的编排与结果管理。

## 3. 产品目标

用户应能够：

1. 明确选择策略定义、策略版本和策略实例。
2. 对平台执行策略完成行情分析和机会判断。
3. 在授权范围内准备并提交交易命令。
4. 跟踪执行批次、交易腿、订单、成交、配平和暴露。
5. 对全部纳管策略查看损益、资金、持仓、订单和数据质量。
6. 将平台执行、外部执行和人工导入数据映射为同一套稳定业务对象。
7. 对订单、成交、持仓、账户和损益差异完成核对和审计。
8. 从汇总结果穿透至策略腿、账户、标的、执行批次、订单、成交和经济事件。
9. 识别未完成执行、异常资金变化、数据缺失、结果未知和人工干预。
10. 向风险管理、报表和金融AI分析提供受控、可追溯的结构化查询。

## 4. 目标用户、权限和数据范围

### 4.1 目标用户

- 研究和交易人员。
- 策略负责人。
- 投资管理人员。
- 风险、运营和数据核对人员。
- 异常处理和授权操作人员。
- 只读观察人员。
- 报表和金融AI分析任务使用者。

### 4.2 候选能力权限

读取能力：

- `strategy.platform.read`。
- `strategy.management.read`。
- `strategy.reconciliation.read`。
- `strategy.audit.read`，适用时。

执行能力：

- `strategy.execution.prepare`。
- `strategy.execution.submit`。
- `strategy.execution.cancel`。
- `strategy.execution.close`。
- `strategy.execution.rebalance`。
- `strategy.execution.override`。
- `strategy.execution.manualResolve`。

数据治理能力：

- `strategy.data.import`。
- `strategy.data.correct`。
- `strategy.reconciliation.confirm`。
- `strategy.adjustment.create`，适用时。
- `report.generate`，适用时。

Live 交易、风险覆盖、正式数据修正和差异接受必须具有独立能力，不得由普通提交权限自动继承。

### 4.3 数据范围

至少可以按以下维度限制：

- StrategyId。
- StrategyInstanceId。
- AccountId 和账户组。
- 市场、交易场所和 Gateway。
- InstrumentId 和资产类别。
- DeploymentEnvironment。
- TradingMode。
- 历史时间范围。
- 原始金额、敏感账户字段和审计详情。
- 数据导入来源。

### 4.4 权限判断规则

页面访问、对象读取、敏感字段、命令准备、正式提交、人工处理、审批、数据修正和正式报表分别判断。

前端隐藏或禁用不能替代后端权限、数据范围、风险和审批校验。

## 5. 策略范围与产品能力

### 5.1 平台执行策略

| 策略 | StrategyId | 交易平台 | 策略管理 |
|---|---|---:|---:|
| 资费套利 | `funding` | 是 | 是 |
| 跨所价差 | `crossSpread` | 是 | 是 |
| 海内外价差 | `domesticOverseas` | 是 | 是 |

### 5.2 非平台执行策略

| 策略 | StrategyId | 交易平台 | 策略管理 |
|---|---|---:|---:|
| 抄底 | `dip` | 否 | 是 |
| 短线交易员 L | `shortLineTraderL` | 否 | 是 |
| 短线交易员 W | `shortLineTraderW` | 否 | 是 |

非平台执行策略不得创建空白交易平台页面。它们通过外部系统、文件、人工录入或其他正式数据源进入策略管理。

### 5.3 能力唯一来源

策略名称、稳定 ID、排序和页面能力由以下内容共同约束：

- 策略定位文档。
- `docs/architecture/strategy-capability-matrix.md`。
- 前端策略注册表。
- 未来 Strategy 服务的正式定义。

前端注册表只负责静态展示和路由能力，不是策略运行状态、账户绑定和交易许可的最终权威。

## 6. 统一策略身份

必须区分：

### 6.1 StrategyDefinition

稳定策略定义，至少表达：

- `strategyId`。
- 正式名称。
- 策略类型。
- 平台执行或外部执行能力。
- 单腿、双腿或多腿结构。
- 支持的管理视角。
- 适用资产和市场范围。

### 6.2 StrategyVersion

正式规则和口径版本，至少表达：

- `strategyVersionId`。
- 关联 StrategyDefinition。
- 生效时间。
- 参数和规则版本。
- 损益口径版本。
- 风险口径版本。
- 状态和变更原因。

历史交易和 PnLResult 必须能够追溯至当时生效版本。

### 6.3 StrategyInstance

具体运行或管理实例，至少表达：

- `strategyInstanceId`。
- StrategyDefinition 和 StrategyVersion。
- DeploymentEnvironment。
- TradingMode。
- 实例状态。
- 参数配置引用。
- 负责人或责任范围，适用时。
- 创建、启用、暂停和终止时间。

同一 StrategyDefinition 可以存在多个 StrategyInstance。

### 6.4 StrategyAccountBinding

表达策略实例与账户的业务用途关系，至少包括：

- `bindingId`。
- StrategyInstanceId。
- AccountId。
- 账户用途或交易腿角色。
- 生效和失效时间。
- 允许的市场、标的和模式。
- 权重、额度或目标关系，适用时。

Account 维护账户主档，Strategy 维护账户如何被某个策略实例使用。

## 7. 信息架构和路由

策略一级模块固定包含：

```text
策略
├─ 交易平台
│  ├─ 行情分析
│  └─ 交易执行
└─ 策略管理
   ├─ 策略损益
   ├─ 账户资金
   └─ 订单信息
```

主要策略和视角必须进入路由状态，刷新、前进和后退能够恢复。

推荐路由语义：

```text
/strategy/platform?strategy=funding&view=analysis
/strategy/platform?strategy=crossSpread&view=execution
/strategy/management?strategy=funding&view=pnl
/strategy/management?strategy=dip&view=orders
```

非法 StrategyId、无权限策略或不支持的视角必须回退至安全状态并修正 URL。

未提交交易参数、账户敏感字段、Live 权限和审批内容不得通过 URL 传递。

## 8. 运行上下文

所有策略页面根据用途明确展示：

- DeploymentEnvironment。
- TradingMode。
- TradingPermissionState。
- StrategyDefinition、StrategyVersion 和 StrategyInstance。
- 当前账户和数据范围。
- 数据时间、数据来源和质量。
- Gateway、执行服务和对账状态，适用时。

规则：

- `production` 不等于 `live`。
- Demo、Simulation、Paper 和 Live 使用清晰、不混淆的正式文案。
- 运行上下文未知时禁止正式交易和高风险数据操作。
- Live 能力由服务端综合用户、账户、策略实例、Runtime、Gateway、风险、行情质量和审批形成。
- 策略管理中的历史数据必须说明其原始 TradingMode 和来源。

## 9. 二级模块协作

### 9.1 平台执行策略

```text
交易平台准备 TradeIntent
→ 后端受理 TradeCommand
→ 创建 ExecutionBatch 和 LegInstruction
→ 产生 Order、Fill、Position 和 EconomicEvent
→ Account、Position、PnL、Risk、Reconciliation 维护各自权威事实
→ 策略管理通过 Backend Read Model 查询长期结果
```

### 9.2 外部执行策略

```text
外部接口／文件／人工来源
→ ImportBatch 或同步任务
→ Adapter 标准化
→ 数据质量检查
→ 对账与差异处理
→ 平台 Order／Fill／Position／EconomicEvent
→ PnLResult 和策略管理 Read Model
```

### 9.3 协作规则

- 交易平台前端不得直接向策略管理前端传递权威业务对象。
- 策略管理不得重新计算第二套 Order、Position、Account 和 PnL 事实。
- 两个二级模块使用同一稳定 ID 体系。
- 实时执行 Read Model 与长期管理 Read Model 可以不同，但对象语义和身份一致。
- 当前执行状态通过 Query 恢复，不依赖前端内存和实时事件永久保存。
- 策略管理中的修正不能无痕覆盖交易平台或外部源事实。

## 12. 数据与数值标准

所有策略数据至少明确：

- 稳定业务 ID 和外部 ID。
- 数据来源和来源类型。
- businessDate。
- occurredAt。
- sourceTime。
- receivedAt。
- calculatedAt。
- updatedAt。
- reconciledAt，适用时。
- 原始币种和统一计价币种。
- 单位、合约乘数和精度。
- 汇率来源和时间。
- 预计、未核对、已核对、已结算或已修正属性。
- 数据、策略和计算版本。

缺失值不得静默转换为零。

正式金融计算不得依赖前端 JavaScript 浮点数作为最终权威。

## 13. 外部执行和数据导入

外部或人工执行数据进入策略管理前必须：

1. 建立 ImportBatch 或同步任务身份。
2. 保留原始文件、来源、外部 ID 和原始状态。
3. 通过 Adapter 映射为平台稳定对象。
4. 校验 StrategyId、AccountId 和 InstrumentId。
5. 校验时间、时区、币种、单位、精度和状态。
6. 识别重复记录和覆盖范围。
7. 标记 DataQualityStatus。
8. 对 Order、Fill、Position、Balance 和 PnL 执行适用对账。
9. 对修正、差异接受和 AdjustmentEntry 保留授权、原因和审计。

未核对、冲突或数据不完整的结果不得无提示进入正式统计和报表。

## 14. 数据质量与对账

策略模块至少表达：

- `complete`。
- `partial`。
- `delayed`。
- `stale`。
- `missing`。
- `conflicted`。
- `unverified`。
- `invalid`。

Reconciliation 至少可以关联：

- StrategyInstance。
- Account。
- Order。
- Fill。
- Position。
- BalanceSnapshot。
- EconomicEvent。
- PnLResult。

规则：

- 差异不直接无痕覆盖源事实。
- 接受差异需要能力权限、原因和审计。
- 正式修正使用 DataCorrectionRecord 或 AdjustmentEntry。
- 修正影响 PnL 时触发版本化重算。
- DataQualityStatus 和 ReconciliationStatus 分开表达。

## 15. 风险、审批和审计

- Risk 维护风险规则、额度、判断、事件和处置。
- Approval 对高风险配置、风险覆盖、Live 操作、正式数据修正和差异接受进行独立复核，适用时。
- Audit 记录交易命令、实例变更、账户绑定、导入、审批、修正和人工处理。
- Strategy 页面只在授权范围内读取风险结果或发起目标领域流程。

审批通过不等于交易、修正、导入或对账已经成功完成。

风险、审批、执行状态、数据质量和对账状态不得使用同一个状态字段表达。

## 16. 异常、空数据和降级

至少识别：

- StrategyDefinition 或版本缺失。
- StrategyInstance 不可用或状态冲突。
- 账户绑定缺失、失效或越权。
- 行情、账户或执行数据延迟。
- 外部来源不可用。
- 导入格式错误或部分失败。
- 订单、成交、持仓和余额差异。
- PnL 计算失败或版本不一致。
- 实时事件断线。
- 权限变化。
- 结果未知。

降级规则：

- 交易执行不可用时，行情分析和历史策略管理可以继续只读使用，数据具备时。
- PnL 失败不应隐藏订单、成交和账户事实。
- 外部导入失败不得污染已确认历史数据。
- 实时事件中断后通过 Query 恢复。
- 缓存或最后成功值必须显示时间和数据质量。
- 高风险写入条件不明确时默认拒绝。

## 17. 跨模块关系

- 对冲基金看板提供研究数据和背景，不拥有策略执行事实。
- 新闻日历与理财提供事件和内容输入，不生成 TradeCommand。
- 风险管理提供风险判断、限制、账户管理入口、对账和审计查询。
- Account 维护账户主档和账户事实；Strategy 维护策略账户用途。
- Reporting 读取正式 PnL、Account、Order、Risk 和 Reconciliation 结果生成版本化输出。
- 金融AI分析可以读取授权策略材料进行研究和复盘，不修改业务事实和执行状态。

跨模块跳转只传递稳定 ID 和安全筛选，目标模块重新执行权威 Query。

## 18. UI 与交互

- 交易平台和策略管理使用不同的二级入口和视觉层级。
- 策略切换、视角切换和实例切换必须明确区分。
- 页面持续展示策略、实例、环境、模式、数据时间和质量。
- 不适用内容不显示无意义空白卡片或虚构零值。
- 正式交易、普通操作、危险操作和数据修正具有不同视觉语义。
- 风险、涨跌、订单、数据质量、对账和审批状态不得混用颜色含义。
- 加载、空数据、延迟、错误、结果未知、只读、待核对和降级状态完整。

## 19. 非功能要求

- 桌面工作台优先。
- 高频行情渲染不能阻塞订单、风险和账户事件。
- 前端断线不终止已经受理的后台执行或导入任务。
- 页面刷新后可以恢复未完成 ExecutionBatch 和长期管理上下文。
- 实时事件不是唯一权威来源。
- 核心 Command 具备幂等、requestId、correlationId 和审计上下文。
- 大型历史查询支持分页、游标、聚合和按需加载。
- 敏感账户、订单、审计和个人信息按最小权限展示。
- Demo、Simulation、Paper 和 Live 清晰隔离。
- 单一外部来源故障不应导致整个策略模块白屏。

## 20. 明确不包含

一级策略模块需求不直接定义：

- 外部 Gateway 的具体 SDK 和技术选型。
- 数据库、消息队列和部署拓扑。
- 每个策略的具体金融公式和风险阈值。
- 公司财务总账。
- 全局用户和权限管理后台。
- 全局风险规则配置后台。
- 完整报表设计。
- 金融AI分析实现。

上述内容分别由策略文档、架构文档和对应产品模块定义。

## 21. 验收标准

### 产品范围

- 策略一级模块只包含交易平台和策略管理。
- 三类平台执行策略和六类纳管策略范围准确。
- 非平台执行策略不创建空交易页面。

### 策略身份

- StrategyDefinition、StrategyVersion、StrategyInstance 和 StrategyAccountBinding 明确区分。
- 历史交易和损益可以追溯到策略版本。
- Account 主档和策略账户用途所有权清晰。

### 二级模块协作

- 交易平台和策略管理读取同一套后端权威事实。
- 当前执行和长期管理可以使用不同 Read Model，但稳定 ID 和语义一致。
- 页面之间不复制 Order、Position、Account 和 PnL 权威对象。

### 数据和治理

- 外部数据具有来源、外部 ID、导入批次、质量和对账状态。
- 缺失、冲突、估算、未核对和已修正数据明确区分。
- 修正和差异接受可审计且不覆盖原始事实。

### 权限与安全

- 页面访问、数据读取、交易提交、人工处理、导入、修正和审批分别授权。
- Live 权限独立判断。
- 前端控制不能绕过后端权限和数据范围。

### 状态和恢复

- 权限、风险、审批、执行、数据质量和对账分别表达。
- 页面通过 Query 恢复权威状态。
- 结果未知不会被直接当作失败后重复提交。

### 文档一致性

- 两份二级模块需求与本文不存在冲突。
- 六份策略文档是策略专属口径的唯一来源。
- 公共状态和对象引用正式架构唯一来源。

## 22. 未决事项

以下事项在专项架构或后续规划中确认：

- StrategyInstance 的完整配置治理和版本发布流程。
- 自动策略运行、暂停和恢复的产品范围。
- 外部执行策略的标准导入模板。
- 不同策略的正式数据完整性门槛。
- 高风险实例变更和账户绑定的审批等级。
- 正式 Live 数据和交易的发布门禁。
