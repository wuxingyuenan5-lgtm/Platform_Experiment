# 风险管理内部子板块与历史路由映射

状态：`active`  
适用基线：Platform V5  
说明：为兼容现有引用，暂时保留原文件名 `支撑模块-模块定位.md`。

## 1. 文档目的

本文档不再把数据、账户、财务、报表、监控、审计、用户、设置和通知定义为独立一级模块。

这些能力按照当前前端设计，统一归入一级模块“风险管理”内部，作为二级或三级子板块。本文件只记录它们的业务对象、当前历史路由和内部边界。

风险管理的正式定位以 `docs/modules/风控管理-模块定位.md` 为准。

## 2. 内部子板块总表

| 风险管理内部子板块 | 主要业务对象 | 当前历史路由或入口 |
|---|---|---|
| 风控详情 | 风险状态、风险事件、等级、关联对象和处置记录 | `/risk/detail` |
| 账户与资产 | 账户主档、权益、可用资金、资产结构和账户状态 | `/account`；风控详情内已有账户与资产区域 |
| 财务与资金 | 财务概览、费用、收支和经营资金口径 | `/finance` |
| 数据与服务监控 | 数据源、同步状态、质量、服务健康和运行异常 | `/data`、`/monitor`；风控详情内已有服务状态区域 |
| 报表 | 风险、策略、账户、资金和运营汇总 | `/reports`；风控详情内已有报表区域 |
| 审计 | 用户操作、配置变更、登录和系统行为追溯 | `/audit`；风控详情内已有审计区域 |
| 用户与权限 | 用户资料、角色、权限和启停状态 | `/risk/users`、`/user` |
| 个人账号 | 当前用户身份、个人信息和个人配置 | `/risk/profile` |
| 系统设置 | 平台基础配置、功能开关和已确认规则配置 | `/settings` |
| 消息通知 | 消息内容、来源、时间、阅读状态和跳转 | `/notification`；风控详情内已有通知区域 |

历史独立路由的存在不改变产品层级。这些路由可以暂时保留，也可以作为风险管理内部页面的直接访问入口。

## 3. 子板块边界

### 3.1 账户与资产

负责业务账户、交易账户和资金账户主档，以及平台级资产结构。

不负责：

- 用户登录身份。
- 策略完整损益。
- 公司财务收支。
- 风险事件处置。

### 3.2 财务与资金

负责经营和财务口径的费用、收支和资金变化。

不负责：

- 策略损益归因。
- 交易保证金执行。
- 风险事件管理。

### 3.3 数据与服务监控

负责数据源、同步、质量、更新时间、服务连接和运行异常。

不负责：

- 市场研究结论。
- 策略风险判断。
- 用户操作审计。

### 3.4 报表

负责跨子板块和业务模块的结构化汇总、查看和后续导出。

报表消费其他模块结果，不成为原始风险、账户、策略或审计对象的写入入口。

### 3.5 审计

负责关键操作、配置变更、登录和系统行为记录。

审计记录可以关联风险事件和交易执行，但不能用普通执行日志替代系统审计。

### 3.6 用户、权限和个人账号

- 用户与权限负责用户资料、角色、权限和启停。
- 个人账号负责当前用户身份和个人配置。
- 账户与资产负责业务账户和资金账户。

三者必须保持概念区分。

### 3.7 系统设置

负责平台基础配置和功能开关，以及经过验证、确认后需要配置化的规则。

具体策略参数、临时风险处置和用户个人偏好不应全部混入平台通用设置。

### 3.8 消息通知

负责消息投递、展示、阅读状态和关联跳转。

消息通知不拥有原始风险事件、新闻内容、审计记录或监控对象。

## 4. 风控详情的聚合规则

风控详情可以展示其他内部子板块的摘要，例如：

- 总资产和可用资金。
- 账户风险状态。
- 数据或服务异常。
- 未读消息数量。
- 最近审计记录。
- 关键报表摘要。

但风控详情不应在一个页面内重复实现所有子板块的完整管理流程。

判断标准：

- 只需要帮助识别和处置风险的信息，可以作为摘要保留。
- 需要完整查询、编辑、配置或长期管理的能力，应进入对应内部子板块。
- 当前前端已经使用嵌入式布局的，可以先保持布局，再逐步拆分组件和状态。

## 5. 初创阶段建设原则

- 风险规则数量可以较少。
- 风险阈值可以先作为观察值，不必立即成为强制限制。
- 优先保留数据、事件和复盘记录，为后续校准提供依据。
- 子板块先满足当前实际管理需求，不为追求“完整后台”堆叠无用功能。
- 具体规则和执行标准通过真实交易与运营结果逐步验证。

## 6. 后续治理要求

- 不新增新的一级支撑模块。
- 新管理能力优先归入风险管理已有子板块。
- 相同业务对象只保留一个完整管理入口。
- 多个历史路由指向同一能力时，应逐步统一页面和数据模型，而不是复制实现。
- 路由整理不得改变用户已确认的六个一级模块。

## 7. 验收标准

- 数据、账户、财务、报表、监控、审计、用户、设置和通知均被描述为风险管理内部子板块。
- 历史路由与产品层级可以清晰区分。
- 风控详情的摘要聚合与各子板块完整能力边界明确。
- 账户、用户和个人账号概念明确区分。
- 策略损益与财务资金口径明确区分。
- 风险建设符合轻量、渐进和可校准原则。
