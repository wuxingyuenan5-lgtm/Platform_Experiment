# 交易平台：模块定位

状态：`active`  
适用基线：Platform V5

## 1. 模块定位

交易平台是面向交易前分析、交易判断和交易执行的策略工作台。

它只覆盖当前需要通过本平台完成下单的三类策略：

- 资费套利。
- 跨所价差。
- 海内外价差。

抄底、短线交易员 L 和短线交易员 W 当前不需要通过平台下单，因此不进入交易平台。这是既定业务设计，不是功能缺失。

## 2. 核心用户

- 负责观察策略机会的研究人员或交易人员。
- 负责确认参数和执行交易的操作人员。
- 需要查看当前成交、配平和异常暴露的策略负责人。

## 3. 核心任务

用户进入交易平台后，需要完成：

1. 选择需要观察或执行的策略。
2. 在行情分析中判断当前是否存在交易机会。
3. 查看与执行直接相关的市场结构、分位、价差和成本。
4. 进入交易执行页面确认下单参数。
5. 完成策略双腿交易。
6. 确认两腿成交、配平和异常暴露状态。

## 4. 固定页面结构

### 4.1 行情分析

行情分析回答：

- 当前是否存在可交易机会？
- 机会处于什么历史位置？
- 预期收益是否覆盖成本和风险？
- 应关注哪个交易所、标的、合约或市场组合？

可以包含：

- 市场报价。
- 主图和价差图。
- 历史分位。
- 期限结构。
- 统计分析。
- 多市场对比。
- 与当前策略执行直接相关的研究指标。

行情分析页不承担正式下单主操作，也不复制对冲基金看板的完整研究体系。

### 4.2 交易执行

交易执行回答：

- 当前是否允许交易？
- 两条交易腿应分别交易多少？
- 预计收益、成本和风险是多少？
- 执行是否成交、配平并符合当前限制？

可以包含：

- 执行前状态。
- 开仓、平仓和方向选择。
- 数量、价格、订单类型和账户选择。
- 双腿配平。
- 预计收益和成本。
- 当前执行订单。
- 当前持仓摘要。
- 执行反馈和异常提示。

## 5. 策略范围

| 策略 | 行情分析 | 交易执行 |
|---|---:|---:|
| 资费套利 | 有 | 有 |
| 跨所价差 | 有 | 有 |
| 海内外价差 | 有 | 有 |
| 抄底 | 无 | 无 |
| 短线交易员 L | 无 | 无 |
| 短线交易员 W | 无 | 无 |

## 6. 模块主责的操作上下文

交易平台主责：

- 当前分析上下文。
- 当前交易参数。
- 当前执行指令。
- 当前执行批次。
- 当前执行反馈。
- 当前配平状态。
- 执行视角下的持仓和风险摘要。

这些内容描述交易平台的操作职责，不代表订单、成交、持仓和账户数据只属于某个前端页面。完整历史查询和复盘入口位于策略管理。

## 7. 明确负责

- 与具体策略执行直接相关的行情分析。
- 下单前判断。
- 下单参数确认。
- 订单提交和当前执行反馈。
- 双腿执行与配平。
- 当前执行批次的异常提示。
- 当前持仓的执行视角。

## 8. 明确不负责

- 抄底和短线交易策略的平台下单。
- 策略长期绩效评价。
- 完整损益归因。
- 全生命周期历史订单查询。
- 全平台账户主档和资金管理。
- 完整宏观和跨资产研究。
- 全局风险规则定义、用户权限和系统审计。

## 9. 与其他模块的关系

### 对冲基金看板

交易平台可以引用与具体策略执行相关的研究结论和市场数据，但不复制完整研究看板。

### 策略管理

交易平台负责当前执行过程；策略管理负责实际结果的统计、查询、归档和复盘。

### 风险管理

交易平台读取当前适用的风险状态、基础限制和告警结果，并在执行前进行提示或限制。风险规则、阈值和处置标准由风险管理逐步建立和维护。

## 10. 验收标准

- 交易平台只展示 `platform.enabled = true` 的三类策略。
- 三类策略均明确区分行情分析和交易执行。
- 行情分析页不出现正式下单主操作。
- 交易执行页不重复建设完整研究体系。
- 当前订单、持仓和风险摘要均服务于执行目的。
- 策略管理可以查询和复盘执行结果，但不复制实时下单能力。
