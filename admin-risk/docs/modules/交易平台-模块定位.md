# 交易平台：模块定位

状态：`active`  
适用基线：Platform V5

## 1. 模块定位

交易平台是面向盘中研究、交易判断和交易执行的工作台。

它只覆盖当前需要通过本平台完成下单的三类策略：

- 资费套利。
- 跨所价差。
- 海内外价差。

抄底、短线交易员 L 和短线交易员 W 当前不需要通过平台下单，因此不进入交易平台。这是既定业务设计，不是功能缺失。

## 2. 核心用户

- 负责观察策略机会的研究人员或交易人员。
- 负责确认参数和执行交易的操作人员。
- 需要查看当前持仓、配平和执行反馈的策略负责人。

## 3. 核心任务

用户进入交易平台后，需要完成：

1. 选择需要观察或执行的策略。
2. 在行情分析中判断当前是否存在机会。
3. 查看与执行直接相关的市场结构、分位、价差和成本。
4. 进入交易执行页面确认下单参数。
5. 执行单腿、双腿或多腿交易。
6. 确认成交、配平、当前暴露和异常状态。

## 4. 固定页面结构

交易平台固定分为：

### 4.1 行情分析

回答：

- 当前是否存在可交易机会？
- 机会处于什么历史位置？
- 机会是否覆盖成本和风险？
- 应关注哪个交易所、标的、合约或市场组合？

行情分析页可以包含：

- 市场报价。
- 主图和价差图。
- 历史分位。
- 期限结构。
- 统计分析。
- 多市场对比。
- 与当前策略直接相关的研究指标。

行情分析页不承担正式下单动作。

### 4.2 交易执行

回答：

- 当前是否允许交易？
- 每条腿应该交易多少？
- 预计收益、成本和风险是多少？
- 执行是否成交、配平并符合限制？

交易执行页可以包含：

- 当前执行前状态。
- 开仓、平仓和方向选择。
- 数量、价格、订单类型和账户选择。
- 双腿或多腿配平。
- 预计收益和成本。
- 当前执行订单。
- 当前持仓摘要。
- 执行反馈和异常提示。

## 5. 策略范围

| 策略 | 行情分析 | 交易执行 |
|---|---:|---:|
| 资费套利 | 有 | 有 |
| 跨所价差 | 有 | 有 |
| 海内外价差 | 有 | 有 |
| 抄底 | 无 | 无 |
| 短线交易员 L | 无 | 无 |
| 短线交易员 W | 无 | 无 |

## 6. 模块拥有的业务对象

交易平台主要拥有：

- 当前分析上下文。
- 当前交易参数。
- 当前执行指令。
- 当前执行批次。
- 当前执行反馈。
- 当前配平状态。
- 当前执行视角下的持仓和风险摘要。

完整的长期订单档案和策略绩效不由本模块拥有。

## 7. 明确负责的内容

- 与具体策略交易直接相关的行情分析。
- 下单前判断。
- 下单参数确认。
- 订单提交和执行反馈。
- 双腿及多腿配平。
- 当前执行批次的异常处理提示。
- 当前持仓的执行视角。

## 8. 明确不负责的内容

- 抄底和短线交易策略的平台下单。
- 策略长期绩效评价。
- 完整损益归因。
- 全生命周期历史订单档案。
- 全平台账户资金管理。
- 完整宏观和跨资产研究体系。
- 用户、权限和系统审计管理。

## 9. 与其他模块的关系

### 对冲基金看板

输入：宏观、市场和跨资产研究信息。  
边界：交易平台只引用与具体策略执行相关的研究结论，不复制完整研究看板。

### 策略管理

输出：实际持仓、订单、成交和执行记录。  
边界：交易平台负责当前执行，策略管理负责长期统计、归档和复盘。

### 风控相关模块

输入：风险规则、交易限制、告警和是否允许执行的结果。  
边界：交易平台执行风险限制，但不自行建设另一套全局风险规则。

## 10. 当前 V5 实现状态

已实现：

- 三类策略切换。
- 行情分析和交易执行切换。
- 资费套利行情与执行页面。
- 跨所价差行情与执行页面。
- 海内外价差行情与执行页面。
- 统一顶部页签和主题基座。

待完善：

- 统一策略注册表。
- 页面和大型组件职责拆分。
- Mock、业务配置和页面硬编码分离。
- 控件、图表卡片和筛选器进一步统一。

## 11. 验收标准

- 交易平台只展示注册表中 `platform.enabled = true` 的策略。
- 三类策略都具备清晰的行情分析和交易执行边界。
- 行情分析页不出现正式下单主操作。
- 交易执行页不重复建设完整研究体系。
- 当前订单、持仓和风险摘要服务于执行目的。
- 策略管理可以读取交易平台产生的结果，但不复制下单能力。
