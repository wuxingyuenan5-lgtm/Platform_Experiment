# 策略管理：需求文档

状态：`active`  
产品基线：Platform V5  
架构版本：Platform V6  
适用分支：`refactor/frontend-architecture-v6`  
文档层级：二级产品模块需求

模块定位依据：`docs/modules/策略管理-模块定位.md`

## 1. 文档定位

本文档定义策略管理的产品范围、三类管理视角、权限、数据标准、Read Model、对账、风险展示、交互、非功能要求和验收标准。

策略管理是全部纳管策略的持续监控、结果统计、资金观察、历史查询、数据核对和复盘工作台。

策略管理不承担：

- 实时行情机会判断。
- 正式下单、改单和撤单主操作。
- 双腿实时执行和配平。
- 账户主档和公司财务管理。
- 全局风险规则、用户权限和平台配置维护。

## 2. 产品目标

用户应能够：

1. 选择策略、管理视角、统计区间和计价币种。
2. 判断策略整体表现和当前状态。
3. 分析收益、成本、损失、汇率和执行偏差来源。
4. 查看关联账户的权益、可用资金、保证金和资金效率。
5. 查询当前持仓、历史订单、成交和执行批次。
6. 查看平台执行和外部执行数据的来源、完整性和对账状态。
7. 穿透策略腿、账户、标的、订单、成交和时间维度。
8. 识别异常表现、异常资金变化、数据差异和人工干预。
9. 为风险管理、报表和金融AI分析提供授权的结构化查询。

## 3. 策略范围

| 策略 | StrategyId | 策略损益 | 账户资金 | 订单信息 | 执行来源 |
|---|---|---:|---:|---:|---|

| 短线交易员 W | `shortLineTraderW` | 有 | 有 | 有 | 外部交易来源 |

策略名称、ID 和管理能力由统一策略注册表与能力矩阵维护。

## 4. 用户与权限

### 4.1 用户类型

- 策略负责人。
- 投资管理人员。
- 风险与运营人员。
- 数据核对人员。
- 只读观察人员。

### 4.2 操作能力

至少区分：

- `strategy.management.read`。
- `strategy.reconciliation.read`。
- `strategy.reconciliation.confirm`。
- `strategy.data.import`。
- `strategy.data.correct`。
- `report.generate`，适用时。

导入、确认差异、数据修正和正式报表等操作分别执行权限、数据范围、ApprovalPolicy 和 Audit 校验。

策略管理不因为用户具有交易权限而显示实时交易主操作。

## 5. 信息架构与路由

具有两个主要切换维度：

1. 策略。
2. 管理视角：策略损益、账户资金、订单信息。

推荐路由语义：

```text
/strategy/management?strategy=funding&view=pnl
/strategy/management?strategy=dip&view=orders
```

规则：

- StrategyId 必须有效且 `management.enabled = true`。
- 切换策略时保留当前管理视角。
- 切换视角时保留当前策略。
- 日期区间、计价币种等兼容公共条件可以保留。
- 策略特有账户、标的和状态条件重新加载。
- 不适用区块不显示空白卡片和虚构零值。
- 主要策略和视角刷新后可以恢复。

## 6. 查询架构

页面通过 Backend Read Model 获取管理视图：

```text
权威领域事实
→ Backend Read Model
→ API DTO
→ Frontend Adapter
→ View Model
```

规则：

- Read Model 可以聚合多个领域。
- Read Model 不接受业务写入。
- 页面不直接依赖数据库表或外部接口字段。
- 页面不重新计算第二套订单、账户、持仓和实际损益事实。
- Read Model 标记数据截止时间、来源、质量和版本。
- Read Model 可以缓存和重建，不成为最终权威。

## 7. 策略损益

### 7.1 页面目标

用于回答：

- 策略取得多少收益。
- 收益、成本和损失来自哪些因素。
- 策略腿、标的、账户和交易的贡献如何。
- 当前结果是否伴随异常执行、数据差异或风险。
- 总损益与归因项是否可核对。

### 7.2 页面结构

1. 结果总览。
2. 趋势表现。
3. 损益归因。
4. 明细穿透。
5. 计算版本、数据质量和核对信息。

### 7.3 通用指标

根据策略适用性展示：

- 累计总损益。
- 区间损益和收益率。
- 日度、周度或月度损益。
- 策略净值。
- 当前和最大回撤。
- 已实现和未实现损益。
- 交易成本。
- 资金使用效率。
- 执行偏差和异常损失。

不适用指标不得显示无意义零值。

### 7.4 损益归因

必须满足：

- 总损益与归因项可核对。
- 收益、成本、损失和 AdjustmentEntry 分开。
- 估算和结算结果分开。
- 归因名称、正负号和口径来自对应策略文档。
- 结果具有计算版本、策略版本和数据截止时间。
- 汇率折算具有来源和时间。

页面组件不得自行发明归因项或通过字符串猜测损益方向。

### 7.5 穿透分析

按数据能力支持：

- 策略腿。
- 标的或合约。
- 平台或账户。
- ExecutionBatch。
- Order 和 Fill。
- 日期和交易时段。
- 其他已确认策略维度。

穿透结果使用与总览一致的统计区间、币种和版本。

## 8. 账户资金

### 8.1 页面目标

用于回答：

- 策略使用多少资金。
- 可用资金、权益、保证金和资金占用如何。
- 单端或多端账户是否失衡。
- 当前资金和风险状态如何。
- 净值、回撤和资金效率如何变化。

### 8.2 页面结构

1. 策略账户合并总览。
2. 当前风险和数据质量摘要。
3. 单账户或多账户结构。
4. 资金占用、保证金和效率。
5. 净值、回撤和趋势。
6. 账户异常和对账信息。

### 8.3 通用字段

- 策略总资金或分配额度。
- Account 权益和余额。
- 可用资金和冻结资金。
- 保证金占用和保证金率。
- 风险占用。
- 当前持仓名义价值。
- 资金使用率。
- 策略净值和回撤。
- AccountStatus。
- 数据时间、质量和 ReconciliationStatus。

### 8.4 单账户和多账户

单账户策略不创建无意义双端结构。

多账户策略：

- 先展示合并总览，再展示各端。
- 明确 Account、平台、币种和账户用途。
- 账户用途来自 StrategyAccountBinding。
- 展示原始值和统一折算值。
- 展示汇率来源、时间和换算结果。
- 识别资金、保证金和名义价值失衡。

### 8.5 数据权威

- Account 服务维护账户主档、余额和保证金事实。
- Strategy 服务维护 StrategyAccountBinding。
- PnL 服务维护策略净值和损益结果。
- Risk 服务维护风险判断。
- 页面 Read Model 负责组合，不形成第二套事实。

## 9. 订单信息

### 9.1 页面目标

用于回答：

- 当前持有哪些头寸。
- 历史执行过哪些批次和订单。
- 每笔订单产生哪些成交。
- 是否存在失败、撤单、部分成交、结果未知和人工干预。
- 外部执行数据是否完整并已对账。

### 9.2 固定数据视图

- 当前持仓。
- 历史订单。
- 成交记录。
- 执行批次和执行记录。

根据策略可增加：

- 交易腿记录。
- 资金费和费用结算。
- 信号记录。
- 止盈止损记录。
- 风险事件关联。
- 人工干预和修正记录。

附加视图必须由策略文档和真实数据源支持。

### 9.3 通用筛选

至少支持：

- 日期范围。
- 记录类型。
- OrderStatus、ExecutionBatchStatus 或 ReconciliationStatus。
- 标的、账户、方向和交易腿，适用时。
- OrderId 或 ExecutionBatchId。
- 数据来源。
- 是否人工干预。
- 分页或游标。

筛选变化后分页回到安全起点。

### 9.4 关联关系

- StrategyInstance 与 Account。
- StrategyInstance 与 Instrument。
- ExecutionBatch 与 LegInstruction。
- LegInstruction 与 Order。
- Order 与 Fill。
- Fill 与 Position 变化。
- 异常、人工处理和对账差异与目标对象。

用户可以从汇总进入明细，不依赖手工拼接多个表格。

## 10. 外部执行数据

来源可以包括：

- 交易所或经纪商接口。
- 外部交易终端。
- 文件导入。
- 人工录入。
- 其他已确认数据服务。

进入正式管理视图前：

1. 保留原始来源、外部 ID 和原始状态。
2. 通过 Adapter 转换为平台对象。
3. 校验 StrategyId、AccountId 和 InstrumentId。
4. 校验时间、币种、单位和精度。
5. 标记 DataQualityStatus。
6. 对 Order、Fill、Position、Balance 和 PnL 执行适用对账。
7. 对修正和接受差异执行权限、审批和审计。

## 11. Reconciliation 与 Data Quality

Reconciliation 是正式平台领域。

页面展示：

- ReconciliationJob 或任务摘要。
- ReconciliationResult。
- ReconciliationDifference。
- 差异影响范围。
- 自动或人工处理状态。
- 操作人、时间、原因和结果。

规则：

- 差异不直接无痕覆盖源事实。
- `accepted_difference` 需要授权和审计。
- DataCorrectionRecord 或 AdjustmentEntry 记录正式修正。
- 修正影响损益时触发重算。
- 数据质量不足时正式统计和报表明确提示。

## 12. 风险展示

策略管理只读展示与策略运行直接相关的：

- RiskStatus。
- RiskSnapshot。
- RiskEvent。
- 限制和告警摘要。
- 指标、当前值、参考值、时间和判断依据。

RiskRule、RiskLimit、GlobalTradingBlock 和处置标准由 Risk 领域维护。

未经验证的指标可以作为观察或警告，不由页面自行升级为限制和阻断。

## 13. 状态唯一来源

策略管理涉及：

- StrategyInstanceStatus。
- OrderStatus。
- ExecutionBatchStatus。
- ReconciliationStatus。
- DataQualityStatus。
- RiskStatus。

完整枚举和生命周期以 `docs/architecture/domain/status-enums-and-lifecycles.md` 为唯一来源，本文件不重复维护清单。

## 14. 数据和数值标准

至少使用：

- `strategyId`、`strategyInstanceId`。
- `accountId`、`instrumentId`、`positionId`。
- `executionBatchId`、`orderId`、`executionId`。
- `pnlResultId`、`reconciliationResultId`。
- 数据来源 ID。

时间区分：

- businessDate。
- occurredAt。
- sourceTime。
- receivedAt。
- calculatedAt。
- updatedAt。
- reconciledAt。

金额和数量明确：

- 原始数值。
- 原始币种和统一计价币种。
- 单位和合约乘数。
- 汇率来源和时间。
- 预计、未核对、已核对或已结算属性。

## 16. UI 与交互

遵循：

- `docs/design/platform-ui-guidelines.md`
- `docs/architecture/shared-ui-governance.md`

特有要求：

- 六类策略使用统一页面骨架和路由语义。
- 切换策略时保留当前管理视角。
- 不适用内容不显示空白卡片和虚构零值。
- 总览、趋势、归因和明细层级清晰。
- 表格、图表和卡片使用同一统计上下文。
- 加载、空数据、延迟、错误、待核对和差异状态完整。
- 页面不出现正式实时交易主操作。
- 风险、涨跌、订单和数据质量使用不同视觉语义。

## 17. 跨模块关系

- 交易平台提交命令并展示当前执行；策略管理查询后端事实和长期结果。
- 风险管理读取策略相关事实并维护风险判断、事件和处置。
- 账户与资产维护 Account 主档；Strategy 维护绑定。
- 报表读取正式结果生成版本化输出。
- 审计记录导入、核对、修正、审批和人工处理。
- 金融AI分析可以读取授权结果生成复盘材料，不修改源数据。

## 18. 非功能要求

- 面向桌面管理工作台。
- 大型查询使用分页、游标和按需加载。
- 页面刷新后恢复策略、视角和核心筛选。
- 实时事件不是唯一数据来源。
- 汇总能够穿透至权威明细。
- 导入、核对、修正和导出可审计。
- 敏感账户、订单和审计信息按数据范围展示。

## 19. 验收标准

### 范围

- 展示全部六类纳管策略。
- 不提供正式实时交易入口。

### 策略损益

- 具备总览、趋势、归因和明细。
- 总损益与归因可核对。
- 口径和版本来自正式来源。

### 账户资金

- 单账户和多账户结构符合实际。
- Account、StrategyAccountBinding、PnL 和 Risk 权威边界正确。
- 多币种折算可追溯。

### 订单信息

- 持仓、订单、成交、执行批次和人工处理可关联。
- 外部数据具有来源、质量和对账状态。

### 数据和状态

- Reconciliation 是正式领域对象。
- 状态统一引用公共规范。
- Read Model 不形成第二套权威事实。
- 汇总、明细和报表使用一致统计上下文。

### UI

- 三类视角稳定且清晰。
- 不同策略差异不破坏统一阅读顺序。
- 风险、订单、涨跌和数据质量语义不混用。
