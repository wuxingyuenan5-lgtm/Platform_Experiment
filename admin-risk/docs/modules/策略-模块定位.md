# 策略：一级模块定位

状态：`active`  
适用基线：Platform V5

## 1. 模块定位

“策略”是平台中承接具体投资策略研究、执行、统计和复盘的一级业务模块。

该一级模块固定包含两个二级模块：

- 交易平台。
- 策略管理。

本次不改变该一级架构。

## 2. 二级模块分工

### 2.1 交易平台

负责需要通过平台完成下单的策略：

- 资费套利。
- 跨所价差。
- 海内外价差。

固定提供：

- 行情分析。
- 交易执行。

### 2.2 策略管理

负责全部纳管策略：

- 资费套利。
- 跨所价差。
- 海内外价差。
- 抄底。
- 短线交易员 L。
- 短线交易员 W。

固定提供：

- 策略损益。
- 账户资金。
- 订单信息。

## 3. 核心业务链路

平台执行策略：

`交易平台行情分析 → 交易平台交易执行 → 策略管理损益/资金/订单`

非平台执行策略：

`外部执行结果 → 策略管理损益/资金/订单`

两条链路最终都进入策略管理，但只有前三类策略进入交易平台。

## 4. 一级模块拥有的业务对象

- 策略定义和策略 ID。
- 策略能力配置。
- 策略分析上下文。
- 策略执行结果。
- 策略损益。
- 策略账户资金视图。
- 策略订单、成交和执行档案。

全局市场研究、全局风险规则、用户权限和系统运行状态不由本模块拥有。

## 5. 统一规则

- 策略只能在统一策略注册表中定义一次。
- 交易平台与策略管理使用同一策略 ID。
- 策略是否进入交易平台由 `platform.enabled` 决定。
- 策略是否进入策略管理由 `management.enabled` 决定。
- 不因两个二级模块策略数量不同而复制策略定义。
- 不为未通过平台执行的策略创建空交易页面。

## 6. 与其他一级模块的关系

### 对冲基金看板

提供宏观、资产类别和跨市场研究信息。策略模块只引用与具体策略直接相关的研究结果。

### 新闻日历与理财

提供事件、新闻和理财机会等信息输入，不直接拥有策略执行和绩效统计。

### 风控管理

读取策略持仓、资金、订单和损益，输出风险限制、告警和处置结果。

### 金融 AI 分析

可以辅助生成研究摘要、情景推演和策略 Memo，但不直接替代策略规则或执行确认。

## 7. 当前 V5 技术债务

- 交易平台和策略管理目前仍分别维护部分策略列表。
- Mock 数据分散在多个目录。
- 部分大型页面同时承担页面编排、图表配置和业务数据。
- 策略文档曾存在多份重复或过期口径。

这些问题应通过统一注册表、有效文档入口和后续本地代码整理解决，不改变一级导航。

## 8. 验收标准

- “策略”一级模块仍包含交易平台和策略管理两个二级模块。
- 交易平台只出现三类平台执行策略。
- 策略管理出现全部六类纳管策略。
- 两个二级模块使用同一策略身份体系。
- 策略执行、统计和复盘边界清晰。
