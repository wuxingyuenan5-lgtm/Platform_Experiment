# 策略：一级模块定位

状态：`active`  
产品基线：Platform V5  
架构版本：Platform V6  
适用分支：`refactor/frontend-architecture-v6`  
文档层级：一级产品模块定位

## 1. 模块定位

“策略”是承接具体投资策略分析、平台执行、结果统计、核对和复盘的一级产品模块。

固定包含两个二级模块：

- 交易平台。
- 策略管理。

该一级产品结构不因后端服务划分、Gateway 接入或前端重构而改变。

## 2. 核心用户

- 研究和交易人员。
- 策略负责人。
- 投资管理人员。
- 风险与运营观察人员。
- 具有授权数据范围的只读用户。

## 3. 二级模块分工

### 3.1 交易平台

面向需要通过平台完成分析和交易执行的策略：

- 资费套利。
- 跨所价差。
- 海内外价差。

固定提供：

- 行情分析。
- 交易执行。

交易平台负责当前机会分析、交易参数、TradeCommand 发起、ExecutionBatch 反馈、订单成交、执行配平和暴露处理的产品工作流。

### 3.2 策略管理

面向全部六类纳管策略：

- 资费套利。
- 跨所价差。
- 海内外价差。
- 抄底。
- 短线交易员 L。
- 短线交易员 W。

固定提供：

- 策略损益。
- 账户资金。
- 订单信息。

策略管理负责实际结果查询、统计、对账、异常穿透和复盘，不提供正式实时交易主操作。

## 4. 核心业务链路

平台执行策略：

```text
行情分析
→ 交易执行发起 TradeCommand
→ 后端 ExecutionBatch / Order / Fill
→ 策略管理查询 PnL、资金、持仓、订单与对账结果
```

非平台执行策略：

```text
外部执行来源
→ Adapter 标准化
→ Reconciliation / Data Quality
→ 策略管理查询和复盘
```

两个页面模块读取同一套后端权威事实，不通过前端页面之间复制数据完成衔接。

## 5. 产品主责内容与主要视图

策略模块是以下内容的主要产品入口：

- 策略身份和能力展示。
- 策略分析上下文。
- 交易执行工作流。
- 策略损益和归因视图。
- 策略账户资金视图。
- 持仓、订单、成交和执行查询。
- 策略相关对账、数据质量和异常复盘。

技术领域和数据权威仍分别属于 Strategy、Trading and Execution、Account and Position、PnL and Strategy Economic Ledger、Risk、Reconciliation and Data Quality 等后端领域，以 `docs/architecture/module-ownership-matrix.md` 为准。

## 6. 统一策略身份

- 策略只使用统一 `StrategyId`。
- 产品策略范围以 `docs/architecture/strategy-capability-matrix.md` 为准。
- 前端静态能力由统一策略注册表声明。
- 策略版本、策略实例、账户绑定和运行状态由未来 Strategy 服务维护。
- 交易平台与策略管理不得分别维护冲突的策略名称、排序和 ID。
- 不为非平台执行策略创建空交易页面。

## 7. 与其他一级模块的关系

### 对冲基金看板

提供 Research Data、研究图表和跨市场背景。策略模块只引用与具体策略决策直接相关的研究结果。

### 新闻日历与理财

提供 Content and Calendar Data。重要事件可以成为交易前提醒，但不直接生成正式交易命令。

### 风险管理

Risk 领域维护风险规则、判断、事件和处置；策略页面读取当前风险状态、限制和 TradingPermissionState。

### 金融AI分析

可以读取授权研究、策略、损益和复盘材料，生成摘要、情景推演和策略 Memo；不能直接修改策略版本、交易参数、订单或风险规则。

## 8. 明确不负责

- 平台级宏观和跨资产研究体系。
- 新闻与内容数据维护。
- 账户主档、用户权限、审计和系统配置的权威维护。
- 公司财务会计总账。
- AI 模型和分析任务管理。
- 在浏览器中保存订单、账户、持仓、损益和风险最终事实。

## 9. 验收标准

- 策略一级模块固定包含交易平台和策略管理。
- 交易平台只展示三类平台执行策略。
- 策略管理展示全部六类纳管策略。
- 两个二级模块使用同一策略身份体系。
- 页面之间不复制第二套订单、成交、账户、持仓或损益事实。
- 外部执行数据在进入正式统计前具有来源、质量和对账状态。
- 正式模块名称统一使用“风险管理”和“金融AI分析”。
