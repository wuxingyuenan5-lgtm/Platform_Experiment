# Platform V6 策略产品能力矩阵

状态：`active`  
适用分支：`refactor/frontend-architecture-v6`  
架构层级：产品能力与前端展示

## 1. 文档定位

本文档统一说明各策略在哪些产品页面中出现，以及具备哪些前端能力。

它不定义：

- 后端策略运行实例。
- 真实账户绑定。
- 交易执行内核。
- 风险阈值。
- 策略损益公式。

上述内容分别由公共领域模型、后端架构、前后端协作规范和策略文档定义。

## 2. 判断原则

策略是否进入交易平台，取决于是否需要通过本平台完成行情判断和正式下单。

策略是否进入策略管理，取决于是否需要被平台统计、查询、复盘和监督。

两个模块使用相同稳定策略 ID，但不要求展示相同策略集合。

## 5. 能力定义

### 行情分析

用于研究市场结构、交易规律、分位、联动和可交易窗口，不承担正式下单动作。

### 交易执行

用于执行前判断、参数确认、交易命令提交、双腿配平、执行反馈和必要的即时风险展示。

页面具备交易执行能力不代表后端交易系统已经实现；真实命令必须遵循前后端协作架构。

### 策略损益

用于展示策略整体结果、损益归因、收益和成本构成、净值和明细穿透。

### 账户资金

用于展示策略关联账户的权益、可用资金、保证金、资金占用、效率和风险状态，不维护账户主档。

### 订单信息

用于展示当前持仓、历史订单、成交、执行和核对记录，不承担实时下单主操作。

## 6. 新增策略规则

新增策略时，应先确认：

1. 稳定策略 ID。
2. 正式名称。
3. 策略类型。
4. 是否通过交易平台下单。
5. 是否进入策略管理。
6. 是否具备行情分析、交易执行、损益、资金和订单能力。
7. 单腿、双腿或多腿结构。
8. 单账户、双账户或多账户结构。
9. 后端是否需要 StrategyInstance 和真实账户绑定。
10. 数据来源、损益口径和风险指标是否已经确认。

完成确认后：

- 更新对应策略文档。
- 更新本能力矩阵。
- 更新前端策略注册表。
- 需要后端支持时更新公共领域模型和接口契约。

## 7. 验收标准

- 交易平台只显示三类平台执行策略。
- 策略管理显示全部六类纳管策略。
- 页面能力与策略注册表一致。
- 产品页面能力不被误认为后端运行状态。
- 新增策略不会通过页面硬编码绕过正式确认流程。
