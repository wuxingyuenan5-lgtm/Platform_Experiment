# 共享组件与主题治理规范

状态：`active`  
适用基线：Platform V5

## 1. 目标

在不改变一级架构、不大规模迁移策略页面的前提下，规范共享组件、业务组件、主题变量和页面样式的归属，避免 Vibe Coding 过程中出现：

- 同一种控件存在多套实现。
- 局部修改影响多个页面。
- 业务组件被错误抽到全局共享层。
- 页面文件同时承担数据、图表、结构和样式。
- 为了消除少量重复而过度抽象。

本规范当前只指导后续本地修改，不要求立即重构阶段 7－10 的策略代码。

## 2. 组件分层

前端组件按四层管理。

### 2.1 模块入口层

职责：

- 读取路由。
- 管理一级或二级页签。
- 管理当前策略、分类或模块状态。
- 装配页面组件。

允许：

- 少量路由和页面状态。
- 页面级组件选择。

禁止：

- 大量业务计算。
- 大量 ECharts 配置。
- 大块 Mock 数据。
- 复杂数据表格定义。
- 为每个子页面重复定义完整样式体系。

当前参考：

- `src/views/platform/index.vue`
- `src/views/strategy/management/index.vue`

### 2.2 页面编排层

职责：

- 决定页面包含哪些业务区块。
- 决定区块顺序和布局。
- 管理页面级筛选上下文。
- 协调多个业务区块之间的状态。

示例：

- 资费行情分析页。
- 跨所价差执行页。
- 策略损益页。
- 风控详情页。

页面编排层不应直接保存大型静态数据或实现可复用图表算法。

### 2.3 业务区块层

职责：表达一个明确业务概念。

示例：

- 资金费率主图。
- 双腿执行参数区。
- 损益归因总图。
- 账户风险总览。
- 订单记录表。
- 宏观流动性看板区块。

业务区块可以知道策略或模块含义，但应避免同时承担多个不相关业务目的。

### 2.4 基础组件层

职责：提供没有具体策略含义的通用 UI 能力。

示例：

- 页签。
- 按钮。
- 筛选器。
- 指标卡片。
- 图表容器。
- 数据表格。
- 分页。
- 状态标签。
- 空状态和错误状态。

基础组件不得直接出现：

- 资费套利。
- 黄金跨所价差。
- 海内外价差。
- 短线交易员 L/W。

等具体业务名称。

## 3. 共享范围

### 3.1 全局共享

放置位置优先使用项目现有 `src/components/`。

适用条件：

- 与具体业务模块无关。
- 多个一级模块真实复用。
- API 和视觉相对稳定。

不建议当前直接将大量策略组件移动到全局共享目录。

### 3.2 策略域共享

当前放置位置：

`src/views/strategy/shared/`

适用条件：

- 交易平台和策略管理共同使用。
- 多个策略真实复用。
- 仍属于策略业务域。

当前应保留：

- `CompactSegmentTabs.vue`
- `strategy-theme.less`
- `strategyRegistry.ts`

### 3.3 模块内部共享

如果组件仅在一个模块内多个页面使用，应留在该模块内部，例如：

```text
views/hedgeBoard/components/
views/strategy/management/components/
views/strategy/funding-carry/components/
```

不要因为出现两次就立刻提升为全局共享组件。

## 4. 何时抽取共享组件

至少满足以下多数条件：

- 已在两个或以上页面真实重复。
- 业务含义一致。
- 输入和输出结构可以稳定描述。
- 样式差异可以通过有限配置解决。
- 抽取后不会增加大量条件分支。
- 后续维护确实会同时修改这些副本。

不应抽取的情况：

- 只是视觉相似，但业务含义不同。
- 只使用一次。
- 为了减少几十行代码而引入复杂配置。
- 组件需要大量 `variant` 和布尔参数才能工作。
- 抽取后更难理解页面业务结构。

## 5. 当前共享组件治理

### 5.1 `CompactSegmentTabs.vue`

定位：统一紧凑型页签组件。

适用：

- 策略切换。
- 页面视角切换。
- 对冲基金看板分类切换。

约束：

- 只接收稳定的 `key` 和 `label`。
- 不直接读取路由。
- 不直接读取策略注册表。
- 不内置具体业务权限。
- 不在单个页面复制一套相同样式的页签。

### 5.2 后续候选共享组件

按优先级观察，不要求立即创建：

- `ModuleToolbar`：模块顶部左右分区工具栏。
- `FilterBar`：集中展示筛选条件。
- `MetricCard`：统一指标名称、数值和辅助信息。
- `ChartCard`：统一图表标题、工具栏、加载、空状态和错误状态。
- `StatusBadge`：统一状态语义。
- `RecordsTable`：统一筛选、分页和空状态。
- `AccountComparison`：双账户或多账户对照骨架。

只有确认多处真实复用后才落地。

## 6. 主题变量治理

当前策略视觉基座：

`src/views/strategy/shared/strategy-theme.less`

### 6.1 变量优先

需要统一视觉时，优先使用或新增变量：

- 背景。
- 表面颜色。
- 边框。
- 文字层级。
- 强调色。
- 状态色。
- 阴影。
- 圆角。
- 间距。
- 字号。
- 控件高度。

避免在多个页面重复硬编码同一颜色、圆角和字号。

### 6.2 选择器控制

禁止：

- 为解决单页问题扩大通用类选择器范围。
- 使用过宽的 `.card-head`、`.input-row`、`.select` 等选择器影响整个策略域。
- 通过大量 `!important` 修复层叠冲突。
- 在主题文件内加入具体策略页面布局。

要求：

- 页面布局保留在页面或模块样式中。
- 主题文件只管理稳定视觉基座。
- 新增通用选择器前检查影响页面。

### 6.3 颜色语义

统一区分：

- 品牌或选中强调色。
- 正向状态。
- 负向状态。
- 警告状态。
- 中性信息。

交易涨跌色与风险严重程度不得仅依赖同一套红绿逻辑。

所有状态除颜色外必须有文字或图标语义。

## 7. 字体和数字层级

当前策略域已经定义：

- 页面标题。
- 区块标题。
- 卡片标题。
- 正文。
- 小字号说明。
- 数据字体。

治理要求：

- 同层级标题使用相同字号和字重。
- 关键数字不能仅因页面不同而随意放大。
- 数值和单位分开表达时保持固定间距。
- 金额、比例、价格和数量应优先使用等宽数字特征。
- 不使用多个超大数字争夺同一屏主视觉。

## 8. 页面密度和布局

### 8.1 通用阅读顺序

- 先总览。
- 再核心业务区。
- 再细分和归因。
- 最后记录、补充和低优先级内容。

### 8.2 卡片使用

卡片必须有明确业务边界。

禁止：

- 每一行文字都单独放卡片。
- 通过嵌套多层卡片制造层级。
- 卡片标题下堆积无决策价值的副标题和说明。

### 8.3 响应式

当前主要面向桌面工作台。

要求：

- 常用桌面宽度下核心区域不出现无必要横向滚动。
- 超宽业务表格允许独立横向滚动。
- 顶部页签和筛选器在窄屏时允许换行。
- 不为移动端强行牺牲桌面交易工作台密度。

## 9. 图表组件治理

图表组件至少拆分以下职责：

- 数据输入。
- 图表配置生成。
- 图表容器和生命周期。
- 页面筛选状态。

要求：

- 图表不直接读取分散页面全局变量。
- 同一指标图表和表格使用同一数据源。
- 图表具备加载、空数据和异常状态。
- 时间缩放、图例和 Tooltip 交互保持一致。
- 不在页面模板中堆叠大量内联 SVG 或图表样式对象，除非确有必要。

## 10. 数据表格治理

统一能力：

- 明确列名和单位。
- 状态显示。
- 无数据状态。
- 必要筛选。
- 分页。
- 超宽滚动。

要求：

- 页面不得通过字符串正负号随意推断所有业务状态。
- 状态、方向和数值语义应尽量由数据字段明确提供。
- 不同策略可以拥有不同列，但基础交互保持一致。

## 11. 文件和命名规范

### 入口文件

- `index.vue` 只用于明确目录入口。
- 不将所有业务逻辑长期保留在入口文件。

### 业务组件

使用业务含义命名，例如：

- `FundingRateChart.vue`
- `SpreadExecutionSummary.vue`
- `StrategyPnlOverview.vue`

避免：

- `Panel1.vue`
- `NewCard.vue`
- `TestComponent.vue`
- `FinalVersion.vue`

### Legacy 命名

出现 `Legacy` 表示已知替换候选，必须在遗留代码清单中记录；不得长期新增更多业务依赖。

## 12. 修改流程

共享样式或组件修改前：

1. 搜索全部引用。
2. 判断是局部问题还是共享问题。
3. 记录预期影响页面。
4. 做最小范围修改。
5. 检查相关页面。
6. 必要时增加专项验证脚本。

禁止因为一个页面问题顺手重写共享层。

## 13. 本轮不执行的工作

- 不迁移资费套利具体页面。
- 不迁移跨所价差具体页面。
- 不迁移海内外价差具体页面。
- 不迁移抄底和短线策略页面。
- 不批量抽取共享组件。
- 不重写主题文件。

这些工作由用户后续本地修改时参考本规范。

## 14. 验收标准

- 组件可以明确归入入口、编排、业务区块或基础组件层。
- 共享组件没有具体策略含义。
- 主题文件以变量和稳定视觉规则为主。
- 局部样式不通过宽泛选择器影响多个页面。
- 新增共享组件有真实复用依据。
- 后续本地策略重构不需要改变一级架构。
