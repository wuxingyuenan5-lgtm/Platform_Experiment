# Platform V6 前端状态归属规范

状态：`active`  
适用分支：`refactor/frontend-architecture-v6`  
架构层级：前端架构

## 1. 文档定位

本文档定义浏览器前端中的路由状态、页面状态、模块状态、全局状态和服务端数据状态如何归属。

前端状态用于组织页面交互，不是订单、账户、持仓、损益和风险的最终业务权威。前端总览参见 `frontend/frontend-overview.md`。

## 2. 状态分类

### 2.1 路由状态

适用于：

- 用户刷新页面后应保留。
- 可以通过链接直接打开。
- 影响页面主视图或主要业务上下文。
- 浏览器前进和后退应恢复。

典型内容：

- 当前策略。
- 当前行情分析／交易执行视角。
- 当前策略损益／账户资金／订单信息视角。
- 当前对冲基金看板分类。
- 当前新闻日历分类。

规则：

- 优先使用 path、route meta 或 query。
- 参数必须有默认值、类型检查和非法值回退。
- 页面不得同时维护另一份不同步的主状态。
- 不在 URL 中保存敏感数据、完整交易参数或大量临时筛选。

### 2.2 页面本地状态

适用于只在当前页面生命周期内有效的交互：

- 图表显示项。
- 展开和折叠。
- 当前分页。
- 临时筛选条件。
- 输入中的交易参数。
- 弹窗和确认框。
- 未提交的表单修改。

规则：

- 使用 `ref`、`reactive` 或页面级 composable。
- 页面卸载后无需保留的状态不得进入全局 Store。
- 复杂状态应抽成当前模块内的组合式函数，不直接堆积在入口页。
- 未提交交易参数离开页面时按照需求提示确认放弃。

### 2.3 模块共享状态

适用于同一模块多个页面或业务区块共享，但不需要全平台使用的内容：

- 当前策略上下文。
- 当前账户组合。
- 当前执行批次。
- 模块级筛选条件。
- 模块内临时选择和草稿。

规则：

- 优先使用模块内 composable 或 provider／inject。
- 只有确实跨路由并需要保留时，才建立模块级 Pinia Store。
- 模块 Store 不得承载其他模块的业务对象。
- 当前执行批次只保存前端展示和恢复所需信息，权威状态来自后端查询或事件。

### 2.4 全局状态

仅适用于全平台共同依赖：

- 当前登录用户。
- 权限能力和数据范围。
- 全局通知状态。
- 全局风险阻断状态。
- 用户界面偏好。
- 当前运行环境标识。
- 全局账户上下文，仅在产品明确需要时使用。

规则：

- 全局 Store 数量应保持克制。
- 页面筛选、图表开关和普通分页不得放入全局 Store。
- 全局状态必须有明确初始化、清理、过期和持久化规则。
- 敏感权限和安全状态不能仅依赖浏览器持久化值。

### 2.5 服务端数据状态

服务端数据包括：

- 行情。
- 账户和余额。
- 持仓。
- 订单和成交。
- 执行批次。
- 损益。
- 风险状态。
- 数据质量和对账结果。

每类服务端数据应区分：

- 数据主体。
- `loading`。
- `refreshing`。
- `error`。
- `lastUpdated`。
- 数据来源。
- 数据质量。

规则：

- 服务端数据通过 Repository／Adapter 获取。
- 不把 Mock 数据本身复制进全局 Store。
- 实时事件更新后仍应能够通过查询接口恢复权威状态。
- 页面卸载不代表服务端业务状态被清除。

## 3. 界面状态、请求状态和业务数据分离

同一页面中应区分：

- 业务数据：订单、持仓、损益、账户、风险记录。
- 请求状态：加载、刷新、错误和更新时间。
- 界面状态：页签、筛选、折叠和选中项。
- 命令状态：未提交、提交中、已受理、已拒绝、结果未知。

不得使用一个大型 reactive 对象同时承载全部状态。

## 4. 模块规则

### 4.1 交易平台

- `desk`、`section`：路由状态。
- 交易所、标的和时间粒度：页面或模块状态；需要分享链接时再进入 query。
- 下单参数：页面本地状态。
- 当前执行批次：模块共享状态，权威状态来自后端。
- 订单、成交、配平和暴露：服务端数据状态。

切换策略时：

- 返回目标策略行情分析。
- 清理不兼容执行参数。
- 保留兼容的公共分析条件。

### 4.2 策略管理

- `strategy`、`section`：路由状态。
- 切换策略时保留当前管理视角。
- 日期、订单状态和分页：页面本地状态；需要链接复现时可以进入 query。
- 当前策略基础信息：从统一策略注册表或后端策略定义读取，不复制进 Store。
- 损益、账户、订单和核对结果：服务端数据状态。

### 4.3 对冲基金看板

- `category`：路由 meta 或 path。
- 图表时间区间和显示项：页面本地状态。
- 市场数据：服务端数据状态。
- 用户收藏工具：用户偏好状态。

### 4.4 风险管理

- 当前子板块：路由状态。
- 风险规则编辑草稿：页面本地状态。
- 当前风险状态和全局阻断：服务端数据；必要摘要进入全局状态。
- 用户、账户、审计和通知数据不应塞进一个 Risk Store。

## 5. 持久化规则

允许持久化：

- 用户界面偏好。
- 最近使用但不敏感的筛选条件。
- 合法且可验证的最近页面上下文。

不得仅依赖前端持久化：

- 权限。
- 订单和成交状态。
- 账户余额。
- 风险阻断结果。
- 交易命令完成状态。

所有持久化值必须有版本和非法值回退策略。

## 6. 禁止事项

- 不因多个组件需要使用就立即放入 Pinia。
- 不在路由状态和本地状态中同时保存同一个主字段。
- 不把 Mock 数据本身存入全局 Store。
- 不使用全局事件总线代替清晰数据流。
- 不把后端响应原样当作长期领域状态。
- 不把按钮禁用状态视为最终权限控制。
- 不把 WebSocket 事件缓存视为不可恢复的唯一事实。

## 7. 验收标准

- 刷新页面后主要视图上下文符合需求。
- 浏览器前进、后退能够恢复主视图。
- 页面离开后临时交互状态正确清理。
- 全局 Store 中不存在普通页面分页和图表开关。
- 同一个状态只有一个前端权威来源。
- 服务端业务事实能够通过查询重新恢复。
- 交易命令状态与订单、成交状态分别表达。
