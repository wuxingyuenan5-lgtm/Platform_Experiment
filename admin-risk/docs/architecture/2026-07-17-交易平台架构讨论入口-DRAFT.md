## 1. 当前讨论目标

本轮目标是设计一套满足 Variable-Global 实际需求、适合初创团队开发维护并可逐步接入真实交易的自有平台架构。

当前已明确的 V1 范围：

- 第一版本后端优先落地策略模块。
- 初期同时接入 MT5 和 Crypto。
- CTP 和国内期货自动执行延后。
- 资费套利和跨所价差形成平台真实执行链路。
- 海内外价差保留分析、导入和管理能力，CTP 执行延后。
- 策略管理覆盖六类策略。
- 其他一级模块暂不建设完整后端。
- 金融AI分析只完善信息和读取边界，暂不开发。

当前不直接决定：

- 固定开发工期和负责人。
- Live 真实资金开放时间。
- 最终生产部署拓扑。
- 微服务和高可用体系。

## 3. 当前推荐工程画像

```text
Variable-Global
├─ admin-risk
│  └─ Vue 前端
├─ platform-backend
│  └─ Python 模块化单体
├─ execution-runtime
│  ├─ Crypto Gateway Workers
│  └─ MT5 Runtime / Worker
├─ PostgreSQL
└─ Redis
```

六层是逻辑职责，不等于六个服务。

## 5. 讨论与确认顺序

建议按以下顺序逐项确认：

1. 策略模块 V1 产品范围。
2. 三工程结构和默认技术基线。
3. Platform Backend 与 Runtime 的边界。
4. Crypto 三家交易所的接入顺序和 V1 验收深度。
5. MT5 Worker 模型和首个 Demo 环境。
6. ExecutionPlan 值对象和双腿执行政策。
7. Runtime Command／Event 契约。
8. PostgreSQL、Redis 和 Runtime Journal 的职责。
9. 策略 PnL、EconomicEvent 和外部导入范围。
10. 恢复、对账和 READY 条件。
11. 各开源能力的采用方式。
12. 对 active 架构的修改清单和 ADR。
13. 最后创建代码骨架、正式开发任务和发布门禁。
