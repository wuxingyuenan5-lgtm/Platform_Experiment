## 1. 当前讨论目标

本轮目标是设计一套满足 Variable-Global 实际需求、适合初创团队开发维护并可逐步接入真实交易的自有平台架构。

当前不讨论：

- 新增产品功能清单。
- 开发排期、工期和负责人。
- 首个实盘策略和真实账户。
- 金融AI分析实际开发。

## 3. 当前推荐工程画像

```text
Variable-Global
├─ admin-risk
│  └─ Vue 前端
├─ platform-backend
│  └─ Python 模块化单体
├─ execution-runtime
│  └─ 独立交易执行与连接进程
├─ PostgreSQL
└─ Redis
```

六层是逻辑职责，不等于六个服务。

## 4. 讨论与确认顺序

建议按以下顺序逐项确认：

1. 三工程结构是否接受。
2. 默认技术基线是否接受。
3. Platform Backend 与 Runtime 的边界。
4. ExecutionPlan 是否成为正式对象。
5. Runtime Command／Event 契约。
6. PostgreSQL 和 Redis 的初期职责。
7. MT5 Worker 模型。
8. 恢复、对账和 READY 条件。
9. 各开源能力的采用方式。
10. 对 active 架构的修改清单和 ADR。
