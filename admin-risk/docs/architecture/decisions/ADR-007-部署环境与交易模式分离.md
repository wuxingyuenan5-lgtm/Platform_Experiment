# ADR-007：部署环境与交易模式分离

状态：`accepted`  
产品基线：Platform V5  
架构版本：Platform V6  
适用分支：`refactor/frontend-architecture-v6`  
日期：2026-07-16

## 背景

早期架构将 `demo`、`simulation`、`test`、`paper` 和 `live` 放在同一环境枚举中。该写法混合了两个不同问题：

- 系统部署在哪里。
- 当前是否会产生真实交易结果。

例如生产部署可以运行 Paper Trading，测试部署也可能连接受控测试账户。若只使用一个 `environment` 字段，权限、账户隔离、风险限制和页面提示容易产生歧义。

## 决策

Platform V6 将以下维度分开：

### DeploymentEnvironment

表示系统部署环境：

- `development`
- `testing`
- `staging`
- `production`

### TradingMode

表示交易执行模式：

- `demo`
- `simulation`
- `paper`
- `live`

### TradingPermissionState

表示当前上下文的交易能力结果：

- `disabled`
- `read_only`
- `enabled`
- `blocked`

交易按钮是否可用，不由任一单字段决定，而由以下条件共同形成：

- DeploymentEnvironment。
- TradingMode。
- 用户能力权限。
- 数据范围。
- 风险状态和全局阻断。
- 账户、Gateway 和交易服务健康。
- 报价及必要数据质量。

## 约束

- 三个维度由受信任的后端会话、配置或权限服务返回。
- 前端不得通过域名、URL query、页面颜色或本地常量推断实盘能力。
- `production` 不等于 `live`。
- `testing` 不等于 `paper`。
- `live` 模式必须配合服务端权限、风险、账户和环境隔离。
- 页面在状态未知时不得开放正式交易。

## 影响

需要逐步更新：

- 前端路由、权限与环境规范。
- 状态枚举和领域模型。
- API 会话上下文。
- 交易命令、审计、日志和告警字段。
- 页面环境标识和按钮可用性判断。

## 不在本 ADR 中决定

- 实际部署平台。
- 生产和测试域名。
- Paper Trading 的具体供应商实现。
- 实盘账户和 Gateway 选型。

## 重新讨论条件

当平台需要支持更多隔离维度，例如地区、租户、业务线或灾备区域时，可以增加独立上下文字段，但不得重新将部署位置和交易模式合并为一个枚举。
