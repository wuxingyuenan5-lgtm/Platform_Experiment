# ADR-004：交易工具目录由 Markdown 维护并生成前端数据

状态：`accepted`  
日期：2026-07-15  
适用基线：Platform V5

## 背景

对冲基金看板中的交易工具数量较多，涉及宏观、股市、加密、金属、量化和综合工具。如果直接在 TypeScript 中人工维护，容易出现结构不统一、修改门槛高和人工生成文件被覆盖的问题。

V5 已建立 Markdown 到 TypeScript 的同步脚本。

## 决策

交易工具目录采用以下单一数据流：

1. 人工维护 `docs/trading-tools-bookmarks-review.md`。
2. 执行 `pnpm sync:trading-tools`。
3. 生成 `src/views/hedgeBoard/tradingTools/data/marketTools.ts`。
4. 前端页面读取生成后的数据。

`marketTools.ts` 视为生成文件，不作为日常内容编辑入口。

## 原因

- Markdown 更适合人工整理和审阅大量外部工具。
- 生成脚本可以统一分类、字段和格式。
- 避免文档与页面数据分别维护。
- 便于后续批量校验链接和分类。

## 影响

- 修改工具内容时，优先修改 Markdown 源文件。
- 修改数据结构或生成逻辑时，才修改同步脚本。
- 构建和开发前保持同步脚本自动执行。
- 代码评审时应区分人工源文件变更和生成结果变更。

## 异常处理

如果生成结果不正确：

1. 检查 Markdown 格式。
2. 检查同步脚本解析规则。
3. 修复源文件或脚本后重新生成。
4. 不直接长期修补生成文件。

## 重新讨论条件

当交易工具迁移到正式后台管理或远端配置服务时，可以替换 Markdown 源，但必须保留“唯一人工维护源”和“自动生成/适配”的原则。
