# ADR-001：一级架构保持不变

状态：`accepted`  
日期：2026-07-15  
适用基线：Platform V5

## 背景

Platform V5 的一级架构、一级导航和主路由由产品负责人完成设计，并作为当前平台的既定产品骨架。

本轮工作的目标是明确模块边界、需求口径、策略定义和前端工程规范，而不是重新设计一级信息架构。

## 决策

Platform V5 当前一级模块只有：

1. 首页。
2. 对冲基金看板。
3. 新闻日历与理财。
4. 策略。
5. 风险管理。
6. 金融 AI。

本轮及后续常规前端重构中：

- 不调整上述六个一级模块。
- 不擅自更改一级导航名称和产品定位。
- 不因为存在独立代码目录、隐藏路由或历史页面，就新增一级模块。
- 数据、账户、财务、报表、监控、审计、用户、设置和通知等能力，按照当前前端设计归入六个一级模块内部，作为二级或三级子板块。
- 不因为局部页面职责混乱而合并、拆分或移除一级模块。
- 模块内部问题通过子板块定位、职责矩阵、页面拆分和数据边界治理解决。

## 原因

- 一级架构属于产品决策，而不是代码整洁度问题。
- 当前主要问题发生在模块内部职责扩散、需求来源分散和组件自然生长。
- 隐藏路由和历史独立页面是工程实现现状，不等于产品一级模块。
- 重做一级架构会显著扩大重构风险，并干扰已经确认的产品方向。

## 影响

- 架构讨论必须在六个一级模块框架内进行。
- 新功能必须先确定一级模块，再按照当前前端设计确定二级或三级位置。
- 发现跨模块重复时，优先确定核心业务对象的主责子板块和写入入口，而不是立即改导航。
- 风险管理内部的账户、报表、审计、监控、用户、设置和通知等能力，应按照内部层级治理，不再被描述为独立一级模块。

## 重新讨论条件

仅在以下情况之一成立时重新讨论：

- 产品负责人明确提出一级架构调整。
- 现有六个一级模块无法承载已经确认的新业务模式。
- 某个一级模块在长期运行中被证明不存在独立用户任务和产品价值。

重新讨论必须形成新的 ADR，并明确替代本文件。
