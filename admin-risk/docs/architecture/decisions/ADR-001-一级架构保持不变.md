# ADR-001：一级架构保持不变

状态：`accepted`  
日期：2026-07-15  
产品基线：Platform V5  
架构版本：Platform V6  
适用分支：`refactor/frontend-architecture-v6`

## 背景

Platform V5 的一级产品架构、导航和主路由已经作为当前平台的既定产品骨架。

后续架构治理目标是明确模块边界、需求口径、策略定义和工程规范，而不是因代码目录、后端服务或局部页面问题重新设计一级信息架构。

## 决策

平台一级产品模块固定为：

1. 首页。
2. 对冲基金看板。
3. 新闻日历与理财。
4. 策略。
5. 风险管理。
6. 金融AI分析。

正式模块名称以 `docs/governance/glossary.md` 为唯一来源。

常规前端、后端和架构重构中：

- 不擅自调整上述六个一级模块。
- 不因存在独立代码目录、隐藏路由、后端领域或历史页面新增一级模块。
- 账户、财务、报表、监控、审计、用户、设置和通知等能力按照产品设计归入现有模块内部。
- 产品菜单归属不等于后端服务和数据权威归属。
- 模块内部问题通过子板块定位、职责矩阵、页面拆分和领域边界治理解决。

## 原因

- 一级架构属于产品决策，不是代码整洁度或微服务划分问题。
- 当前主要问题发生在模块内部职责扩散、需求来源分散和实现边界不清。
- 隐藏路由和独立服务是工程实现，不等于产品一级模块。
- 重做一级架构会扩大风险并干扰已确认产品方向。

## 影响

- 架构讨论必须在六个一级模块框架内进行。
- 新功能先确定产品入口，再确定技术领域和数据权威。
- 跨模块重复优先通过唯一对象、唯一写入入口和 Read Model 解决。
- 风险管理内部账户、报表、审计、监控、用户、设置和通知等页面不被描述为独立一级模块。
- “金融AI分析”作为正式一级模块名称，旧称“金融AI”不再作为正式名称。

## 重新讨论条件

仅在以下情况之一成立时重新讨论：

- 产品负责人明确提出一级架构调整。
- 现有六个一级模块无法承载已确认的新业务模式。
- 某一级模块长期运行后被证明不存在独立用户任务和产品价值。

重新讨论必须形成新的 ADR，并明确替代本文件。
