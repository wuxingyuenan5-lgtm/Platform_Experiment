# ADR-001：一级架构保持不变

状态：`accepted`  
日期：2026-07-15  
适用基线：Platform V5

## 背景

Platform V5 的一级架构、一级导航、模块名称和主路由由产品负责人已经完成设计，并作为当前平台的既定产品骨架。

本轮工作的目标是重新明确模块边界、需求口径、策略定义和前端工程规范，而不是重新设计一级信息架构。

## 决策

本轮及后续常规前端重构中：

- 不调整现有一级架构。
- 不擅自更改一级导航名称。
- 不因为局部页面职责混乱而合并、拆分或移除一级模块。
- 模块内部问题通过模块定位、职责矩阵、页面拆分和支撑模块边界治理解决。

## 原因

- 一级架构属于产品决策，而不是代码整洁度问题。
- 当前主要问题发生在模块内部职责扩散、需求来源分散和组件自然生长。
- 重做一级架构会显著扩大重构风险，并干扰已经确认的产品方向。

## 影响

- 架构讨论必须在现有一级模块框架内进行。
- 发现跨模块重复时，优先确定业务对象主责，而不是立即改导航。
- 风控页、账户页、报表页等存在职责混杂时，先治理页面和数据边界。

## 重新讨论条件

仅在以下情况之一成立时重新讨论：

- 产品负责人明确提出一级架构调整。
- 现有一级架构无法承载已经确认的新业务模式。
- 多个一级模块在长期运行中被证明不存在独立用户任务和业务对象。

重新讨论必须形成新的 ADR，并明确替代本文件。
