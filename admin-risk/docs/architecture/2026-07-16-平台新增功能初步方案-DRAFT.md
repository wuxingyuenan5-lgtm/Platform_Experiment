# 1. 文档目标

本文档用于明确 Variable-Global 平台在现有框架基础上，需要新增哪些功能，以及这些功能应如何结合：

- vn.py；
- aiomql；
- Freqtrade；
- rotki；
- NautilusTrader；
- PyTrader。

本文不重新定义平台总体架构，而是聚焦：

1. 具体增加哪些前端功能；
2. 后端需要增加哪些模块；
3. 每项功能参考哪个项目；
4. 每项功能如何落到现有策略模块；
5. 每项功能的优先级；
6. 每项功能如何验收。

---

# 2. 核心结论

平台新增功能不应围绕“再增加几个页面”展开，而应围绕真实交易系统的完整链路展开：

```text
连接
→ 策略运行
→ 指令
→ 风控
→ 执行
→ 订单
→ 成交
→ 持仓
→ 对账
→ 账本
→ 损益
→ 恢复
→ 审计
```

新增功能的主来源如下：

| 项目 | 主要吸收能力 |
|---|---|
| vn.py | Gateway、订单、成交、持仓、OMS、基础风控、算法执行 |
| aiomql | MT5底层访问、重连、账户、订单、持仓、历史和异步封装 |
| Freqtrade | 策略实例运营、启动暂停、禁止开仓、环境模式、Web控制 |
| rotki | 经济事件、账本、缺失数据、会计规则和PnL报告 |
| NautilusTrader | 状态机、对账、恢复、降级、幂等和可靠性 |
| PyTrader | 远程MT4/MT5节点和EA桥接备用能力 |

最终仍遵循：

> **现有Vue平台负责产品和操作，vn.py负责统一交易执行，其他项目只提供功能设计和局部技术参考。**

# 4. Gateway连接中心

## 4.1 功能定位

Gateway连接中心用于统一管理：

- Bybit；
- Binance；
- OKX；
- MT5；
- CTP；
- 后续其他交易所和经纪商。

它应成为全平台底层状态入口，而不是让每个策略页面分别显示一个静态“在线”标签。

## 4.2 前端功能

### Gateway总览表

| Gateway | 类型 | 账户 | 行情 | 交易 | 延迟 | 最后同步 | 状态 |
|---|---|---|---|---|---:|---|---|
| BYBIT-01 | Crypto | Crypto Main | 正常 | 正常 | 24ms | 21:30:08 | RUNNING |
| MT5-SPREAD-01 | MT5 | Exness Spread | 正常 | 正常 | 85ms | 21:30:07 | RUNNING |
| MT5-TRADER-A | MT5 | Trader A | 正常 | 只读 | 92ms | 21:30:05 | DEGRADED |
| CTP-GOLD | CTP | 国内黄金 | 断开 | 断开 | — | 21:28:10 | FAULTED |

### Gateway详情

显示：

- Gateway ID；
- Gateway类型；
- 绑定账户；
- 行情连接；
- 交易连接；
- 终端连接；
- 经纪商服务器连接；
- 最后心跳；
- 最后行情时间；
- 行情新鲜度；
- P50/P95/P99延迟；
- 最近重连次数；
- 最近错误；
- 是否允许新开仓；
- 当前运行环境；


### GatewayCapability

用于描述每个Gateway支持什么：

```text

```

前端根据能力动态开放或禁用操作。

## 4.4 适用策略

- 资金费率套利；
- 跨所价差；
- 海内外价差；
- 短期交易员A；
- 短期交易员B。

## 4.5 验收标准

- Gateway断开后前端10秒内可见；
- 自动重连过程可见；
- 行情过期自动标记DEGRADED；
- DEGRADED时禁止新开仓；
- Gateway重启后可重新同步账户和持仓；
- 不同Gateway故障相互隔离。

# 6. 策略实例控制中心

## 6.1 功能定位

平台不能只按“资金费率套利、跨所价差”展示页面，还需要统一管理每一个真实运行实例。

## 6.2 核心模型

```text
StrategyTemplate
    ↓
StrategyVersion
    ↓
StrategyInstance
```

### StrategyTemplate

例如：

- Funding Arbitrage；
- Crypto-MT5 Spread；
- MT5-SHFE Spread；
- Short-Term Trader。

### StrategyVersion

记录：

- 信号规则；
- 参数；
- 执行逻辑；
- 风控规则；
- 归因规则；
- 生效时间；
- 创建人；
- 审批人。

### StrategyInstance

记录：

- 实例ID；
- 使用版本；
- 绑定账户；
- 绑定Gateway；
- 环境；
- 当前状态；
- 当前持仓；
- 当前PnL；
- 风控状态；
- 最后心跳。

## 6.3 前端功能

### 策略实例表

### 可执行操作


## 6.4 状态

```text

READY
STARTING
RUNNING
```

## 6.5 验收标准

- 策略启动和停止有完整日志；
- STOP_ENTRY只禁止新仓，不影响平仓；
- RISK_FROZEN由风控系统触发；
- RECOVERING状态下禁止自动开仓；
- 同一策略模板可运行多个实例；
- 短期交易员A/B共享模板但账户和规则独立。

# 7. 环境模式管理

## 7.1 模式定义

```text
BACKTEST
PAPER
DEMO
LIVE
```

| 环境 | 行情 | 成交 | 账户 |
|---|---|---|---|
| BACKTEST | 历史数据 | 模拟撮合 | 虚拟 |
| PAPER | 实时数据 | 平台模拟 | 虚拟 |
| DEMO | 实时数据 | 经纪商Demo | Demo账户 |
| LIVE | 实时数据 | 真实成交 | 实盘账户 |

## 7.2 前端功能

所有策略页面顶部固定显示当前环境。

LIVE模式：

- 使用高辨识度标识；
- 二次确认；
- 显示真实账户；
- 显示预计资金影响；
- 显示风险检查结果。

## 7.3 切换流程

PAPER切换LIVE：

```text
权限检查
→ 参数冻结
→ 账户确认
→ Gateway确认
→ 风控复核
→ 版本快照
→ 审批
→ 启用
```

## 7.4 验收标准

- 环境不能由前端本地切换；
- LIVE模式必须记录审批和操作者；
- 不同环境数据不能混入同一PnL报告；
- DEMO和LIVE使用不同账户和密钥。

# 10. 执行前检查中心

## 10.1 功能定位

执行前检查必须同时覆盖：

- 用户权限；
- 策略状态；
- 市场状态；
- 账户资金；
- 合约规则；
- 风控限制；
- 多腿风险。

## 10.2 前端检查表

| 检查项 | 当前值 | 阈值 | 结果 |
|---|---:|---:|---|
| 行情新鲜度 | 120ms | 500ms | 通过 |
| MT5保证金率 | 850% | 300% | 通过 |
| Crypto强平距离 | 18.2% | 8% | 通过 |
| 预计残腿敞口 | 100oz | 150oz | 通过 |
| 策略仓位 | 400oz | 500oz | 警告 |
| 日内亏损 | -1.8% | -2% | 警告 |

## 10.3 检查分类

### 市场

- 行情在线；
- 行情新鲜；
- 交易时段；
- Bid/Ask有效；
- 市场深度；
- 价格跳动异常。

### 合约

- 合约存在；
- 最小价格变动；
- 最小下单量；
- 最大下单量；
- 合约乘数；
- Filling Mode；
- Position Mode。

### 账户

- 可用资金；
- 保证金；
- 杠杆；
- 强平距离；
- 预计下单后风险。

### 策略

- 策略允许开仓；
- 最大仓位；
- 最大回撤；
- 日内亏损；
- 最大残腿；
- 最大裸露时间。

## 10.4 验收标准

# 31. 最终功能定位

平台最终应具备四类能力。

## 31.1 交易能力

- 多Gateway；
- 多账户；
- 单腿执行；
- 多腿执行；
- 算法订单；
- 风控；
- 残腿；
- Kill Switch。

## 31.2 运营能力

- 策略模板；
- 策略版本；
- 策略实例；
- 启停；
- PAPER/DEMO/LIVE；
- 权限；
- 审批；
- 日志。

## 31.3 可靠性能力

- 对账；
- 恢复；
- 幂等；
- 告警；
- 降级；
- 数据质量；
- 审计。

## 31.4 管理与归因能力

- 账户资金；
- 经济事件；
- 不可变账本；
- PnL归因；
- 报告版本；
- 策略表现分析。

最终原则：

> **新增功能必须服务于统一交易链路，不能形成多套策略状态、多套订单状态、多套账本和多套损益口径。**

> **vn.py负责真实交易基础能力，Variable-Global负责策略运营、风险编排、账户管理、账本归因和前端产品体验。**
