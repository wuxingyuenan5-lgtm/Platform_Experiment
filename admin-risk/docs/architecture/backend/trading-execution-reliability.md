# Platform V6 交易执行与可靠性架构

状态：`active`  
适用分支：`refactor/frontend-architecture-v6`  
架构层级：后端架构

## 1. 文档定位

本文档定义真实交易接入前必须具备的交易命令、执行批次、订单状态、异常恢复、配平和人工处理边界。

本文不指定具体交易内核或 Gateway 技术，但规定任何实现都必须满足的可靠性要求。

## 2. 核心原则

- 用户的业务目标不等于交易所订单。
- 命令已受理不等于订单已提交。
- 订单已提交不等于已成交。
- 单腿成交不等于策略组合完成。
- 前端连接断开不影响后端执行。
- 未知结果必须显式记录，不能假定成功或失败。
- 所有高风险操作可审计、可恢复、可人工接管。

## 3. 标准执行链路

```text
TradeIntent
   ↓
TradeCommand
   ↓ permission / validation / risk
ExecutionBatch
   ↓
LegInstruction
   ↓
Order
   ↓
Execution / Fill
   ↓
Position / Exposure / PnL
```

## 4. TradeCommand

正式命令至少包含：

- `tradeCommandId`
- `requestId`
- `idempotencyKey`
- `strategyInstanceId`
- 操作类型
- 操作人
- 目标账户和标的
- 命令参数
- 客户端提交时间
- 服务端受理时间
- 当前环境

命令状态建议：

- `received`
- `validating`
- `rejected`
- `accepted`
- `executing`
- `completed`
- `failed`
- `result_unknown`
- `cancelled`

## 5. 幂等

以下操作必须支持幂等：

- 提交交易。
- 撤单。
- 平仓。
- 配平。
- 人工确认异常。

同一 `idempotencyKey` 和同一业务上下文重复提交时：

- 不创建重复执行批次。
- 返回原受理结果或当前状态。
- 记录重复请求。

幂等键的有效范围和保留时间由后端确定，前端不得自行生成可重复冲突的固定值。

## 6. 执行前校验

至少包括：

- 身份和能力权限。
- 环境是否允许该操作。
- 策略实例状态。
- 账户可用性。
- 标的和合约规则。
- 报价新鲜度。
- 数量、价格和精度。
- 余额和保证金。
- 两腿方向和比例。
- 风险规则和全局阻断。
- 是否存在冲突中的执行批次。

校验结果应形成结构化 `RiskDecision` 或 `ValidationResult`，不能只返回自然语言。

## 7. ExecutionBatch

一个双腿或多腿交易目标必须由一个执行批次组织。

执行批次至少记录：

- 目标组合和策略实例。
- 交易腿列表。
- 目标名义价值和配平关系。
- 执行策略，例如顺序、并行或条件触发。
- 当前状态。
- 已成交数量。
- 当前暴露。
- 异常和人工处理状态。

建议状态：

- `created`
- `prechecking`
- `ready`
- `submitting`
- `partially_filled`
- `balancing`
- `completed`
- `cancel_requested`
- `cancelled`
- `exception`
- `manual_intervention`
- `result_unknown`
- `terminated`

## 8. 订单状态

平台订单状态与外部状态码分开。

建议平台枚举：

- `pending_submit`
- `submitted`
- `acknowledged`
- `partially_filled`
- `filled`
- `cancel_pending`
- `cancelled`
- `rejected`
- `expired`
- `failed`
- `status_unknown`

外部 Gateway 负责将交易所、券商或 MT5 状态映射到平台枚举，并保留原始状态码。

## 9. 成交与订单分离

- 一张订单可以产生多笔成交。
- 成交记录不可因订单状态变化被覆盖。
- 成交至少保留价格、数量、费用、成交时间和外部成交 ID。
- 订单撤销不删除已经发生的成交。
- 持仓变化依据成交或经核对后的外部持仓事实生成。

## 10. 配平与暴露

执行批次必须独立计算：

- 目标配平比例。
- 实际成交比例。
- 名义价值偏差。
- 数量偏差。
- Delta 或方向暴露。
- 汇率暴露，适用时。
- 暴露持续时间。

配平状态建议：

- `not_calculated`
- `unbalanced`
- `partially_balanced`
- `balanced`
- `outside_tolerance`
- `manual_override`

## 11. 异常类型

至少包括：

- 报价过期。
- 账户不可用。
- 上游连接中断。
- 提交超时。
- 订单被拒绝。
- 单腿成交。
- 部分成交。
- 撤单结果未知。
- 成交回报重复或乱序。
- 实际持仓与订单推导不一致。
- 保证金不足。
- 风险状态在执行中变化。
- 数据源冲突。

异常必须关联：

- 执行批次。
- 交易腿。
- 订单或成交。
- 当前暴露。
- 处理动作。
- 操作人和时间。

## 12. 结果未知

出现网络超时或上游返回不确定时，不得直接标记失败并重新下单。

处理顺序：

1. 标记 `result_unknown`。
2. 暂停自动重复提交。
3. 使用客户端订单 ID、外部订单 ID 或账户订单查询进行确认。
4. 重新同步订单、成交和持仓。
5. 根据权威查询恢复状态。
6. 无法自动确认时进入人工处理。

## 13. 重试原则

可以自动重试：

- 只读查询。
- 明确未到达上游的幂等命令。
- 具有稳定幂等键和可确认结果的操作。

不得盲目自动重试：

- 结果未知的下单。
- 无幂等支持的外部接口。
- 可能扩大单腿暴露的操作。
- 风险状态已经变化的命令。

## 14. 恢复与重启

执行服务重启后必须能够：

- 读取未完成执行批次。
- 查询外部订单和成交。
- 恢复账户和持仓快照。
- 重建当前执行状态。
- 识别重复事件。
- 继续自动流程或进入人工处理。

运行状态不得只保存在进程内存。

## 15. 对账

至少定期核对：

- 平台订单与外部订单。
- 平台成交与外部成交。
- 推导持仓与外部持仓。
- 平台余额与外部余额。
- 损益和费用。

发现差异时：

- 不直接覆盖原始记录。
- 生成差异项。
- 标记影响范围。
- 必要时阻止继续执行。
- 记录人工确认或修正。

## 16. 人工处理

人工处理能力包括：

- 确认外部订单真实状态。
- 选择撤销、补单或配平。
- 终止执行批次。
- 接受已知偏差。
- 关联外部成交或持仓。
- 添加处理备注。

所有人工操作必须进行权限校验和审计。

## 17. 全局交易阻断

系统应预留全局或范围化阻断能力：

- 全平台阻断。
- 某环境阻断。
- 某 Gateway 阻断。
- 某账户阻断。
- 某策略实例阻断。
- 某标的阻断。

阻断状态由后端权威维护，并推送至前端。阻断默认禁止新增风险，不应无条件自动平仓。

## 18. 监控指标

至少监控：

- 命令受理量和拒绝量。
- 提交成功率。
- 上游延迟。
- 订单确认延迟。
- 单腿暴露数量和持续时间。
- `result_unknown` 数量。
- 对账差异。
- Gateway 连接状态。
- 人工处理积压。

## 19. 分阶段启用

真实交易能力按以下阶段启用：

1. 前端 Mock。
2. 后端模拟执行。
3. 测试网或沙盒。
4. 模拟账户／Paper Trading。
5. 小范围实盘只读。
6. 小资金、单策略、受控实盘。
7. 扩展账户和策略。

每个阶段必须有进入和退出条件，不直接从前端 Mock 跳到真实交易。

## 20. 验收标准

- 交易命令具有幂等键和稳定 ID。
- 双腿交易由 ExecutionBatch 组织。
- 订单和成交分开保存。
- 结果未知不会被误判为失败并重复下单。
- 服务重启后可以恢复未完成执行。
- 单腿暴露和配平状态可追踪。
- 对账差异和人工处理可审计。
- 前端断线不会中止后台执行。
