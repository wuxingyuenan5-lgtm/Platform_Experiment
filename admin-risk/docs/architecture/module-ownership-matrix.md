# Platform V6 模块职责与技术领域矩阵

状态：`active`  
适用分支：`refactor/frontend-architecture-v6`

## 1. 文档定位

本文档定义六个一级产品模块及其内部子板块之间的业务归属、读取权限和操作入口，并补充对应技术领域和数据权威。

必须区分：

- 产品归属：用户从哪个模块进入。
- 前端归属：页面、路由和组件放在哪里。
- 技术领域：后端业务规则和模型属于哪个领域。
- 数据权威：哪个服务或数据域维护最终事实。

产品模块不等同于后端服务边界。

## 2. 一级产品模块

Platform V6 保持六个一级模块：

1. 首页。
2. 对冲基金看板。
3. 新闻日历与理财。
4. 策略。
5. 风险管理。
6. 金融 AI。

## 3. 产品职责原则

- 每项核心业务能力具有唯一主责产品模块和主责子板块。
- 其他模块可以读取、展示摘要、引用结果或提供跳转，但不建立第二套冲突逻辑。
- 同一对象可以在多个页面展示，但展示目的、字段范围和操作权限必须明确。
- 页面、组件和数据源复用不改变产品归属。
- 一级菜单位置不决定后端代码包、数据库表或服务名称。

## 4. 模块与子板块

| 一级模块 | 主要子板块 |
|---|---|
| 首页 | 品牌主视觉、市场摘要、核心模块入口 |
| 对冲基金看板 | 宏观、商品、加密、美股、A 股、全球、交易工具 |
| 新闻日历与理财 | 宏观日历、新闻整理、理财信息 |
| 策略 | 交易平台、策略管理 |
| 风险管理 | 风控详情、账户与资产、财务与资金、数据与服务监控、报表、审计、用户与权限、个人账号、系统设置、消息通知 |
| 金融 AI | 研究问答、分析案例、信息归纳、情景推演、策略 Memo、结果容器 |

|---|---|---|---|---|

## 6. 信息镜像规则

| 信息 | 交易平台 | 策略管理 | 风险管理 | 权威领域 |
|---|---|---|---|---|
| 可用资金 | 判断当前是否具备执行条件 | 观察策略资金占用和效率 | 展示账户和风险视图 | Account |
| 当前持仓 | 支持继续执行、调整或平仓 | 完整查询、统计和复盘 | 展示风险摘要和关联事件 | Position |
| 收益 | 展示预计收益和当次影响 | 展示实际损益和归因 | 读取风险相关损益摘要 | PnL／Ledger |
| 风险 | 展示当前限制和执行许可 | 展示策略风险状态和历史变化 | 维护规则、事件和处置 | Risk |
| 订单与成交 | 展示当前执行批次 | 查询完整历史记录 | 读取异常和风险关联 | Trading／Execution |
| 用户权限 | 控制交易动作 | 控制查看和核对能力 | 提供管理入口 | IAM／Permission |

信息镜像不得形成独立数据口径或重复写入入口。

## 7. 风险治理原则

- 优先建立关键风险指标、明显异常提示和基础限制。
- 完整记录异常、人工干预、限制触发和处置结果。
- 阈值依据真实交易、资金占用、回撤和异常数据进行测试与校准。
- 未经验证的指标作为观察项，不直接形成强制阻断。
- 经过验证的阈值和处置标准再纳入正式风险规则。

## 8. 新增功能归属检查

新增页面、接口、服务或业务能力前，应确认：

1. 所属一级产品模块和子板块。
2. 处理的公共领域对象。
3. 前端权限是写入、操作、只读摘要还是跳转。
4. 后端技术领域和数据权威。
5. 是否已存在主责入口、模型、接口或组件。
6. 是否会形成重复管理或冲突口径。
7. 是否需要新的 ADR 或接口契约。

## 9. 验收标准

- 所有用户功能均归入六个一级产品模块之一。
- 每个核心业务对象具有明确技术领域和数据权威。
- 产品菜单位置不会导致技术领域被错误合并。
- 跨模块展示具有不同且清晰的使用目的。
- 同一对象不存在冲突口径或重复写入入口。
- 后续前端、后端和接口设计可以依据本矩阵判断归属。
