# 模块职责矩阵

状态：`active`  
适用基线：Platform V5

## 1. 文档定位

本文档定义六个一级模块及其内部子板块之间的业务归属、读取权限和操作入口，用于避免重复建设、数据口径冲突和跨模块职责扩散。

Platform V5 的一级模块为：首页、对冲基金看板、新闻日历与理财、策略、风险管理和金融 AI。

## 2. 职责原则

- 每项核心业务能力应具有唯一的主责一级模块和主责子板块。
- 核心业务对象的定义、完整管理能力和写入权限应保持唯一。
- 其他模块可以读取、展示摘要、引用结果或提供跳转，但不建立第二套冲突逻辑。
- 同一对象可以在多个页面展示，但展示目的、字段范围和操作权限必须明确。
- 页面、组件和数据源的复用不改变产品归属。

## 3. 模块与子板块

| 一级模块 | 主要子板块 |
|---|---|
| 首页 | 品牌主视觉、市场摘要、核心模块入口 |
| 对冲基金看板 | 宏观、商品、加密、美股、A 股、全球、交易工具 |
| 新闻日历与理财 | 宏观日历、新闻整理、理财信息 |
| 策略 | 交易平台、策略管理 |
| 风险管理 | 风控详情、账户与资产、财务与资金、数据与服务监控、报表、审计、用户与权限、个人账号、系统设置、消息通知 |
| 金融 AI | 研究问答、分析案例、信息归纳、情景推演、策略 Memo、结果容器 |

## 4. 核心职责矩阵

## 5. 信息镜像规则

同一业务对象在多个模块展示时，应遵循以下边界：

| 信息 | 交易平台 | 策略管理 | 风险管理 |
|---|---|---|---|
| 可用资金 | 判断当前是否具备执行条件 | 观察策略资金占用和效率 | 维护账户与资产主视图 |
| 当前持仓 | 支持继续执行、调整或平仓 | 完整查询、统计和复盘 | 展示风险摘要和关联事件 |
| 收益 | 展示执行前预计收益和当次影响 | 展示实际损益和归因 | 读取风险相关损益摘要 |
| 风险 | 展示当前限制、告警和执行许可 | 展示策略风险状态和历史变化 | 维护规则、事件和处置记录 |
| 订单与成交 | 展示当前执行批次 | 查询完整历史记录 | 读取异常订单和风险关联 |

信息镜像不得形成独立的数据口径或重复写入入口。

## 6. 风险治理原则

风险体系采用渐进式建设方式：

- 优先建立关键风险指标、明显异常提示和基础限制。
- 完整记录异常、人工干预、限制触发和处置结果。
- 阈值依据真实交易、资金占用、回撤和异常数据进行测试与校准。
- 未经验证的指标可作为观察项，不直接形成强制阻断。
- 经过验证的阈值和处置标准再纳入正式风险规则。

## 7. 功能归属检查

新增页面、组件或业务能力前，应确认：

1. 所属一级模块和子板块。
2. 处理的核心业务对象。
3. 对该对象的权限是写入、操作、只读摘要还是跳转。
4. 是否已经存在主责入口、数据模型或同类组件。
5. 新增能力是否会形成重复管理或冲突口径。

## 8. 验收标准

- 所有业务能力均归入六个一级模块之一。
- 每个核心对象具有明确的主责子板块和写入入口。
- 跨模块展示具有清晰、不同的使用目的。
- 同一业务对象不存在冲突的数据口径或重复操作入口。
- 风险规则符合渐进、可记录、可测试和可校准原则。
- 后续页面、数据和权限设计能够以本矩阵判断归属和边界。
