# 模块职责矩阵

状态：`active`  
适用基线：Platform V5

## 1. 目的

本文件不调整一级架构、一级导航或模块名称，只用于明确现有模块之间的职责边界，避免相同功能在多个模块重复建设。

核心原则：

> 同一个业务对象只能有一个主负责模块。其他模块可以展示必要摘要、镜像信息或跳转入口，但不得形成第二套完整管理逻辑。

## 2. 职责矩阵

| 业务对象或能力 | 主负责模块 | 其他模块允许展示 | 禁止重复建设 |
|---|---|---|---|
| 宏观和市场研究 | 对冲基金看板 | 交易平台可引用与具体交易相关的少量研究结果 | 策略管理不建设完整市场研究页 |
| 研究工具目录 | 对冲基金看板 | 其他模块可提供入口链接 | 不在多个模块维护不同工具清单 |
| 交易机会分析 | 交易平台 | 对冲基金看板可展示研究观察，不产生具体指令 | 策略管理不复制机会分析工作台 |
| 下单参数 | 交易平台 | 策略管理只读取最终结果 | 不在策略管理放完整下单表单 |
| 交易指令与执行 | 交易平台 | 策略管理展示执行档案 | 其他模块不得直接形成第二套交易入口 |
| 当前执行反馈 | 交易平台 | 策略管理可保留历史执行结果 | 不把历史档案逻辑塞回执行页 |
| 策略损益 | 策略管理 | 交易平台可展示预计收益、当次执行影响 | 不在交易平台建设完整长期归因体系 |
| 损益归因 | 策略管理 | 风控模块可读取风险相关归因摘要 | 不在其他模块复制完整归因图表 |
| 策略账户资金 | 策略管理 | 交易平台展示执行所需可用资金和保证金摘要 | 不在执行页建设完整资金管理页 |
| 当前持仓 | 策略管理负责完整记录；交易平台负责盘中执行视图 | 两个模块均可展示，但字段和目的不同 | 不维护两个独立且口径冲突的持仓数据模型 |
| 历史订单 | 策略管理 | 交易平台只展示当前执行订单 | 不在交易平台承担长期订单检索 |
| 成交记录 | 策略管理 | 交易平台展示当前执行批次反馈 | 不在两个模块分别定义成交状态口径 |
| 执行日志 | 策略管理负责归档 | 交易平台展示实时或本次执行日志 | 不形成两套日志分类 |
| 风险规则 | 风控相关现有模块 | 交易平台和策略管理只读取、提示与执行限制 | 不在策略页面单独维护冲突的全局规则 |
| 风险告警 | 风控相关现有模块 | 其他模块展示与当前任务相关的告警摘要 | 不在页面内自行定义另一套告警等级 |
| 用户、角色和权限 | 系统管理相关现有模块 | 各业务模块读取权限结果 | 业务页面不得独立维护权限体系 |
| 操作审计 | 审计相关现有模块 | 业务模块提供必要操作上下文 | 不用普通执行日志替代系统审计 |

## 3. 交易平台与策略管理的关键边界

### 3.1 交易平台拥有的内容

- 行情分析。
- 交易机会判断。
- 下单参数。
- 双腿或多腿执行。
- 配平状态。
- 当前执行订单。
- 当前持仓的执行视角。
- 执行即时反馈。

### 3.2 策略管理拥有的内容

- 策略整体损益。
- 损益归因。
- 账户资金。
- 净值、回撤和资金效率。
- 完整持仓记录。
- 历史订单。
- 成交记录。
- 执行记录和穿透查询。

### 3.3 允许存在的信息镜像

信息可以在两个模块出现，但必须明确目的：

- 可用资金：交易平台用于判断能否执行；策略管理用于观察资金安全和效率。
- 当前持仓：交易平台用于继续下单或平仓；策略管理用于完整统计和复盘。
- 预计收益：交易平台显示执行前估算；策略管理显示实际结果和归因。
- 风险信息：交易平台显示是否允许执行；策略管理显示策略风险状态和历史变化。

## 4. 对冲基金看板与交易平台的边界

### 对冲基金看板

回答：

- 当前宏观和市场环境是什么？
- 不同资产类别处于什么状态？
- 哪些图表、数据或工具值得进一步研究？

### 交易平台

回答：

- 当前具体策略是否出现可交易机会？
- 如果交易，应如何配置参数和执行？
- 执行是否成功、是否配平、是否产生异常暴露？

研究看板可以支持决策，但不直接承担策略执行。

## 5. 页面新增检查

新增页面或组件前必须回答：

1. 它处理的核心业务对象是什么？
2. 哪个模块拥有该对象？
3. 其他模块是否已经存在同类完整功能？
4. 当前页面需要的是完整能力，还是摘要镜像？
5. 能否复用已有数据模型和组件？

无法回答以上问题时，不应直接新增页面。
