# 策略模块结构设计方案（方案A + A1）

## 1. 文档定位

本文档用于定义平台 `策略模块` 的下一阶段信息架构与页面职责边界，目标是：

- 保留现有成熟策略页面中的高价值结构，尤其是 `跨所价差-交易执行`
- 重构当前混杂、重复、堆叠严重的策略管理模块
- 统一交易平台与策略管理的产品边界
- 为后续前端优化、组件抽象、接口接入提供稳定的结构基线

本文档只定义：

- 模块职责
- 页面骨架
- 各策略在统一骨架中的映射方式
- 内容迁移原则
- 后续实施优先级

本文档不直接定义：

- 最终视觉稿细节
- 每个图表的最终样式
- 真实后端接口字段

---

## 2. 总体设计原则

### 2.1 模块拆分原则

策略模块分为两大子模块：

1. `交易平台`
2. `策略管理`

二者不是简单重复，而是按使用时点和职责分开：

- `交易平台`：负责盘中工作，包括日常看盘、规律查找、执行前判断与下单执行
- `策略管理`：负责下单后的日常管理，包括结果复盘、账户安全、资金运营、订单追溯与执行归因

### 2.2 允许有限重复原则

本次设计不追求机械式去重，而遵循 `允许必要重复，禁止无意义重复`：

允许重复的内容：

- 当前市场价格
- 当前价差 / 当前费率 / 当前信号状态
- 执行前必须知道的简单统计
- 当前持仓总览
- 执行反馈摘要

这些内容允许出现在 `交易平台-交易执行`，因为它们直接服务下单判断与执行安全。

不允许重复的内容：

- 大量研究型图表在执行页重复出现
- 策略管理里重复出现完整下单面板
- 行情分析页和策略管理页反复展示同一批无差别统计卡片
- 订单信息页和执行页都承担实时执行主操作

### 2.3 骨架统一、因子差异化原则

统一的应该是：

- 主导航结构
- 页签逻辑
- 第一屏信息组织方式
- 组件职责边界
- 页面节奏与阅读顺序

不应强行统一的应该是：

- 各策略分析因子
- 执行页中的核心判断字段
- 归因维度
- 账户风险字段
- 订单字段体系

设计原则总结为：

- `结构统一`
- `因子差异化`
- `执行逻辑分层复用`

## 3. 交易平台设计

## 3.1 模块定位

`交易平台` 的定位为策略的 `盘中工作台`。

只承担两件事：

1. `行情分析`
2. `交易执行`

职责定义：

- `行情分析`：用于对应策略的日常看盘和规律查找
- `交易执行`：用于具体的下单执行、参数确认、执行反馈与即时持仓观察

其中：

- 行情分析解决“值不值得做、什么时候做、背后的规律是什么”
- 交易执行解决“现在怎么下、下完是否成功、当前持仓是否安全”

## 3.2 统一主骨架

所有策略默认采用统一双页结构：

1. `行情分析`
2. `交易执行`

允许少量特例：

- 个别策略可以追加补充研究模块
- 个别策略可以在分析页内存在额外的专属研究区
- 但不新增完全独立的新主页签，不打散双页骨架

即：

- `统一主骨架`
- `少量策略特例`
- `不做完全策略自由化导航`

---

## 4. 策略管理设计

## 4.1 模块定位

`策略管理` 的定位为策略下单后的 `日常管理中台`。

固定包含三个子界面：

1. `策略损益`
2. `账户资金`
3. `订单信息`

职责定义：

- `策略损益`：看策略整体结果、收益来源、风险来源、穿透贡献
- `账户资金`：看账户安全状态与资金使用效率
- `订单信息`：看订单档案、成交链路、执行结果、历史追溯

## 4.2 默认进入逻辑

进入 `策略管理` 后：

- 默认进入 `策略损益`
- 第一屏优先展示 `策略整体`
- 但“策略整体”不是一条简单总收益横幅，而是一个可直接用于日常巡检和晨会的策略驾驶舱

## 4.3 穿透层级原则

策略管理采用：

- `先看策略整体`
- `再向下穿透`

推荐穿透顺序：

1. 策略整体
2. 账户层
3. 腿仓层 / 标的层
4. 订单层
5. 执行层

即，策略管理采用：

- `策略总览优先`
- `账户与执行穿透次之`

而不是一进入就掉入账户表或订单流水表。

## 5. 各子界面的第一屏结构

## 5.1 交易平台 - 行情分析

目标：

- 服务 `日常看盘`
- 服务 `规律查找`
- 形成稳定研究框架

第一屏固定四层结构：

### 第一层：策略研究头部

展示当前研究上下文：

- 当前策略名
- 当前标的 / 腿仓组合
- 时间粒度
- 筛选器
- 当前观察标签

这一层不放执行动作，不放下单按钮。

### 第二层：核心观察区

这是第一视觉重点，展示该策略当天最关键的研究主画面。

示例：

- 跨所价差：价差联动主图、结构、关键价差位
- 海内外价差：内外价差、汇率映射、期限差异
- 资费：资金费率主图、现货/永续价差、交易所机会对比
- 抄底：价格位置、区间分位、波动与信号触发情况

该区域回答：

- 今天有没有观察价值
- 当前是否处于重点观察区间

### 第三层：规律分析区

专门放研究型内容：

- 历史分位
- 区间统计
- 季节性
- 热力矩阵
- 期限结构
- 联动关系
- 波动结构
- 对比研究表

该区域回答：

- 当前信号或现象是否有历史规律支撑
- 当前所处位置是否极端
- 当前条件是否偏离常态

### 第四层：补充研究区

放低优先级信息：

- 样本表
- 补充对比表
- 研究备注
- 次级图表
- 观察结论卡

### 行情分析页设计规则

必须保留：

- 规律查找相关模块
- 结构与分位分析
- 研究主图

必须迁出：

- 下单动作
- 开平仓参数
- 风控执行按钮

可以保留但应弱化：

- 研究结论摘要
- 当前状态提示

---

## 5.2 交易平台 - 交易执行

目标：

- 完成具体下单
- 做执行前必要判断
- 做执行后即时反馈

这一页采用 `轻分析 + 执行终端` 口径。

第一屏固定五层结构：

### 第一层：执行前状态区

允许保留必要重复内容：

- 当前市场价格
- 当前价差 / 当前费率 / 当前信号状态
- 当前简单统计
- 当前持仓总览摘要
- 当前执行反馈摘要

这些内容允许与分析页重复，因为它们服务的是即时执行决策。

### 第二层：执行指令区

这是执行页主操作区，应成为公共模板核心：

- 开仓 / 平仓切换
- 市价 / 限价切换
- 数量 / 杠杆 / 阈值输入
- 止盈 / 止损 / 可接受区间
- 自动配平
- 核心执行按钮

### 第三层：轻分析区

只保留执行前必须知道的少量判断信息：

- 当前分位
- 当前触发条件
- 风险阈值
- 当前可接受范围
- 简单监控条件

不能承载完整研究内容。

### 第四层：持仓与风险区

展示执行后立刻需要看的内容：

- 当前持仓总览
- 双边 / 单边损益
- 爆仓价 / 风险价
- 当前状态
- 执行后账户影响

### 第五层：执行反馈区

展示最新执行结果：

- 最近执行日志
- 最近成交反馈
- 是否成功
- 是否需要人工介入

### 交易执行页设计规则

允许保留重复内容：

- 当前价格
- 当前价差
- 当前简单统计
- 当前持仓总览
- 执行反馈

必须迁出到分析页的内容：

- 大型历史统计图
- 季节性图
- 热力矩阵
- 深研究结构图
- 长篇研究表

### 跨所价差特殊规则

`跨所价差-交易执行` 当前已是成熟样板，不进行结构性推翻。

后续只做：

- 视觉统一
- 字体层级优化
- 字段命名统一
- 响应式优化
- 轻微交互精修

不做：

- 主布局推倒重来
- 大量迁移模块
- 以去重为名删除执行必要信息

### 当前交易平台已补充的优化方向

交易平台近期已开始向统一工作台结构收口，后续按以下口径继续整理：

- 资费套利行情分析：已从单一图表页扩展为 `交易所 / 币种 / 时间粒度` 上下文联动，补充资金费率热力表、最高 / 最低资金费率机会、主图筛选、日期区间与粒度控制
- 资费套利交易执行：继续保留当前费率、现货 / 永续腿、开平仓切换、执行反馈、持仓列表和轻量历史分析，不迁入完整研究图表
- 跨所价差行情分析：保留主图、期限结构、机会分析、统计分析、季节性、热力矩阵，但需要统一控件位置、标题字号、卡片样式和表格密度
- 海内外价差行情分析：已独立增强 `金 / 银 / 铜` 标的切换、内外盘价差分析、实时价差列表，并继承跨所价差的研究骨架
- 跨所价差与海内外价差交易执行：继续以跨所价差执行页为模板源，海内外价差只做因子增强，不另起完全不同的执行模板

当前交易平台存在的主要问题已经不是产品结构方向，而是前端一致性：

- 同一模块内标题字号、按钮尺寸、卡片圆角、表格字体、控件高度不一致
- 行情分析页与交易执行页使用了不同的局部样式命名和局部视觉规则
- 部分页面中文文案存在编码异常或乱码风险，需要优先修复
- 少数卡片仍保留解释性文案，应删除，只保留业务字段和值
- 交易平台与策略管理虽然都引用策略主题变量，但落地层级仍不统一

## 5.3 策略管理 - 策略损益

目标：

- 第一屏先看策略整体
- 同屏具备收益归因与风险归因能力
- 可继续向下穿透到细节层

第一屏固定五层结构：

### 第一层：策略损益总览曲线

保留现有成熟总览模块，放在策略损益页最上方：

- 日度收益柱状图
- 净值曲线
- 日报 / 周报 / 月报 / 自定义切换
- 总资金
- 底部时间滚轴

这是策略损益页的第一眼，不得下移。

### 第二层：策略整体驾驶舱

展示最重要的结果指标：

- 累计收益
- 今日收益
- 近7日 / 近30日收益
- 30天内最大回撤
- 胜率
- 夏普
- 风险状态
- 当前运行状态

### 第三层：收益归因 + 风险归因

直接放在总览之后：

- 收益主要来自哪里
- 风险主要来自哪里
- 哪个账户贡献最大
- 哪条腿拖累最大
- 哪类执行偏差最影响结果

这是策略损益页的关键特色，不能拖到很下面。

### 第四层：核心曲线区

展示最重要的策略走势：

- 回撤曲线
- 累计收益曲线
- 时间区间切换
- 不再保留波动率 / 夏普比率这类辅助风险小图

该区域只保留收益相关曲线，不重复账户资金页的风险辅助曲线。

### 第五层：损益细分曲线 + 穿透明细区

继续下钻查看：

- 策略损益总览曲线保留在细分内容之前
- 各一级损益项的细分曲线
- 账户贡献
- 腿仓贡献
- 标的贡献
- 执行贡献
- 明细表格

新的策略损益页面已转为正式 `策略损益` 入口，原策略损益旧入口和旧版策略损益组件已删除。

后续策略损益优化重点不再是大框架重组，而是各策略损益拆分口径、字段命名、曲线数据和穿透明细的精修。

### 策略损益页设计规则

必须保留：

- 策略损益总览曲线
- 策略整体驾驶舱
- 第一屏归因能力
- 各损益细分曲线
- 可穿透的细节

必须删除或弱化：

- 纯展示级重复卡片
- 与账户资金页完全重复的安全面板
- 与订单信息页重复的大量订单流水表

## 5.4 策略管理 - 账户资金

目标：

- 先看账户状态
- 再看风控与资金结构
- 最后看净值与回撤演变

第一屏固定三层结构：

### 第一层：账户总览区

统一展示：

- 账户净值
- 累计收益 XXXX（XX%）
- 过去24H盈亏 XXXX（XX%）
- 过去7天盈亏 XXXX（XX%）
- 过去30天盈亏 XXXX（XX%）
- 可用资金
- 保证金占用
- 杠杆
- 风险等级

- 资费、跨所价差、海内外价差的 `保证金占用` 采用双端并列展示
- 收益相关字段统一使用 `绝对值 + 百分比`
- 风险等级统一使用 `等级 + 短因`
- 跨所价差、海内外价差、短线交易员L、短线交易员W 保留 `胜率`
- 抄底 当前阶段不强制展示 `胜率`

该区域回答：

- 这个策略现在赚没赚钱
- 当前账户是否安全
- 近期资金状态是在修复还是恶化

### 第二层：风控与资金结构区

统一保留：

- 轻风控信息
- 资金结构观察
- 账户效率观察

建议统一展示：

- 保证金安全垫
- 预警次数
- 按策略适配的 `MMR` / `爆仓价` / 专属风控字段

双端策略统一增强：

- 资费套利
- 跨所价差
- 海内外价差

这三类策略统一增加 单卡合并对照模块：

- 只保留一个环形图
- 两端账户分别展示金额与占比
- 数据格式统一为 `XXXX（XX%）`
- 同一张卡内同时承接资金对照与风险对照

统一口径：

- 不以抽象占比为核心表达
- 以两端账户分别展示为核心
- 让用户一眼看清哪一侧更紧、哪一侧风险更高

单端策略处理：

- 抄底：展示仓位利用率、现金缓冲、爆仓价、保护单覆盖等单策略结构信息
- 短线交易员L、短线交易员W：展示股指 / 黄金 / 币账户结构，同时单独保留专属风控组件

当前页面结构已经收敛为：

- 账户总览
- 风控栏
- 资金结构观察
- 双端对照模块
- 净值 + 回撤曲线
- 净值曲线下方追加辅助风险曲线区

### 第三层补充：辅助风险曲线区

统一放在账户资金净值曲线下方，所有策略都保留：

- 波动率曲线
- 夏普比率曲线
- 时间轴滚动条

设计边界：

- 这是账户层辅助风控观察，不属于策略损益主归因
- 策略损益页不再重复这组小图
- 后续如需新增其他辅助风险指标，也在这里继续扩展

### 第四层：账户曲线区

所有策略统一保留：

- 净值曲线
- 回撤曲线
- 时间维度切换
- 口径切换
- 底部缩略时间轴

设计边界：

- 这里看的是账户状态演变
- 不是策略损益页里的收益归因图重复
- 不在这里继续堆收益归因、风险归因、订单流水

### 账户资金页设计规则

必须保留：

- 账户总览区
- 风控栏
- 双端对照或单策略结构观察区
- 净值 + 回撤曲线区

必须迁出：

- 大量策略绩效图
- 大量订单执行流水
- 下单控制与执行动作
- 与双端结构区高度重复的抽象状态说明

## 5.5 策略管理 - 订单信息

目标：

- 偏复盘
- 偏追责
- 偏穿透查询
- 不再承担实时执行操作

当前设计定为 `档案台优先`。

第一屏固定三层结构：

### 第一层：订单摘要区

展示：

- 今日订单数
- 成交成功率
- 撤单率
- 异常单数

## 11.1 策略模块 UI 统一方案

当前策略模块的产品结构已经基本明确，下一阶段重点应从结构重组转为 `视觉与交互一致性收口`。

### 统一范围

- 交易平台：资费套利、跨所价差、海内外价差、抄底、短线交易员相关页面
- 策略管理：策略损益、账户资金、订单信息
- 公共组件：顶部策略切换、二级页签、卡片、KPI、表格、筛选器、按钮、图表容器

### 统一原则

- 页面结构统一：同类页面遵循同一阅读顺序
- 视觉层级统一：标题、字段名、数值、辅助信息必须有固定字号和字重
- 控件尺寸统一：页签、按钮、选择器、日期框、输入框高度统一
- 颜色语义统一：红色只用于风险、亏损、警示和选中态；绿色用于盈利、正常、通过；蓝色用于中性信息和图表主线；不使用黄色作为大面积底色
- 卡片系统统一：统一圆角、边框、阴影、内边距和间距
- 文案克制：不展示解释型副标题，只展示业务字段、数值、状态和必要操作
- 响应式统一：桌面优先，兼容窄屏时只改变排列，不改变字段职责

### 字体与字号建议

- 一级页面标题：20px / 800
- 模块标题：18px / 800
- 卡片标题：15px / 800
- 表格标题与页签文字：14px / 700
- 字段名：13px / 700
- 普通正文：13px / 500
- 辅助信息：12px / 600
- 关键数值：24px - 32px / 800
- 表格数值：13px - 14px / 700

### 颜色与状态建议

- 主文本：`--strategy-text-1`
- 次级文本：`--strategy-text-2`
- 辅助文本：`--strategy-text-3`
- 边框：`--strategy-border`
- 卡片背景：白色或极浅灰白
- 主强调：使用当前策略红，但只用于选中态、关键按钮和亏损风险
- 盈利 / 正常：绿色
- 中性图表 / 信息：蓝色
- 警示：红色，不再用黄色大面积提示

### 组件规范

顶部策略切换：

- 所有策略页统一使用同一种胶囊页签
- 字号、间距、选中态、边框统一
- 策略名称较长时不换行，允许横向滚动或压缩间距

二级页签：

- `策略损益 / 账户资金 / 订单信息` 和 `行情分析 / 交易执行` 使用统一页签样式
- 当前页签更突出，但不能过度放大

卡片：

- 普通卡片统一 14px - 16px 圆角
- 卡片内边距统一 16px - 20px
- 卡片间距统一 12px - 16px
- 禁止同一页面内混用强阴影、无边框和重边框三套风格

表格：

- 表头字体加粗，字号不低于 13px
- 单元格数值适当加粗
- 当前持仓、历史订单、成交记录、执行记录等同级标题统一放大并加粗
- 表格优先保证可读性，不追求极限压缩

图表：

- 图表容器统一卡片样式
- 图例、时间滚轴、筛选控件位置统一
- 策略损益图表与账户资金图表职责分离，不互相重复

### 统一落地顺序

1. 先修复明显问题：乱码文案、重复解释句、标题大小混乱、页签尺寸不一致
2. 再抽统一样式：把卡片、页签、按钮、表格、KPI 的基础样式收敛到 `strategy-theme.less` 和公共组件
3. 然后统一交易平台内部：优先资费套利、跨所价差、海内外价差三类已经有明显页面基础的策略
4. 最后统一策略管理细节：策略损益、账户资金、订单信息只做视觉一致化，不再重开结构

### 不建议做的事

- 不建议一次性重写全部策略页面
- 不建议为了统一而删除策略差异字段
- 不建议继续增加解释型副标题
- 不建议给每个页面写一套局部 UI 风格
- 不建议把账户资金、策略损益、订单信息里的图表互相搬来搬去

## 12. 结论

本方案采用：

- `方案A：双中台标准版`
- `A1口径：交易执行允许必要镜像`

其核心结论为：

- `交易平台` 做盘中研究与执行
- `策略管理` 做盘后管理与穿透
- `跨所价差交易执行` 作为成熟模板保留
- `策略管理` 大框架已基本收口，后续进入策略细节优化
- `行情分析` 仍是下一阶段主要结构优化对象
- `结构统一、因子差异化、执行逻辑分层复用` 作为后续所有改造的基础原则
