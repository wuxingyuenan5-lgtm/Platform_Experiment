# 首页布局与响应式标准

状态：`active`  
适用页面：`admin-risk/src/views/dashboard/index.vue`  
上位规范：`../architecture/frontend/responsive-layout-architecture.md`

## 1. 设计目标

首页不是完整业务工作台，而是品牌入口、少量摘要和跨模块导航页。布局优先保证：

1. 用户首先识别“全球变量”品牌与平台定位。
2. 用户其次读取市场与组合摘要。
3. 用户随后通过稳定的业务卡片进入研究、策略和日历页面。
4. 1280–2560 CSS px 内不因宽度变化产生跳跃式密度变化、组件错位或背景断裂。
5. 数据缺失、长文本和低高度视口不会破坏主要结构。

## 2. 信息层级

首页固定分为两层：

```text
品牌主视觉 Hero
├─ 品牌文案
└─ 摘要区
   ├─ 全球市场概览
   └─ 投资组合总览

首页工作区
├─ 市场脉搏
├─ 组合概览
├─ 策略概览
└─ 重要日历
```

品牌主视觉与工作区不使用负 margin 重叠。两层通过统一背景、间距和圆角形成连续关系。

## 3. 页面宽度

- 页面背景占满应用主内容区。
- Hero 背景占满主内容区宽度；Hero 内部文字与摘要卡通过左右安全边距约束，不把背景限制在窄容器中。
- 首页工作区采用宽桌面框架，最大内容宽度为 `2040px`。
- 页面左右间距通过 `clamp(18px, 2vw, 42px)` 控制。
- 2560px 超宽屏不继续无限拉伸卡片。
- 不使用固定页面宽度、固定左偏移或负 margin 对齐侧边栏。

## 4. Hero 标准

### 4.1 Large：≥ 1600px

- 两列结构。
- 左侧品牌文案占主要视觉宽度。
- 右侧两张摘要卡纵向排列。
- Hero 最小高度由内容和有界 `clamp()` 共同决定，不使用固定视口高度。

### 4.2 Standard：1200–1599px

- 保持左右分栏，左侧为品牌文案与主视觉安全区，右侧为摘要区。
- 两张摘要卡纵向排列，只占右侧栏，不横向铺满 Hero。
- 该断点对应常规笔记本宽度和低高度桌面，不能把它当作手机单列处理。
- 右侧摘要卡不得覆盖蝴蝶、水面和地图亮点等背景主体。

### 4.3 Compact：< 1200px

- 品牌文案、市场摘要、组合摘要依次单列排列。
- 该范围属于安全降级，不作为当前桌面产品的主要密度目标。

### 4.4 Hero 内容约束

- 品牌标题使用 `clamp()` 控制，不按单一屏幕写死字号。
- 摘要卡最小宽度不足时内部降列，而不是扩大页面宽度。
- 背景图只承担品牌氛围，不决定内容坐标。
- 主视觉位图不得包含真实 UI 文案、按钮或 logo；页面文字必须由 HTML 渲染。
- 文案区必须位于背景主体之外的安全区。若背景图含蝴蝶、水波、地图亮点等强视觉主体，主体不得落在标题、标语、主按钮或摘要卡的默认位置下方。
- 所有文本容器允许收缩，关键网格子项设置 `min-width: 0`。
- 首页断点和 LESS 安全约束纳入 `pnpm test:homepage-layout`，修改首页样式后必须运行。

## 5. 工作区标准

### 5.1 支持桌面范围

在 1600–2560px 内，四张业务卡使用稳定的四列网格：

```text
市场脉搏 | 组合概览 | 策略概览 | 重要日历
```

低于 1600px 时降级为两列，低于 1080px 时降级为单列。四列只用于宽屏主工作台，不把中等桌面强行压缩成四列。

### 5.2 安全降级

- 小于 1600px 时切换为两列，小于 1080px 时切换为单列。
- 卡片高度由内容决定；同一网格行可以自然等高，但不得设置固定高度。
- 卡片底部入口使用弹性布局保持可见，不通过绝对定位贴底。

## 6. 内部组件规则

### 市场摘要

- 宽容器使用四列。
- 紧凑容器使用两列。
- Sparkline 宽度不得强迫父容器扩张。

### 组合摘要

- 宽容器为两个数值区 + 环图。
- 紧凑容器允许环图换到下一行。

### 市场与策略行

- 文本区域必须 `min-width: 0`。
- 标题和说明允许省略，不得推开 Sparkline 或操作区。
- 行级按钮提供 hover 和 focus-visible 反馈。

### 重要日历

- 宽容器保持时间、地区、事件、预期四段结构。
- 紧凑容器改为两列信息块，不压缩事件标题到不可读。

## 7. 视觉连续性

- 页面底色由首页根容器负责，避免内容区结束后出现不同底色。
- Hero 与业务卡共享冷灰白视觉基座，但通过表面透明度和阴影区分层级。
- 卡片圆角、边框和阴影保持一致，不为单个断点重新定义一套视觉语言。
- 不使用大面积深阴影或多个高饱和强调色。

## 8. 禁止模式

首页不得使用：

- `height: calc(100vh - 固定像素)` 作为页面主高度。
- 响应后仍保留失效的 `grid-column` 或 `grid-row`。
- 为卡片衔接设置负 top margin。
- 中等桌面强制单行四列。
- 依赖背景图位置确定真实内容坐标。
- 使用 `overflow: hidden` 掩盖页面级横向溢出。
- 针对 1366、1440、1536 或 1920 某一个分辨率写专用偏移。
- 运营式、营销式补充文案占据工作台卡片标题区。例如“捕捉机会”“全局视角”“稳健致远”“把握脉动”等不承载操作或数据含义的句子。
- 在 `<style lang="less">` 中直接使用会被 LESS 计算的 CSS 原生 `min()` / `max()` 表达式。需要限制宽度时使用 `width: calc(...); max-width: ...`，或用 `clamp()` / `minmax()` 等已验证不会触发 LESS 数值运算的写法。

## 9. LESS 与 CSS 函数约束

本项目页面样式使用 LESS。LESS 会尝试把 `min()`、`max()` 解析为预处理函数，而不是原样交给浏览器；当参数里包含 `calc()`、百分比减法或 CSS 变量时，容易触发编译错误：

```text
[plugin:vite:css] [less] Error evaluating function `min`: Operation on an invalid type
```

正式写法：

```less
.dashboard-grid {
  width: calc(100% - calc(var(--home-page-gutter) * 2));
  max-width: 2040px;
}

.sparkline {
  width: 100%;
  max-width: 76px;
}
```

不推荐写法：

```less
.dashboard-grid {
  width: min(100% - calc(var(--home-page-gutter) * 2), 2040px);
}
```

首页样式修改后必须至少执行：

```powershell
npx pnpm@9.15.9 type:check
```

如果改动涉及 LESS 复杂表达式，还必须在本地 Vite 页面中确认没有红色编译 overlay。

## 10. 验收重点

至少检查：

- 1280×720
- 1366×768
- 1440×900
- 1536×864
- 1680×900
- 1920×1080
- 2560×1080

每个视口确认：

- Hero 阅读顺序一致。
- 摘要卡没有隐式列、覆盖或裁切。
- 工作区在宽屏为四列，中等桌面为两列，低于安全阈值才单列。
- 页面没有非预期横向滚动。
- 卡片背景和页面底色连续。
- 浏览器缩放 90%、100%、110%、125% 时关键入口可访问。
- Vite dev overlay 不出现 LESS/CSS 编译错误。
- 卡片标题区没有无业务含义的补充性文案。

## 11. 后续边界

本标准只负责首页布局。颜色、字体和 Design Token 仍由 `platform-ui-guidelines.md` 管理；全平台滚动、Page Shell 和 Overlay 规则仍由响应式布局主文档管理。其他页面不得直接复制首页的品牌型 Hero 结构。
