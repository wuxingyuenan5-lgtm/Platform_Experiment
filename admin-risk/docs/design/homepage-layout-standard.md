# 首页布局与响应式标准

状态：`active`  
适用页面：`admin-risk/src/views/dashboard/index.vue`  
上位规范：`../architecture/frontend/responsive-layout-architecture.md`

## 1. 设计目标

首页不是完整业务工作台，而是品牌入口、少量摘要和跨模块导航页。布局优先保证：

1. 用户首先识别“全球变量”品牌与平台定位。
2. 用户其次读取市场与组合摘要。
3. 用户随后通过稳定的业务卡片进入研究、策略和日历页面。
4. 1280–2560 CSS px 内不因宽度变化产生跳跃式密度变化、组件错位或背景断裂。
5. 数据缺失、长文本和低高度视口不会破坏主要结构。

## 2. 信息层级

首页固定分为两层：

```text
品牌主视觉 Hero
├─ 品牌文案
└─ 摘要区
   ├─ 全球市场概览
   └─ 投资组合总览

首页工作区
├─ 市场脉搏
├─ 组合概览
├─ 策略概览
└─ 重要日历
```

品牌主视觉与工作区不使用负 margin 重叠。两层通过统一背景、间距和圆角形成连续关系。

## 3. 页面宽度

- 页面背景占满应用主内容区。
- 首页内容采用宽桌面框架，最大内容宽度为 `1840px`。
- 页面左右间距通过 `clamp(16px, 1.6vw, 30px)` 控制。
- 2560px 超宽屏不继续无限拉伸卡片。
- 不使用固定页面宽度、固定左偏移或负 margin 对齐侧边栏。

## 4. Hero 标准

### 4.1 Large：≥ 1600px

- 两列结构。
- 左侧品牌文案占主要视觉宽度。
- 右侧两张摘要卡纵向排列。
- Hero 最小高度由内容和有界 `clamp()` 共同决定，不使用固定视口高度。

### 4.2 Standard：1200–1599px

- 品牌文案独占第一行。
- 两张摘要卡在第二行并列。
- 不保留上一断点的显式列号或跨行设置。

### 4.3 Compact：< 1200px

- 品牌文案、市场摘要、组合摘要依次单列排列。
- 该范围属于安全降级，不作为当前桌面产品的主要密度目标。

### 4.4 Hero 内容约束

- 品牌标题使用 `clamp()` 控制，不按单一屏幕写死字号。
- 摘要卡最小宽度不足时内部降列，而不是扩大页面宽度。
- 背景图只承担品牌氛围，不决定内容坐标。
- 所有文本容器允许收缩，关键网格子项设置 `min-width: 0`。

## 5. 工作区标准

### 5.1 支持桌面范围

在 1280–2560px 内，四张业务卡使用稳定的两列网格：

```text
市场脉搏 | 组合概览
策略概览 | 重要日历
```

不在宽屏切换为四列。原因：四个区块的信息结构不同，强制四列会使日历、图例和行列表在中间宽度被压缩，并导致 1500px 两侧出现过大的视觉跳变。

### 5.2 安全降级

- 小于 1080px 时切换为单列。
- 卡片高度由内容决定；同一网格行可以自然等高，但不得设置固定高度。
- 卡片底部入口使用弹性布局保持可见，不通过绝对定位贴底。

## 6. 内部组件规则

### 市场摘要

- 宽容器使用四列。
- 紧凑容器使用两列。
- Sparkline 宽度不得强迫父容器扩张。

### 组合摘要

- 宽容器为两个数值区 + 环图。
- 紧凑容器允许环图换到下一行。

### 市场与策略行

- 文本区域必须 `min-width: 0`。
- 标题和说明允许省略，不得推开 Sparkline 或操作区。
- 行级按钮提供 hover 和 focus-visible 反馈。

### 重要日历

- 宽容器保持时间、地区、事件、预期四段结构。
- 紧凑容器改为两列信息块，不压缩事件标题到不可读。

## 7. 视觉连续性

- 页面底色由首页根容器负责，避免内容区结束后出现不同底色。
- Hero 与业务卡共享冷灰白视觉基座，但通过表面透明度和阴影区分层级。
- 卡片圆角、边框和阴影保持一致，不为单个断点重新定义一套视觉语言。
- 不使用大面积深阴影或多个高饱和强调色。

## 8. 禁止模式

首页不得使用：

- `height: calc(100vh - 固定像素)` 作为页面主高度。
- 响应后仍保留失效的 `grid-column` 或 `grid-row`。
- 为卡片衔接设置负 top margin。
- 四张异构业务卡在宽屏强制单行四列。
- 依赖背景图位置确定真实内容坐标。
- 使用 `overflow: hidden` 掩盖页面级横向溢出。
- 针对 1366、1440、1536 或 1920 某一个分辨率写专用偏移。

## 9. 验收重点

至少检查：

- 1280×720
- 1366×768
- 1440×900
- 1536×864
- 1680×900
- 1920×1080
- 2560×1080

每个视口确认：

- Hero 阅读顺序一致。
- 摘要卡没有隐式列、覆盖或裁切。
- 工作区始终为两列，低于安全阈值才单列。
- 页面没有非预期横向滚动。
- 卡片背景和页面底色连续。
- 浏览器缩放 90%、100%、110%、125% 时关键入口可访问。

## 10. 后续边界

本标准只负责首页布局。颜色、字体和 Design Token 仍由 `platform-ui-guidelines.md` 管理；全平台滚动、Page Shell 和 Overlay 规则仍由响应式布局主文档管理。其他页面不得直接复制首页的品牌型 Hero 结构。
