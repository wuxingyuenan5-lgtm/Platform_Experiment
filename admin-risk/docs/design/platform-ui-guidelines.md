# Platform V5 全平台 UI 设计规范

状态：`active`  
适用范围：Platform V5 全部一级模块、二级或三级子板块及共享组件

## 1. 文档定位

本文档定义 Platform V5 的统一视觉语言、页面结构、组件表现和交互反馈规则，是全平台 UI 设计与前端实现的主要依据。

本规范负责回答：

- 页面应采用什么视觉风格和信息密度。
- 标题、文字、数字、颜色、间距和卡片如何形成统一层级。
- 导航、页签、筛选器、按钮、图表、表格和状态反馈如何设计。
- 首页、研究看板、交易工作台、策略管理和风险管理如何在统一基座上保留任务差异。
- 新页面和新组件如何判断是否符合全平台设计体系。

组件分层、共享范围和代码组织规则参见：

- `docs/architecture/shared-ui-governance.md`

模块职责和业务对象归属参见：

- `docs/architecture/module-ownership-matrix.md`

## 2. 设计目标

Platform V5 是面向研究、交易、策略管理和风险管理的专业工作台。UI 设计应同时满足以下目标：

### 2.1 决策效率

页面优先呈现影响判断和操作的核心信息。用户应能够快速识别：

- 当前状态。
- 关键变化。
- 主要机会或风险。
- 下一步可执行动作。

### 2.2 清晰层级

页面必须具有稳定的阅读顺序：

1. 页面或模块上下文。
2. 核心状态与摘要。
3. 主要分析或操作区域。
4. 细分信息和归因。
5. 历史记录、补充数据和低优先级内容。

### 2.3 专业与克制

视觉风格应简洁、精确、可信，避免：

- 过度装饰。
- 大量渐变和强阴影。
- 多个高饱和颜色同时争夺注意力。
- 为填充页面而增加无决策价值的说明文字。
- 将普通信息包装成过多卡片。

### 2.4 统一与可扩展

同类页面、控件和状态必须具有统一结构和视觉语义。新增模块和策略应在现有设计体系内扩展，不重新建立独立视觉语言。

### 2.5 桌面工作台优先

平台以桌面研究和交易工作台为主要使用场景。设计优先保证：

- 1280px 以上宽度的可用性。
- 1440px 至 1920px 的高效信息密度。
- 图表、表格和双栏工作区的完整表达。

移动端适配不应牺牲桌面端的专业信息密度。

## 3. 全平台视觉语言

### 3.1 整体风格

全平台采用浅色、冷中性、低饱和的视觉基座：

- 页面背景使用浅灰蓝或冷白。
- 主要内容表面使用白色。
- 次级表面使用轻微灰蓝。
- 边框轻、阴影弱、留白清晰。
- 文字以深蓝灰为主，不使用纯黑覆盖所有层级。

整体感受应接近专业基金研究终端和现代资产管理工作台，而不是传统通用后台或营销型网站。

### 3.2 品牌表达

“全球变量、蝴蝶效应、变量传导”是平台品牌概念，但只在以下区域重点表达：

- 首页主视觉。
- 登录页。
- 品牌介绍或金融 AI 展示区域。
- 少量过渡动画和背景纹理。

业务工作台不使用大面积蝴蝶、水纹、拓扑线或装饰动画。品牌概念进入业务页面时，应转化为低对比度背景纹理、连接关系或数据传导示意，不得干扰图表和操作。

登录页标题区采用统一品牌字体族。主提示标题与平台名称不混用不同字体现代感，默认使用 `Georgia, Times New Roman, Noto Serif SC, serif`；“欢迎登录”等主提示标题为 `18px`，平台名称为 `30px`，两者之间保持 `10px` 以上稳定间距。

### 3.3 色彩占比

推荐视觉占比：

- 80%：背景、表面、边框和中性文字。
- 15%：品牌色、选中态和主要交互。
- 5%：成功、警告、风险和异常等语义色。

同一屏幕不应出现多个面积相近的高强调色区域。

## 4. 设计令牌

全平台设计应优先通过 Design Token 管理。页面不得重复硬编码相同颜色、字号、圆角、阴影和间距。

### 4.1 基础色板

| 用途 | 建议值 | 使用规则 |
|---|---|---|
| 页面背景 | `#F3F7FA` | 页面和模块主背景 |
| 背景渐层辅助 | `#F8FAFC` | 首页或大型页面顶部的轻微层次 |
| 主表面 | `#FFFFFF` | 卡片、表格、工具栏和弹窗 |
| 次级表面 | `#F7F9FC` | 表头、筛选区、轻量分组 |
| 选中表面 | `#EEF5F4` | 页签、菜单和轻量选中态 |
| 主边框 | `#E5EBF3` | 卡片、输入框和表格分隔 |
| 强边框 | `#D7E0EC` | 可交互控件和重点分隔 |
| 主文字 | `#13243D` | 页面标题、关键数字和主要内容 |
| 次级文字 | `#2F3E52` | 正文和主要标签 |
| 辅助文字 | `#667085` | 单位、时间和次要信息 |
| 禁用文字 | `#98A2B3` | 禁用、占位和低优先级说明 |

### 4.2 品牌与交互色

全平台主品牌与主要交互采用低饱和深青绿色：

| 用途 | 建议值 |
|---|---|
| 品牌主色 | `#1F5555` |
| 品牌深色 | `#183F45` |
| 品牌悬停 | `#286666` |
| 品牌浅色背景 | `#EEF6F5` |
| 品牌焦点环 | `rgba(31, 85, 85, 0.18)` |

主品牌色用于：

- 主要按钮。
- 一级或二级导航选中态。
- 链接和关键交互。
- 少量品牌识别元素。

不得使用红色作为普通页签、普通按钮或无风险含义的默认选中颜色。

### 4.3 辅助品牌色

低饱和金色可作为高级感和品牌辅助色：

- 建议值：`#B88945`。
- 仅用于小面积品牌标识、稀有状态、徽标或重点装饰。
- 不作为全平台默认主按钮色。
- 不大面积用于拓扑线、背景和数据区域。

### 4.4 语义色

| 语义 | 主色 | 浅色背景 |
|---|---|---|
| 正向／成功 | `#189B50` | `#ECF8F0` |
| 负向／错误 | `#DF4D4D` | `#FFF4F4` |
| 警告 | `#B9802F` | `#F8F4EC` |
| 信息 | `#3E6F8F` | `#EEF5F9` |
| 中性 | `#667085` | `#F2F4F7` |

语义色规则：

- 涨跌、盈亏、执行状态和风险等级必须由明确业务字段决定，不通过字符串正负号临时推断。
- 默认市场表现采用正向绿色、负向红色。
- 风险严重程度与市场涨跌必须使用不同的标签、图标或文字组合，不能只依赖红绿颜色。
- 颜色之外必须保留文字、图标或形状语义。

### 4.5 圆角

| 对象 | 建议圆角 |
|---|---:|
| 输入框、按钮、状态标签 | `8–10px` |
| 页签组和小卡片 | `12–14px` |
| 标准业务卡片 | `16px` |
| 大型面板 | `18–20px` |
| 首页品牌主视觉 | `24–30px` |

业务页面不应普遍使用 24px 以上大圆角。大圆角仅用于首页或品牌展示区域。

### 4.6 阴影

业务页面使用低对比度阴影：

```css
--ui-shadow-soft: 0 1px 2px rgba(148, 163, 184, 0.08);
--ui-shadow-card: 0 8px 24px rgba(15, 23, 42, 0.04);
--ui-shadow-overlay: 0 16px 40px rgba(15, 23, 42, 0.10);
```

规则：

- 普通卡片优先通过边框区分，阴影只提供轻微层次。
- 弹窗、抽屉和浮层可以使用更明显阴影。
- 不使用深黑、大范围或多层重阴影。

## 5. 字体与数字层级

### 5.1 字体族

正文和控件：

```css
'Segoe UI Variable Text',
'PingFang SC',
'Hiragino Sans GB',
'Microsoft YaHei UI',
'Segoe UI',
sans-serif
```

标题：

```css
'Segoe UI Variable Display',
'PingFang SC',
'Hiragino Sans GB',
'Microsoft YaHei UI',
'Segoe UI',
sans-serif
```

数字：

```css
'Segoe UI',
'Bahnschrift',
'DIN Alternate',
sans-serif
```

金额、价格、比例和数量应启用等宽数字特征：

```css
font-feature-settings: 'tnum' 1;
```

### 5.2 字号层级

| 层级 | 字号 | 字重 | 使用场景 |
|---|---:|---:|---|
| 页面标题 | `20–24px` | `700` | 普通业务页面标题 |
| 区块标题 | `17–18px` | `700` | 页面主要业务区块 |
| 卡片标题 | `14–15px` | `700` | 表格和指标卡 |
| 图表型 widget 标题 | `17px` | `700–800` | 对冲基金看板等高密度图表卡 |
| 正文 | `14px` | `400–500` | 主要文字和表格内容 |
| 标签／控件 | `13–14px` | `500–600` | 筛选器、按钮、表单标签 |
| 辅助信息 | `12–13px` | `400–500` | 时间、单位、来源、提示 |
| 关键指标 | `24–32px` | `700` | 指标卡主要数值 |
| 首页主标题 | `40–56px` | `700` | 仅首页品牌主视觉 |

规则：

- 同层级内容使用一致字号和字重。
- 同一区域不放置多个 32px 以上数字争夺视觉主次。
- 数值与单位分开显示时，单位字号低一级，并保持固定间距。
- 表格和高密度研究页面不随意放大文字。
- 页签、子导航或锚点导航中的序号与标题属于同一导航标签时，默认使用同一颜色和字号，不用强调色单独突出序号。

## 6. 间距与布局系统

### 6.1 间距基准

全平台采用 4px 基础网格，常用间距为：

- `4px`：图标与短文本的微间距。
- `8px`：同组元素内部间距。
- `12px`：紧凑控件和卡片内部间距。
- `16px`：标准组件间距。
- `20px`：业务区块内部间距。
- `24px`：主要区块之间的间距。
- `32px`：大型页面段落或品牌区域间距。

不得在相同层级中混用大量无规则间距值。

### 6.2 页面容器

业务页面默认规则：

- 页面外边距：`16–24px`。
- 页面主要区块间距：`16–24px`。
- 标准卡片内边距：`16–20px`。
- 高密度表格或工具栏内边距：`10–16px`。
- 内容宽度以可用工作区为主，不设置限制数据展示的窄版最大宽度。

### 6.3 网格

采用 12 列或等比分栏思路：

- 总览区可使用 3、4、6 列指标卡。
- 图表区优先使用 1:1、2:1、3:2 等稳定比例。
- 交易执行可使用参数区与反馈区的双栏布局。
- 表格和主图需要完整宽度时占满一行。

禁止为了视觉对称将不同信息量的区块强制设为相同高度。

## 7. 页面结构

### 7.1 标准业务页面

推荐结构：

1. 页面标题和必要操作。
2. 模块或策略切换。
3. 筛选和上下文工具栏。
4. 状态或指标摘要。
5. 核心业务区域。
6. 细分分析、归因或明细。
7. 历史记录和辅助信息。

同一页面中，模块切换、页面切换和局部内容切换必须使用不同视觉层级，避免出现多组相同页签相互竞争。

### 7.2 首页

首页允许使用：

- 品牌主视觉。
- 大字号标题。
- 蝴蝶、水面和拓扑传导概念。
- 轻量滚动动画。
- 一级模块入口。
- 有限的市场摘要。

首页不承担完整研究、交易执行、策略复盘或风险处置。

首页中的概念说明必须转化为正式品牌文案，不展示“滚动动画概念”“初始状态”“过渡阶段”等设计过程性文字。

### 7.3 对冲基金看板

研究看板采用高信息密度结构：

- 顶部一级分类切换。
- 模块内子导航。
- 图表区块。
- 市场快照和明细表。
- 研究工具目录。

要求：

- 图表和数据是主体，装饰性内容降到最低。
- 模块内子导航保持紧凑、可定位和可滚动。
- 模块内子导航序号和标题采用同色黑字；对冲基金研究子导航标准字号为 `14px`，序号不得使用强调色与标题形成不必要的视觉分裂。
- 单个区块内图表数量过多时，应按研究主题分组，不无限延长同一网格。
- 图表或表格 widget 已经由外层卡片标题命名时，内部组件不得重复渲染同名标题。例如外层标题为“宏观市场明细”“商品市场明细”或“加密市场明细”时，内部 `TerminalDetailPanel` 不再重复显示“市场明细”，只保留必要操作区。
- 图表型 widget 标题默认使用 `17px`，在图表卡 header 中水平居中，不靠左贴边；外部来源链接统一放在 header 右上角，不得叠加在图表绘图区内。例如“全球各地区 ETF 每周流入”“全球 ETF 年内汇总”等黄金 ETF 图表必须按此规则处理。

### 7.4 新闻日历与理财

该模块以信息检索和时间排序为主：

- 时间、类别、重要性和来源是主要筛选维度。
- 日历、新闻和理财信息使用清晰区分的内容模板。
- 标题、摘要、时间和来源形成稳定阅读层级。
- 不通过大量卡片、图标和高饱和颜色降低扫描效率。

### 7.5 交易平台

交易平台必须清晰区分：

- 行情分析。
- 交易执行。

行情分析以图表、价差、分位、成本和机会判断为主；交易执行以账户、方向、数量、价格、订单类型、两腿关系、配平状态和执行反馈为主。

正式交易动作应具备明确层级：

- 主要交易动作。
- 次要调整动作。
- 取消或返回动作。
- 风险或破坏性动作。

不得将正式下单按钮与普通筛选按钮设计为同一权重。

### 7.6 策略管理

策略管理以统计、查询和复盘为主：

- 策略损益突出收益、成本、归因和净值变化。
- 账户资金突出资金占用、保证金、净值、回撤和账户对照。
- 订单信息突出持仓、订单、成交、执行和筛选穿透。

页面应保持统一框架，但不同策略允许拥有不同的业务字段和归因结构。

### 7.7 风险管理

风险管理以状态识别、记录和管理为主：

- 风控详情突出风险指标、风险事件、等级、状态和处置。
- 账户、财务、监控、报表、审计、用户、设置和通知按各自子板块组织。
- 风险等级、市场涨跌、订单状态和系统状态不得混用同一颜色语义。

风险体系采用渐进式建设方式。UI 必须支持：

- 观察项。
- 提示项。
- 已确认风险。
- 限制或阻断状态。
- 人工确认与处置记录。

### 7.8 金融 AI

金融 AI 页面可以使用对话、任务、报告和情景推演结构，但必须保持与全平台一致的：

- 页面框架。
- 标题层级。
- 输入控件。
- 状态反馈。
- 结果卡片。
- 表格和图表样式。

AI 结果应区分：

- 用户输入。
- 分析范围。
- 关键结论。
- 依据和数据。
- 风险与不确定性。
- 可引用结果。

不得使用纯装饰性“AI 光效”替代真实信息层级。

## 8. 导航与页签

### 8.1 一级导航

- 一级导航保持稳定，不因页面重构改变顺序和命名。
- 选中态使用品牌浅色背景、品牌文字或左侧指示，不使用大面积高饱和色块。
- 图标与文字保持固定间距和统一尺寸。
- 折叠状态仍需提供 Tooltip 或可识别图标。

### 8.2 模块页签

模块、策略或主要页面切换优先使用统一的紧凑页签组件。

规则：

- 一个页签组只表达一个维度。
- 标签使用稳定名词，不使用完整句子。
- 当前页签必须有明确选中态。
- 页签数量超过可用宽度时允许横向滚动或折叠，不压缩到无法阅读。
- 不在单个页面复制另一套相同功能的页签样式。

### 8.3 局部切换

图表视角、统计周期、记录类型等局部切换应弱于模块页签，可使用：

- 小型分段控件。
- 文本按钮组。
- 下拉选择。
- 单选按钮。

局部切换不得与一级或二级页签使用完全相同的尺寸和视觉权重。

## 9. 工具栏与筛选器

### 9.1 工具栏结构

标准工具栏由以下区域组成：

- 左侧：模块、策略或主要视角。
- 中部：必要筛选条件。
- 右侧：刷新、导出、设置或辅助操作。

工具栏应紧凑、单行优先，窄屏时可有序换行。

### 9.2 筛选器

- 标签与控件靠近显示。
- 控件高度统一为 `34–36px`。
- 同类筛选器宽度尽量一致。
- 日期范围、市场、标的、账户和周期使用明确字段名。
- 当前筛选条件较多时，提供重置或恢复默认值。
- 不使用输入框占位文字替代表单标签。

## 10. 按钮

### 10.1 按钮层级

| 类型 | 用途 |
|---|---|
| 主要按钮 | 页面或操作组的首要动作 |
| 次要按钮 | 次一级操作、保存之外的常规动作 |
| 轻量按钮 | 刷新、查看、展开、导出等低风险动作 |
| 危险按钮 | 删除、强制平仓、撤销关键配置等破坏性动作 |
| 文本按钮 | 表格行内操作或低权重链接动作 |

规则：

- 同一操作区域最多设置一个主要按钮。
- 主要按钮使用品牌主色，不使用红色。
- 危险按钮使用红色，并在必要时要求二次确认。
- 按钮文字使用动词，如“提交订单”“导出报表”“确认处理”。
- 禁用按钮必须同时降低颜色、边框和交互反馈。

### 10.2 尺寸

- 紧凑按钮：`32–34px`。
- 标准按钮：`36–40px`。
- 首页品牌按钮：`48–50px`。
- 表格行内按钮可使用文本或小型按钮，不应抢占表格主内容。

## 11. 卡片与面板

### 11.1 使用原则

卡片用于表达明确的业务边界，例如：

- 指标摘要。
- 图表。
- 交易参数。
- 账户对照。
- 损益归因。
- 订单记录。

不应为每行文字、每个标签或每个小操作单独创建卡片。

### 11.2 层级

- 页面容器不需要再次包裹无意义大卡片。
- 标准页面最多使用两层可见卡片层级。
- 卡片内嵌卡片时，内层优先使用浅背景和分隔线，而不是再次使用完整边框与阴影。

### 11.3 卡片标题

卡片标题区可包含：

- 标题。
- 单位或时间范围。
- 局部筛选。
- 必要的查看详情或导出操作。

避免堆积：

- Eyebrow。
- 重复副标题。
- 无决策价值的说明句。
- 重复数据来源。
- 与标题含义相同的辅助文案。

## 12. 指标卡

指标卡应包含稳定结构：

1. 指标名称。
2. 主要数值。
3. 单位。
4. 变化值或对比基准。
5. 必要状态。

规则：

- 单个指标卡只突出一个主数值。
- 同组指标卡保持相同高度和对齐方式。
- 数值精度依据业务定义，不展示无意义小数。
- 变化值必须说明比较周期或基准。
- 同屏指标卡通常不超过 4–6 个；更多指标应分组或进入明细表。

## 13. 图表

### 13.1 图表卡结构

图表卡至少包含：

- 明确标题。
- 单位或数据口径。
- 时间范围。
- 图例。
- 图表主体。
- 加载、空数据和异常状态。

必要时可包含：

- 数据来源。
- 更新时间。
- 局部筛选。
- 查看明细。

图表型 widget 的标题应与图表主体形成明确的中轴关系，默认使用 `17px` 并放在图表卡 header 中水平居中。数据来源、原网址、下载等操作属于 header 右侧操作区，不得悬浮或叠加在绘图区内。

### 13.2 图表视觉

- 同一业务指标在不同页面使用相同颜色语义。
- 主序列使用品牌色或业务固定色，辅助序列降低饱和度和线宽。
- 网格线和坐标轴使用低对比度中性色。
- 不使用大面积渐变、3D 柱状图、发光线和无意义动画。
- 面积图透明度保持克制，不遮挡其他序列。
- 双轴图仅在量纲不同且关系明确时使用，并清晰标注左右轴。

### 13.3 图表交互

- Tooltip 的日期、数值、单位和精度保持一致。
- 图例支持识别，不使用难以区分的近似颜色。
- 时间缩放、拖动、数据区间和恢复默认行为在同类图表中保持一致。
- 图表与对应表格使用同一数据来源和口径。

## 14. 数据表格

### 14.1 表格结构

- 文本列左对齐。
- 数字列右对齐。
- 状态、图标和操作列可居中。
- 单位优先写入列标题，不在每个单元格重复。
- 时间格式和数值精度在同一列保持一致。

### 14.2 密度

- 标准行高：`40–44px`。
- 高密度研究表可使用 `36–40px`。
- 表头与正文保持清晰对比，但不使用过深背景。
- 行悬停使用轻微背景变化。
- 不使用过多纵向分隔线。

### 14.3 功能

表格根据业务需要提供：

- 排序。
- 筛选。
- 分页。
- 固定表头。
- 固定关键列。
- 超宽横向滚动。
- 空数据和异常状态。

行内操作应控制数量。超过三个操作时使用更多菜单或详情入口。

## 15. 表单与输入

### 15.1 表单规则

- 标签始终可见，不以 Placeholder 替代。
- 必填、可选、单位和输入格式表达清晰。
- 数量、价格、比例和金额使用对应输入类型及校验。
- 错误提示靠近字段显示，并说明如何修正。
- 长表单按业务步骤或逻辑分组，不连续堆叠大量字段。

### 15.2 交易输入

交易参数必须明确：

- 账户。
- 市场或交易所。
- 标的或合约。
- 方向。
- 数量。
- 价格。
- 订单类型。
- 两腿关系。
- 预计成本和影响。

高风险交易动作提交前，应提供明确的参数摘要和确认状态。

## 16. 状态与反馈

### 16.1 必备状态

所有异步数据和操作组件应覆盖：

- 默认状态。
- 加载状态。
- 空数据状态。
- 错误状态。
- 成功状态。
- 禁用状态。

### 16.2 加载

- 页面初次加载优先使用骨架屏或区块级加载。
- 小范围刷新使用局部 Loading，不阻塞整个页面。
- 长时间任务显示进度、阶段或可取消状态。

### 16.3 空状态

空状态应说明：

- 当前没有什么数据。
- 是否因为筛选条件。
- 用户可以采取什么动作。

不得只显示空白卡片或单独一个“暂无数据”。

### 16.4 错误状态

错误信息应区分：

- 数据加载失败。
- 权限不足。
- 参数错误。
- 服务不可用。
- 交易或操作失败。

错误提示应保留必要上下文，并提供重试、返回或查看详情入口。

### 16.5 消息层级

- Toast：短时、低风险、操作结果反馈。
- Inline Alert：与当前区块持续相关的提示或异常。
- Modal：高风险确认、破坏性操作或必须处理的阻断信息。
- Notification Center：跨模块、可回看、需要阅读状态的消息。

## 17. 风险、订单与交易状态

### 17.1 风险等级

建议统一为：

- 观察。
- 低。
- 中。
- 高。
- 严重。

“观察”用于尚未验证或不构成强制限制的指标。

### 17.2 风险状态

建议统一为：

- 待确认。
- 待处理。
- 处理中。
- 已解决。
- 已忽略。
- 已升级。

### 17.3 订单状态

订单状态应使用统一枚举和标签，例如：

- 待提交。
- 已提交。
- 部分成交。
- 已成交。
- 已撤销。
- 已拒绝。
- 失败。

### 17.4 双腿执行状态

双腿策略应同时展示：

- 主腿状态。
- 对冲腿状态。
- 已成交数量。
- 未成交数量。
- 配平比例。
- 暴露方向和金额。
- 当前是否需要人工处理。

不得仅用一个总状态掩盖单腿失败或部分成交。

## 18. 图标

- 图标用于增强识别，不替代必要文字。
- 同一操作使用同一图标。
- 常用图标尺寸保持在 `16–20px`。
- 指标卡和品牌区域可使用更大图标，但不抢占数值主体。
- 不混用不同线宽、不同圆角体系的图标库。
- 纯图标按钮必须提供 Tooltip 和可访问名称。

## 19. 动效

### 19.1 业务页面

业务页面动效以状态反馈为主：

- Hover、选中和展开：`160–220ms`。
- 抽屉和弹窗：`200–280ms`。
- 图表更新：平滑但克制，不超过 `400ms`。

禁止：

- 无限循环的装饰动画。
- 大幅位移和弹跳。
- 影响数据读取的发光、闪烁和粒子特效。

### 19.2 首页与品牌区域

首页可以使用较完整的视觉过渡，但必须：

- 支持减少动态效果偏好。
- 不阻塞页面操作。
- 不显著增加首屏加载时间。
- 保持品牌叙事，不展示设计说明或动画阶段名称。

## 20. 文案规范

### 20.1 语言

- 用户界面以中文为主。
- 标的、合约、标准指标、公司名和行业通用缩写可保留英文。
- 同一状态不得在不同页面混用中英文口径。

### 20.2 标题

- 页面标题使用模块或任务名称。
- 区块标题使用业务对象或分析主题。
- 卡片标题应简洁，避免标题后再重复同义副标题。

### 20.3 按钮

按钮使用明确动作：

- 开仓。
- 平仓。
- 提交订单。
- 保存设置。
- 导出报表。
- 确认处理。

避免：

- 点击这里。
- 立即体验。
- 查看更多信息内容。
- 不明确的“确定”。

### 20.4 辅助说明

只有在以下情况下保留说明文字：

- 业务口径可能被误解。
- 操作具有风险。
- 数据存在限制或延迟。
- 用户需要说明才能完成任务。

不为完整感增加无决策价值的 Eyebrow、Subtitle、Source Note 和概念说明。

## 21. 可访问性

### 21.1 焦点状态

所有可交互元素必须具有可见键盘焦点状态。全局 `outline: none` 不得作为最终交互表现，必须通过统一焦点环替代：

```css
:focus-visible {
  outline: 2px solid var(--ui-brand);
  outline-offset: 2px;
}
```

### 21.2 对比度

- 正文和背景的对比度应满足 WCAG AA。
- 辅助文字不得淡到无法阅读。
- 禁用状态与普通状态应明显区分。
- 状态不能仅通过颜色表达。

### 21.3 键盘与语义

- 页签、按钮、表格操作和弹窗可通过键盘访问。
- 图标按钮提供可访问名称。
- 表单标签与输入框建立关联。
- 弹窗打开后管理焦点，关闭后返回触发元素。

## 22. 响应式规则

### 22.1 桌面断点

建议：

- `≥ 1600px`：允许多列研究和执行布局。
- `1280–1599px`：标准桌面布局。
- `980–1279px`：减少列数，工具栏允许换行。
- `< 980px`：进入紧凑布局，复杂表格独立滚动。

### 22.2 降级顺序

空间不足时按以下顺序调整：

1. 收紧非核心留白。
2. 工具栏有序换行。
3. 指标卡减少列数。
4. 双栏改为单栏。
5. 超宽表格独立横向滚动。
6. 次要操作折叠到更多菜单。

不得通过将文字缩小到不可读或强行压缩图表来适配窄屏。

## 23. 组件与样式实现

### 23.1 样式层级

建议采用以下层级：

1. `src/design/`：全平台基础变量和组件库覆盖。
2. 业务域主题文件：一级模块或业务域的语义别名。
3. 共享组件样式：稳定结构和交互状态。
4. 页面样式：页面布局和少量局部差异。

`src/views/strategy/shared/strategy-theme.less` 应逐步引用全平台 Design Token，不长期维护与全局完全独立的颜色、字号和间距体系。

### 23.2 样式规则

- 优先使用 CSS 变量或 Less 变量。
- 不在多个页面硬编码相同值。
- 页面选择器应有明确作用域。
- 不扩大 `.card-head`、`.input-row`、`.select` 等宽泛选择器影响范围。
- 除第三方组件必要覆盖外，避免使用 `!important`。
- 不通过深层选择器修改未知组件内部结构。

### 23.3 共享组件

以下组件类型应在真实复用后统一：

- 模块和策略页签。
- 页面工具栏。
- 筛选栏。
- 指标卡。
- 图表卡。
- 状态标签。
- 记录表格。
- 加载、空数据和错误状态。
- 账户对照和双腿执行骨架。

共享组件提供稳定结构，不内置具体策略名称和业务判断。

## 24. 模块允许的视觉差异

全平台共用设计基座，但不同模块可保留以下差异：

| 模块 | 允许差异 |
|---|---|
| 首页 | 品牌主视觉、大字号、背景艺术和滚动叙事 |
| 对冲基金看板 | 更高图表密度、子导航和研究工具布局 |
| 新闻日历与理财 | 时间线、列表和信息卡片结构 |
| 交易平台 | 双腿执行、参数区、交易动作和即时反馈 |
| 策略管理 | 指标、归因、资金和历史记录密集布局 |
| 风险管理 | 状态标签、异常提示、管理表格和处置流程 |
| 金融 AI | 对话、任务、报告和情景推演结果结构 |

允许差异不得改变：

- 基础色板。
- 字体层级。
- 控件高度。
- 卡片和边框体系。
- 状态语义。
- 加载、错误和空状态。
- 按钮层级。

## 25. 禁止事项

- 为单个页面建立独立配色体系。
- 使用红色表达普通选中态或品牌主操作。
- 在业务页面大面积使用金色、渐变、发光和拓扑装饰。
- 同一页面出现多套圆角、阴影和控件高度。
- 在卡片标题下堆积无决策价值说明。
- 通过嵌套多层卡片制造视觉层级。
- 用颜色代替状态文字。
- 使用过多超大数字和高饱和指标卡。
- 在页面中复制一套已有页签、表格或图表容器。
- 为移动端适配牺牲桌面工作台的核心数据可读性。
- 将设计过程、临时方案和实现进度写入正式 UI 文案。

## 26. UI 验收清单

新增或修改页面时，应逐项检查：

### 视觉与层级

- 页面主任务是否清晰。
- 阅读顺序是否从总览到核心再到明细。
- 标题、正文、辅助信息和数字层级是否统一。
- 品牌色和语义色是否使用正确。
- 页面是否存在无意义装饰和重复说明。

### 布局与组件

- 是否使用统一间距和控件高度。
- 是否存在无意义嵌套卡片。
- 同类页签、按钮、筛选器和状态标签是否复用统一组件。
- 图表和表格是否具有加载、空数据和错误状态。
- 窄屏和常用桌面宽度下是否保持可用。

### 交互与状态

- 主要操作是否明确。
- 危险操作是否有正确提示与确认。
- 键盘焦点是否可见。
- 状态是否同时具有颜色和文字语义。
- 操作成功、失败和加载是否有及时反馈。

### 业务一致性

- 页面是否符合所属一级模块和子板块职责。
- 是否建立了重复管理或写入入口。
- 数据单位、精度、时间范围和状态口径是否一致。
- 交易、订单、风险和账户信息是否区分当前操作视角与长期管理视角。

通过上述检查后，页面方可视为符合 Platform V5 全平台 UI 设计规范。
