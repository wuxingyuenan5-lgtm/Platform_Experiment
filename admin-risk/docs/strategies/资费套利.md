# 资费套利：策略定位与需求

状态：`active`  
适用基线：Platform V5  
策略 ID：`funding`

## 1. 策略定位

资费套利是通过同时持有现货与永续合约对冲方向风险，主要获取正向资金费率及相关价差收益的双腿套利策略。

当前策略原则：

- 仅做正资金费率机会。
- 现货腿与永续腿方向相反。
- 核心目标是降低方向性暴露，获取资金费和价差相关收益。
- 当前主要交易平台包括 Binance、OKX、Bybit。

## 2. 平台能力

| 能力 | 是否启用 |
|---|---:|
| 交易平台·行情分析 | 是 |
| 交易平台·交易执行 | 是 |
| 策略管理·策略损益 | 是 |
| 策略管理·账户资金 | 是 |
| 策略管理·订单信息 | 是 |

资费套利通过交易平台完成研究和执行，并在策略管理中进行长期统计、资金观察和订单归档。

## 3. 核心用户问题

### 行情分析

- 当前资金费率是否足够高？
- 资金费率能否持续？
- 现货与永续之间的综合价差是否有利？
- 哪个交易所和标的机会更好？
- 预计收益是否覆盖手续费、滑点和其他成本？

### 交易执行

- 现货腿和永续腿分别交易多少？
- 两腿是否完成名义价值配平？
- 当前是否存在单腿暴露？
- 预计资金费收益和综合价差收益是多少？
- 执行后的持仓和账户状态是否安全？

### 策略管理

- 累计赚了多少钱？
- 收益来自资金费、综合基差还是其他部分？
- 手续费和执行偏差消耗了多少收益？
- 两端账户的资金和保证金是否安全？
- 每次现货、永续和资金费结算能否被追溯？

## 4. 交易结构

### 4.1 交易腿

- 现货腿：持有现货实寸。
- 永续腿：持有与现货方向相反的永续合约。

典型正费率场景：

- 买入现货。
- 卖出永续。

### 4.2 腿模型

`dual`

### 4.3 账户模型

`dual`

现货与永续可以位于同一交易所的不同账户，也可以位于不同交易平台。前端必须明确展示每条腿的平台、账户、币种、数量和名义价值。

## 5. 行情分析需求

必须包含：

- 交易所选择。
- 标的选择。
- 当前资金费率。
- 历史资金费率曲线。
- 历史分位。
- 现货与永续综合价差。
- 多交易所对比。
- 时间精度和统计区间。
- 当前机会收益与成本摘要。

建议观察维度：

- 当前费率。
- 下一结算时间。
- 历史平均费率。
- 费率分位。
- 现货与永续综合价差。
- 手续费。
- 预计滑点。
- 预估年化。

## 6. 交易执行需求

### 6.1 执行参数

- 交易所。
- 标的。
- 开仓、平仓或调整。
- 现货腿方向、价格、数量和订单类型。
- 永续腿方向、价格、数量和订单类型。
- 两腿名义价值比例。
- 滑点或价格保护参数。

### 6.2 执行前预估

- 预计资金费收入。
- 综合价差收益或成本。
- 预计手续费。
- 预计滑点。
- 预计净收益。
- 执行后资金占用。
- 执行后保证金状态。

### 6.3 执行反馈

- 两腿订单状态。
- 两腿成交数量。
- 两腿成交均价。
- 当前配平比例。
- 单腿暴露。
- 失败、撤单或人工干预状态。

## 7. 策略损益结构

### 7.1 累计总损益

资费套利的累计总损益由以下部分组成：

- 库存费累计收益。
- 综合基差损益。
- 累计交易成本。
- 必要的执行偏差或其他已确认调整项。

### 7.2 库存费累计收益

指持有永续合约期间实际结算获得的资金费收益。

应支持：

- 按标的统计。
- 按交易所统计。
- 按结算周期统计。
- 累计曲线。

### 7.3 综合基差损益

现货平台溢价损益与永续基差损益合并为一个损益项，不再拆成两个独立一级归因。

该项表达现货腿和永续腿之间价格关系变化带来的综合损益。

### 7.4 累计交易成本

至少包含：

- 现货手续费。
- 永续手续费。
- 已确认的滑点成本。
- 其他明确归属于交易执行的成本。

### 7.5 不使用配平误差

资费套利当前损益体系不设置“配平误差”一级归因。

两腿数量偏差、执行时间差等问题应进入执行偏差、交易成本或明确的异常记录，不得为了表格完整而新增配平误差项。

### 7.6 核对关系

原则上：

`累计总损益 = 库存费累计收益 + 综合基差损益 + 累计交易成本 + 已确认调整项`

成本项在数据中应保持统一正负号规则。

## 8. 账户资金需求

### 8.1 合并总览

- 策略总资金。
- 合并权益。
- 合并可用资金。
- 总资金占用。
- 资金效率。
- 策略净值。
- 最大回撤。

### 8.2 现货端

- 平台和账户。
- 现货资产数量。
- 现货市值。
- 可用余额。
- 资金占用。

### 8.3 永续端

- 平台和账户。
- 合约持仓。
- 保证金占用。
- 可用保证金。
- 强平或风险距离。
- 未结算资金费。

### 8.4 风险提示

- 两端资金失衡。
- 永续端保证金不足。
- 单腿暴露。
- 标的或平台集中度过高。
- 资金费率方向发生变化。

## 9. 订单信息需求

固定页签：

- 当前持仓。
- 历史订单－现货。
- 历史订单－合约。
- 成交记录。
- 执行记录。

建议增加：

- 资金费结算记录。

关键字段：

- 时间。
- 策略 ID。
- 执行批次 ID。
- 标的。
- 腿类型。
- 平台和账户。
- 方向。
- 委托价和成交价。
- 委托量和成交量。
- 手续费。
- 订单状态。
- 资金费结算金额。

## 10. 风险结构

主要风险：

- 资金费率快速反转。
- 综合基差不利变化。
- 单腿成交或单腿暴露。
- 永续端保证金风险。
- 交易所、账户或资产托管风险。
- 流动性和滑点风险。
- 标的集中度风险。

当前前端阶段只要求清晰展示风险状态和必要提示，不定义完整风控引擎。

## 11. 当前 V5 前端状态

已具备：

- 交易所和标的切换。
- 资金费行情和图表。
- 行情分析与交易执行分离。
- 现货与永续订单展示。
- 策略损益、账户资金和订单信息入口。

后续本地整理重点：

- 统一损益命名。
- 将现货平台溢价与永续基差归并为综合基差损益。
- 保证交易平台和策略管理使用同一策略 ID。
- 避免在多个 Mock 文件重复定义同一基础数据。

## 12. 明确不包含

- 负资金费率方向策略。
- 借币困难场景的自动借币系统。
- 完整交易所风险评级系统。
- 后端订单路由和真实撮合逻辑。
- 配平误差一级损益项。

## 13. 验收标准

- 交易平台具备完整行情分析和交易执行。
- 策略管理具备损益、资金和订单三类页面。
- 现货腿和永续腿能够通过同一执行批次关联。
- 损益归因包含库存费累计收益、综合基差损益和累计交易成本。
- 不单独展示现货平台溢价损益和永续基差损益。
- 不设置配平误差一级归因。
- 合并总损益能够与各归因项核对。
- 两端账户资金、保证金和暴露状态表达清晰。
