# 跨所价差：策略定位与需求

状态：`active`  
适用基线：Platform V5  
策略 ID：`crossSpread`

## 1. 策略定位

跨所价差是通过在两个不同交易场所或报价体系中建立方向相反的头寸，获取价差回归或结构性偏离收益的双腿套利策略。

当前平台的核心场景是黄金跨所价差：

- 主腿：`XAUTUSDT.P`。
- 对冲腿：`XAUUSD`。

后续可以扩展其他跨市场组合，但不得在未确认业务口径前将所有价差策略混入同一损益模型。

## 2. 平台能力

| 能力 | 是否启用 |
|---|---:|
| 交易平台·行情分析 | 是 |
| 交易平台·交易执行 | 是 |
| 策略管理·策略损益 | 是 |
| 策略管理·账户资金 | 是 |
| 策略管理·订单信息 | 是 |

## 3. 核心用户问题

### 行情分析

- 当前跨所价差是多少？
- 当前价差处于什么历史分位？
- 当前偏离是否具有回归价值？
- 两个市场的交易时间、流动性和报价结构是否允许交易？
- 预期价差收益能否覆盖手续费、滑点和资金成本？

### 交易执行

- 两条腿分别交易多少？
- 两腿名义价值是否匹配？
- 当前价格是否满足目标价差？
- 两腿是否同时成交？
- 是否出现单腿暴露或执行异常？

### 策略管理

- 总损益和价差收益是多少？
- 交易成本和执行偏差消耗了多少收益？
- 两端账户和保证金是否安全？
- 每次开仓、平仓和人工干预能否追溯？

## 4. 交易结构

### 4.1 交易腿

- 主腿：当前主要为 `XAUTUSDT.P`。
- 对冲腿：当前主要为 `XAUUSD`。

两腿方向相反，以降低黄金方向性风险并获取跨所价差变化收益。

### 4.2 腿模型

`dual`

### 4.3 账户模型

`dual`

两条腿通常位于不同交易平台或账户。前端必须明确展示：

- 市场或平台。
- 账户。
- 标的。
- 报价币种。
- 方向。
- 数量。
- 名义价值。
- 换算口径。

## 5. 价差定义

当前核心价差表达：

`XAUTUSDT.P - XAUUSD`

实际展示和计算时必须明确：

- 两个价格是否已经统一单位。
- 两个价格是否需要币种换算。
- 合约乘数和数量换算。
- 买卖价或中间价口径。
- 时间同步口径。

前端 Mock 阶段也必须保持同一口径，避免图表、统计和执行页使用不同价差定义。

## 6. 行情分析需求

必须包含：

- 主交易所或主要交易场景选择。
- 主腿和对冲腿选择。
- 当前价差。
- 两腿价格。
- 价差主图。
- 历史分位。
- 区间统计。
- 机会分析。
- 时间精度和日期区间。
- 季节性或周期性分析。
- 必要的期限结构或市场结构信息。

### 6.1 统计分析

至少支持：

- 当前值。
- 均值或中位数。
- 标准差。
- 10%、50%、90% 分位。
- 区间最大值和最小值。
- 必要时展示 Z 值或偏离程度。

具体统计口径应由策略需求确认，不在组件内自行改变。

### 6.2 图表要求

- 价差作为主序列。
- 可以按需要叠加黄金价格等参考序列。
- 支持时间区间缩放。
- 图例能够控制序列显示。
- 图表、统计表和实时价差使用同一分析上下文。

## 7. 交易执行需求

### 7.1 执行前状态

- 当前两腿报价。
- 当前价差。
- 目标开仓或平仓价差。
- 两端流动性状态。
- 当前持仓。
- 当前是否允许执行。

### 7.2 执行参数

- 开仓、平仓或调整。
- 主腿方向、价格、数量和订单类型。
- 对冲腿方向、价格、数量和订单类型。
- 两腿数量或名义价值比例。
- 价格保护或滑点参数。
- 执行顺序或同步执行模式。

### 7.3 预估信息

- 预期价差收益。
- 手续费。
- 滑点。
- 资金成本。
- 预计净收益。
- 执行后的两端资金和保证金变化。

### 7.4 执行反馈

- 两腿订单状态。
- 成交数量和均价。
- 当前实际价差。
- 两腿名义价值差异。
- 单腿暴露。
- 撤单、失败和人工干预。

## 8. 策略损益结构

### 8.1 累计总损益

当前建议由以下部分组成：

- 跨所价差损益。
- 交易成本。
- 资金成本。
- 执行偏差。
- 已确认的其他调整项。

### 8.2 跨所价差损益

表达两腿价格关系变化带来的核心策略收益。

应支持：

- 累计金额。
- 区间金额。
- 时间序列。
- 按执行批次、标的或平台穿透。

### 8.3 交易成本

至少包含：

- 主腿手续费。
- 对冲腿手续费。
- 已确认滑点成本。

### 8.4 资金成本

按实际策略需要包含：

- 保证金或资金占用成本。
- 明确归属于持仓期间的融资成本。

不适用时不得为了表格完整而虚构该项。

### 8.5 执行偏差

表达由于成交时间、成交价格、部分成交或人工执行差异产生的可识别损益影响。

### 8.6 不使用配平误差

跨所价差当前损益体系不设置“配平误差”一级归因。

两腿数量、名义价值或成交时间不一致应进入执行偏差、交易成本、持仓风险或异常记录，不单独构造配平误差损益项。

### 8.7 核对关系

原则上：

`累计总损益 = 跨所价差损益 + 交易成本 + 资金成本 + 执行偏差 + 已确认调整项`

## 9. 账户资金需求

### 9.1 合并总览

- 策略总资金。
- 合并权益。
- 合并可用资金。
- 保证金占用。
- 资金使用率。
- 策略净值。
- 最大回撤。

### 9.2 主腿账户

- 平台和账户。
- 持仓数量。
- 名义价值。
- 可用资金。
- 保证金或资金占用。
- 风险状态。

### 9.3 对冲腿账户

字段与主腿保持可比较，但允许根据市场类型展示特有字段。

### 9.4 风险提示

- 单腿暴露。
- 两腿名义价值失衡。
- 单端保证金不足。
- 某一市场流动性显著下降。
- 报价源或市场状态异常。
- 平台集中度风险。

## 10. 订单信息需求

固定页签：

- 当前持仓。
- 历史订单－主腿。
- 历史订单－对冲腿。
- 成交记录。
- 执行记录。

关键字段：

- 时间。
- 策略 ID。
- 执行批次 ID。
- 腿类型。
- 平台和账户。
- 标的。
- 方向。
- 委托价和成交价。
- 委托量和成交量。
- 手续费。
- 订单状态。
- 实际成交价差。
- 人工干预记录。

## 11. 风险结构

主要风险：

- 价差继续扩大。
- 单腿成交和单腿暴露。
- 两个市场交易时间不一致。
- 两个市场流动性差异。
- 报价延迟和时间不同步。
- 平台或账户风险。
- 合约规格、乘数和单位换算错误。
- 资金和保证金不足。

当前前端阶段只要求清晰表达风险，不定义完整风控引擎。

## 12. 当前 V5 前端状态

已具备：

- 跨所价差行情分析。
- 价差主图、机会分析和统计区。
- 行情分析与执行分离。
- 双腿执行工作区。
- 策略管理中的损益、资金和订单入口。

后续本地整理重点：

- 统一价差计算和展示口径。
- 将大型页面按分析区、统计区和执行区拆分。
- 确保执行和策略管理使用同一执行批次与策略 ID。
- 统一损益项名称。

## 13. 明确不包含

- 海内外价差中的完整汇率损益模型。
- 未确认的新标的和新市场组合。
- 后端自动路由和真实订单执行。
- 配平误差一级损益项。

## 14. 验收标准

- 交易平台具备完整行情分析和交易执行。
- 核心价差定义在图表、统计和执行页一致。
- 两腿订单能够通过同一执行批次关联。
- 策略损益包含价差损益、成本和执行偏差等已确认项。
- 不设置配平误差一级归因。
- 两端账户和名义价值状态表达清晰。
- 策略管理可以穿透到主腿、对冲腿、成交和执行记录。
