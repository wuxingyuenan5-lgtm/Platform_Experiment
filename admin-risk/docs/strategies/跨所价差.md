## 1. 文档定位

本文定义跨所价差策略的业务目标、黄金核心场景、标的与单位标准化、Crypto 与 MT5 双端账户、行情分析、跨 Runtime 执行、订单成交与持仓关系、EconomicEvent、损益归因、风险、对账、数据质量、策略管理 Read Model、外部组件能力依赖和验收标准。

本文是以下专项口径的唯一来源：

- 当前核心组合为 `XAUTUSDT.P - XAUUSD`。
- 两腿价格必须先完成单位、币种、合约乘数和时间口径标准化。
- 跨所价差损益与累计交易成本的一级归因结构。
- Funding、MT5 Swap、手续费、佣金和已确认滑点的归属。
- 执行偏差属于执行质量、风险和明细穿透，不单独作为一级损益项。
- 不设置“配平误差”一级损益归因。

通用交易命令、权限、状态、运行可靠性和页面共同规则仍以上位文档为准。

## 2. 策略定位与核心约束

跨所价差是通过在两个不同交易场所或报价体系建立方向相反的头寸，降低黄金方向性暴露，并获取标准化价差回归或结构性偏离收益的双腿策略。

当前核心场景：

- Crypto 腿：`XAUTUSDT.P` 或经正式映射确认的等价黄金代币永续产品。
- MT5 腿：`XAUUSD` 或经经纪商 Symbol Mapping 后确认的等价黄金差价合约。

当前正式原则：

1. 两腿方向相反，目标是降低黄金价格方向性暴露。
2. 价差计算前必须统一黄金数量单位、报价币种和时间口径。
3. 外部 symbol 只作为映射值，平台使用稳定 InstrumentId。
4. 不默认假设所有经纪商 `XAUUSD` 合约规格相同。
5. 不默认假设 Crypto 合约数量与金衡盎司一一对应，必须读取产品元数据或正式配置。
6. USDT 与 USD 不直接无条件视为完全相同，必须明确换算口径和数据来源。
7. 交易机会必须覆盖两端手续费、Funding、Swap、滑点及其他实际成本。
8. 两端报价时间差、市场状态和流动性差异必须显式表达。
9. 两腿执行由同一 ExecutionBatch 组织，前端不得分别提交后自行拼接。
10. 数量偏差和残腿属于执行与风险状态，不建立配平误差一级损益。

## 4. 核心用户问题

### 4.1 行情分析

- 当前标准化后的跨所价差是多少？
- 当前使用的是哪两个可执行报价？
- 两端报价时间差和数据质量如何？
- 当前价差处于什么历史分位、Z 值或区间位置？
- 当前偏离是否可能覆盖交易与持有成本？
- 两端市场是否同时开放、可交易且流动性充足？
- USDT／USD 换算对价差有多大影响？
- 当前合约规格和数量换算是否有效？

### 4.2 交易准备与执行

- 两腿分别使用哪个账户、Gateway、Runtime 和 Instrument？
- 目标黄金敞口是多少金衡盎司或统一基础数量？
- Crypto 数量和 MT5 lot 应分别是多少？
- 采用并行、主动腿／被动腿还是顺序执行？
- 当前价差是否达到开仓、平仓或调整条件？
- 两腿成交后实际黄金等价数量是否匹配？
- 是否出现单腿成交、部分成交、拒单或结果未知？
- 当前单腿暴露金额和持续时间是多少？

### 4.3 策略管理

- 累计跨所价差损益是多少？
- 手续费、Funding、Swap、佣金和滑点消耗了多少？
- 两端账户权益、保证金和可用资金是否安全？
- 每个 ExecutionBatch 的开仓、平仓、调整和人工处理能否追溯？
- Crypto 与 MT5 的订单、成交、持仓和费用是否已对账？
- Symbol Mapping、合约规格和汇率数据是否可靠？

## 5. 策略身份、版本与实例

### 5.1 StrategyDefinition

稳定定义：

- `strategyId = crossSpread`。
- 正式名称：跨所价差。
- 执行类型：平台执行策略。
- 腿模型：双腿。
- 当前核心资产：黄金。
- 当前核心市场：Crypto 永续与 MT5 黄金差价合约。
- 主要收益来源：标准化跨所价差变化。

### 5.2 StrategyVersion

每个正式版本至少记录：

- 允许的市场组合和 Instrument Mapping。
- 价差方向和正式公式。
- 统一数量单位和计价币种。
- USDT／USD 换算方法。
- Crypto 合约乘数和黄金单位换算。
- MT5 Contract Size、lot 步进和 Symbol Mapping。
- 允许的执行模式。
- 主动腿／被动腿规则。
- 目标配平和容忍范围。
- 最大订单规模、最大单腿暴露和最大残腿时间。
- 开仓、平仓和调整条件。
- 交易与持有成本口径。
- PnL 公式和正负号规则。
- 数据质量门槛和交易时段限制。
- 生效时间、审批和替代关系。

### 5.3 StrategyInstance

至少表达：

- `strategyInstanceId`。
- StrategyVersionId。
- DeploymentEnvironment 和 TradingMode。
- Crypto Venue、Account 和 Gateway。
- MT5 Broker、Account、Terminal、Worker 和 Gateway。
- 允许的 Instrument 组合。
- 实例额度和风险限制。
- 是否允许开仓、平仓、调整和紧急对冲。
- 当前运行状态和最近对账状态。

### 5.4 StrategyAccountBinding

账户用途至少区分：

- `crypto_leg`。
- `mt5_leg`。
- `settlement`，适用时。
- `observation_only`，适用时。

每个绑定必须记录：

- AccountId。
- Gateway／Runtime／Worker。
- 允许的 Instrument 和交易动作。
- 额度和名义价值上限。
- 适用 TradingMode。
- 生效和失效时间。
- 是否允许 Live。
- 审批和审计，适用时。

## 6. Instrument、合约规格与 Symbol Mapping

### 6.1 平台 Instrument

平台使用稳定 InstrumentId，不以 `XAUTUSDT.P`、`XAUUSD`、`XAUUSDm` 等外部字符串直接作为业务权威。

每个 Instrument 至少包含：

- Venue／Broker。
- 市场类型。
- 基础资产和计价资产。
- 外部 symbol。
- 产品类型。
- 合约乘数。
- 数量单位。
- 价格单位。
- 最小数量和数量步进。
- 最小名义价值。
- 价格精度。
- 交易时段和休市规则。
- 元数据版本和更新时间。

### 6.2 Crypto 腿规格

至少确认：

- XAUT 代币或等价产品对应的黄金单位关系。
- 永续合约是线性还是其他结构。
- 合约数量的基础资产等价值。
- 结算币种和保证金币种。
- Position Mode。
- Funding Interval 和 Funding 语义。
- 订单类型和 Reduce Only 支持。

### 6.3 MT5 腿规格

至少确认：

- 经纪商正式 symbol 和后缀。
- Contract Size。
- lot 最小值、最大值和步进。
- Tick Size 和 Tick Value。
- 报价位数。
- Hedging／Netting 模式。
- Market、Limit、Stop、Stop Limit 和部分平仓能力。
- 交易时段、每日休市和周末规则。
- Commission 和 Swap 规则。

不能将常见经纪商经验值硬编码为所有 MT5 账户统一规格。

## 7. 价差定义与标准化

### 7.1 当前核心价差

概念表达：

```text
cross_spread = normalized_crypto_gold_price - normalized_mt5_gold_price
```

页面可以展示为：

```text
XAUTUSDT.P - XAUUSD
```

但正式计算必须明确两端已完成标准化。

### 7.2 数量标准化

统一黄金基础数量候选：

```text
crypto_gold_ounce_equivalent
mt5_gold_ounce_equivalent
```

计算必须记录：

- 原始数量。
- 原始数量单位。
- 产品或合约乘数。
- token-to-ounce 或 contract-to-ounce 转换参数。
- 标准化后的黄金数量。
- 取整规则和剩余偏差。
- 参数版本和来源。

### 7.3 币种标准化

Crypto 腿通常以 USDT 计价，MT5 腿通常以 USD 计价。

必须选择正式报告币种，例如 USD 或 USDT，并记录：

- USDT／USD 汇率或稳定币换算来源。
- sourceTime 和 receivedAt。
- 是否使用实时、中间价、结算价或固定假设。
- 数据质量和异常条件。
- 计算版本。

不得无提示把 `1 USDT = 1 USD` 作为永久事实。允许在明确的分析情景中采用固定 1:1 假设，但必须显示假设和用途，不能用于正式 PnL 而不留记录。

### 7.4 方向相关的可执行价差

机会分析应优先使用方向相关 Bid／Ask：

- 买入某腿使用 Ask。
- 卖出某腿使用 Bid。
- 退出时使用对应反向可执行价格。

Mid、Last 或 Mark 可以用于研究和估值，但不得无条件替代执行价格。

### 7.5 时间同步

正式价差至少记录：

- Crypto sourceTime。
- MT5 sourceTime。
- 两端 receivedAt。
- 最大允许时间差。
- 是否使用最近邻、时间桶或其他同步方法。
- 数据延迟和质量状态。

两端报价时间差超限时，价差必须标记 stale／invalid，并按规则禁止正式提交。

## 8. 行情和数据需求

### 8.1 Crypto 数据

- Bid／Ask 和必要订单簿深度。
- Last、Mark 和 Index Price，适用时。
- Funding Rate 和 Funding Time。
- 成交量和流动性摘要。
- Instrument 元数据。
- 账户、余额、持仓、订单和成交。
- 实际 FundingSettlement 和交易费用。

### 8.2 MT5 数据

- Tick Bid／Ask 和 sourceTime。
- 必要 K 线历史。
- SymbolInfo 和 ContractSpecification。
- 账户、余额、权益、保证金和持仓。
- Order、Deal 和 Position 历史。
- Commission、Swap 和其他费用。
- Terminal、Broker、Account 和 Worker 状态。

### 8.3 汇率和换算数据

- USDT／USD 或正式换算数据。
- 数据来源、时间和质量。
- 缺失或脱锚状态。
- 历史换算序列，正式 PnL 重算需要时。

### 8.4 历史研究数据

- 标准化价差时间序列。
- 两腿价格历史。
- 价差分位、均值、中位数、标准差和 Z 值。
- 时段、星期和季节性统计。
- 两端流动性、滑点和市场开放重叠区间。
- Funding、Swap 和费用历史。

### 8.5 数据质量

至少检查：

- 两端报价新鲜度和时间差。
- Instrument／Symbol Mapping 是否有效。
- 合约规格是否完整和最新。
- USDT／USD 数据是否可用。
- Bid、Ask、Last、Mark 是否正确区分。
- 交易时段是否有效。
- 账户和 Gateway 是否同步。
- MT5 Terminal 是否 READY。
- 历史序列是否存在缺口、重复或异常跳变。

## 9. 行情分析与统计

### 9.1 页面结构

至少包含：

1. StrategyInstance、Crypto 与 MT5 上下文。
2. 两腿当前报价和数据质量。
3. 当前标准化价差。
4. 价差主图。
5. 历史分位、统计和分布。
6. 交易时段和市场状态。
7. 流动性、预计滑点和目标规模。
8. Funding、Swap、手续费和预计净收益。
9. 账户资金和保证金摘要。
10. 进入交易执行的安全参数准备入口。

### 9.2 统计指标

至少支持：

- 当前值。
- 均值和中位数。
- 标准差。
- 10%、25%、50%、75%、90% 分位，按产品确认展示。
- 区间最大值和最小值。
- Z 值或偏离程度。
- 价差变化速度。
- 不同交易时段的统计。
- 回归持续时间和历史持有期，具备正式定义时。

所有图表、卡片和表格使用同一标准化、币种、时间同步和统计上下文。

### 9.3 机会预估

预计净收益候选结构：

```text
预计跨所价差收益
+ 预计累计交易成本
= 预计净收益
```

累计交易成本作为带符号项，通常为负，至少考虑：

- Crypto 手续费。
- MT5 Commission。
- Crypto Funding。
- MT5 Swap／OvernightFee。
- 两端预计滑点。
- USDT／USD 转换或其他明确成本。

预估必须明确持有期、退出价差、费用假设、Funding 和 Swap 假设以及数据时间。

## 10. TradeIntent 与 ExecutionPlan

### 10.1 TradeIntent

至少包含：

- StrategyInstanceId。
- 开仓、平仓、调整或紧急减险。
- Crypto Account、Gateway 和 Instrument。
- MT5 Account、Worker、Gateway 和 Instrument。
- 两腿方向。
- 目标统一黄金数量或名义价值。
- Crypto 数量和 MT5 lot 计算结果。
- 目标价差和价格保护。
- 订单类型。
- 执行模式。
- 最大滑点。
- 最大单腿暴露时间。
- 部分成交、残腿和结果未知政策。
- 预计收益、成本、保证金和风险计算引用。

### 10.2 ExecutionPlan

候选模式：

- `parallel`：Crypto 与 MT5 两腿近似同时派发。
- `active_passive`：主动腿实际成交驱动被动腿数量。
- `sequential`：一腿达到指定状态后执行另一腿。
- `manual_confirmed`：关键步骤由人工确认。
- `simulation`：使用模拟 Gateway。

ExecutionPlan 至少记录：

- 主动腿和被动腿。
- Runtime／Worker 路由。
- 每腿订单政策。
- 数量换算、精度和取整规则。
- 最大滑点和价格保护。
- 超时、撤单和重试政策。
- 实际成交量驱动对冲规则。
- 最大裸露时间。
- 残腿处理和紧急减险。
- 计划版本。

### 10.3 跨 Runtime 协调

Crypto 与 MT5 可能运行在不同 Gateway、进程或 Worker 中。

平台必须：

- 由 ExecutionBatch 统一拥有两腿业务关系。
- 使用稳定 commandId、correlationId 和 legInstructionId。
- 分别跟踪两端命令受理和外部订单状态。
- 不假设两个 Runtime 可以共享内存。
- 不以单次 RPC 超时直接判断外部订单失败。
- 支持重复、延迟、乱序和补发事件。
- 支持某一端恢复后重新对账和继续人工处理。

## 11. 执行前校验

除平台通用校验外，至少检查：

- StrategyVersion 和 StrategyInstance 有效。
- Crypto 与 MT5 Account 绑定有效。
- 两端 Gateway／Runtime／Worker 均满足当前能力。
- Instrument 和 Symbol Mapping 有效。
- 合约规格、单位和乘数完整。
- USDT／USD 换算数据有效。
- 两端报价在新鲜度和时间差范围内。
- 当前市场和 MT5 交易时段允许交易。
- Crypto 账户余额、保证金和 Position Mode 满足要求。
- MT5 账户 Margin、Hedging／Netting 和 AutoTrading 状态满足要求。
- Crypto 数量和 MT5 lot 满足精度、步进和最小值。
- 目标黄金等价数量在容忍范围内。
- 订单类型和 Reduce Only／部分平仓等能力可用。
- 当前流动性和预计滑点满足限制。
- 当前无冲突的未完成 ExecutionBatch。
- RiskDecision、GlobalTradingBlock 和 ApprovalGrant 满足要求。

## 12. 执行、订单、成交与持仓

### 12.1 标准业务链路

```text
TradeIntent
→ TradeCommand
→ ExecutionBatch
→ ExecutionPlan
→ Crypto LegInstruction + MT5 LegInstruction
→ 预创建平台 Order
→ 分别派发至 Crypto Runtime 和 MT5 Worker
→ 外部 Order／Deal／Fill 回报
→ Position 更新
→ 数量配平和 Exposure 判断
→ 完成、异常、结果未知或人工处理
```

### 12.2 稳定身份

至少使用：

- tradeCommandId。
- executionBatchId。
- legInstructionId。
- platformOrderId。
- clientOrderId，Crypto 支持时。
- Magic Number／Comment，MT5 适用时。
- externalOrderId。
- externalTradeId／dealId。
- fillId／executionId。

### 12.3 MT5 订单与 Deal

平台必须明确：

- MT5 Order、Deal 和 Position 是不同对象。
- 一张 Order 可以产生多个 Deal。
- Hedging 和 Netting 账户的 Position 语义不同。
- 部分平仓必须关联原 Position 和关闭数量。
- 外部手工订单和 Deal 进入对账与归属流程。
- Magic Number 和 Comment 只作为映射证据之一，不是唯一业务身份。

### 12.4 配平与暴露

分别展示：

- Crypto 统一黄金数量。
- MT5 统一黄金数量。
- 目标比例。
- 实际委托比例。
- 实际成交比例。
- 数量和名义价值偏差。
- ExecutionBalanceStatus。
- ExposureStatus。
- 暴露方向、黄金数量、报告币种金额和持续时间。

未配平不建立配平误差一级 PnL。

### 12.5 结果未知

任一端结果未知时：

1. 保留原 commandId、platformOrderId 和 idempotencyKey。
2. Crypto 端查询 open orders、closed orders、trades 和 positions。
3. MT5 端查询 orders、deals、positions 和 history。
4. 通过 clientOrderId、externalOrderId、Magic Number、Comment、时间和数量综合匹配。
5. 不使用新幂等身份盲目重复下单。
6. 必要时进入人工处理和紧急减险。

## 13. 持有、调整与平仓

### 13.1 持有期间

持续监控：

- 标准化价差。
- 两端持仓和数量配平。
- Crypto Funding。
- MT5 Swap 和 Commission。
- USDT／USD 汇率。
- Crypto 账户和 MT5 保证金状态。
- 两端市场开放和流动性。
- Gateway、Runtime、Worker 和 Terminal 状态。
- 对账和数据质量。

### 13.2 调整

调整场景可以包括：

- 两端持仓数量偏离。
- MT5 lot 取整导致长期偏差。
- 部分平仓后重新配平。
- 账户保证金或风险需要减仓。
- 价差目标变化。

调整必须产生新的 TradeCommand／ExecutionBatch 或明确关联的 Rebalance 批次，不直接编辑 Position 数字。

### 13.3 平仓

平仓需要记录：

- 目标退出价差。
- 关闭原因。
- 两腿目标和实际关闭数量。
- 执行模式和顺序。
- 实际成交价格和标准化退出价差。
- 剩余持仓。
- 交易与持有成本。
- 最终对账和人工处理。

## 14. EconomicEvent

从第一笔交易开始至少记录：

- Crypto Fill。
- MT5 Deal／Fill。
- Crypto TradingFee。
- MT5 Commission。
- Crypto FundingSettlement。
- MT5 Swap／OvernightFee。
- FXConversion／CurrencyTranslation 输入，适用时。
- TransferFee，正式启用时。
- ManualAdjustment。

每个 EconomicEvent 至少关联：

- StrategyId、StrategyVersionId 和 StrategyInstanceId。
- AccountId 和 InstrumentId。
- ExecutionBatchId、OrderId、FillId 或 PositionId，适用时。
- 外部 ID。
- 事件类型。
- 原始金额、币种和单位。
- 统一报告币种金额和换算引用，适用时。
- occurredAt、receivedAt 和 businessDate。
- 数据来源、质量和对账状态。

## 15. 损益结构与核对

### 15.1 累计总损益

当前正式一级结构：

```text
累计总损益
= 跨所价差损益
+ 累计交易成本
+ 已确认调整项
```

累计交易成本作为带符号项，成本通常为负，也允许个别持有事件产生正收益。

### 15.2 跨所价差损益

跨所价差损益表达两腿标准化价格关系变化形成的组合价格损益。

计算需要：

- Crypto 与 MT5 实际成交和持仓。
- 统一黄金数量。
- 合约乘数和 lot。
- 原始币种。
- USDT／USD 或正式汇率换算。
- 开仓和估值／平仓价格。
- 计算版本和数据截止时间。

支持按以下维度穿透：

- StrategyInstance。
- ExecutionBatch。
- Crypto Venue 和 MT5 Broker。
- Instrument 组合。
- 日期和持有周期。

可以在明细中展示两腿原生价格损益和币种换算影响，但在当前正式一级归因中仍汇总为跨所价差损益，不额外建立未确认的一级汇率损益。

### 15.3 累计交易成本

至少包含：

- Crypto 手续费。
- MT5 Commission。
- Crypto FundingSettlement。
- MT5 Swap／OvernightFee。
- 已确认滑点成本。
- USDT／USD 转换费用或其他明确成本，适用时。
- TransferFee，正式纳入时。

Funding 或 Swap 可能为正或负，数据层保留真实方向；页面可以继续使用“累计交易成本”一级名称，并在明细中拆分实际组成。

### 15.4 执行偏差

执行偏差用于衡量：

- 决策价差与实际成交价差差异。
- 两腿成交时间差。
- 预期价格与实际成交价格差异。
- 部分成交和追价效果。
- MT5 lot 取整和 Crypto 数量取整影响。

执行偏差是执行质量、风险和复盘指标，不单独作为一级 PnL 归因。

其实际经济影响最终进入：

- 跨所价差损益。
- 已确认滑点等累计交易成本。
- AdjustmentEntry，只有在正式修正时。

### 15.5 不使用配平误差

跨所价差不设置“配平误差”一级损益项。

数量和名义价值不一致通过以下方式表达：

- ExecutionBalanceStatus。
- ExposureStatus。
- 数量和金额偏差指标。
- 风险事件。
- 执行质量明细。
- 实际价差损益和交易成本。

### 15.6 AdjustmentEntry

正式调整至少记录：

- 原因和证据。
- 目标 StrategyInstance 和期间。
- 关联订单、成交、费用或对账差异。
- 金额、币种和方向。
- 创建人和审批。
- 生效、替代和撤销关系。

### 15.7 PnLResult

至少包含：

- pnlResultId。
- StrategyVersionId 和 StrategyInstanceId。
- 统计期间和 businessDate。
- 报告币种。
- 累计总损益。
- 跨所价差损益。
- 累计交易成本及明细。
- 已确认调整项。
- 数据截止时间。
- EconomicEvent 截止位置。
- 汇率来源和时间。
- 计算版本。
- DataQualityStatus 和 ReconciliationStatus。
- 估算、已核对或已结算属性。

## 16. 账户资金

### 16.1 合并总览

- 策略分配资金。
- 两端合并权益。
- 合并可用资金。
- 总保证金和资金占用。
- 两端持仓统一黄金数量和名义价值。
- 资金使用率。
- 策略净值和回撤。
- 风险、数据质量和对账状态。

### 16.2 Crypto 账户

- Venue、Account 和账户模式。
- Balance、Equity 和 Available Funds。
- Margin Used 和 Available Margin。
- 永续持仓和统一黄金数量。
- Funding 和交易费用。
- 强平或风险距离，数据源支持时。

### 16.3 MT5 账户

- Broker、Account、Terminal 和 Worker。
- Balance、Equity、Free Margin 和 Margin Level。
- XAUUSD Position 和 lot。
- 统一黄金数量和名义价值。
- Commission、Swap 和未实现损益。
- Terminal、AutoTrading 和同步状态。

### 16.4 双端资金风险

- 单端保证金不足。
- Crypto 与 MT5 资金失衡。
- 无法及时划转或补充保证金。
- USDT 或结算币种异常。
- 单一平台、经纪商或账户集中度。

## 17. 风险、异常与人工处理

### 17.1 主要风险

- 价差继续扩大。
- 两端市场流动性差异。
- 市场开放时间不一致。
- Crypto 或 MT5 单腿成交。
- 报价延迟和时间不同步。
- USDT／USD 换算异常。
- Symbol Mapping 或 ContractSpecification 错误。
- MT5 lot 和 Crypto 数量取整偏差。
- Crypto Funding 或 MT5 Swap 不利变化。
- MT5 保证金和强平风险。
- Gateway、Runtime、Worker 或 Terminal 故障。
- 经纪商、交易所、托管和对手方风险。
- 外部手工订单造成持仓变化。

### 17.2 风险指标候选

- 当前价差和历史分位。
- 价差变化速度。
- 两端报价时间差。
- 两端订单簿或流动性。
- 配平偏差和单腿暴露持续时间。
- Crypto 和 MT5 保证金率。
- Funding 和 Swap 预估。
- USDT／USD 偏离。
- Gateway／Runtime／Worker Ready 状态。
- 对账差异数量和金额。

具体阈值由 StrategyVersion 和 RiskRule 维护。

### 17.3 人工操作

在授权范围内可以：

- 撤销一端或两端未成交订单。
- 停止未完成批次。
- 补对冲或重新配平。
- 紧急减小单腿暴露。
- 关闭一端或两端持仓。
- 确认外部手工订单归属。
- 处理结果未知。
- 请求数据修正或接受差异。

所有人工操作必须保留原因、操作人、对象版本、审批和最终结果。

## 18. 对账与数据质量

### 18.1 对账范围

至少覆盖：

- Crypto Order 与平台 Order。
- Crypto Trade／Fill 与平台 Fill。
- MT5 Order／Deal 与平台 Order／Fill。
- Crypto Position 与平台持仓。
- MT5 Position 与平台持仓。
- 两端 Balance／Margin。
- Crypto FundingSettlement。
- MT5 Commission 和 Swap。
- Symbol Mapping 和 ContractSpecification。
- PnLResult 与 EconomicEvent 完整度。

### 18.2 外部手工订单

- Crypto 或 MT5 外部手工订单必须被识别。
- 未归属订单进入 `unallocated`／`unverified` 或等价状态。
- 不得自动强行归属某个 StrategyInstance。
- 人工归属需要权限、证据和审计。
- 手工订单改变持仓后应重新计算配平、风险和 PnL。

### 18.3 差异处理

- 优先补查询和重新同步。
- 保留原始外部状态和错误码。
- 不无痕覆盖订单、成交、持仓和费用。
- 正式修正通过 DataCorrectionRecord 或 AdjustmentEntry。
- 影响 PnL 时产生新计算版本。
- 数据不完整时正式统计显示质量和对账状态。

## 21. 实现能力依赖与外部组件候选

本节只描述能力候选，不改变策略业务定义，也不代表已批准采用具体仓库或版本。

### 21.1 平台必须自建

- Strategy、ExecutionBatch 和 ExecutionPlan 业务权威。
- Crypto 与 MT5 跨 Runtime 协调。
- Instrument、ContractSpecification 和 Symbol Mapping。
- 黄金数量、lot、合约乘数和币种标准化。
- 平台 Order、Fill、Position 和 ExternalReference。
- 配平、暴露、残腿和人工处理。
- EconomicEvent、PnLResult 和跨所价差归因。
- RiskDecision、Reconciliation 和数据质量。

### 21.2 vn.py 候选能力

可以研究封装或参考：

- EventEngine：Runtime 内部事件驱动。
- MainEngine：Gateway 和 Engine 宿主。
- OmsEngine：Runtime 当前订单、成交和持仓缓存。
- BaseGateway：Gateway Adapter 模式参考。
- SpreadTrading：自定义价差、合成行情、主动腿／被动腿和成交驱动对冲思路。
- AlgoTrading：TWAP、Sniper、Iceberg、BestLimit 等低层订单算法。
- RiskManager：低层订单频率、数量和流控检查。
- RPC：跨进程通信 PoC 候选之一。

边界：

- vn.py SpreadTrading 不能直接取代平台 ExecutionBatch 和跨 Runtime 业务编排。
- Crypto 与 MT5 分处不同进程、Worker 或状态模型时，需要平台自有 Command／Event 和恢复机制。
- OmsEngine 只作为运行缓存，不能成为永久订单、成交和持仓权威。
- vn.py 不拥有策略损益、权限、审批、对账和正式修正。

### 21.3 Crypto 组件候选

- CCXT：统一市场元数据、行情、Funding、订单和账户接口候选。
- 交易所官方 API／SDK：私有订单、成交、账户、FundingSettlement 和恢复的权威接入候选。
- 成熟 vn.py Crypto Gateway：按单个交易所、版本、许可证和维护状态独立评估。

所有外部数据通过平台 Gateway Port 和 Adapter 转换，不能直接成为 Domain Model。

### 21.4 MT5 组件候选

- 官方 MetaTrader5 Python 包：基础访问和下单查询主候选。
- aiomql：异步包装、初始化、重试、Session、账户、订单、持仓和历史查询的设计参考或局部封装候选。
- vn.py Gateway 模式：MT5 Gateway 统一接口设计参考。
- 自建 MT5 Worker 和 Supervisor：账户、Terminal、进程、凭证、日志和恢复隔离。

aiomql 的 Bot、Strategy、RAM、SQLite 结果库等高层框架不默认作为平台策略、风险和账本权威。

### 21.5 SpreadTrading 复用判断

对当前 Crypto—MT5 场景，初步建议：

- 复用其价差定义、主动腿／被动腿、成交驱动数量和算法思想。
- 可在单一 Runtime 内 PoC 部分 Spread Leg 工具。
- 不直接使用其策略和持仓对象作为平台业务对象。
- 不让其自行跨两个独立 Runtime 形成第二套 ExecutionBatch。
- 必须验证暂停、恢复、部分成交、结果未知和对账能力。

## 22. 明确不包含

- 海内外价差中的国内期货和完整汇率损益模型。
- 未确认的新资产、新 Token 和新 MT5 产品自动通用化。
- 通过前端分别下单并拼接双腿。
- 无稳定 ID 的外部订单作为正式平台记录。
- 把常见 MT5 合约规格硬编码为所有经纪商事实。
- 无提示使用 USDT＝USD 永久假设。
- 将执行偏差或配平误差设为一级 PnL 归因。
- 将外部组件对象作为平台业务权威。
- 在本文确定具体仓库最终采用、Fork 或版本锁定。

## 23. 可测试验收标准

### 23.1 价差和数据

- `XAUTUSDT.P - XAUUSD` 在图表、统计、执行和 PnL 中使用同一标准化定义。
- Crypto 与 MT5 报价单位、币种、合约乘数和时间口径可追溯。
- USDT／USD 假设或汇率来源明确。
- Symbol Mapping 和 ContractSpecification 有版本和质量状态。
- 报价时间差超限时价差失效并阻止正式执行。

### 23.2 执行

- Crypto 与 MT5 两腿由同一 ExecutionBatch 组织。
- 两腿可以分布在不同 Runtime／Worker，但使用统一业务身份。
- Order 在外部提交前具有稳定平台身份。
- 部分成交、拒单、撤单、结果未知、未配平和单腿暴露可表达。
- MT5 Order、Deal、Position 和 Crypto Order、Trade、Position 正确映射。
- 页面或 Runtime 重启后可通过 Query、补查询和对账恢复。

### 23.3 PnL

- 一级归因为跨所价差损益、累计交易成本和已确认调整项。
- Crypto 手续费、Funding、MT5 Commission、Swap 和已确认滑点可以穿透。
- 执行偏差作为执行质量指标，不建立独立一级 PnL。
- 不设置配平误差一级归因。
- 累计总损益与 EconomicEvent、归因和 AdjustmentEntry 可核对。

### 23.4 账户、风险和对账

- Crypto 与 MT5 账户资金和保证金可比较且不混淆。
- 两端统一黄金数量、名义价值和偏差清晰。
- 外部手工订单可检测、隔离和人工归属。
- Order、Fill／Deal、Position、Balance、Funding、Commission 和 Swap 可对账。
- 差异和修正不无痕覆盖原始事实。

### 23.5 外部组件边界

- vn.py SpreadTrading 只作为低层能力或设计参考，不拥有平台 ExecutionBatch。
- MetaTrader5／aiomql、CCXT 和官方 SDK 均通过 Adapter 接入。
- Runtime OMS 不成为永久账本。
- 具体采用经过 PoC、许可证、安全、恢复和对账评审后形成 ADR。
