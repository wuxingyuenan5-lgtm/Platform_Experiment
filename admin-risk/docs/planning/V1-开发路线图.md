# V1 开发路线图

状态：`draft`  
产品基线：Platform V5  
架构版本：Platform V6 Simplified  
文档层级：执行计划草案  
更新日期：2026-07-19

## 1. V1 目标

V1 不追求完整大平台一次性落地，只追求两条策略链路能被真实管理、查询、对账和复盘：

```text
资费套利完整闭环
+
跨所价差完整闭环
```

完成后，策略管理应能看到资金、账户、订单、成交、持仓、费用、PnL 和固定时间净值。

## 2. 阶段划分

| 阶段 | 目标 | 完成标准 |
|---|---|---|
| P0 文档和边界统一 | 统一参考代码采用、V1 范围、架构边界 | 入口文档、参考矩阵、目标架构和本路线图一致 |
| P1 后端最小骨架 | 让 Platform Backend 成为业务权威 | Strategy、Account、Instrument、Order、Fill、Position、PnL 最小表和 API 可用 |
| P2 Runtime 最小闭环 | 让命令能进入独立执行进程 | TradeCommand -> Runtime -> Fake Gateway -> Event -> Backend 可恢复 |
| P3 策略管理最小查询 | 让前端不再依赖核心 Mock | 订单、成交、持仓、PnL、净值快照可在页面查询 |
| P4 Crypto Paper PoC | 资费套利进入真实 API 模拟盘/测试盘 | 首个 Crypto Venue 可下单、撤单、查订单、查成交、查 Funding/费用 |
| P5 资费套利闭环 | 资费套利形成策略级结果 | Funding、费用、持仓、PnL、StrategyNavSnapshot 可追踪 |
| P6 MT5 Demo PoC | 跨所价差具备 MT5 腿 | MT5 Order、Deal、Position、Swap、Account 快照可进入平台 |
| P7 跨所价差闭环 | Crypto 腿 + MT5 腿形成管理闭环 | 双腿订单、成交、持仓、费用、Swap、PnL 和净值可查询 |
| P8 风险、对账、审计 | 降低真实 API 链路风险 | result_unknown、重复命令、持仓差异、服务异常可处理 |

- ContractSpecification
- TradeCommand
- ExecutionBatch
- Order
- Fill / Deal
- PositionSnapshot
- BalanceSnapshot

优先 API：

- 审计基础字段。

## 5. P2：Execution Runtime 最小闭环

Runtime 必须保持独立进程。

最小链路：

```text
TradeCommand
-> Runtime Command
-> Fake Gateway
-> Runtime Event
-> Order / Fill / Position / EconomicEvent
```

必须支持：

- 重复命令不重复下单。
- Runtime 执行前写 Journal。
- Backend 重复事件去重。
- `result_unknown` 进入查询和人工处理状态。
- Runtime 健康状态可查询。

## 6. P3：策略管理最小查询

前端先做“业务验收面板”，不是大改 UI。

优先页面：

- 策略实例详情。
- 账户绑定。
- 订单和成交。
- 当前持仓。
- Funding / Swap / 费用事件。
- PnL 结果。
- 固定时间净值快照。
- Runtime / Gateway 状态。

页面规则：

- 前端不直接计算正式净值。
- 预览数据必须标注为预览。
- 交易模式必须明确显示：Simulation / Paper / Live。
- Live 未开放前，不出现误导性的真实资金执行入口。

## 7. P4：Crypto Paper PoC

首个 Crypto Venue 需要单独确认。建议优先从一个你最可能真实使用、API 文档和测试环境最稳定的交易所开始。

PoC 范围：

- API 认证。
- Market / Instrument 元数据。
- Ticker / OrderBook。
- 下单、撤单、查单。
- 成交历史。
- Balance / Position。
- Funding Rate。
- Funding Settlement 或账户账本。
- Client Order ID。
- 限频和错误码。
- 断线后补查询。

验收标准：

- 外部订单状态能稳定映射到平台订单状态。
- 结果未知能通过外部查询恢复。
- Funding / 费用能进入 EconomicEvent。
- 凭证不进入代码和日志。

## 8. P5：资费套利完整闭环

资费套利 V1 闭环：

```text
行情 / Funding
-> 策略实例
-> 交易命令
-> Crypto Gateway
-> Order / Fill
-> PositionSnapshot
-> Funding / Fee EconomicEvent
-> PnLResult
-> StrategyNavSnapshot
```

验收标准：

- 至少一个策略实例跑通。
- 固定时间生成净值快照。
- Funding、费用、交易损益可分开看。
- 页面能查询完整链路。
- 对账差异不被静默覆盖。

## 9. P6：MT5 Demo PoC

优先采用官方 MetaTrader5 Python 包，PyTrader 只作为备选。

PoC 范围：

- MT5 初始化和登录。
- SymbolInfo。
- AccountInfo。
- OrderSend。
- Orders 查询。
- Deals 历史。
- Positions 查询。
- Commission / Swap / Profit。
- Magic Number / Comment。
- 手工订单识别。
- Worker 重启恢复。

验收标准：

- MT5 Deal 能进入平台 Deal / Fill。
- Position 能进入 PositionSnapshot。
- Swap 和费用能进入 EconomicEvent。
- MT5 Demo 账户异常不会影响 Platform Backend。

## 10. P7：跨所价差完整闭环

跨所价差 V1 闭环：

```text
Crypto 腿
+
MT5 腿
-> ExecutionBatch
-> 双腿 Order / Fill / Deal
-> 双端 PositionSnapshot
-> Fee / Swap EconomicEvent
-> PnLResult
-> StrategyNavSnapshot
```

验收标准：

- 双腿订单可以归属到同一个 ExecutionBatch。
- 单腿失败、部分成交、结果未知能被表达。
- 持仓差异可以进入人工处理。
- PnL 能区分 trading、fees、swap。
- 策略管理页面能看完整结果。

## 11. P8：风险、对账、审计

优先做轻量但有效的控制：

- 全局交易模式门禁。
- Gateway 能力状态。
- 单策略最大下单金额。
- 单账户最大暴露。
- 单腿残留暴露提醒。
- 重复命令拦截。
- `result_unknown` 查询和人工处理。
- 订单、成交、持仓定时对账。
- 关键操作审计。
- 服务健康检查和通知。

不做：

- 完整基金会计。
- 投资人权限。
- 复杂审批流。
- CTP。
- 金融 AI 分析。

## 12. 当前优先级

下一步正式执行时，优先顺序是：

```text
1. P1 后端最小骨架
2. P2 Runtime + Fake Gateway
3. P3 策略管理最小查询
4. P4 Crypto Paper PoC
5. P5 资费套利闭环
6. P6 MT5 Demo PoC
7. P7 跨所价差闭环
8. P8 风险、对账、审计
```

P1 到 P3 是工程地基；P4 到 P7 是策略闭环；P8 是进入更真实交易前的保护层。
