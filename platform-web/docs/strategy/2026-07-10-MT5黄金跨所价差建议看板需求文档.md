# MT5 黄金跨所价差建议看板需求文档

## 1. 文档定位

本文档用于定义一套部署在 `MT5` 端的 `黄金跨所价差建议看板`。

该看板面向的核心场景是：

- 以 `海外黄金报价` 与 `MT5 端黄金报价` 的实时差值为核心，持续输出做多价差 / 做空价差建议
- 让交易员在 `MT5` 内部直接看到机会、风险、建议仓位、建议止盈止损、当前持仓状态与预警、下单操作
  

本文档默认先覆盖 `XAUUSD` 主场景。

-

## 2. 产品目标

### 2.1 核心目标

1. 在 MT5 中实时展示黄金跨所价差机会
2. 用统一口径计算价差、分位、波动、滑点、预期收益与风险
3. 输出明确的交易建议，而不是只给原始行情
4. 让交易员快速完成 `观察 -> 判断 -> 执行 -> 持仓跟踪 -> 平仓`
5. 为程序员提供足够细的字段、状态机、交互、刷新机制和异常处理要求

### 2.2 非目标

当前版本默认不做以下能力，除非你后续明确追加：

- 不默认自动下单
- 不负责复杂组合风控审批流
- 不承担完整研究平台职责，只聚焦 `黄金跨所价差建议`

---

## 3. 用户与使用场景

### 3.1 用户角色

1. 交易员
   关注是否有机会、建议方向、建议仓位、止盈止损、当前持仓盈亏
2. 风控/负责人
   关注信号是否可靠、执行是否偏离、风险是否超阈值、日志是否完整
3. 研发/运维
   关注数据连接是否正常、报价延迟、计算结果是否异常、看板是否卡死

### 3.2 典型使用流程

1. 打开 MT5 建议看板
2. 看板显示当前实时价差、分位位置、信号等级、建议动作
3. 若满足开仓条件，交易员查看建议手数、止盈止损、最大可接受滑点
4. 交易员手动在 MT5 下单，或点击“已执行”回写状态
5. 看板切换到持仓监控态，持续显示当前价差、浮盈浮亏、风险预警
6. 到达止盈/止损/时间退出条件后，看板提示平仓建议

## 4. 策略定义范围

### 4.1 当前建议覆盖的策略类型

本看板先覆盖一套最核心的 `黄金跨所价差双向回归策略`：

- `做多价差`
  解释：主观察价差低于合理区间下沿，预期价差向上修复
- `做空价差`
  解释：主观察价差高于合理区间上沿，预期价差向下修复

### 4.2 建议版本的核心原则

- 必须给出 `为什么建议`
- 必须给出 `建议是否可执行`
- 必须给出 `风险边界`
- 必须给出 `建议失效条件`

## 5. 价差口径定义

这一节必须在开发前锁死，否则后面信号、回测、实盘会全部口径错位。

### 5.1 主要行情腿

- 主腿：外部黄金报价源
  可选来源：
  - Bybit `XAUTUSDT.P`
  - 其他数字黄金或外部黄金报价
- 对冲腿：MT5 `XAUUSD`

### 5.2 价差定义

建议同时计算并显示两套价差：

1. `做多价差`
   公式：`主腿 Ask - MT5 Bid`
   含义：按最保守可成交口径，衡量“买主腿、卖对冲腿”或对应回归结构的进入成本

2. `做空价差`
   公式：`主腿 Bid - MT5 Ask`
   含义：按最保守可成交口径，衡量“卖主腿、买对冲腿”或对应回归结构的进入成本

### 5.3 展示口径

前端必须同时展示：

- 主腿 `Bid / Ask / Mid`
- 对冲腿 `Bid / Ask / Mid`
- 做多价差
- 做空价差
- 中间价差 `MidSpread`
  公式：`主腿 Mid - 对冲腿 Mid`

### 5.4 汇率与单位

若主腿与 MT5 腿币种或报价单位不一致，必须先转换再算价差。必须明确：

- 是否需要 `USD/CNH`
- 是否需要 `盎司 -> 克`
- 是否需要 `合约乘数`
- 是否需要 `点值`

建议系统内保留以下字段：

- `price_unit`
- `contract_multiplier`
- `tick_size`
- `tick_value`
- `fx_rate`
- `normalized_spread`

## 6. 看板总体结构

MT5 建议看板建议采用 `上中下三层结构`。

### 6.1 顶部区：市场与系统状态

顶部固定显示，不滚动。

包含：

- 面板标题：`黄金跨所价差建议看板`
- 策略状态：观察中 / 待开仓 / 持仓中 / 待平仓 / 风险冻结 / 数据异常
- 主腿标的
- 对冲腿标的
- 当前连接状态
- 主腿延迟
- MT5 行情延迟
- 最近刷新时间
- 当前账户

### 6.2 中部区：建议核心区

这是交易员第一眼必须看的区域。

包含：

- 当前实时价差卡片
- 分位与历史位置卡片
- 建议动作卡片
- 建议仓位卡片
- 风险提示卡片

### 6.3 底部区：图表与明细区

包含：

- 实时价差走势图
- 历史统计
- 当前持仓表
- 信号日志表
- 预警日志表

## 7.3 模块 C：建议动作卡

这是本产品最重要的模块。

### 7.3.1 输出内容

- 当前建议：观望 / 开多价差 / 开空价差 / 减仓 / 平仓 / 禁止交易
- 建议等级：弱 / 中 / 强 / 极强
- 建议理由 1
- 建议理由 2
- 建议理由 3
- 信号生成时间
- 有效期倒计时

### 7.3.2 建议动作规则

必须至少支持以下动作状态：

- `观望`
- `关注做多价差`
- `确认开多价差`
- `关注做空价差`
- `确认开空价差`
- `持仓继续`
- `建议减仓`
- `建议平仓`
- `风险冻结`

### 7.3.3 建议文案要求

每次建议必须可解释，示例：

- 当前做空价差处于过去 90 日 92% 分位，且 5 分钟斜率转弱，满足做空价差观察条件
- 主腿与 MT5 腿报价延迟均低于阈值，流动性正常，可执行性通过
- 当前滑点估计偏高，虽然信号成立，但仅建议半仓执行

### 7.3.4 交互

- 点击“展开理由”显示详细因子分解
- 点击“复制建议”复制文字版建议给交易员
- 点击“标记已执行”将状态切换为持仓监控态

## 8. 状态机设计

程序员必须按状态机开发，不能只靠按钮堆逻辑。

### 8.1 主状态

- `idle` 观察中
- `watch_long` 关注做多价差
- `watch_short` 关注做空价差
- `ready_long` 确认可开多价差
- `ready_short` 确认可开空价差
- `position_long` 已持有做多价差
- `position_short` 已持有做空价差
- `exit_ready` 满足退出条件
- `risk_freeze` 风险冻结
- `data_error` 数据异常

### 8.2 状态切换条件

必须由以下维度驱动：

- 价差阈值
- 分位阈值
- 延迟阈值
- 滑点阈值
- 保证金阈值
- 人工执行确认

### 8.3 状态切换示例

- `idle -> watch_short`
  当前做空价差达到观察阈值
- `watch_short -> ready_short`
  分位、波动、延迟、滑点同时通过
- `ready_short -> position_short`
  用户点击已执行或系统接收到持仓回写
- `position_short -> exit_ready`
  到达止盈、止损或时间退出
- `任意状态 -> risk_freeze`
  数据延迟、滑点失控、账户风险超限

## 9. 建议信号规则

## 9.1 必须拆成三层

1. `机会层`
   当前价差是否偏离
2. `确认层`
   偏离是否具有回归价值
3. `执行层`
   当前是否真的适合下手

## 9.2 建议字段

- `signal_direction`
- `signal_strength`
- `signal_score`
- `entry_spread`
- `target_spread`
- `stop_spread`
- `expected_holding_minutes`
- `execution_allowed`
- `execution_reason`

## 9.3 最低可行规则建议

第一版建议先用可解释规则，不建议一开始就上黑箱模型。

例如：

- 分位条件
- Z-Score 条件
- 短周期斜率条件
- 波动率过滤
- 点差过滤
- 延迟过滤

## 11. 数据输入与刷新机制

## 11.1 输入源

至少包含：

- MT5 本地行情
- 外部主腿行情
- 账户信息
- 当前持仓
- 历史成交

## 11.2 刷新频率

建议：

- 行情刷新：1 秒内
- 建议信号刷新：1 秒内
- 账户与持仓刷新：3 到 5 秒
- 统计重算：5 到 10 秒

## 11.3 数据异常定义

以下任一情况触发异常：

- 行情时间戳倒退
- 超过刷新阈值未更新
- Bid 大于 Ask
- 汇率缺失
- 持仓回写失败

---

## 12. MT5 端交互要求

这部分是给程序员最容易漏掉的。

## 12.1 看板形态

建议作为 `MT5 图表附着面板` 或 `独立浮窗面板`。

要求：

- 不遮挡主图关键区域
- 支持拖动位置
- 支持最小化
- 支持固定在右侧

## 12.2 按钮

第一版只建议保留以下按钮：

- 手动刷新
- 复制建议
- 标记已执行
- 标记已平仓
- 展开日志
- 参数查看

不建议第一版直接给“自动开仓”按钮。

## 12.3 声音与提醒

- 信号出现时可提示音
- 风险冻结时必须强提醒
- 可设置静音时段

---

## 13. 视觉与优先级要求

## 13.1 视觉原则

- 第一屏必须先看到结论，再看到解释
- 风险提示优先级高于统计分析
- 有持仓时，持仓模块优先级高于研究模块

## 13.2 数值颜色

- 做空价差机会：红色偏暖
- 做多价差机会：绿色偏冷
- 中性观察：灰蓝
- 风险冻结：高亮红

## 13.3 信息密度

- 顶部必须紧凑
- 中部建议区必须大字号
- 底部图表和明细允许高密度

---

## 14. 异常与容错

## 14.1 异常场景

- 外部行情断流
- MT5 行情断流
- 账户读取失败
- 当前持仓无法识别
- 计算结果出现 NaN

## 14.2 处理方式

- 面板不能崩
- 所有异常必须可见
- 异常期间禁止继续给出强执行建议
- 日志必须记录异常开始和恢复时间

## 18. 建议给程序员的实现口径

建议程序员按以下分层开发：

1. 行情层
   负责接行情、统一时间戳、清洗异常
2. 计算层
   负责价差、分位、波动、仓位、止盈止损
3. 信号层
   负责输出建议与状态机
4. 展示层
   负责 MT5 面板 UI
5. 日志层
   负责记录事件与调试

不要把计算逻辑写死在界面刷新函数里。

## 19. 我给你的落地建议

如果你是要先交给程序员开工，最稳的做法不是直接让他做“自动交易”，而是先做：

1. `建议看板 V1`
   先把实时价差、建议、风控、持仓跟踪做扎实
2. `执行回写 V1`
   支持交易员手动标记已执行、已平仓
3. `半自动执行 V2`
   再决定是否接 MT5 一键下单

这样能最大限度避免第一版就把风险和复杂度拉满。
