## 1. 文档定位

本文定义抄底策略的业务定位、策略身份、信号与真实交易关系、外部执行来源、数据导入、订单成交与持仓归属、EconomicEvent、损益统计、账户资金、风险、对账、数据质量、策略管理 Read Model、外部组件候选和验收标准。

当前抄底策略不通过平台交易模块下单。`platform.enabled = false` 是正式产品设计，不是待补页面。

V1 只做策略管理入口和外部来源占位，不建设完整外部导入、Signal、TradeCycle、止盈止损归因和正式 PnL 体系。没有真实外部数据或人工确认来源时，页面只能显示 `missing`、`not_connected`、`unverified` 或等价状态。

本文必须保证：

- 信号记录不等于真实订单。
- 外部订单不能只因为时间接近就自动归属于本策略。
- 策略规则未确认时，不在页面或代码中虚构公式和阈值。
- 外部执行数据进入策略管理前具有来源、质量、归属和对账状态。

## 2. 策略定位与核心约束

抄底策略是根据价格位置、回撤、波动、成交量、估值或其他已确认条件，在目标标的出现低位机会时建立方向性仓位的策略。

当前正式约束：

1. 当前只进入策略管理，不进入交易平台。
2. 当前执行来源为外部系统、交易终端、文件或人工记录。
3. 方向性风险是策略核心风险，不能按套利策略展示为中性敞口。
4. SignalRecord、Order、Fill、Position 和 ExitRecord 必须分别表达。
5. 策略损益使用实际订单、成交、持仓、费用和正式调整计算。
6. 未确认的信号规则、仓位规则和止盈止损规则只作为未决事项。
7. 外部交易归属需要稳定标识、账户绑定或人工确认，不能仅用 symbol 和时间猜测。

## 3. 产品能力

| 能力 | 是否属于当前正式范围 |
|---|---:|
| 交易平台·行情分析 | 否 |
| 交易平台·交易执行 | 否 |
| 策略管理·策略损益 | 是 |
| 策略管理·账户资金 | 是 |
| 策略管理·订单信息 | 是 |
| SignalRecord 查询 | 是，数据源具备时 |
| 外部数据导入 | 是 |
| 自动信号引擎 | 当前否 |
| 自动下单 | 当前否 |

V1 阶段，抄底只要求进入策略管理并保留外部数据占位：展示 StrategyInstance、账户绑定、外部来源状态、最近数据时间、基础账户／持仓／订单占位和 DataQualityStatus。完整 SignalRecord、ImportBatch、TradeCycle、退出原因、外部订单自动归属和正式 PnL 归因不作为 V1 必做项。

V1 不展示正式 PnL、胜率、盈亏比、TradeCycle、退出原因统计和信号命中率，除非底层订单、成交、持仓、费用、Signal 或人工确认记录已经接入并完成最小质量标记。不得使用 Mock、样例或前端静态数据包装成真实表现。

## 4. 核心用户问题

### 4.1 策略损益

- 策略累计和区间收益是多少？
- 已实现和未实现损益分别是多少？
- 哪些标的、账户和持有周期贡献最大？
- 胜率、盈亏比、净值和回撤如何？
- 交易成本消耗多少？
- 计划退出、止盈、止损和人工退出分别产生什么结果？
- 当前统计是否基于完整且已对账的外部数据？

### 4.2 账户资金

- 当前为策略分配多少资金？
- 当前持仓市值、仓位利用率和可用资金如何？
- 单标的、行业或相关资产集中度是否过高？
- 当前回撤和风险状态如何？
- 外部账户是否还有无法归属的持仓或订单？

### 4.3 订单、信号与持仓

- 当前持有哪些标的？
- 哪个 SignalRecord 与某笔交易有关？
- 实际订单和成交由哪个外部系统产生？
- 止盈、止损或人工退出是否按计划执行？
- 是否存在人工加仓、减仓或策略外交易？
- 外部订单、成交和持仓是否已对账？

## 5. 策略身份、版本与实例

### 5.1 StrategyDefinition

稳定定义：

- `strategyId = dip`。
- 正式名称：抄底。
- 执行类型：外部或人工执行策略。
- 腿模型：单腿方向性策略。
- 当前产品能力：仅策略管理。

### 5.2 StrategyVersion

每个正式版本至少可以记录：

- 适用市场和标的范围。
- 信号定义和版本，确认后。
- 入场条件和失效条件。
- 仓位计算方法。
- 加仓、减仓和最大持仓规则。
- 止盈、止损和时间退出规则。
- 基准和绩效计算口径。
- 费用和 PnL 口径。
- 风险指标和限制。
- 数据来源和质量门槛。
- 生效时间、审批和替代关系。

未确认字段可以为空或标记 `unconfirmed`，不得使用前端默认值伪装为正式策略版本。

### 5.3 StrategyInstance

至少表达：

- `strategyInstanceId`。
- StrategyVersionId。
- DeploymentEnvironment 和 TradingMode，外部事实也需要环境语义。
- AccountId 或账户集合。
- 适用市场和 Instrument 范围。
- 资金分配和风险范围。
- 外部执行来源。
- 当前状态。
- 数据截止时间和对账状态。

### 5.4 StrategyAccountBinding

至少记录：

- AccountId。
- 账户用途。
- 外部平台或终端。
- 允许归属的市场和 Instrument。
- 数据来源和同步方式。
- 绑定生效和失效时间。
- 是否允许自动归属。
- Magic Number、Tag、Subaccount 或其他归属规则，适用时。

## 6. SignalRecord

### 6.1 业务定位

SignalRecord 表达某个策略版本在某一时刻产生的观察、候选机会或正式信号。

SignalRecord 不等于：

- TradeCommand。
- Order。
- Fill。
- Position。
- 保证已执行的交易。

### 6.2 核心字段

数据源支持时，至少包含：

- `signalId`。
- StrategyVersionId 和 StrategyInstanceId。
- InstrumentId。
- 信号类型。
- 方向。
- 发生时间和计算时间。
- 输入数据截止时间。
- 信号值和阈值。
- 目标价格或价格区间，适用时。
- 建议仓位或风险预算，适用时。
- 失效时间或失效条件。
- 数据来源和计算版本。
- DataQualityStatus。
- 人工确认状态，适用时。

### 6.3 信号与交易关联

允许的关联证据：

- 外部订单明确携带 signalId 或 strategyInstanceId。
- 专属账户或子账户。
- Magic Number、Client Order ID、Tag 或 Comment。
- 导入文件中的正式关联字段。
- 经授权人工确认的关联。

不允许只依据“相同标的且时间接近”自动形成正式归属。

## 7. 外部执行来源与数据进入

### 7.1 来源类型

- 经纪商或交易所 API。
- MT5 或其他交易终端。
- 文件导入。
- 人工录入。
- 其他已确认执行系统。

### 7.2 ExternalExecutionRecord

外部执行记录至少表达：

- externalExecutionRecordId。
- 外部来源和账户。
- 外部 Order／Trade／Position ID。
- 原始 symbol 和平台 InstrumentId。
- 方向、价格、数量和币种。
- 订单、成交和业务时间。
- 手续费和费用。
- 原始状态和平台状态。
- StrategyInstance 归属状态。
- SignalRecord 关联，适用时。
- ImportBatchId 或同步任务 ID。
- 数据质量和对账状态。

### 7.3 ImportBatch

文件或人工批量导入必须建立 ImportBatch：

```text
创建 ImportBatch
→ 保存原始来源
→ 解析和字段校验
→ Account／Instrument 映射
→ 重复和冲突检查
→ StrategyInstance 和 Signal 归属预览
→ 授权确认
→ 写入主责领域
→ 对账与 PnL 重算
→ 更新 Read Model
```

部分失败不得污染已确认历史记录。

### 7.4 归属状态

至少支持：

- `allocated`：已确认归属策略实例。
- `unallocated`：尚未归属。
- `unverified`：疑似归属但证据不足。
- `conflicted`：存在多个可能归属或数据冲突。
- `excluded`：确认不属于本策略。

具体状态名称进入公共状态规范后生效。

## 8. Order、Fill、Position 与退出记录

### 8.1 Order 与 Fill

- 每张外部 Order 保留外部 ID 和原始状态。
- 一张 Order 可以产生多笔 Fill。
- 取消订单不删除已发生 Fill。
- 重复导入不能重复增加成交数量。
- 手工订单和系统订单必须可区分。

### 8.2 Position

至少表达：

- positionId。
- StrategyInstanceId。
- AccountId。
- InstrumentId。
- 方向和数量。
- 平均成本或成本基础。
- 当前价格和估值时间。
- 原始和统一币种名义价值。
- 已实现和未实现 PnL。
- 关联 Signal、Order 和 Fill。
- 来源、质量和对账状态。

### 8.3 PositionLot／TradeCycle

为了统计胜率、盈亏比和持有期，可以建立 TradeCycle 或等价分析对象：

- 入场时间和价格。
- 加仓和减仓。
- 最大持仓。
- 出场时间和价格。
- 实现 PnL。
- 持有期。
- 退出原因。
- 关联 Signal 和订单成交。

该对象是派生分析结果，不修改底层 Order、Fill 和 Position 事实。

### 8.4 ExitRecord

退出原因可以包括：

- 计划止盈。
- 计划止损。
- 时间退出。
- 信号失效。
- 人工退出。
- 风险减仓。
- 数据无法确认。
- 其他正式原因。

退出原因需要来自外部系统字段、正式规则或人工确认，不能由前端仅根据盈亏方向猜测。

## 9. EconomicEvent 与损益

### 9.1 EconomicEvent

至少记录：

- Fill。
- TradingFee。
- Financing／Interest，适用时。
- Dividend／Distribution，适用时。
- FXConversion，适用时。
- ManualAdjustment。

### 9.2 PnLResult

至少包含：

- StrategyVersionId 和 StrategyInstanceId。
- 统计期间和 businessDate。
- 原始币种和报告币种。
- 累计损益。
- 已实现损益。
- 未实现损益。
- 累计交易成本。
- AdjustmentEntry。
- 数据截止时间。
- 计算版本。
- DataQualityStatus 和 ReconciliationStatus。

### 9.3 通用归因维度

按数据能力支持：

- Instrument 贡献。
- Account 贡献。
- 已实现和未实现。
- 交易成本。
- Signal 或入场原因。
- TradeCycle。
- 计划止盈。
- 计划止损。
- 人工退出。
- 持有期。

“止盈贡献”“止损损失”和“人工退出影响”需要依据正式 ExitRecord 或关联证据，不通过收益正负自动推断。

### 9.4 绩效指标

可以包括：

- 区间收益率。
- 日度、周度和月度收益。
- 策略净值。
- 当前和最大回撤。
- 胜率。
- 平均盈利、平均亏损和盈亏比。
- 持有期。
- 交易次数。
- 单标的贡献。
- 资金使用效率。

所有指标具有统计区间、计算版本、数据完整度和币种口径。

## 10. 账户资金

至少展示：

- 策略分配资金。
- Account Equity 和 Available Funds。
- 已用资金。
- 当前持仓市值和名义价值。
- 仓位利用率。
- 单标的、行业或资产类别集中度。
- 策略净值。
- 当前和最大回撤。
- 数据时间、质量和对账状态。

账户中存在无法归属的订单或持仓时，合并总览必须提示，不得将其自动纳入本策略。

V1 如需展示净值，只能显示 `estimated`、`missing`、`not_connected` 或 `unverified` 状态，不作为正式收益表现。未接入真实外部数据前，不计算或展示正式策略净值。

## 11. 风险、异常与人工处理

### 11.1 主要风险

- 抄底后价格继续下跌。
- 多标的同步下跌和相关性上升。
- 仓位、行业或单标的集中度过高。
- 止损未执行或执行延迟。
- 流动性不足和滑点扩大。
- 外部执行数据缺失、延迟或重复。
- 信号与真实交易无法对应。
- 人工加仓、减仓或退出偏离策略规则。
- 外部账户存在策略外持仓。
- 汇率、融资或公司行动数据缺失，适用时。

### 11.2 风险指标候选

- 当前回撤和最大回撤。
- 仓位利用率。
- 单标的和行业集中度。
- 相关资产总暴露。
- 单笔和累计亏损。
- 止损计划与实际执行差异。
- 数据延迟和对账差异。
- 未归属订单和持仓数量。

具体阈值由 StrategyVersion 和 RiskRule 维护。

### 11.3 人工处理

可以包括：

- 确认 Signal 与订单关联。
- 归属或排除外部订单和持仓。
- 补录退出原因。
- 请求数据修正。
- 接受对账差异。
- 创建 AdjustmentEntry。
- 标记某段数据不进入正式统计。

所有人工处理必须有原因、证据、操作人和审计。

## 12. 对账与数据质量

### 12.1 对账范围

至少覆盖：

- 外部 Order 与平台 Order。
- 外部 Trade／Fill 与平台 Fill。
- 外部 Position 与平台 Position。
- Balance 与账户数据。
- TradingFee 和其他 EconomicEvent。
- StrategyInstance 和 Signal 归属。
- PnLResult 与底层数据完整度。

### 12.2 差异类型

- 外部有订单，平台无记录。
- 平台有记录，外部未找到。
- 成交数量、价格或时间不同。
- 重复订单或成交。
- 持仓和余额不同。
- 费用缺失或币种错误。
- Signal 关联错误。
- 策略归属冲突。
- 退出原因缺失或冲突。

### 12.3 处理规则

- 优先重新同步和补查询。
- 不无痕覆盖原始事实。
- 人工归属、差异接受和修正需要权限与审计。
- 修正影响 PnL 时产生新计算版本。
- 数据不完整时正式指标和报表显示质量状态。

## 15. 实现能力依赖与外部组件候选

本节只描述候选能力，不改变策略业务定义。

### 15.1 平台必须自建

- StrategyVersion、StrategyInstance 和账户绑定。
- SignalRecord 和真实交易的关联模型。
- ExternalExecutionRecord、ImportBatch 和归属流程。
- 平台 Order、Fill、Position、TradeCycle 和 ExitRecord。
- EconomicEvent、PnLResult、数据质量和对账。
- 人工确认、修正和审计。

### 15.2 vn.py 候选能力

根据实际外部市场可以参考或封装：

- Gateway：外部账户、订单、成交和持仓接入。
- OmsEngine：Runtime 当前状态缓存。
- DataManager／DataRecorder：历史行情和文件导入参考。
- CTA／Portfolio 模块：策略回测和信号结构参考，只有策略规则确认后评估。

边界：

- 当前不使用 vn.py 自动运行抄底策略。
- vn.py Strategy、Order 和 PnL 对象不直接成为平台业务权威。
- 外部执行归属、SignalRecord、正式 PnL 和审计由平台维护。

### 15.3 MT5／Crypto 组件候选

外部数据来自 MT5 时：

- 官方 MetaTrader5 Python 包用于账户、Order、Deal、Position 和历史查询候选。
- aiomql 用于异步、重试、Session 和查询模式参考。
- Magic Number、Comment 和账户绑定用于归属证据。

外部数据来自 Crypto 时：

- CCXT 或交易所官方 API／SDK 用于订单、成交、账户和持仓接入候选。
- Client Order ID、Subaccount 和 Tag 用于归属证据。

### 15.4 Freqtrade 候选参考

可以参考：

- 策略参数版本。
- Signal、Trade 和运行状态区分。
- 回测与绩效指标。
- 禁止新开仓、暂停和恢复等运营思想。

当前不采用其 Bot、Trade 数据库或自动执行作为本策略平台权威。

## 16. 明确不包含

- 交易平台行情分析页。
- 交易平台执行页。
- 自动信号生成引擎。
- 自动下单和订单路由。
- 未确认的信号公式和阈值。
- 未接入真实外部数据时展示正式 PnL、胜率、盈亏比、TradeCycle 和信号命中率。
- 根据盈利或亏损方向自动推断退出原因。
- 根据时间接近自动归属外部订单。
- 将外部组件对象作为平台业务权威。
- 在本文确定具体仓库最终采用、Fork 或版本锁定。

## 17. 可测试验收标准

### 17.1 产品范围

- 抄底策略只出现在策略管理，不出现在交易平台。
- platform.enabled 固定为 false。
- 策略损益、账户资金和订单信息三类能力完整。

### 17.2 策略身份和信号

- StrategyVersion 和 StrategyInstance 可追溯。
- SignalRecord 与 Order／Fill／Position 分开。
- Signal 与真实交易关联具有稳定证据或人工确认。
- 未确认策略规则不会被硬编码为正式版本。

### 17.3 外部执行和数据

- 外部来源、Account、Instrument 和 ID 可追溯。
- ImportBatch 支持预览、重复检查、部分失败和审计。
- 未归属和冲突数据不会无提示进入策略统计。
- 外部 Order、Fill、Position、Balance 和 Fee 可以对账。

### 17.4 PnL 和管理视图

- 累计、已实现、未实现、交易成本、净值和回撤可核对。
- 胜率、盈亏比和退出原因基于 TradeCycle 与正式记录。
- 单标的、账户、Signal 和持有期可以穿透。
- PnLResult 具有数据截止时间、版本、质量和对账状态。

### 17.5 外部组件边界

- vn.py、MetaTrader5、aiomql、CCXT 和 Freqtrade 只作为接入或设计候选。
- 外部组件不拥有 Signal 归属、策略 PnL 和平台审计。
- 具体采用经过 PoC、许可证、安全和数据完整性评审后形成 ADR。

## 18. 未决事项

1. 正式标的、市场和账户范围。
2. 信号计算公式和 Signal 类型。
3. 入场、失效和时间窗口。
4. 仓位计算、加仓和减仓规则。
5. 止盈、止损和时间退出规则。
6. 最大持仓、仓位利用率和回撤限制。
7. 主要外部执行来源和数据接入方式。
8. Signal 与订单自动关联所需的正式字段。
9. TradeCycle 的开闭合并和部分退出规则。
10. 绩效基准和收益率分母。
11. 是否需要独立融资、股息或公司行动归因。
12. vn.py、MT5、Crypto 或其他外部 Adapter 的 PoC 范围。

未决事项不得由前端 Mock、固定常量或外部组件默认行为替代正式决策。

以上未决事项不阻塞资费套利和跨所价差 V1。抄底进入完整管理闭环前，必须先确认信号规则、外部执行来源、订单归属证据、退出原因和 PnL 口径。
