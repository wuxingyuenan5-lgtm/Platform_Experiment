## 1. 文档定位

本文定义海内外价差策略的业务目标、黄金核心场景、国内与海外市场结构、单位和汇率换算、期限结构、库存费、双腿执行、EconomicEvent、完整损益归因、账户资金、风险、对账、数据质量、策略管理 Read Model、外部组件能力依赖和验收标准。

本文是以下专项口径的唯一来源：

- 黄金海内外价差的单位、汇率和合约换算原则。
- 国内腿、海外腿及国内对冲持仓的业务角色。
- 累计总损益（含汇率）、累计损益（除汇率）、汇率损益和配平误差的四层结构。
- 累计损益（除汇率）的四项固定细分。
- 汇率损益的五项固定细分。
- 配平误差的两项固定细分。
- 各归因项之间禁止重复计算的边界。

通用交易命令、权限、状态、运行可靠性和页面共同规则以上位文档为准。

本文保留的是海内外价差的长期正式业务口径，不代表 V1 需要完整实现。V1 只落地分析、模拟、字段预留和策略管理展示骨架；真实国内交易、CTP、人民币汇率损益、完整四层 PnL、换月、平今平昨和结算单对账均不进入当前执行计划。

## 2. 策略定位与核心约束

海内外价差是通过国内市场与海外市场之间的价格关系、汇率换算、期限结构和持仓成本差异建立对冲头寸，获取海内外溢价回归、期限结构变化及库存费等结构性收益的多因素双腿策略。

当前正式研究和损益口径以黄金为主。

海内外价差不属于 V1 完整交易闭环。第一阶段只保留行情分析、模拟盘、字段预留和策略管理展示骨架；国内 Gateway、CTP、真实交易执行、人民币和汇率损益正式落地、完整四层 PnL、换月、平今平昨、结算单对账和配平误差计算均延后。若需要演示交易执行，只能使用 Simulation 或明确的外部记录模式，不能伪造真实国内订单和成交。

当前原则：

1. 国内和海外价格必须先统一单位、币种和合约数量。
2. 汇率是正式业务变量，不能只作为展示层换算。
3. 国内外市场交易日、交易时段和结算规则必须分别表达。
4. 海外库存费／Swap 的实际结算与预计值分开。
5. 期现价差与海内外溢价使用不同归因口径，避免重复。
6. 理论配平和实际持仓必须可追溯。
7. 配平误差是本策略正式损益结构的一部分，与资费套利和跨所价差不同。
8. 金、银、铜等其他标的只有在单位、合约、汇率、库存费和损益公式独立确认后才能启用正式统计。
9. 产品目标可以支持完整交易执行，但某一环境未接入国内 Gateway 时必须真实显示为分析、只读或外部记录模式。

## 3. 产品能力与接入状态

| 能力 | 目标产品范围 | 当前可按环境配置 |
|---|---:|---|
| 交易平台·行情分析 | 是 | 国内外数据可用时启用 |
| 交易平台·交易执行 | 是 | V1 仅 Simulation／record_external；正式执行依赖国内和海外 Gateway |
| 策略管理·策略损益 | 是 | 支持平台事实、接口同步和导入 |
| 策略管理·账户资金 | 是 | 支持平台事实、接口同步和导入 |
| 策略管理·订单信息 | 是 | 支持平台事实、接口同步和导入 |
| MT5 海外执行 | 是 | V1 可复用 MT5 Demo 能力观察或模拟，不形成海内外正式闭环 |
| CTP 国内期货执行 | 目标范围 | 当前可延后接入 |
| 国内现货自动执行 | 待具体接口确认 | 可先只读或导入 |
| 外部执行记录 | 是 | `record_external` 模式 |

V1 明确暂缓：

- CTP 和国内真实交易 Gateway。
- 国内现货自动执行。
- 人民币、USDCNY／USDCNH 和多币种正式会计落地。
- 累计总损益（含汇率）、汇率损益五项和配平误差两项的正式计算。
- 国内换月、平今平昨和结算单对账。
- 海内外价差 Live 交易和完整发布门禁。

四层 PnL、五项汇率损益和两项配平误差是长期正式口径，不作为 V1 计算验收项。V1 若展示相关区域，只能显示占位、模拟、估算或未接入状态，不能包装成正式结果。

页面必须根据 GatewayCapability 表达：

- `analysis_only`。
- `record_external`。
- `simulation`／`paper`。
- `live_execution`。

不得使用前端 Mock 成交替代未接入的国内交易能力。

## 4. 核心用户问题

### 4.1 行情分析

- 国内价格和海外价格按统一单位和汇率换算后的价差是多少？
- 当前使用的是 USDCNY、USDCNH 还是其他正式汇率？
- 当前海内外价差处于什么历史分位？
- 国内现货、国内期货和海外价格之间的期限结构如何？
- 海外库存费对持有收益有什么影响？
- 当前价差是否覆盖国内外手续费、滑点、库存费和资金成本？
- 国内和海外市场当前是否同时开放且报价可比？
- 当前数据是否完整、新鲜并经过正确换算？

### 4.2 交易准备与执行

- 国内腿和海外腿分别使用哪个账户、Gateway 和 Instrument？
- 国内数量、海外 lot 和黄金克／盎司如何换算？
- 当前汇率保护和最大允许报价时间差是多少？
- 采用并行、主动腿／被动腿还是顺序执行？
- 国内期货是否涉及开仓、平仓、平今和平昨？
- 两端实际持仓与理论配平关系如何？
- 是否出现单腿、汇率或配平风险？
- 国内 Gateway 未接入时，如何记录外部执行并进入对账？

### 4.3 策略管理

- 累计总损益（含汇率）是多少？
- 累计损益（除汇率）、汇率损益和配平误差分别是多少？
- 库存费、海内外溢价、期现价差和交易成本分别贡献多少？
- 汇率损益来自海外本金、库存费、国内持仓、海外持仓还是国内对冲持仓？
- 配平误差来自海外持仓还是国内对冲持仓？
- 国内外账户的资金、保证金、币种和持仓是否安全？
- 订单、成交、Swap、汇率和调整记录是否完整可追溯？

## 5. 策略身份、版本与实例

### 5.1 StrategyDefinition

稳定定义：

- `strategyId = domesticOverseas`。
- 正式名称：海内外价差。
- 执行类型：平台执行或外部记录均可。
- 腿模型：双腿，损益穿透可包含国内对冲持仓。
- 当前核心资产：黄金。
- 主要收益来源：海内外溢价、期现结构、库存费及相关汇率和配平归因。

### 5.2 StrategyVersion

每个正式版本至少记录：

- 适用资产和 Instrument 组合。
- 国内场景：SHFE、AU9999 或其他正式标的。
- 海外场景：MT5 XAUUSD 或其他正式标的。
- 国内外单位和合约乘数。
- 金衡盎司到克等转换常量和版本。
- 汇率品种、方向和价格口径。
- 理论配平公式和容忍范围。
- 国内对冲持仓的定义和用途。
- 执行模式和主动腿／被动腿规则。
- 最大订单规模、单腿暴露和最大残腿时间。
- 开仓、平仓、换月和调整政策。
- 库存费、期现价差和海内外溢价公式。
- 四层 PnL 归因和正负号规则。
- 数据质量和交易时段门槛。
- 生效时间、审批和替代关系。

### 5.3 StrategyInstance

至少表达：

- `strategyInstanceId`。
- StrategyVersionId。
- DeploymentEnvironment 和 TradingMode。
- 国内 Account、Gateway 和 Instrument。
- 海外 Account、MT5 Worker、Gateway 和 Instrument。
- 国内对冲账户或持仓来源，适用时。
- 实例资金和名义价值额度。
- 是否允许平台下单或仅记录外部执行。
- 当前运行、对账和数据质量状态。

### 5.4 StrategyAccountBinding

账户用途至少区分：

- `domestic_leg`。
- `overseas_leg`。
- `domestic_hedge`，适用时。
- `settlement`，适用时。
- `observation_only`，适用时。

绑定至少记录：

- AccountId。
- 市场、Gateway、Runtime／Worker。
- 允许的 Instrument 和动作。
- 账户币种。
- 额度和风险范围。
- TradingMode。
- 生效和失效时间。
- 平台执行、外部记录或只读能力。
- 审批和审计，适用时。

## 6. 市场、标的与业务场景

### 6.1 国内腿候选

- SHFE 黄金期货。
- AU9999 或其他已确认国内现货黄金。
- 其他国内期货、现货或对冲标的，需单独确认。

### 6.2 海外腿候选

- MT5 Broker 的 XAUUSD 或正式映射 symbol。
- 海外现货、CFD 或期货，需单独确认合约和损益口径。

### 6.3 当前正式场景

当前文档重点覆盖：

- `SHFE / XAUUSD`。
- `AU9999 / XAUUSD`。

不同场景必须具有独立 ScenarioId 或稳定配置，不能仅依赖展示名称。

### 6.4 Instrument 与 Symbol Mapping

每个 Instrument 至少包含：

- 市场和 Venue／Broker。
- 产品类型。
- 外部 symbol／合约代码。
- 基础资产和计价币种。
- 价格单位。
- 数量单位。
- 合约乘数。
- 最小数量和步进。
- Tick Size 和 Tick Value，适用时。
- 交易日历和交易时段。
- 到期和换月信息，期货适用时。
- 元数据版本和更新时间。

## 7. 单位、合约和汇率换算

### 7.1 统一价格单位

黄金场景候选统一单位：

```text
CNY per gram
```

海外 XAUUSD 常见原始单位为 USD per troy ounce，正式换算候选：

```text
normalized_overseas_price_cny_per_gram
= overseas_price_usd_per_oz
× fx_cny_per_usd
÷ grams_per_troy_ounce
```

其中：

- `grams_per_troy_ounce` 作为受控常量统一维护。
- `fx_cny_per_usd` 必须明确使用 USDCNY、USDCNH 或其他正式汇率。
- 公式和常量不能在多个前端组件中重复硬编码。

### 7.2 汇率方向

必须明确：

- 汇率品种。
- 国内币／海外币方向。
- Bid、Ask、Mid、结算价或其他口径。
- sourceTime、receivedAt 和 businessDate。
- 适用场景和数据质量。

页面和计算服务不得通过字段名称猜测乘除方向。

### 7.3 国内数量标准化

至少记录：

- 原始手数或数量。
- 合约乘数。
- 克、千克或其他单位。
- 标准化黄金克数。
- 取整规则。
- 合约版本。

### 7.4 海外数量标准化

至少记录：

- MT5 lot 或原始数量。
- Broker Contract Size。
- 金衡盎司等价数量。
- 克数等价数量。
- 取整规则和最小 lot。
- Symbol Mapping 和规格版本。

### 7.5 理论配平

理论配平必须以统一黄金数量、名义价值和汇率口径计算，至少表达：

- theoreticalDomesticQuantity。
- theoreticalOverseasQuantity。
- actualDomesticQuantity。
- actualOverseasQuantity。
- domesticHedgeQuantity，适用时。
- balanceDeviation。
- 目标容忍范围。
- 使用价格、汇率、乘数和时间。

## 8. 行情和数据需求

### 8.1 国内数据

- 国内现货或期货 Bid／Ask／Last。
- 期货合约信息、到期和换月。
- 期限结构和主次合约。
- 交易日、夜盘和休市。
- 国内账户、持仓、订单和成交。
- 手续费、保证金和结算数据。
- AU9999 等现货数据，适用时。

### 8.2 海外数据

- XAUUSD Bid／Ask 和 Tick 时间。
- 历史 K 线或 Tick，按研究需求。
- MT5 SymbolInfo 和 ContractSpecification。
- Account、Order、Deal、Position 和历史。
- Commission、Swap／OvernightFee。
- Broker、Terminal、Worker 和 Gateway 状态。

### 8.3 汇率数据

- USDCNY、USDCNH 或正式汇率品种。
- Bid／Ask／Mid／结算口径。
- 实时和历史序列。
- sourceTime、receivedAt 和质量。
- 异常、缺失和市场关闭状态。

### 8.4 期限结构和库存费

- 国内期货期限结构。
- 国内现货与期货关系。
- 海外 Swap 或库存费规则。
- 实际 Swap 结算记录。
- 持有天数和结算日历。
- 周三三倍或 Broker 特殊规则，只有正式确认后配置。

### 8.5 数据质量

至少检查：

- 国内、海外和汇率时间差。
- 单位和合约规格完整性。
- 汇率方向和口径。
- 交易日和自然日差异。
- 夜盘归属和 businessDate。
- 国内期货换月和合约状态。
- MT5 symbol 与 Broker 状态。
- Swap 规则和实际结算完整度。
- 订单、成交、持仓和结算数据缺口。

## 9. 行情分析与统计

### 9.1 页面结构

至少包含：

1. StrategyInstance、资产和场景上下文。
2. 国内、海外和汇率当前数据。
3. 换算后的海外价格。
4. 当前海内外价差。
5. 价差主图和历史统计。
6. 国内期现结构和期限结构。
7. 海外库存费和持有成本分析。
8. 交易时段和市场状态。
9. 预计收益、成本、汇率和资金影响。
10. 数据来源、时间、质量和计算版本。

### 9.2 当前海内外价差

概念表达：

```text
domestic_overseas_spread
= normalized_domestic_price
- normalized_overseas_price
```

必须记录：

- 国内价格口径。
- 海外价格口径。
- 汇率。
- 单位和乘数。
- sourceTime 和同步方法。
- 计算版本。

### 9.3 统计指标

至少支持：

- 当前值。
- 均值和中位数。
- 标准差。
- 10%、25%、50%、75%、90% 分位，按产品确认展示。
- 区间最大值和最小值。
- Z 值或偏离程度。
- 不同交易时段和交易日统计。
- 价差回归时间和持有期，具备正式口径时。

### 9.4 期限结构

根据场景展示：

- 国内现货与各期货合约价格。
- 近月和远月价差。
- 剩余天数。
- 年化升贴水。
- 换月影响。
- 海外库存费或期限成本。

### 9.5 预计收益

预计结果至少拆分：

- 预计海内外溢价变化。
- 预计期现价差变化。
- 预计库存费。
- 预计汇率影响。
- 预计交易成本。
- 预计配平偏差影响，作为风险情景而非实际已发生 PnL。

所有预计值明确持有期、汇率、退出条件和数据时间，不与实际 PnLResult 混用。

## 10. TradeIntent 与 ExecutionPlan

### 10.1 TradeIntent

至少包含：

- StrategyInstanceId。
- 开仓、平仓、调整、换月或紧急减险。
- 国内 Account、Gateway 和 Instrument。
- 海外 Account、MT5 Worker、Gateway 和 Instrument。
- 国内对冲账户或持仓角色，适用时。
- 两腿方向。
- 目标统一黄金数量和名义价值。
- 国内手数／数量和海外 lot。
- 汇率和换算版本。
- 目标价差和价格保护。
- 执行模式。
- 最大滑点、最大单腿暴露和残腿政策。
- 预计收益、成本、汇率、保证金和风险引用。

### 10.2 ExecutionPlan

候选模式：

- `parallel`。
- `active_passive`。
- `sequential`。
- `manual_confirmed`。
- `record_external`。
- `simulation`。

ExecutionPlan 至少记录：

- 主动腿和被动腿。
- 国内 Gateway 与海外 Worker 路由。
- 每腿订单政策。
- 国内开平和 Offset 语义，适用时。
- 数量换算和取整。
- 汇率保护和价格保护。
- 最大裸露时间。
- 部分成交、撤单和残腿处理。
- 换月或合约迁移规则，适用时。
- 人工确认和覆盖。
- 计划版本。

### 10.3 国内未接入时

国内 Gateway 未接入时：

- 行情分析可以继续使用正式数据源。
- 交易执行显示 `record_external`、Simulation 或不可用。
- 用户可以记录外部订单和成交，但必须建立 ImportBatch 或 ExternalExecutionRecord。
- 页面不得伪造 CTP OrderStatus 和 Fill。
- 页面不得伪造国内平今平昨、换月、结算单和真实国内成交回报。
- 国内外联合 PnL 必须标记数据来源和对账状态。

## 11. 执行前校验

除平台通用校验外，至少检查：

- StrategyVersion 和 StrategyInstance 有效。
- 国内、海外和汇率数据完整。
- 两端报价在新鲜度和最大时间差范围内。
- Instrument、合约乘数和 Symbol Mapping 有效。
- 国内交易日、夜盘和合约状态允许交易。
- 海外 MT5 Terminal、Worker 和 AutoTrading 满足要求。
- 国内 Account 和海外 Account 余额、保证金和权限满足要求。
- 国内开仓、平仓、平今和平昨语义有效，CTP 适用时。
- 国内数量和海外 lot 满足最小值、步进和目标配平。
- 汇率保护、最大滑点和目标价差满足条件。
- 当前无冲突的未完成 ExecutionBatch。
- RiskDecision、GlobalTradingBlock 和 ApprovalGrant 满足要求。

## 12. 执行、订单、成交与持仓

### 12.1 标准业务链路

```text
TradeIntent
→ TradeCommand
→ ExecutionBatch
→ ExecutionPlan
→ Domestic LegInstruction + Overseas LegInstruction
→ 预创建平台 Order
→ 国内 Gateway／外部记录 + MT5 Worker
→ Order／Trade／Deal／Fill 回报
→ Position 更新
→ 理论配平、实际配平、汇率暴露判断
→ 完成、异常、结果未知或人工处理
```

### 12.2 稳定身份

至少使用：

- tradeCommandId。
- executionBatchId。
- legInstructionId。
- platformOrderId。
- externalOrderId。
- tradeId／dealId／fillId。
- CTP OrderRef／Exchange OrderId，适用时。
- MT5 Magic Number／Comment，适用时。
- ImportBatchId／ExternalExecutionRecordId，外部执行时。

### 12.3 国内期货执行语义

- 开仓和平仓。
- 平今和平昨。
- 交易所和经纪商状态。
- 委托、撤单和成交回报。
- 夜盘和 tradingDay。
- 结算单和持仓核对。
- 合约到期和换月。

- lot、Contract Size 和部分平仓。

- Broker symbol 后缀。
- 外部手工订单。

- 实际国内持仓。
- 理论海外持仓。

## 13. 持有、换月、调整与平仓

### 13.1 持有期间

持续监控：

- 海内外价差。
- 汇率和汇率暴露。
- 国内期限结构和换月风险。
- 海外 Swap／库存费。
- 理论和实际配平。
- 国内外账户资金和保证金。
- 市场交易时段和节假日。
- Gateway、Worker 和数据质量。

### 13.2 换月

国内期货场景可能需要换月：

- 换月规则属于 StrategyVersion，不属于 Gateway 默认行为。
- 必须记录原合约、新合约、数量、价格、时间和换月成本。
- 换月产生新的 ExecutionBatch 或明确的 Migration Batch。
- 期现价差和海内外溢价归因必须避免重复。
- 换月前后理论配平和实际持仓可核对。

### 13.3 调整

调整场景包括：

- 汇率变化导致名义价值偏离。
- 国内或海外部分成交。
- MT5 lot 或国内手数取整。
- 国内合约换月。
- 保证金和风险需要减仓。
- 实际配平误差扩大。

调整必须产生正式 Command／ExecutionBatch，不能直接修改 Position。

### 13.4 平仓

平仓记录：

- 关闭原因和目标价差。
- 国内和海外目标及实际数量。
- 实际成交汇率。
- 关闭顺序和执行模式。
- 剩余持仓和对冲持仓。
- 实际成本、Swap 和最终 PnL。
- 对账和人工处理。

- Domestic Fill／Trade。

## 15. 策略损益总结构

### 15.1 四层结构

海内外价差使用：

1. 累计总损益（含汇率）。
2. 累计损益（除汇率）。
3. 汇率损益。
4. 配平误差。

核对关系：

```text
累计总损益（含汇率）
= 累计损益（除汇率）
+ 汇率损益
+ 配平误差
```

所有归因项使用统一正负号，成本通常为负。

### 15.2 防重复原则

- 同一价格变化不能同时进入海内外溢价和期现价差。
- 同一汇率变化不能重复进入多个汇率归因。
- 配平误差只计算理论与实际数量差异对应的非汇率损益。
- 已经进入交易成本的手续费和滑点不能再次进入配平误差。
- 海外 Swap 的原币收益与汇率折算影响必须拆分。
- AdjustmentEntry 不得掩盖底层数据缺失。

## 16. 累计损益（除汇率）

固定细分：

- 库存费累计收益（除汇率）。
- 海内外溢价损益。
- 期现价差损益。
- 累计交易成本。

### 16.1 库存费累计收益（除汇率）

表达海外持仓实际 Swap／库存费在原始币种产生的收益或成本，剔除从发生时到统一计价时的汇率变化影响。

数据来源优先为 MT5 Deal、Account History 或经正式确认的 Broker 结算记录。

### 16.2 海内外溢价损益

表达标准化国内价格与海外价格之间溢价变化带来的核心策略损益。

必须使用：

- 国内和海外实际持仓。
- 统一黄金数量。
- 固定汇率基准或除汇率计算口径。
- 开仓、估值或平仓价格。
- 计算版本。

### 16.3 期现价差损益

表达国内或海外期货、现货和期限结构变化带来的损益。

至少明确：

- 哪一腿具有期货和现货关系。
- 近月、远月或现货基准。
- 剩余期限和换月。
- 与海内外溢价损益的分界。

### 16.4 累计交易成本

至少包含：

- 国内手续费。
- 海外 Commission。
- 已确认滑点成本。
- 换月成本，归入交易成本时。
- 其他明确属于交易执行的成本。

海外 Swap 不与交易手续费混在一起，正式归入库存费累计收益（除汇率）并保留真实正负方向。

## 17. 汇率损益

固定细分：

- 海外本金汇率损益。
- 库存费汇率损益。
- 国内汇率变动持仓损益。
- 海外持仓汇率损益。
- 国内对冲持仓汇率损益。

### 17.1 海外本金汇率损益

表达海外账户本金或基础资金在统一计价币种下因汇率变化形成的折算损益。

至少需要：

- 本金原币金额。
- 资金进入或基准汇率。
- 当前或结算汇率。
- 资金变动记录。
- 计算期间和版本。

### 17.2 库存费汇率损益

表达海外 Swap／库存费从发生到统一计价过程中由汇率变化形成的影响。

库存费原币收益进入“库存费累计收益（除汇率）”，对应折算变化进入本项。

### 17.3 国内汇率变动持仓损益

表达汇率变化对国内相关持仓在海内外统一比较或折算口径中的影响。

必须明确国内持仓角色、理论关系和汇率敏感数量，避免与海内外溢价损益重复。

### 17.4 海外持仓汇率损益

表达海外持仓原币价值折算为统一计价币种时，由汇率变化形成的损益。

海外标的价格变化形成的非汇率部分不进入本项。

### 17.5 国内对冲持仓汇率损益

表达国内对冲持仓为匹配汇率或名义价值关系而产生的汇率相关损益。

必须使用正式定义的 `domestic_hedge` 角色和持仓关系，不允许通过账户名称猜测。

## 18. 配平误差

固定细分：

- 海外持仓损益（除汇率）。
- 国内对冲持仓损益（除汇率）。

### 18.1 定义

配平误差用于表达实际持仓与理论配平持仓之间的数量差额，在剔除汇率影响后产生的持仓损益。

候选计算链：

```text
理论持仓
→ 实际持仓
→ 差额数量
→ 非汇率价格变化
→ 配平误差损益
```

### 18.2 海外持仓损益（除汇率）

表达海外实际持仓与理论海外持仓差额对应的非汇率价格损益。

### 18.3 国内对冲持仓损益（除汇率）

表达国内实际对冲持仓与理论对冲持仓差额对应的非汇率价格损益。

### 18.4 禁止重复

配平误差不得重复包含：

- 汇率损益。
- 海内外溢价损益。
- 期现价差损益。
- 交易手续费。
- 已确认滑点成本。
- 已经归入 AdjustmentEntry 的正式修正。

配平误差需要保留理论和实际数量、使用价格、汇率基准、计算期间和版本。

- 汇率损益及五项细分。

### 20.1 合并总览

- 策略分配资金。

V1 如需展示策略净值，沿用策略管理统一口径：

```text

```

- `equity`：模拟盘或已确认外部记录在固定时间的 USDT 口径权益。
- `capitalBase`：策略实例初始或指定资金基数。
- `status`：必须标记为 `estimated`、`provisional`、`simulation` 或等价状态，不得包装成正式基金 NAV 或正式海内外策略净值。

### 20.2 国内账户

- Balance、Available Funds 和 Margin。
- 国内现货或期货持仓。
- 国内对冲持仓。

### 20.3 海外账户

- XAUUSD Position、lot 和黄金等价数量。
- 海外本金。
- Commission 和 Swap。
- 汇率折算价值。
- 数据来源和对账状态。

### 20.4 风险提示

- 国内外资金失衡。
- 汇率暴露过大。
- 单端保证金不足。
- 理论与实际配平差异扩大。
- 国内合约换月或到期。
- 市场交易时间不一致。
- 数据或汇率延迟。

## 21. 风险、异常与人工处理

### 21.1 主要风险

- 海内外价差继续扩大。
- 汇率不利变化。
- 国内外交易时间和节假日不一致。
- 单腿成交和单腿暴露。

- 国内平今平昨处理错误。

- Gateway、Worker、Terminal 或数据源故障。

### 21.2 风险指标候选

- 当前海内外价差和历史分位。

- 汇率暴露金额。

### 21.3 人工处理

在授权范围内可以：

- 撤销国内或海外未成交订单。

- 自建 MT5 Worker／Supervisor：账户、Terminal、凭证、日志和恢复隔离。
- vn.py Gateway 模式：统一 MT5 Adapter 设计参考。

### 25.4 国内现货和外部数据

AU9999 等国内现货能力根据正式数据源选择：

- 交易所或数据供应商接口。
- 成熟数据 Adapter。
- 文件或人工导入。

数据源对象不能直接成为策略 Domain Model，必须映射 InstrumentId、时间、单位和质量。

### 25.5 SpreadTrading 复用边界

- 可以参考价差定义、腿角色、合成行情和成交驱动对冲。
- 可在国内 Runtime 或单一执行节点 PoC 低层算法。
- 不直接替代平台跨 MT5、CTP 和外部记录的 ExecutionBatch。
- 不使用其 PnL 和持仓对象替代本策略四层损益体系。
- 必须验证恢复、换月、平今平昨、部分成交和结果未知。

## 26. 明确不包含

- 未经独立确认的其他金属正式 PnL 公式。
- 完整宏观汇率研究体系。
- 将策略经济账本替代公司财务总账。
- 国内 Gateway 未接入时伪造真实订单和成交。
- 将跨所价差的简化损益结构套用到本策略。
- 无来源和版本的固定汇率或单位换算。
- 将外部组件对象作为平台业务权威。
- 在本文确定具体仓库最终采用、Fork 或版本锁定。

## 27. 可测试验收标准

### 27.1 策略身份与场景

- StrategyId 固定为 `domesticOverseas`。
- 黄金核心场景和其他资产扩展边界明确。
- StrategyVersion、Instance 和账户角色可追溯。
- 国内腿按 GatewayCapability 表达分析、外部记录和真实执行状态。

### 27.2 数据和换算

- 国内外价格、黄金单位、合约乘数和汇率使用同一受控转换。
- USDCNY、USDCNH 或其他汇率品种和方向明确。
- 国内、海外和汇率时间差可识别。
- 夜盘、tradingDay、到期和换月可表达。
- 数据缺失和冲突不会静默补零。

### 27.3 执行

- 国内腿和海外腿由同一 ExecutionBatch 组织。
- CTP 平今平昨、MT5 lot 和两端数量换算正确。
- 国内未接入时只允许正式的外部记录流程。
- 部分成交、结果未知、单腿、汇率和配平风险可表达。
- V1 不以 CTP、真实国内成交、平今平昨、换月和结算单对账作为验收项。
- Runtime 或页面重启后可通过 Query、补查询和对账恢复。

### 27.4 PnL

- 累计总损益（含汇率）能够与三个一级组成核对。
- 累计损益（除汇率）固定包含四项细分。
- 汇率损益固定包含五项细分。
- 配平误差固定包含两项细分。
- 各项避免重复计算并可穿透底层 EconomicEvent。
- PnLResult 具有汇率版本、计算版本、质量和对账状态。

### 27.5 账户、风险和对账

- 国内、海外和国内对冲账户或持仓角色明确。
- 原始币种和统一计价币种可追溯。
- 汇率暴露、保证金和理论实际配平清晰。
- Order、Trade／Deal、Position、Fee、Swap、FX 和结算数据可对账。
- 外部执行和修正不无痕覆盖原始事实。

### 27.6 外部组件边界

- vn.py CTP、Spread 和 Algo 能力仅通过 Runtime／Gateway 或低层算法边界使用。
- MetaTrader5／aiomql 通过 MT5 Adapter 使用。
- 外部组件不拥有四层 PnL、汇率归因、配平误差和平台账本。
- 具体采用经过 PoC、许可证、安全、恢复和对账评审后形成 ADR。

## 28. 未决事项

1. 第一批正式国内场景是 SHFE／XAUUSD、AU9999／XAUUSD 还是两者并行。
2. 国内行情和交易的正式数据源与 Gateway。
3. CTP 接入时间、经纪商和测试环境。
4. 第一家 MT5 Broker、XAUUSD symbol 和 ContractSpecification。
5. 正式汇率使用 USDCNY、USDCNH 或组合规则。
6. `grams_per_troy_ounce` 等转换常量的配置与版本管理。
7. 国内对冲持仓的业务定义和账户角色。
8. 海内外溢价与期现价差的精确防重复公式。
9. 五项汇率损益的事件级计算公式和汇率基准。
10. 两项配平误差的理论持仓公式。
11. 默认 ExecutionPlan 和主动腿／被动腿规则。
12. 最大裸露时间、汇率保护和紧急减险政策。
13. 国内期货换月规则和成本归属。
14. MT5 Swap 的结算日历和异常处理。
15. vn.py CTP Gateway、SpreadTrading 和 AlgoTrading 的 PoC 范围。
16. 国内未接入阶段 ExternalExecutionRecord 和 ImportBatch 格式。

未决事项不得由前端 Mock、固定常量或外部组件默认行为替代正式决策。

以上未决事项整体属于后续阶段，不阻塞资费套利和跨所价差 V1。海内外价差进入正式闭环前，必须另行形成专项实施计划和发布门禁。
