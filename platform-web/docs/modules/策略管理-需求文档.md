## 1. 文档定位

本文定义策略管理的用户任务、六类策略范围、三类管理视角、统计上下文、Read Model、外部数据导入、损益、账户资金、订单穿透、对账、数据修正、权限、异常和验收标准。

策略管理是全部纳管策略的持续监控、结果统计、资金观察、历史查询、数据核对和复盘工作台，负责回答：

> 策略实际发生了什么、赚了或亏了多少、资金和持仓如何、数据是否完整、差异和人工干预在哪里。

策略管理不承担：

- 实时行情机会判断。
- 正式下单、改单、撤单和平仓主操作。
- 双腿实时执行和配平控制。
- Account 主档和公司财务管理。
- 全局 Risk 规则、IAM 和平台配置维护。
- Gateway、终端和凭证运维。

## 2. 产品目标

用户应能够：

1. 选择策略、策略实例、管理视角、统计区间和计价币种。
2. 判断策略整体表现、当前状态和数据完整度。
3. 分析收益、成本、损失、Funding、Swap、汇率和执行偏差来源。
4. 查看关联账户的权益、余额、可用资金、保证金和资金效率。
5. 查询当前持仓、历史订单、成交、ExecutionBatch 和人工干预。
6. 区分平台执行、外部执行、文件导入和人工录入数据。
7. 查看数据来源、时间、版本、质量和对账状态。
8. 从汇总穿透至策略腿、账户、标的、批次、订单、成交和 EconomicEvent。
9. 识别异常表现、异常资金变化、缺失记录、对账差异和正式修正。
10. 在授权范围内导入、确认差异、提交数据修正和生成正式报告。
11. 为风险管理、报表和金融AI分析提供授权、可追溯的结构化 Query。

## 2A. 当前阶段落地范围

策略管理当前阶段是策略模块最优先落地的管理工作台，服务自营账户、策略运行和后续客户侧授权展示。第一阶段重点是完整承接资费套利和跨所价差两条 V1 闭环，看清策略实际表现、账户资金、订单成交、费用事件、PnL、固定时间净值和数据质量；其他纳管策略先保留管理入口、账户和订单占位、外部数据来源状态，不建设完整基金会计、正式报表体系和复杂数据修正体系。

V1 的策略管理是内部查询、观察、核对和复盘中枢，不是完整数据治理后台。第一阶段优先做到看得见、查得到、能穿透、知道数据质量；复杂导入治理、正式修正审批、正式报表、客户权益和基金行政能力不作为当前验收主线。

### 2A.1 V1 必须落地

- 六类纳管策略的统一入口。
- 策略实例与账户绑定的最小展示。
- 策略损益、账户资金、订单信息三类视角。
- 资费套利和跨所价差的账户余额、权益、可用资金、保证金和持仓查询。
- 资费套利和跨所价差的订单、成交、执行批次、费用事件和人工处理记录查询。
- 固定时间净值快照，当前统一以 USDT 为主要计价口径。
- 策略净值最小口径：`nav = equity / capitalBase`，允许 `estimated` 或 `provisional`。
- 数据来源、数据时间、DataQualityStatus 和 ReconciliationStatus。
- 从汇总穿透到策略、账户、标的、订单和成交的稳定 ID。
- 海内外价差、抄底、短线交易员 L 和短线交易员 W 的管理入口、外部数据来源状态和最小占位视图。
- 其他四类策略在外部数据未接入或未核对前，只展示来源状态、最近同步时间、占位明细和数据质量状态，不展示伪造 PnL、伪造成交、伪造胜率或无来源归因。

### 2A.2 V1 暂缓

- 标准外部导入模板和完整 ImportBatch 工作流。
- AdjustmentEntry 审批、撤销和正式 PnL 锁定机制。
- 正式基金会计 NAV、申赎、份额和投资人权益计算。
- 多币种正式会计和人民币汇率落地；除模拟盘需要外，仅保留字段和说明。
- 完整报表生成、正式审计包和客户定制报告。
- 客户侧权限、客户门户、客户定制展示和数据授权规则，等用户系统完成后再展开。
- 金融AI分析后端和 AI 自动生成正式结论。
- 抄底、短线交易员 L 和短线交易员 W 的完整外部归属、TradeCycle、违规记录和批量导入闭环。

### 2A.3 净值口径

当前策略净值用于运营观察、策略复盘和授权展示，不等同于正式基金会计 NAV。V1 净值按 StrategyInstance 在固定时间生成快照，以 USDT 作为统一计价口径，允许 `estimated` 或 `provisional` 状态；若原始账户或策略存在其他币种，第一阶段仅保留原始币种、换算字段和数据来源说明，不要求形成正式多币种会计。

V1 最小计算口径：

```text
nav = equity / capitalBase
```

- `equity`：策略实例绑定账户在固定时间的 USDT 口径权益；多账户策略使用可追溯的合并权益。
- `capitalBase`：策略实例初始或指定资金基数，后续资金增减、申赎和份额体系不在 V1 展开。
- `status`：允许 `estimated`、`provisional`、`verified` 等状态，未核对结果不得包装成正式净值。

## 3. 策略范围

| 策略 | StrategyId | 策略损益 | 账户资金 | 订单信息 | 主要执行来源 |
|---|---|---:|---:|---:|---|
| 资费套利 | `funding` | 有 | 有 | 有 | 交易平台或已确认外部来源 |
| 跨所价差 | `crossSpread` | 有 | 有 | 有 | 交易平台或已确认外部来源 |
| 海内外价差 | `domesticOverseas` | 有 | 有 | 有 | 交易平台、外部接口或导入 |
| 抄底 | `dip` | 有 | 有 | 有 | 外部或人工执行 |
| 短线交易员 L | `shortLineTraderL` | 有 | 有 | 有 | 外部交易来源 |
| 短线交易员 W | `shortLineTraderW` | 有 | 有 | 有 | 外部交易来源 |

策略名称、ID、排序和管理能力由统一策略注册表、策略能力矩阵和对应策略文档维护。

不适用某项数据时必须显示“不适用”或隐藏对应区块，不得显示虚构零值。

V1 管理等级：

| 策略 | V1 管理等级 | V1 管理重点 |
|---|---|---|
| 资费套利 | 完整管理闭环 | 账户、持仓、订单、成交、Funding／费用事件、PnL、固定时间净值和数据质量 |
| 跨所价差 | 完整管理闭环 | Crypto／MT5 双端账户、订单／Deal、持仓、费用事件、PnL、固定时间净值和数据质量 |
| 海内外价差 | 分析／模拟／预留 | 管理入口、行情和模拟结果承接、字段预留，不做正式汇率损益和完整四层 PnL |
| 抄底 | 管理入口 + 外部数据占位 | 策略实例、账户占位、外部来源状态、订单和持仓占位，不做完整归属和 TradeCycle |
| 短线交易员 L | 管理入口 + 外部数据占位 | 独立账户占位、外部来源状态、订单和持仓占位，不做完整违规和归属闭环 |
| 短线交易员 W | 管理入口 + 外部数据占位 | 独立账户占位、外部来源状态、订单和持仓占位，不做完整违规和归属闭环 |

## 4. 目标用户、权限和数据范围

### 4.1 目标用户

- 策略负责人。
- 投资管理人员。
- 风险和运营人员。
- 数据核对和财务协作人员。
- 报表生成和审计人员。
- 只读观察人员。
- 金融AI分析任务使用者。

### 4.2 候选能力权限

读取能力：

- `strategy.management.read`。
- `strategy.reconciliation.read`。
- `strategy.audit.read`，适用时。

导入和修正：

- `strategy.data.import`。
- `strategy.data.correct`。
- `strategy.adjustment.create`。
- `strategy.reconciliation.confirm`。

输出能力：

- `strategy.data.export`，适用时。
- `report.generate`，适用时。

高风险数据修正、AdjustmentEntry、差异接受和正式报表必须独立授权，并按规则执行 ApprovalPolicy 和 Audit。

客户侧权限、客户门户和投资者数据范围暂缓到用户系统完成后再设计。当前只保留内部角色和内部数据范围，不把客户侧权限作为 V1 策略管理验收项。

### 4.3 数据范围

至少可以按以下维度限制：

- StrategyId 和 StrategyInstanceId。
- StrategyVersionId。
- AccountId 和账户组。
- InstrumentId 和资产类别。
- 市场、交易所、经纪商和数据来源。
- DeploymentEnvironment 和 TradingMode。
- 历史日期范围。
- 原始金额、统一折算金额和敏感账户字段。
- 外部导入批次和审计详情。

### 4.4 权限规则

- 具有交易权限不自动获得数据修正、差异接受和正式报表权限。
- 具有系统管理权限不自动获得策略经济数据读取权限。
- 无权读取某账户或策略时，汇总、筛选选项、数量和搜索结果均不得泄露相关信息。
- 前端隐藏字段不能替代 Backend Read Model 和明细 Query 的数据范围校验。

## 5. 信息架构、路由和统计上下文

策略管理具有两个主要切换维度：

1. 策略。
2. 管理视角：策略损益、账户资金、订单信息。

推荐路由语义：

```text
/strategy/management?strategy=funding&view=pnl
/strategy/management?strategy=dip&view=orders
```

### 5.1 可恢复上下文

根据视角可以进入 URL 或 Saved View：

- `strategy`。
- `view`。
- `strategyInstanceId`，具备权限时。
- `dateFrom`／`dateTo`。
- `businessDateFrom`／`businessDateTo`，适用时。
- `currency`。
- `accountId`。
- `instrumentId`。
- `status`。
- `sourceType`。
- `reconciliationStatus`。

不得进入 URL：

- 账户凭证和外部登录信息。
- 未授权账户和内部数据源 ID。
- AdjustmentEntry 正文和审批内容。
- 敏感审计备注。

### 5.2 路由规则

- StrategyId 必须有效且 `management.enabled = true`。
- 切换策略时保留兼容的管理视角。
- 切换视角时保留当前策略。
- 日期区间、币种等兼容公共条件可以保留。
- 策略特有账户、标的和状态条件重新加载。
- 非法参数回退到安全默认值并修正 URL。
- 页面刷新后恢复主要策略、视角和核心筛选。

### 5.3 统一统计上下文

所有总览、图表、归因和明细至少使用同一组适用上下文：

- StrategyId。
- StrategyVersionId。
- StrategyInstanceId 或实例集合。
- 统计日期范围。
- businessDate 口径。
- 原始币种和统一计价币种。
- 汇率来源和时间。
- 数据截止时间。
- PnL 计算版本。
- 数据来源范围。
- 对账和质量门槛。

切换统计上下文后，所有卡片、图表、表格和导出必须同步更新。

## 6. 查询架构和 Read Model

页面通过 Backend Read Model 获取管理视图：

```text
权威领域事实
→ 版本化计算与聚合
→ Backend Read Model
→ API DTO
→ Frontend Adapter
→ View Model
```

规则：

- Read Model 可以聚合 Strategy、Trading、Account、Position、PnL、Risk、Reconciliation 和 Audit。
- Read Model 不接受业务写入。
- 页面不直接依赖数据库表和外部接口字段。
- 页面不重新计算第二套 Order、Position、Account 和正式 PnL。
- Read Model 必须标记数据截止时间、来源、质量、版本和重建状态。
- Read Model 可以缓存和重建，不成为最终权威。
- 汇总和明细必须能够通过稳定 ID 对应。
- 实时 Event 只用于更新提示，页面刷新通过 Query 恢复。

## 7. 策略总览

每个管理视角顶部应共享策略上下文摘要：

- 策略正式名称和 StrategyId。
- StrategyVersion 和 StrategyInstance。
- 当前实例状态。
- 主要账户和账户用途。
- 当前数据截止时间。
- DataQualityStatus。
- ReconciliationStatus。
- RiskStatus 摘要。
- 最近重要异常或人工干预。

总览不得将估算 PnL、未核对余额和正式已结算结果混为一个值。

## 8. 策略损益

### 8.1 页面目标

用于回答：

- 策略取得多少收益或损失。
- 收益、成本、损失和调整来自哪些因素。
- 策略腿、标的、账户和执行批次的贡献如何。
- 当前结果是否伴随异常执行、数据差异或风险。
- 总损益与归因项是否可核对。
- 结果使用什么策略版本、数据版本和计算版本。

### 8.2 页面结构

1. 统计上下文和数据状态。
2. 结果总览。
3. 趋势表现。
4. 损益归因。
5. 明细穿透。
6. 计算版本、数据质量和核对信息。
7. AdjustmentEntry 和人工处理，具备权限时。

### 8.3 通用指标

根据策略适用性展示：

- 累计总损益。
- 区间损益和收益率。
- 日度、周度或月度损益。
- 策略净值。
- 当前和最大回撤。
- 已实现和未实现损益。
- 交易成本。
- Funding、Swap、利息或资金成本，适用时。
- 资金使用效率。
- 执行偏差和异常损失。
- 已确认调整项。

不适用指标不得显示无意义零值。

### 8.4 PnLResult

正式 PnLResult 至少表达：

- `pnlResultId`。
- StrategyId、StrategyVersionId 和 StrategyInstanceId。
- 统计范围和 businessDate。
- 原始币种和统一计价币种。
- 总损益。
- 已实现和未实现部分，适用时。
- 归因项集合。
- EconomicEvent 截止时间。
- 计算版本。
- 数据版本。
- 完整度和 DataQualityStatus。
- ReconciliationStatus。
- 是否估算、已核对或已结算。

V1 使用公共最小归因分类承接不同策略：

```text
trading_pnl
funding_pnl
swap_pnl
fees
fx_pnl
other_adjustment
```

V1 映射规则：

- 资费套利重点使用 `funding_pnl`、`fees` 和 `trading_pnl`。
- 跨所价差按 V2 专项口径展示 `价差变动总损益`、`累计资金费`、`累计库存费`、`累计手续费`、`累计总损益` 和单列的 `累计滑点成本`；价差变动损益下钻顺序为 `永续基差变动损益`、`代币基差变动损益`、`U汇变动损益`、`CFD价差变动损益`。后端正式 read model、字段和重算服务后续补齐前，前端 mock 不得被解释为正式结算结果。
- 海内外价差暂不落地完整四层 PnL，第一阶段只保留字段和页面占位。
- 抄底、短线交易员 L 和短线交易员 W 在外部数据未稳定接入前，可以显示 `estimated`、`provisional` 或无数据状态，不虚构归因。

### 8.5 损益归因

必须满足：

- 总损益与归因项可以按策略定义核对。
- 收益、成本、损失和 AdjustmentEntry 分开。
- 估算和实际结算分开。
- 归因名称、层级、正负号和公式来自对应策略文档。
- 结果具有策略版本、计算版本和数据截止时间。
- 汇率折算具有来源、方向、时间和版本。
- 页面组件不得通过字符串猜测归因方向。
- 对不平项必须明确显示，不得用“其他”静默吸收。

### 8.6 EconomicEvent

损益可以穿透至适用的：

- Fill。
- TradingFee。
- FundingSettlement。
- Swap／OvernightFee。
- Interest／FinancingCost。
- FXConversion。
- Transfer 或资金事件，适用时。
- ManualAdjustment。

EconomicEvent 不等于最终会计分录，但必须保留原始经济事实和来源。

### 8.7 趋势和穿透

按数据能力支持：

- 日期和交易时段。
- 策略腿。
- 标的或合约。
- 平台或账户。
- ExecutionBatch。
- Order 和 Fill。
- EconomicEvent 类型。
- 数据来源。
- 人工调整。

穿透结果必须使用与总览一致的统计区间、币种、版本和质量门槛。

## 9. 账户资金

### 9.1 页面目标

用于回答：

- 策略使用多少资金。
- 可用资金、权益、保证金和资金占用如何。
- 单端或多端账户是否失衡。
- 当前资金和风险状态如何。
- 净值、回撤和资金效率如何变化。
- 账户数据是否及时并已核对。

### 9.2 页面结构

1. 策略账户合并总览。
2. 当前风险和数据质量摘要。
3. 单账户或多账户结构。
4. 资金占用、保证金和效率。
5. 净值、回撤和趋势。
6. 账户异常和对账信息。
7. 账户来源和快照时间。

### 9.3 通用字段

- 策略总资金或分配额度，适用时。
- Account 权益和余额。
- 可用资金和冻结资金。
- 保证金占用、可用保证金和保证金率。
- 风险占用。
- 当前持仓名义价值。
- 资金使用率。
- 策略净值和回撤。
- AccountStatus。
- 数据来源、快照时间和质量。
- ReconciliationStatus。

### 9.4 Account 与 StrategyAccountBinding

- Account 维护账户主档和账户事实。
- Strategy 维护 StrategyAccountBinding 和账户用途。
- 页面通过 Read Model 将账户事实和策略用途组合。
- 页面不能根据账户名称字符串猜测交易腿角色。

### 9.5 单账户和多账户

单账户策略不创建无意义双端结构。

多账户策略：

- 先展示合并总览，再展示各端。
- 明确 Account、平台、账户模式、币种和账户用途。
- 展示原始值和统一折算值。
- 展示汇率来源、时间和换算结果。
- 识别资金、保证金和名义价值失衡。
- 单个账户缺失时合并结果必须标记 partial，不能按零处理。

### 9.6 快照和时效

余额、保证金和持仓必须标明：

- sourceTime。
- receivedAt。
- snapshotId。
- 数据来源。
- 是否实时、延迟、历史或导入。
- 是否完成对账。

不同账户快照时间不一致时，合并结果需要明确时间差和可比性。

## 10. 订单信息

### 10.1 页面目标

用于回答：

- 当前持有哪些头寸。
- 历史执行过哪些批次和订单。
- 每笔订单产生哪些成交。
- 是否存在失败、撤单、部分成交、结果未知和人工干预。
- 外部执行数据是否完整并已对账。
- 某项损益和持仓变化对应哪些交易事实。

### 10.2 固定数据视图

- 当前持仓。
- 历史订单。
- 成交记录。
- 执行批次和执行记录。

根据策略和真实数据源可以增加：

- 交易腿记录。
- Funding 和费用结算。
- 信号记录。
- 止盈止损记录。
- 风险事件关联。
- 人工干预和修正记录。

附加视图必须由策略文档和正式数据源支持。

### 10.3 通用筛选

至少支持：

- 日期范围。
- 记录类型。
- StrategyInstanceId。
- OrderStatus、ExecutionBatchStatus 或 ReconciliationStatus。
- 标的、账户、方向和交易腿，适用时。
- OrderId、externalOrderId 或 ExecutionBatchId。
- 数据来源和 ImportBatchId。
- 是否人工干预。
- 分页或游标。

筛选变化后分页回到安全起点。

### 10.4 关联关系

- StrategyInstance 与 Account。
- StrategyInstance 与 Instrument。
- ExecutionBatch 与 LegInstruction。
- LegInstruction 与 Order。
- Order 与 Fill。
- Fill 与 Position 变化和 EconomicEvent。
- 异常、人工处理和对账差异与目标对象。

用户应能够从汇总进入明细，不依赖手工拼接多个表格。

### 10.5 当前持仓

持仓至少表达：

- `positionId`。
- StrategyInstanceId。
- AccountId。
- InstrumentId。
- 方向和数量。
- 平均成本或适用成本基础。
- 当前价格和估值时间。
- 原始和统一币种名义价值。
- 未实现损益，适用时。
- 来源和对账状态。

外部账户持仓与策略归属无法完全确认时，必须显示 `unallocated`、`unverified` 或等价状态，不得强行分配给策略。

## 11. 外部执行数据和导入

### 11.1 数据来源

可以包括：

- 交易所或经纪商接口。
- 外部交易终端。
- 文件导入。
- 人工录入。
- 其他已确认数据服务。

### 11.2 ImportBatch

每次文件或人工批量导入必须建立 ImportBatch，至少包括：

- `importBatchId`。
- 来源类型和来源名称。
- 文件或任务身份。
- 上传或执行用户。
- 创建时间和业务覆盖区间。
- 记录总数、成功数、失败数和重复数。
- 校验状态。
- 提交、确认和回滚状态，适用时。
- 错误摘要和审计信息。

### 11.3 导入流程

```text
创建 ImportBatch
→ 保存原始文件或来源引用
→ 解析和格式校验
→ 标准 ID 映射
→ 重复和覆盖检查
→ 预览和错误报告
→ 授权确认
→ 写入主责领域
→ 对账和 PnL 重算
→ 更新 Read Model
```

### 11.4 校验要求

进入正式管理视图前：

1. 保留原始来源、外部 ID 和原始状态。
2. 通过 Adapter 转换为平台对象。
3. 校验 StrategyId、AccountId 和 InstrumentId。
4. 校验时间、时区、币种、单位、合约乘数和精度。
5. 识别重复、冲突和覆盖范围。
6. 标记 DataQualityStatus。
7. 对 Order、Fill、Position、Balance、EconomicEvent 和 PnL 执行适用对账。
8. 对修正和接受差异执行权限、审批和审计。

导入失败或部分成功不得污染已确认历史数据。

V1 中，完整 ImportBatch 仅作为后续能力预留。资费套利和跨所价差优先通过平台执行事实、Runtime 事件和适配器同步进入管理视图；海内外价差、抄底、短线交易员 L 和短线交易员 W 可以先展示外部来源状态、最近同步时间和占位明细，不要求第一阶段完成批量导入、归属预览和正式提交闭环。

占位策略不得用手工 Mock 或前端静态数据展示正式表现。没有已确认来源时，应显示 `missing`、`unverified`、`not_connected` 或等价状态。

## 12. Reconciliation、Data Quality 和正式修正

### 12.1 对账对象

页面可以展示：

- ReconciliationJob 或运行摘要。
- ReconciliationResult。
- ReconciliationDifference。
- 差异类型、金额或数量。
- 影响对象和影响范围。
- 自动或人工处理状态。
- 操作人、时间、原因和结果。

### 12.2 对账范围

根据数据能力至少覆盖：

- 平台 Order 与外部 Order。
- 平台 Fill 与外部成交。
- Position 与外部持仓。
- Balance／Margin 与外部账户。
- EconomicEvent 与 Funding、Swap、费用和资金事件。
- PnLResult 与底层事实完整度。

### 12.3 差异处理

规则：

- 差异不直接无痕覆盖源事实。
- `accepted_difference` 或等价处理需要授权、原因和审计。
- 缺失外部事实优先通过重新同步和补查询确认。
- 正式修正使用 DataCorrectionRecord 或 AdjustmentEntry。
- 修正影响 PnL 时触发版本化重算。
- 原始记录、修正记录和最终结果可以同时追溯。
- DataQualityStatus 与 ReconciliationStatus 分开表达。

### 12.4 AdjustmentEntry

AdjustmentEntry 至少表达：

- `adjustmentEntryId`。
- 目标策略、实例和统计期间。
- 关联对象，适用时。
- 调整类型和金额。
- 币种和单位。
- 原因和证据。
- 创建人和审批。
- 生效时间。
- 是否影响正式 PnL。
- 被替代或撤销关系。

页面不得允许用户直接编辑历史 PnL 数字而不产生正式调整记录。

V1 不建设完整 AdjustmentEntry 审批、撤销和锁定机制。若发现资费套利或跨所价差的费用、成交或 PnL 需要修正，第一阶段优先通过补同步、重算和 `provisional` 状态表达；正式人工调整进入后续阶段。

## 13. 风险展示

策略管理只读展示与策略运行直接相关的：

- RiskStatus。
- RiskSnapshot。
- RiskEvent。
- 限制和告警摘要。
- 指标、当前值、参考值、时间和判断依据。
- 风险事件关联的账户、持仓、订单和执行批次。

RiskRule、RiskLimit、GlobalTradingBlock 和处置标准由 Risk 领域维护。

未经验证的指标可以作为观察或提示，不由页面自行升级为限制和阻断。

## 18. 异常、空数据和降级

至少识别：

- 策略或实例不存在。
- 当前视角不适用于该策略。
- Read Model 正在重建。
- 数据延迟、部分、冲突或缺失。
- PnL 计算失败。
- 汇率缺失或版本不一致。
- 外部导入失败或部分成功。
- 对账差异未处理。
- 账户快照时间不一致。
- 订单或成交关联缺失。
- 权限变化。
- 报表或导出失败。

降级规则：

- PnL 失败时仍可展示订单、成交和账户事实。
- 账户数据部分缺失时合并结果标记 partial，不按零处理。
- 订单明细失败不应清空已加载的 PnL 总览，但需显示局部错误。
- Read Model 重建期间可以展示最后成功版本，并显示版本和时间。
- 导入失败不影响已确认历史数据。
- 对账未完成的数据可以展示，但正式统计和报表必须标明未核对。
- 实时 Event 中断后通过 Query 恢复。

## 19. UI 与交互

遵循：

- `docs/design/platform-ui-guidelines.md`。
- `docs/architecture/shared-ui-governance.md`。

特有要求：

- 六类策略使用统一页面骨架和路由语义。
- 切换策略时保留当前管理视角，兼容时保留统计上下文。
- 不适用内容不显示空白卡片和虚构零值。
- 总览、趋势、归因、账户和明细层级清晰。
- 表格、图表和卡片使用同一统计上下文。
- 预计、未核对、已核对、已结算和已修正使用不同语义。
- 加载、空数据、延迟、错误、待核对、差异、重算和降级状态完整。
- 页面不出现正式实时交易主操作。
- 风险、涨跌、订单、数据质量和对账使用不同视觉语义。
- AdjustmentEntry、数据修正和差异接受必须显著显示审计属性。

## 20. 跨模块关系

- 交易平台提交命令并展示当前执行；策略管理查询后端事实和长期结果。
- 风险管理读取策略事实并维护风险判断、事件和处置。
- Account 维护账户主档；Strategy 维护绑定。
- Reconciliation 维护对账任务、结果和差异。
- Reporting 读取正式结果生成版本化输出。
- Audit 记录导入、核对、修正、审批和人工处理。
- 金融AI分析可以读取授权结果生成复盘材料，不修改源数据。

跨模块跳转只传递稳定 ID 和安全筛选，目标模块重新 Query。

## 21. 非功能要求

- 面向桌面管理工作台。
- 大型查询使用分页、游标、聚合和按需加载。
- 页面刷新后恢复策略、视角和核心筛选。
- 实时 Event 不是唯一数据来源。
- 汇总能够穿透至权威明细。
- 导入、核对、修正、重算、导出和报表可审计。
- 敏感账户、订单和审计信息按数据范围展示。
- Read Model 可以重建并具有版本。
- 单一外部数据源故障不导致整个模块白屏。
- 正式结果重算不得无提示覆盖旧版本。
- 复杂 PnL 查询和导出不应阻塞普通订单和账户查询。

## 22. 明确不包含

本文不直接定义：

- 正式交易和执行页面。
- Gateway 和外部终端技术实现。
- 公司财务总账和法定会计。
- 全局账户、风险、权限和系统设置后台。
- 每个策略的金融公式和具体风险阈值。
- 报表版式和完整审批流程。
- 金融AI分析实现。

## 23. 验收标准

### 范围和路由

- 展示全部六类纳管策略。
- 不提供正式实时交易入口。
- 策略、视角和核心统计上下文可以恢复。
- 不适用视图不展示虚构内容。

### 策略损益

- 具备总览、趋势、归因和明细。
- 总损益与归因可以按策略口径核对。
- 预计、实际、未核对、已核对和已结算明确区分。
- PnLResult 具有策略、数据和计算版本。
- 可以穿透到 EconomicEvent、Order 和 Fill。
- V1 至少完整支持资费套利和跨所价差的 PnL、净值和费用事件查询。
- 海内外价差复杂四层 PnL、抄底 TradeCycle、短线交易员违规相关损益不作为 V1 验收项。

### 账户资金

- 单账户和多账户结构符合实际。
- Account、StrategyAccountBinding、PnL 和 Risk 权威边界正确。
- 多币种折算可追溯。
- 缺失账户不按零计入合并值。
- 快照时间和对账状态清晰。

### 订单信息

- 持仓、订单、成交、执行批次和人工处理可关联。
- 外部数据具有来源、外部 ID、导入批次、质量和对账状态。
- 汇总可以穿透到稳定明细。

### 导入和对账

- ImportBatch 具有预览、校验、错误和确认状态。
- 部分失败不污染正式历史数据。
- 差异不无痕覆盖源事实。
- AdjustmentEntry 和数据修正具有权限、原因、审批和审计。
- 修正影响 PnL 时产生版本化重算。

### 数据和状态

- Reconciliation 是正式领域对象。
- 状态统一引用公共规范。
- Read Model 不形成第二套权威事实。
- 汇总、明细和报表使用一致统计上下文。
- 缺失、冲突和过期数据不会显示为正式零值。

### UI 和安全

- 三类管理视角稳定且清晰。
- 不同策略差异不破坏统一阅读顺序。
- 风险、订单、涨跌、数据质量和对账语义不混用。
- 无权限用户无法通过筛选、搜索和汇总数量推断敏感数据。

## 24. 未决事项

以下事项由六份策略文档、专项架构或后续规划确认：

- 各策略正式 PnL 完整度门槛。
- 策略净值、收益率和资金分母的统一定义。
- 外部数据标准导入模板和覆盖政策。
- AdjustmentEntry 的审批等级和撤销流程。
- PnLResult 的正式结算和锁定机制。
- Read Model 重建、历史版本和正式报表的关系。
- 多实例合并展示和跨实例比较范围。
## 25. 当前最低管理视图

每个受管策略至少可穿透到绑定账户、订单、成交、当前持仓、正式或明确标注的运营 PnL、NAV/权益质量、风险状态和对账差异。缺失或外部来源数据必须显示来源、时间和质量状态，不能用 Mock 或零值补齐。
