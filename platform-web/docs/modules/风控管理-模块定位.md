# 风险管理：模块定位

状态：`active`  
产品基线：Platform V5  
架构版本：Platform V6  
适用分支：`refactor/frontend-architecture-v6`  
文档层级：一级产品模块定位

> 文件名中的“风控管理”暂时保留历史路径兼容；正式一级模块名称统一为“风险管理”。

## 1. 模块定位

风险管理是面向全平台风险观察、风险处置和内部管理能力的集中产品入口。

它在产品导航中承接风险、账户、资金、监控、报表、审计、权限、设置和通知等子板块，但这些页面归入风险管理，不代表对应后端技术领域全部属于 Risk。

风险管理不负责具体策略机会分析、正式下单、完整研究看板或金融AI分析任务。

## 2. 内部子板块

- 风控详情。
- 账户与资产。
- 财务与资金。
- 数据与服务监控。
- 报表。
- 审计。
- 用户与权限。
- 个人账号。
- 系统设置。
- 消息通知。

具体页面层级以正式前端路由为准，但不新增独立一级产品模块。

## 3. 核心用户

- 风险管理人员。
- 投资管理人员。
- 策略负责人。
- 账户、资金和运营管理人员。
- 系统管理员与审计人员。
- 具有授权数据范围的观察人员。

## 4. 核心任务

用户应能够：

1. 查看风险状态、风险事件和影响对象。
2. 查看账户、资产、资金和保证金摘要。
3. 管理或查看风险规则、限制和全局阻断。
4. 查看数据源、Gateway 和服务健康。
5. 查询正式报表、审计和通知。
6. 管理用户、能力权限、数据范围和个人配置。
7. 对高风险配置、数据修正和风险覆盖执行审批与双人复核。
8. 对异常进行记录、处置、复盘和规则校准。

## 5. 产品主责内容与技术领域

| 子板块 | 产品主责 | 主要技术领域／数据权威 |
|---|---|---|
| 风控详情 | 风险概览、事件、限制、处置和关联对象 | Risk |
| 账户与资产 | 账户主档、资产结构、余额和账户状态管理入口 | Account／Asset |
| 财务与资金 | 公司经营资金、收支和财务口径 | Finance／Treasury |
| 数据与服务监控 | 数据质量、同步、Gateway 和服务健康 | Data Quality／Observability／Gateway |
| 报表 | 正式报表生成、版本、导出和查询 | Reporting |
| 审计 | 用户操作、审批、配置和关键业务行为追溯 | Audit |
| 用户与权限 | 用户、角色、能力和数据范围管理 | IAM／Permission |
| 个人账号 | 当前用户资料和偏好 | IAM／User Preference |
| 系统设置 | 平台配置入口和功能控制 | Configuration／Operations／各业务主责领域 |
| 消息通知 | 消息投递、阅读状态和关联跳转 | Notification |

菜单位置不改变上述数据权威。

## 6. 关键边界

### 6.1 账户与策略绑定

- Account 领域拥有账户主档和账户状态。
- Strategy 领域拥有 `StrategyAccountBinding`。
- 账户与资产页面可以展示或通过授权流程管理绑定，但不得复制第二套绑定事实。

### 6.2 风险与权限

- IAM 判断用户是否有能力操作。
- Risk 判断业务风险是否允许、限制或阻断。
- Approval 对特定高风险操作进行独立复核。
- Audit 记录全过程。

四者不能互相替代。

### 6.3 系统设置

系统设置是产品入口，不是万能配置表。风险规则、策略参数、账户绑定、权限和 Gateway 配置仍由各自主责领域维护，并通过明确命令、权限、审批和审计修改。

### 6.4 数据与服务监控

监控页面展示健康状态和数据质量，不拥有订单、账户、持仓、损益或风险业务事实，也不能因监控数据缺失而静默覆盖源数据。

## 7. 风控详情

聚焦：

- RiskStatus 和风险指标。
- RiskEvent 和影响范围。
- 当前限制、阻断和人工复核。
- 与策略、账户、持仓、订单、执行批次、数据源和系统服务的关联。
- RiskResolution、处置时间和结果。

风控详情可以使用 Backend Read Model 聚合摘要，但不复制其他子板块完整管理功能。

## 8. 渐进式风险建设

初期优先建设：

- 少量关键风险指标。
- 明显异常提示。
- 基础交易和资金限制。
- 风险事件和人工处理记录。
- 全局或范围化交易阻断。
- 阈值复盘和版本管理。

未经验证的规则可以作为观察或警告，不直接升级为强制阻断。正式限制必须具备指标、阈值、范围、版本、生效时间和处置逻辑。

## 9. 与其他一级模块的关系

### 策略

策略页面读取 Risk 的判断、限制和告警；Risk 读取 Trading、Account、Position、PnL 等权威事实进行判断，不通过前端页面互相传递第二套数据。

### 对冲基金看板

可引用 Research Data 作为风险背景，不复制完整研究能力。

### 新闻日历与理财

重要事件可以成为风险背景或提醒，风险管理不维护新闻和理财内容源。

### 金融AI分析

可以在授权范围内解释风险事件和归纳原因，但不能修改风险规则、解除阻断、批准审批或执行交易。

## 10. 明确不负责

- 具体策略行情分析和交易参数。
- 正式交易命令和订单执行。
- 原始研究、新闻和内容数据维护。
- 金融AI分析任务和结果权威。
- 将所有管理功能合并为一个 Risk 后端模块。

## 11. 验收标准

- 风险管理保持六个一级模块之一。
- 子板块具有明确产品职责、技术领域和数据权威。
- StrategyAccountBinding 不再错误归属 Account 或 Risk。
- 权限、审批、风险、审计和命令执行职责分开。
- 系统设置和监控不形成第二套业务事实。
- 风险状态、规则、事件和处置可关联并追溯。
- 正式一级模块名称统一为“风险管理”。
