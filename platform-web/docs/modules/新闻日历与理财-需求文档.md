## 1. 文档定位

本文定义新闻日历与理财模块的用户任务、三个固定栏目、内容对象、数据语义、筛选、收藏、提醒、外部链接、权限、异常、跨模块协作、非功能要求和验收标准。

该模块是 `Content and Calendar Data` 的产品浏览入口，用于将分散的宏观事件、新闻摘要和公开理财信息整理为：

- 可浏览。
- 可筛选。
- 可收藏。
- 可追溯。
- 可安全引用。
- 可带入其他模块继续研究或处理。

该模块不承担：

- 完整宏观、行业和跨资产研究。
- 正式交易、下单、申购、赎回、转账和资金划转。
- 策略绩效、账户和订单管理。
- 风险规则、风险判断和风险处置。
- 金融AI分析任务和生成结果管理。
- 对外部平台安全、收益、兑付或持续可用性作保证。

## 2. 产品目标

用户应能够：

1. 查看近期和历史宏观经济、政策和市场事件。
2. 准确识别事件发生时间、公布时间、时区、重要度和修订状态。
3. 按资产类别、主题、地区和来源浏览经过整理的新闻摘要。
4. 区分原始事实、人工摘要、AI 摘要、编辑标签和未确认信息。
5. 查看公开理财活动、收益展示、期限、锁仓、赎回、地区和参与限制。
6. 识别理财收益是历史、当前展示、预估、浮动还是活动宣传值。
7. 收藏、标记已读和设置个人关注，适用时。
8. 进入明确标识的原始来源或外部页面。
9. 将稳定事件或内容上下文带入对冲基金看板、策略、风险管理或金融AI分析。
10. 在单一外部来源异常时继续使用其他内容和栏目。

本模块的成功标准不是收集尽可能多的链接，而是：

> 让用户快速判断“发生了什么、什么时候发生、来源是否可靠、与我关注的市场或任务有什么关系、下一步应去哪里继续处理”。

## 3. 固定栏目和对象边界

固定栏目：

1. 宏观日历。
2. 新闻整理。
3. 理财信息。

三个栏目共享模块入口、基础搜索、收藏和来源展示，但使用不同业务对象：

| 栏目 | 主要对象 | 核心时间语义 | 是否允许资金操作 |
|---|---|---|---:|
| 宏观日历 | `CalendarEvent` | 计划时间、公布时间、修订时间 | 否 |
| 新闻整理 | `NewsContent`／`StoryCluster` | 原始发布时间、收录时间、更新时间 | 否 |
| 理财信息 | `WealthOpportunity` | 活动起止、产品期限、最近核对时间 | 否 |

禁止因为页面视觉相似而：

- 使用同一个通用对象承载三类业务数据。
- 将新闻方向标签用于宏观事件重要度。
- 将理财收益率字段用于普通新闻。
- 将收藏状态写回原始内容事实。
- 将外部跳转误表示为平台内部交易或申购。

## 4. 目标用户、权限和数据范围

### 4.1 目标用户

- 宏观、行业和资产研究人员。
- 交易和策略人员。
- 策略负责人和投资管理人员。
- 风险、运营和数据核对人员。
- 关注公开理财活动的授权用户。
- 金融AI分析任务使用者。
- 仅具有部分栏目读取权限的只读用户。

### 4.2 候选能力权限

- `content.calendar.read`：访问宏观日历。
- `content.news.read`：访问新闻整理。
- `content.wealth.read`：访问理财信息。
- `content.bookmark.manage`：管理个人收藏。
- `content.readState.manage`：管理个人已读状态。
- `content.reminder.manage`：管理个人事件提醒偏好，启用时。
- `content.export`：导出授权内容或日历结果，启用时。
- `content.internalNote.read`：读取内部备注，适用时。
- `content.internalNote.manage`：维护内部备注，适用时且需审计。
- `content.curation.manage`：执行内容分类、合并、下架或修正，限内容维护角色。

栏目访问、内部摘要、用户收藏、内部备注、导出和内容维护必须分别授权。

### 4.3 数据范围

数据范围可以按以下维度限制：

- 栏目。
- 国家、地区和市场。
- 资产类别和主题。
- 数据源或供应商授权。
- 公开内容、内部摘要或内部备注。
- 历史时间范围。
- 理财平台或产品类别。
- 导出和批量下载范围。

### 4.4 权限规则

- 公开来源不表示所有内部整理结果均可公开读取。
- 收藏和已读状态仅属于当前用户，不向无关用户暴露。
- 内部备注不能出现在公开外部链接或普通分享 URL 中。
- 无权查看正文或摘要时，不得仅通过搜索结果泄露标题、标签或数量。
- 前端隐藏栏目和字段不能替代后端 Query 权限校验。
- 内容维护权限不自动授予正式交易、风险覆盖或系统管理权限。

## 5. 核心用户问题

### 5.1 宏观日历

- 近期有哪些重要经济、政策和市场事件？
- 事件在什么日期、时间和时区发生？
- 哪些事件尚未公布、已经公布、被修订、取消或改期？
- 前值、预期值和实际值分别是多少？
- 实际结果相对预期和前值的差异如何？
- 事件可能影响哪些国家、资产类别和市场？
- 数据来自哪里，最近何时更新，是否存在冲突或修订？

### 5.2 新闻整理

- 近期最重要的宏观、商品、加密、股市和跨市场新闻是什么？
- 多篇报道是否属于同一个事件或故事？
- 当前摘要来自原文、人工整理还是 AI 生成？
- 事实是否已经确认，不同来源是否存在冲突？
- 新闻与哪些资产、主题、策略或宏观事件相关？
- 原始发布时间和平台收录时间分别是什么？
- 原始链接是否仍然有效？

### 5.3 理财信息

- 当前有哪些公开理财产品、活动或收益机会？
- 产品由哪个平台或机构提供，支持什么资产？
- 展示收益率是什么性质，适用于什么期限和条件？
- 是否锁仓、何时可赎回、是否存在提前退出限制？
- 是否有额度、地区、身份认证或新用户限制？
- 产品信息最近何时核对，是否仍然有效？
- 外部参与可能涉及哪些平台、资产、流动性和对手方风险？

## 6. 产品范围

### 6.1 必须包含

- 三个固定栏目。
- 栏目路由和可恢复筛选。
- 来源、时间和数据质量。
- 关键词、分类和日期筛选。
- 列表、详情和外部来源跳转。
- 用户收藏和已读状态，至少预留正式模型。
- 区块级加载、空数据、延迟、错误和降级。
- 与看板、策略、风险管理和金融AI分析的安全跳转。

### 6.2 可以配置包含

- 用户事件提醒。
- 内容专题或 Story Cluster。
- 高优先级内容置顶。
- 内部备注。
- Saved View。
- 内容导出。
- 新闻与图表时间轴联动。
- 理财机会过期提醒。

### 6.3 明确不包含

- 新闻全文镜像和受版权保护正文复制。
- 自动生成 TradeCommand。
- 自动根据新闻标签调整仓位。
- 理财产品申购、赎回、充值、划转和钱包连接。
- 对外部产品进行信用背书或保本承诺。
- 将宣传收益率转化为确定收益。
- 完整研究报告和策略 Memo 工作台。
- 风险事件正式定级和处置。
- 金融AI分析完整任务编排。

## 7. 信息架构和路由

### 7.1 推荐路由语义

```text
/content?section=calendar
/content?section=news
/content?section=wealth
```

也可以采用分层路径，但必须满足：

- 当前栏目属于稳定路由状态。
- 刷新、前进和后退可以恢复栏目。
- 非法栏目回退至安全默认值并修正 URL。
- 分享链接不能携带敏感内部备注和未授权数据集参数。

### 7.2 可进入 URL 的上下文

根据栏目适用性，可以进入 URL：

- `section`。
- `dateFrom`／`dateTo`。
- `countryId`／`regionId`。
- `assetClass`。
- `topicId`。
- `sourceId`，仅限可公开或授权稳定 ID。
- `importance`。
- `platformId`，理财信息适用时。
- `productType`，理财信息适用时。
- `termBucket`，理财信息适用时。
- `bookmarkOnly`。
- 安全的搜索关键词，适用时。

### 7.3 不得进入 URL

- 用户凭证、Cookie、API Key 和外部平台登录信息。
- 内部未授权数据集 ID。
- 内部备注正文。
- 交易账户 ID 和资金操作参数。
- Live 交易或风险覆盖参数。
- 完整金融AI分析提示词和敏感上下文。

### 7.4 页面本地状态

- 临时排序。
- 普通分页游标。
- 列表密度。
- 详情弹窗开关。
- 局部展开。
- 未保存筛选草稿。
- 当前悬浮项。

## 8. 统一内容来源模型

三类内容至少共享以下来源对象：

### 8.1 SourceReference

- `sourceId`。
- 来源名称。
- 来源类型。
- 原始域名或发布机构。
- 原始链接，适用时。
- 原始发布时间，适用时。
- 平台接收或收录时间。
- 最近核对时间。
- 来源语言。
- 来源地区。
- 是否需要登录或订阅，已知时。
- 当前链接状态。
- 数据授权或使用限制，已知时。

### 8.2 来源类型候选

- 官方机构。
- 交易所或市场基础设施。
- 公司正式披露。
- 新闻媒体。
- 数据供应商。
- 第三方研究机构。
- 外部平台活动页。
- 人工导入。
- 内部整理。
- AI 生成摘要，不作为原始事实来源。

### 8.3 来源规则

- AI 摘要不能成为原始事实来源。
- 聚合页面不能隐藏原始发布机构。
- 同一事实来自多个来源时应保留来源关系。
- 来源失效不自动删除历史内容，但必须更新链接状态。
- 来源冲突时不得静默选择一条并隐藏冲突。
- 外部付费内容只展示授权范围内的元数据和摘要。

## 9. 宏观日历详细需求

### 9.1 CalendarEvent 核心字段

- `eventId`。
- 稳定事件类型或指标 ID。
- 正式事件名称。
- 国家或地区。
- 发布机构。
- 事件类别。
- 计划时间。
- 计划时间时区。
- 用户时区展示时间。
- 重要度。
- 影响资产类别或市场标签，适用时。
- 统计期间，经济数据适用时。
- 前值。
- 前值修订值，适用时。
- 市场预期值，适用时。
- 实际初值，适用时。
- 实际修订值，适用时。
- 单位。
- 数值频率。
- 来源。
- 首次发布时间。
- 平台接收时间。
- 最近更新时间。
- 生命周期状态。
- 数据质量。

### 9.2 事件类别

至少支持可配置类别：

- 央行利率决议和政策会议。
- 央行官员讲话。
- 通胀。
- 就业。
- 经济增长。
- 消费和信心。
- 制造业和服务业。
- 房地产。
- 财政和国债发行。
- 监管、政策或重大市场制度事件。
- 交易所休市、合约和结算相关事件，适用时。
- 公司财报等非宏观事件不应默认混入宏观日历，除非形成独立筛选类别。

### 9.3 生命周期状态

候选状态：

- `scheduled`：已计划，尚未发生或公布。
- `imminent`：进入临近时间窗口。
- `released`：已公布初值。
- `revised`：发生正式修订。
- `rescheduled`：时间被调整。
- `cancelled`：事件取消。
- `delayed`：公布延迟。
- `unknown`：状态无法确认。

状态规则：

- 实际值尚未公布时必须为空，不得显示为零。
- 改期必须保留原计划时间和变更时间。
- 取消和延迟不能与普通缺失数据混同。
- 修订值不得无提示覆盖初值。
- 事件生命周期变化应产生可消费事件，供提醒和其他模块更新。

### 9.4 前值、预期值和实际值

- 所有值必须绑定单位和统计期间。
- 前值修订时应区分原前值和修订前值。
- 预期值应标明来源或聚合口径，具备时。
- 实际值可以计算“相对预期差异”，但必须记录计算版本和方向口径。
- 不同指标“高于预期”的经济含义不同，页面不得统一自动标记为利多或利空。
- 对百分比、年化、月环比、同比和绝对值必须明确区分。

### 9.5 页面视图

至少支持：

- 日视图。
- 周视图。
- 列表视图。
- 事件详情。

可以后续支持：

- 月视图。
- 时间轴视图。
- 个人关注日历。

### 9.6 筛选和排序

- 日期范围。
- 国家或地区。
- 发布机构。
- 事件类别。
- 重要度。
- 是否已公布。
- 是否发生修订。
- 影响资产类别。
- 收藏或关注状态。

默认排序应以用户时区下的事件时间为主，并明确已发生和未发生事件的排列规则。

### 9.7 提醒

启用提醒时：

- 提醒是用户偏好，不改变事件事实。
- 可以按具体事件、事件类型、国家或重要度设置。
- 提醒时间基于正式事件时间和用户时区。
- 改期、取消和延迟应更新或撤销相关提醒。
- 提醒发送属于 Notification 能力，本模块只维护偏好和上下文。
- 提醒不等于交易或风险信号。

### 9.8 宏观日历边界

- 日历只提供事件和数据事实，不自动解释完整宏观逻辑。
- 复杂历史分析应进入对冲基金看板。
- 交易许可和新闻禁入规则由交易与风险领域决定。
- 风险事件正式定级由 Risk 领域决定。

## 10. 新闻整理详细需求

### 10.1 NewsContent 核心字段

- `contentId`。
- 标题。
- 摘要。
- 原始发布时间。
- 平台收录时间。
- 最近更新时间。
- 来源名称和来源 ID。
- 原文链接。
- 内容语言。
- 国家、地区和市场。
- 资产分类。
- 主题标签。
- 关联标的、公司、策略或事件稳定 ID，适用时。
- 重要度。
- 方向标签，适用时。
- 摘要类型。
- 摘要生成时间。
- 是否经过人工复核。
- 事实确认状态。
- 重复或聚类关系。
- 链接状态。
- 数据质量。

### 10.2 摘要类型

必须区分：

- 原文提供摘要。
- 平台人工摘要。
- AI 生成摘要。
- 第三方聚合摘要。
- 仅标题，无摘要。

规则：

- AI 摘要必须标明生成属性、生成时间和来源文章。
- 摘要不得改变原文核心事实。
- AI 或人工观点必须与事实摘要分开。
- 原文更新后，旧摘要需要标记可能过期或重新生成。
- 未经核实的社交媒体信息必须显著标记。

### 10.3 内容分类

建议支持：

- 宏观与政策。
- 商品与金属。
- 加密资产。
- 美股与全球股票。
- A 股与中国市场。
- 利率、外汇和信用。
- 公司、行业和财报。
- 交易所、经纪商和市场基础设施。
- 监管与合规。
- 其他已确认分类。

分类体系需要稳定 ID 和版本，不能仅依赖展示字符串。

### 10.4 StoryCluster

同一事件被多家来源报道时，可以形成 `StoryCluster`：

- `clusterId`。
- 统一故事标题。
- 首次发生或首次报道时间。
- 最近更新时间。
- 代表性内容。
- 关联内容列表。
- 来源数量。
- 已确认事实摘要，适用时。
- 冲突点，适用时。
- 关联资产和主题。

规则：

- 聚类不删除原始内容记录。
- 用户可以查看不同来源。
- 自动聚类置信度不足时不得强制合并。
- 同一新闻的转载、翻译和轻微改写应尽量识别重复。
- 重大事实冲突必须保留，而不是通过聚类隐藏。

### 10.5 方向和影响标签

方向或影响标签可以包括：

- 正向。
- 负向。
- 中性。
- 混合。
- 不确定。
- 未标注。

但必须明确：

- 标签是内容整理属性。
- 标签不是 `TradeSignal`。
- 标签不是 `RiskStatus`。
- 标签不能直接触发下单、风险覆盖和仓位变化。
- 同一新闻对不同资产的影响方向可能不同，不能只保留一个无上下文方向。

### 10.6 搜索、筛选和排序

至少支持：

- 关键词。
- 日期范围。
- 资产分类。
- 主题。
- 国家、地区和市场。
- 来源。
- 重要度。
- 摘要类型。
- 是否人工复核。
- 事实确认状态。
- 收藏和已读状态。
- 是否属于 StoryCluster。

排序候选：

- 最新发布。
- 最近更新。
- 重要度。
- 相关性。

排序算法和字段需要稳定、可解释，不得让同一筛选在短时间内无原因大幅重排。

### 10.7 版权和引用

- 不复制受版权保护的完整新闻正文。
- 展示原始来源、标题、合规摘要和链接。
- 直接引用应遵守授权和长度限制。
- 付费墙内容只展示授权元数据和摘要。
- 原文被删除时按保留规则保留元数据，并标记链接状态。
- 导出内容同样遵守来源和授权限制。

## 11. 理财信息详细需求

### 11.1 产品定位

理财信息用于汇总公开产品、活动和收益机会，帮助用户比较条件并进入外部来源核对。

本模块：

- 不代替用户完成申购。
- 不托管用户资产。
- 不保存外部平台资金密码。
- 不连接用户钱包进行授权。
- 不承诺本金和收益。
- 不把平台宣传文案当成独立验证事实。

### 11.2 WealthOpportunity 核心字段

- `opportunityId`。
- 产品或活动名称。
- 平台或机构。
- 产品类型。
- 支持资产。
- 计价资产。
- 收益展示值。
- 收益类型。
- 收益频率。
- 收益区间，适用时。
- 奖励构成，适用时。
- 产品期限。
- 锁仓条件。
- 赎回或退出条件。
- 起始时间。
- 截止时间。
- 到期时间。
- 最低参与金额。
- 最高额度或个人额度，已知时。
- 总活动额度，已知时。
- 新用户限制。
- KYC 限制。
- 地区限制。
- 账户等级或资格限制。
- 参与步骤摘要。
- 风险和限制说明。
- 来源和外部链接。
- 原始发布时间。
- 最近核对时间。
- 生命周期状态。
- 数据质量。

### 11.3 产品类型候选

- 活期或灵活储蓄。
- 定期或锁仓产品。
- 交易所 Earn 类产品。
- 稳定币收益产品。
- 新用户或充值活动。
- 交易返利和手续费活动。
- Staking 或链上收益入口，明确外部性质。
- 结构化或双币产品，必须显著提示非线性风险。
- 其他经产品确认的公开机会。

分类不代表产品安全等级，风险需要独立表达。

### 11.4 收益类型

必须区分：

- 历史已实现收益率。
- 当前展示年化。
- 预估收益率。
- 浮动收益率。
- 固定合同收益率，只有正式条款明确时。
- 分档收益率。
- 限时加息。
- 奖励、返券或代币激励折算值。
- 活动宣传值。

规则：

- 不将 APR 和 APY 混用。
- 必须标明收益计算周期和复利假设。
- 分档收益必须展示适用额度区间。
- 限时加息必须展示有效期和基础收益。
- 奖励代币价值必须标明价格时间和估算属性。
- 浮动收益不得用“锁定收益”文案。
- 活动宣传值必须保留来源和原始条件。

### 11.5 生命周期状态

- `upcoming`：尚未开始。
- `active`：当前可参与，依据外部信息。
- `quota_limited`：可能受额度限制。
- `ending_soon`：临近截止。
- `expired`：已到期或活动结束。
- `suspended`：外部暂停。
- `unverified`：无法确认当前状态。
- `invalid`：信息明显无效或不适用。

页面不能因为外部链接仍可访问就自动判断产品仍可参与。

### 11.6 风险维度

至少展示已知项：

- 平台或对手方风险。
- 托管风险。
- 稳定币或基础资产风险。
- 流动性和锁仓风险。
- 提前退出和赎回限制。
- 收益率浮动风险。
- 活动额度和资格不确定性。
- 地区、KYC 和合规限制。
- 结构化产品本金损失风险。
- 链上智能合约风险，适用时。
- 汇率和计价资产风险。

风险说明是信息披露，不等于平台完成正式尽调或提供投资建议。

### 11.7 筛选和排序

- 平台或机构。
- 产品类型。
- 支持资产。
- 收益类型。
- 展示收益区间。
- 期限。
- 是否锁仓。
- 是否允许灵活赎回。
- 最低参与金额。
- 新用户限制。
- 地区和 KYC 限制。
- 生命周期状态。
- 最近核对时间。
- 收藏状态。

排序候选：

- 最近核对。
- 截止时间。
- 产品期限。
- 展示收益率。

按收益率排序时必须保留收益类型和条件，不能将不可比较产品伪装为同口径排名。

### 11.8 外部参与入口

- 明确显示真实平台、域名和跳转目的。
- 资金相关跳转应提示即将离开平台。
- 平台不得自动填充密码、API Key、助记词或资金地址。
- 页面不得自动触发钱包连接和授权。
- 外部链接失效、重定向异常或域名变化时应阻止或提示。
- 用户最终参与前必须在外部正式页面核对条款。

## 12. 收藏、已读和个人关注

### 12.1 UserBookmark

至少包含：

- 用户 ID。
- 目标对象类型。
- 目标对象 ID。
- 收藏时间。
- 用户标签，启用时。
- 用户备注，启用时。

### 12.2 ReadState

至少包含：

- 用户 ID。
- 内容 ID。
- 首次阅读时间。
- 最近阅读时间。
- 是否手动标记未读，适用时。

### 12.3 规则

- 收藏和已读属于用户偏好，不改变源对象。
- 内容被合并、下架或失效时，收藏应保留可解释状态。
- 权限被撤销后不得继续通过收藏读取内容。
- 用户备注与正式内容摘要分开。
- 收藏数量、用户行为和内部备注可能属于敏感数据。
- 收藏和已读操作应幂等。

## 14. 数据质量、确认和内容状态

### 14.1 通用质量状态

至少支持：

- `complete`。
- `partial`。
- `delayed`。
- `stale`。
- `missing`。
- `conflicted`。
- `unverified`。
- `invalid`。

### 14.2 事实确认状态

新闻和部分理财信息可以支持：

- `official`：官方或正式披露。
- `confirmed`：由多个可靠来源确认。
- `single_source`：仅单一来源。
- `reported`：已报道但尚未充分确认。
- `disputed`：来源存在重大冲突。
- `retracted`：来源撤回。
- `unknown`：无法判断。

质量状态和事实确认状态不得混同。例如：

- 数据可以完整但仍只有单一来源。
- 内容可以来源官方但因接口延迟处于 stale。

### 14.3 通用规则

- 缺失值不得显示为零。
- 过期数据保留最近值时必须显示最后核对时间。
- 冲突数据应显示冲突来源或选定规则。
- 撤回、删除和修订必须保留历史关系。
- AI 摘要错误不得修改原始来源内容。
- 内容质量异常可以跳转至风险管理的数据与服务监控，具备权限时。

## 15. 外部链接安全

- 链接必须明确展示来源和目标域名。
- 不使用误导性短链隐藏最终目标，除非经过安全解析。
- 跳转前可以执行域名白名单、恶意链接和重定向检查。
- 高风险、资金和钱包相关跳转应二次提示。
- 域名变化、证书异常或重定向异常应阻止自动打开并展示原因。
- 外部网站的 Cookie、登录和支付流程不进入平台会话。
- 平台不向外部页面传递内部 Token、账户信息、订单信息和敏感查询参数。
- 外部页面不可用时保留来源元数据和失效状态。

## 16. 异常、空数据和降级

### 16.1 通用页面状态

每个栏目至少区分：

- 初次加载。
- 后台刷新。
- 无符合条件的数据。
- 部分来源失败。
- 全部来源失败。
- 数据延迟或过期。
- 来源冲突。
- 无权限。
- 外部链接失效。
- 结果未知。

### 16.2 局部降级

- 宏观日历失败不影响新闻和理财栏目。
- 某个新闻来源失败不影响其他来源。
- Story Cluster 服务失败时可以降级为普通新闻列表。
- 理财收益字段缺失时仍可展示产品条件，但不能虚构收益。
- 收藏服务失败时不影响内容读取，并明确收藏状态暂不可用。
- 提醒服务失败时不影响日历事实展示。
- 搜索服务失败时可以降级为基础筛选或最近内容列表。

### 16.3 缓存和过期内容

允许显示缓存时必须同时显示：

- 最后成功更新时间。
- 当前质量状态。
- 是否仍在刷新。
- 哪些字段可能过期。

不得将缓存内容标记为实时或最新。

## 17. 跨模块关系

### 17.1 对冲基金看板

可以引用：

- 宏观事件时间和实际结果。
- 新闻和 Story Cluster 作为图表注释和研究背景。
- 稳定 `eventId`、`contentId` 和 `topicId`。

看板不复制完整新闻和理财列表，也不成为内容维护入口。

### 17.2 策略

交易平台可以读取：

- 临近高重要度事件。
- 与当前标的、市场和策略相关的内容摘要。
- 数据时间和质量。

但：

- 本模块不生成 `TradeCommand`。
- 新闻方向标签不成为交易信号。
- 新闻提醒不代替交易禁入和风险规则。
- 策略管理可以在 ExecutionBatch、PnL 或异常复盘中关联稳定内容 ID。

### 17.3 风险管理

风险事件可以关联：

- 宏观事件。
- 新闻内容。
- 来源冲突。
- 数据源和外部链接异常。

但风险规则、风险判断、风险级别和处置仍由 Risk 领域维护。

### 17.4 金融AI分析

可以读取授权：

- 事件。
- 新闻摘要。
- Story Cluster。
- 理财信息元数据。
- 来源和质量状态。

要求：

- AI 输出保留引用的稳定 ID、来源和时间。
- AI 不反向覆盖原始内容。
- AI 不把理财宣传值改写为确定收益。
- AI 不直接触发交易或资金操作。

### 17.5 首页

首页仅展示少量授权内容或近期事件摘要，并跳转至本模块；不复制完整列表和详情。

## 18. 非功能要求

### 18.1 性能和分页

- 列表使用分页、游标或按需加载。
- 大日期范围查询应采用服务端筛选和聚合。
- 搜索、筛选和排序结果应稳定可预测。
- 详情加载不应阻塞列表浏览。
- 单一来源超时不应拖慢全部来源到不可用。

### 18.2 时间和时区

- 数据库和接口保留原始时区与标准时间。
- 页面按用户时区展示，并明确时区。
- 相对时间不能替代精确时间。
- 夏令时变化需要正确处理。
- 宏观事件改期和跨日必须可追溯。

### 18.3 可访问性和桌面体验

- 颜色不能是重要度、方向和质量的唯一表达方式。
- 表格、列表和日历支持键盘焦点和基本屏幕阅读语义。
- 长标题和多语言内容不能破坏布局。
- 外部链接、AI 摘要和风险提示具有明确文本标识。

### 18.4 可观测性

至少监控：

- 数据源同步成功率和延迟。
- 来源冲突和重复率。
- 链接失效率。
- 新闻聚类失败率。
- 宏观事件更新时间偏差。
- 理财信息过期未更新数量。
- 搜索和列表查询错误率。
- 收藏和提醒服务错误率。

## 19. 导入、导出和内容维护

### 19.1 数据导入

外部或人工导入至少保留：

- 导入批次 ID。
- 来源文件或接口。
- 原始记录 ID。
- 导入时间。
- 字段映射版本。
- 校验错误。
- 重复判断结果。
- 操作者或任务。

导入记录不得绕过内容对象、质量和来源模型直接写入前端 Read Model。

### 19.2 导出

导出必须遵守：

- 数据权限。
- 来源授权。
- 内部备注权限。
- 时间和质量字段保留。
- 版权和外部使用限制。

### 19.3 内容修正

修正不得直接覆盖历史而不留记录。需要保留：

- 原值。
- 新值。
- 修正原因。
- 证据来源。
- 操作者。
- 时间。
- 复核状态，适用时。

## 20. 前端要求

- 三个栏目共享统一模块骨架，但组件和 View Model 不强制共用同一业务对象。
- 前端通过 API DTO 和 Adapter 生成栏目 View Model。
- 页面不得直接依赖外部 API 的原始字段。
- 重要度、方向、事实确认和数据质量分别展示。
- 外部链接、内部跳转和详情弹窗具有不同交互表现。
- 收藏、已读和提醒属于独立用户状态。
- 页面刷新后可以恢复栏目和安全筛选。
- 断线重连后重新 Query 权威状态，不依赖前端事件补齐。
- 失效理财信息不得继续以普通 active 卡片展示。

## 21. 后端和数据依赖

候选依赖：

- Content and Calendar Data。
- Source Registry。
- Content Ingestion／Curation。
- Search and Index，启用时。
- User Preference。
- Notification，提醒启用时。
- IAM 和 Data Scope。
- Backend Read Model。
- Audit。
- Data Quality。

本模块页面不能成为：

- 原始内容存储的唯一来源。
- 用户权限权威。
- 外部链接安全判断的唯一实现。
- 交易和风险命令入口。

## 22. 验收标准

### 22.1 产品边界

- 三个栏目具有清晰独立对象和业务语义。
- 页面不包含正式交易、申购、赎回、转账和风险处置主操作。
- 看板、策略、风险和金融AI分析只通过稳定 ID 和权威 Query 获取内容。

### 22.2 宏观日历

- 事件具有稳定 ID、国家、时间、时区、重要度、来源和质量。
- 前值、修订前值、预期值、实际初值和修订值可以正确区分。
- 未公布实际值不会显示为零。
- 改期、取消、延迟和修订具有明确生命周期。
- 用户时区和原始时区均可追溯。

### 22.3 新闻整理

- 新闻具有来源、原始发布时间、收录时间和摘要类型。
- AI 摘要和人工摘要明确区分。
- 方向标签不会被误作 TradeSignal 或 RiskStatus。
- 重复新闻和 Story Cluster 不删除原始来源记录。
- 来源冲突、撤回和链接失效可以表达。
- 页面不复制受版权保护的完整正文。

### 22.4 理财信息

- 产品具有平台、资产、期限、锁仓、赎回、限制、来源和最近核对时间。
- APR、APY、浮动、历史、预估和活动宣传值不会混用。
- 收益条件、额度和资格限制可以展示。
- 过期、暂停和无法确认的产品不会继续显示为普通 active。
- 外部参与入口清晰提示离开平台和资金风险。
- 页面不保存外部平台密码、API Key、助记词和资金地址。

### 22.5 权限和用户状态

- 栏目、数据集、内部备注、导出和内容维护分别授权。
- 收藏、已读和提醒只修改用户偏好，不修改源内容。
- 权限撤销后不能通过收藏继续访问内容。
- 前端隐藏不能替代后端权限校验。

### 22.6 数据和异常

- 所有对象具有来源、原始时间、平台时间和数据质量。
- 缺失值不会静默转换为零。
- 单一数据源失败不会导致整个模块白屏。
- 缓存和过期数据明确显示最后成功时间。
- 外部链接失效、重定向异常和来源冲突具有明确状态。

### 22.7 路由和交互

- 栏目、日期和安全筛选可通过刷新、前进、后退恢复。
- 不安全或未授权参数不会进入 URL。
- 筛选变化后分页回到安全起点。
- 外部链接、内部跳转和详情查看不会混淆。

## 23. 未决事项

以下内容需要在数据源、运营流程和安全架构讨论后确定：

1. 宏观日历的正式数据源组合和冲突优先级。
2. 是否建设独立内容编辑和人工复核工作台。
3. 新闻 Story Cluster 的自动化深度和人工修正流程。
4. AI 摘要默认是否必须人工复核。
5. 理财信息允许覆盖的产品和平台范围。
6. 理财信息是否需要正式风险等级，若需要应由哪个领域维护。
7. 用户提醒的通知渠道和频率。
8. 收藏、已读和 Saved View 的保存周期。
9. 内容导出范围和版权限制。
10. 外部链接安全检查与域名白名单策略。
11. 内部备注是否进入当前产品范围。
12. 内容保留、归档和删除周期。
