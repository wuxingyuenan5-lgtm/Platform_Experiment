# 交易平台：模块定位

状态：`active`  
产品基线：Platform V5  
架构版本：Platform V6  
适用分支：`refactor/frontend-architecture-v6`  
文档层级：二级产品模块定位

## 1. 模块定位

交易平台是策略模块中的交易前分析与交易执行工作台，负责将机会判断、交易参数准备、TradeCommand 发起、ExecutionBatch 跟踪、订单成交、执行配平和异常处理组织为完整产品流程。

覆盖：

- 资费套利。
- 跨所价差。
- 海内外价差。

抄底、短线交易员 L 和短线交易员 W 不通过交易平台执行。

交易平台是内部交易和执行工作台，不面向投资者或客户侧开放。投资者或客户侧未来只能通过策略管理、报表或专门客户展示页读取产品化后的结果；具体客户权限和客户侧页面等用户系统完成后再展开。

## 2. 核心用户

- 研究和交易人员。
- 具有交易准备或提交权限的操作人员。
- 策略负责人。
- 查看执行状态的只读观察人员。

## 3. 核心任务

1. 选择策略实例、市场、标的和账户。
2. 判断当前是否存在可执行机会。
3. 评估价差、费率、分位、成本、收益和风险。
4. 准备两条交易腿的方向、数量、价格和订单类型。
5. 查看 DeploymentEnvironment、TradingMode 和 TradingPermissionState。
6. 完成执行前校验和提交确认。
7. 发起 TradeCommand。
8. 跟踪 ExecutionBatch、Order、Fill、执行配平和暴露。
9. 处理部分成交、结果未知、单腿暴露和人工介入。

当前阶段交易平台必须同时支持两层验证：第一层是 Simulation／Fake Gateway，用于本地工程闭环和故障演练；第二层是真实交易所或经纪商 API 的模拟盘、测试盘或 Demo 账户链路，用于验证真实外部接口、订单回报、成交回报、断线恢复和账户同步。V1 需要把真实 API 接入链路跑通，但不等同于默认开放真实资金 Live 下单。

真实外部 API 接入前后，页面都必须稳定表达命令受理、订单创建、成交回报、结果未知、部分成交和单腿暴露。第一阶段不要求实现复杂自动补单、自动配平和高级算法执行。

## 4. 页面结构

固定分为：

### 行情分析

回答：

- 当前是否存在机会。
- 机会处于何种历史位置。
- 预期收益是否覆盖成本和风险。
- 应选择哪些交易场所、标的或合约组合。

行情分析不提供正式交易主操作。

### 交易执行

回答：

- 当前是否允许交易。
- 两条交易腿如何配置。
- 预计收益、成本、资金和风险影响如何。
- 命令是否受理。
- 执行批次、订单、成交、配平和暴露处于什么状态。
- 是否需要撤单、补单、配平或人工处理。

## 5. 产品主责内容与数据权威

交易平台是以下内容的主要产品工作台：

- 当前分析上下文。
- 未提交交易参数。
- TradeIntent 准备。
- TradeCommand 发起和受理反馈。
- 当前 ExecutionBatch 工作视图。
- 当前订单、成交、配平、暴露、账户和风险摘要。

技术权威分别属于：

- Market Data：报价与合约规则。
- Strategy：策略实例和账户绑定。
- Trading and Execution：TradeCommand、ExecutionBatch、Order 和 Fill。
- Account and Position：账户、余额、保证金和持仓。
- Risk：风险判断和阻断。

页面和浏览器状态不是上述事实的最终权威。

## 6. 执行链路

```text
前端准备 TradeIntent
→ 提交 TradeCommand
→ 后端权限、参数、模式、风险、审批和幂等校验
→ 创建 ExecutionBatch
→ 生成 LegInstruction
→ Gateway 创建 Order
→ 接收 Fill
→ 计算 ExecutionBalanceStatus 和 ExposureStatus
```

前端不得分别提交两张订单并自行假定形成可靠双腿交易。

V1 的执行目标是让风险和执行状态可见、可恢复、可人工处理；不要求系统自动消除所有执行风险。

跨所价差 V1 必须特别处理跨 Runtime、跨账户和跨市场的执行事实恢复。Crypto 腿和 MT5 腿不能被前端简单拼接成一笔交易；MT5 的 Order、Deal 和 Position 语义必须单独映射，断线后以服务端 Query 和外部历史查询恢复，不依赖浏览器内存判断是否成交。

## 7. 状态维度

交易平台需要展示：

- QuoteStatus。
- DataQualityStatus。
- TradingPermissionState。
- TradeCommandStatus。
- ExecutionBatchStatus。
- OrderStatus。
- ExecutionBalanceStatus。
- ExposureStatus。
- RiskStatus。
- GatewayStatus。

完整状态码和生命周期以 `docs/architecture/domain/status-enums-and-lifecycles.md` 为唯一来源，本文件不重复维护状态清单。

## 8. 与其他模块的关系

- 对冲基金看板提供研究背景和 Research Data。
- 新闻日历与理财提供重要事件提醒。
- 策略管理通过后端权威事实和 Read Model 查询长期结果，不接收前端页面复制数据。
- 风险管理维护风险规则、事件和处置，交易平台读取服务端判断与交易许可。
- 金融AI分析可以读取授权分析和执行材料，不修改交易事实。

## 9. 明确不负责

- 非平台执行策略的正式下单。
- 长期绩效和完整损益归因。
- 全生命周期订单、成交和对账档案主入口。
- 账户主档和公司财务。
- 全局研究、风险规则、用户权限和审计管理。

## 10. 验收标准

- 只展示三类 `platform.enabled = true` 策略。
- 行情分析与交易执行边界清晰。
- TradeCommand 和 ExecutionBatch 分开。
- 双腿执行由后端 ExecutionBatch 组织。
- 运行环境、交易模式和交易能力清晰展示。
- 结果未知不会被误判为失败并直接重复下单。
- 当前执行视图与长期查询和复盘边界清晰。
