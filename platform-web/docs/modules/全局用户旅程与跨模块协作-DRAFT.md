# Variable-Global 全局用户旅程与跨模块协作

状态：`draft`  
产品基线：Platform V5  
架构讨论版本：Platform V6+  
适用分支：`refactor/frontend-architecture-v6`  
文档层级：跨模块产品需求  
更新日期：2026-07-17

## 1. 文档定位

本文定义用户如何在六个一级模块之间完成完整任务，以及模块之间允许传递哪些上下文、读取哪些权威事实、发起哪些流程。

本文不重新定义各模块内部页面，也不允许通过跨模块旅程建立第二套业务事实。

---

## 2. 六个一级模块

1. 首页。
2. 对冲基金看板。
3. 新闻日历与理财。
4. 策略。
5. 风险管理。
6. 金融AI分析。

跨模块旅程必须保留一级模块边界，不能因为用户从一个页面跳到另一个页面，就把两个模块合并成一个产品或技术领域。

---

## 3. 跨模块协作原则

### 3.1 通过稳定 ID 传递上下文

允许传递：

- StrategyId。
- strategyInstanceId。
- accountId。
- instrumentId。
- venueId。
- orderId。
- fillId。
- executionBatchId。
- riskEventId。
- reconciliationRunId。
- reportVersionId。
- analysisTaskId。
- 时间区间、币种和已确认筛选条件。

不允许直接传递并信任：

- 页面内存中的完整 Order 对象。
- 页面自行计算的 Position 或 PnL。
- 前端生成的风险状态。
- 未验证的账户余额。
- 未经服务端授权的数据范围。

目标页面应根据稳定 ID 重新执行权威 Query。

### 3.2 跳转不改变数据权威

例如：

- 从风险页面跳到订单详情，Order 仍由 Trading and Execution 负责。
- 从策略管理跳到账户详情，Account 仍由 Account 负责。
- 从金融AI分析跳到策略材料，AI 结果不成为策略事实。
- 从首页进入风险页面，首页摘要不成为风险权威。

### 3.3 摘要与详情分开

源模块负责完整详情，其他模块只展示：

- 必要摘要。
- 状态提示。
- 来源时间。
- 跳转入口。

摘要不得增加独立写入和独立计算口径。

### 3.4 写入由目标领域执行

跨模块页面可以发起流程，但正式写入由目标领域完成。

示例：

- 策略页面发起 TradeCommand，Trading 执行。
- 风险页面发起账户修正，Account 或 Reconciliation 执行。
- 报表页面发起报告生成，Reporting 执行。
- AI 页面提出分析任务，AI Orchestration 执行。

## 4. 旅程一：首页进入业务模块

### 4.1 用户目标

用户希望从首页快速理解当前平台概况，并进入下一步工作。

### 4.2 首页可展示

- 市场或研究摘要。
- 重要策略状态摘要。
- 风险或服务异常提示。
- 待处理审批或任务数量。
- 模块入口。

具体显示项可以按权限和配置变化。

### 4.3 跳转上下文

首页可以传递：

- 目标模块。
- 指定 StrategyId 或 riskEventId，适用时。
- 时间区间。
- 预设筛选。

目标模块必须重新查询详情。

### 4.4 降级

当摘要数据不可用时：

- 首页仍保留模块导航。
- 明确显示延迟或不可用。
- 不显示虚构零值。
- 不因为摘要不可用阻断目标模块独立访问。

---

## 5. 旅程二：研究信息进入策略机会分析

### 5.1 起点

- 对冲基金看板。
- 新闻日历与理财。
- 金融AI分析结果，适用时。

### 5.2 用户目标

将研究背景带入某个策略的行情分析页面，继续判断是否存在交易机会。

### 5.3 允许传递

- StrategyId。
- instrumentId 或资产类别。
- Venue 或地区。
- 时间区间。
- 研究条目、新闻或日历事件的稳定引用 ID。

### 5.4 目标行为

策略行情分析页面：

1. 验证 StrategyId 是否具备行情分析能力。
2. 验证用户数据范围。
3. 重新查询 Execution Market Data 和策略分析数据。
4. 可以展示来源研究条目的只读引用。
5. 不将新闻标签或 AI 观点直接解释为交易信号。

### 5.5 边界

- Research Data 不自动变成 Execution Market Data。
- 研究时间可能晚于或早于实时行情，必须分别显示。
- 研究结论不能绕过策略专项规则、风险和执行前检查。

---

## 6. 旅程三：策略行情分析进入交易执行

### 6.1 用户目标

在同一 StrategyId 和市场上下文下，从机会分析进入交易参数准备。

### 6.2 可继承内容

- StrategyId。
- instrumentId。
- Venue 和市场组合。
- 时间精度和分析区间。
- 已选择的交易场景。
- 只读机会摘要。

### 6.3 不自动继承

- 上一次未提交的数量、价格和订单类型，除非明确保存在当前策略草稿。
- 其他 StrategyId 的交易参数。
- 已过期报价。
- 前端计算的最终风险许可。

### 6.4 进入执行页后

必须重新获取：

- 最新报价和 QuoteStatus。
- Account、BalanceSnapshot 和 MarginSnapshot。
- Gateway 和 Runtime 状态。
- TradingPermissionState。
- RiskDecision。
- Approval 要求。

### 6.5 离开保护

存在未提交参数时：

- 切换策略、账户或模式前提示。
- 页面刷新后是否恢复草稿由产品规则决定。
- 草稿不得被误认为已经提交的 TradeCommand。

---

## 7. 旅程四：交易执行进入策略管理复盘

### 7.1 用户目标

从当前或已完成的执行批次进入长期结果、账户和订单查询。

### 7.2 传递 ID

- StrategyId。
- strategyInstanceId。
- executionBatchId。
- orderId，适用时。
- 目标管理视角。

### 7.3 目标视角

#### 策略损益

查看：

- 执行批次对总损益和归因的影响。
- 费用、Funding、Swap 和调整项。
- 计算版本和数据质量。

#### 账户资金

查看：

- 执行前后账户、余额、保证金和持仓变化。
- 多账户失衡。
- 对账状态。

#### 订单信息

查看：

- LegInstruction、Order 和 Fill。
- 部分成交、撤单、结果未知和人工处理。
- 外部 ID 和来源。

### 7.4 边界

策略管理不得重新计算第二套 Order、Fill、Position 和实际 PnL。

---

## 8. 旅程五：异常执行进入风险与对账

### 8.1 触发条件

- 单腿暴露。
- 最大残腿时间超限。
- 订单结果未知。
- 外部订单与平台记录不一致。
- 持仓或账户差异。
- Gateway 或 Runtime 异常。
- 数据质量不满足要求。

### 8.2 用户目标

判断异常影响范围，并完成阻断、核对、人工处理或恢复。

### 8.3 路径

```text
交易执行异常
→ RiskEvent 或 ReconciliationDifference
→ 风险管理／风控详情或数据与服务监控
→ 关联 ExecutionBatch、Order、Account、Runtime
→ 人工决定或授权命令
→ 原领域执行处置
→ 审计和状态回写
```

### 8.4 允许动作

按权限和异常类型：

- 只读查看。
- 阻断新增风险。
- 撤销活动订单。
- 补对冲或减仓。
- 标记等待外部确认。
- 发起对账。
- 确认外部手工订单。
- 发起数据修正。

### 8.5 边界

- 风险管理不直接覆盖 Order 和 Position 原始事实。
- 对账差异不等于自动修正。
- 人工处理必须记录原因、操作者和目标对象。

---

## 9. 旅程六：账户异常进入策略影响分析

### 9.1 起点

风险管理／账户与资产或财务与资金。

### 9.2 用户目标

了解账户余额、保证金、币种或资金异常影响哪些策略实例和执行批次。

### 9.3 路径

```text
Account / Balance / Margin 异常
→ 查询 StrategyAccountBinding
→ 显示受影响 StrategyInstance
→ 跳转策略管理账户资金
→ 必要时进入交易执行减仓或人工处理
```

### 9.4 边界

- Account 主档属于 Account。
- StrategyAccountBinding 属于 Strategy。
- 策略页面不得修改账户主档。
- 风险状态属于 Risk，不通过账户字段字符串推断。

---

## 10. 旅程七：数据质量异常进入源数据和业务影响

### 10.1 起点

风险管理／数据与服务监控，或任意业务页面的数据质量提示。

### 10.2 用户目标

识别数据异常来源、影响对象和是否需要阻断业务。

### 10.3 数据异常类型

- 延迟。
- 缺失。
- 冲突。
- 顺序错误。
- 来源不可用。
- 修订。
- 计算失败。
- 单位或币种不一致。

### 10.4 路径

```text
DataQualityState
→ 查看来源、时间和影响范围
→ 关联图表、策略、订单、PnL 或 AI 结果
→ 决定只读降级、阻断交易或等待恢复
→ 必要时发起重新同步或对账
```

### 10.5 边界

业务页面只展示状态和限制；数据质量主责模块维护来源状态和诊断信息。

---

## 11. 旅程八：外部或人工数据导入策略管理

### 11.1 适用场景

- 抄底。
- 短线交易员 L。
- 短线交易员 W。
- 海内外价差国内腿外部执行。
- 其他未通过平台执行的历史数据。

### 11.2 流程

```text
选择导入类型和策略
→ 上传文件或连接外部来源
→ 建立 ImportBatch
→ 字段、时间、币种、单位和 ID 校验
→ 映射为平台标准对象
→ 生成错误和差异
→ 用户确认或修正
→ 进入正式查询和 PnL 计算
```

### 11.3 要求

- 保留原始文件或来源引用。
- 保留外部 ID。
- 记录导入版本和时间。
- 不直接写入前端 Read Model。
- 未通过校验的数据不得无提示进入正式统计。
- 修正不得覆盖原始导入记录。

---

## 12. 旅程九：业务数据生成正式报表

### 12.1 起点

- 策略管理。
- 风险管理。
- 报表入口。

### 12.2 流程

```text
选择 ReportDefinition
→ 选择时间、策略、账户和币种范围
→ 读取权威事实和版本化结果
→ 生成 ReportRun
→ 校验数据质量和截止时间
→ 形成 ReportVersion
→ 审阅、发布或导出
```

### 12.3 要求

- 报表版本不可被静默覆盖。
- 明确数据截止时间。
- 明确计算版本。
- 正式发布与临时预览分开。
- 报表不自行形成新的业务事实。

---

## 13. 旅程十：授权业务数据进入金融AI分析

### 13.1 起点

- 对冲基金看板。
- 新闻日历与理财。
- 策略管理。
- 风险管理。

### 13.2 流程

```text
用户选择问题和授权来源
→ 创建 AnalysisTask
→ 读取受控 Query / Read Model
→ 保留来源、时间和数据质量
→ 生成 AnalysisResult
→ 标记事实、引用、假设、推断和情景
→ 用户查看、编辑或引用
```

### 13.3 要求

- AI 只能读取用户有权访问的数据。
- 输出继承来源权限。
- 必须保留来源引用和截止时间。
- AI 结果不得直接提交 TradeCommand、RiskCommand 或 CorrectionCommand。
- 人工编辑与 AI 原始版本分开。

---

## 14. 跨模块通知和待办

通知可以来自：

- 交易执行。
- 风险事件。
- 对账差异。
- 数据质量。
- 审批。
- 报表。
- AI 任务。
- 系统和服务。

通知只负责：

- 告知状态。
- 提供摘要。
- 提供目标对象和跳转。
- 记录阅读状态。

通知本身不执行目标业务操作。

---

## 15. 跨模块路由要求

路由至少应支持恢复：

- 一级模块。
- 二级模块或主要视角。
- StrategyId，适用时。
- 目标对象 ID，适用时。
- 日期范围和币种等兼容筛选。

禁止在 URL 中放置：

- 密钥和凭证。
- 完整敏感对象。
- 能直接赋予权限或 Live 能力的参数。

非法、无权限或失效的深链接应：

- 跳转到安全默认页面或无权限页面。
- 明确原因。
- 不泄露目标对象敏感信息。

---

## 16. 验收标准

- 六个一级模块之间的主要用户旅程可解释。
- 跨模块只传递稳定 ID 和兼容筛选，不传递权威对象副本。
- 目标页面重新查询权威事实。
- 研究、新闻和 AI 结果不会自动变成交易信号。
- 交易异常可以进入风险、对账和人工处理闭环。
- 外部执行数据可以通过导入、校验和对账进入策略管理。
- 正式报表和 AI 结果均保留来源、时间和版本。
- 通知不承担目标业务写入。
- 深链接、刷新和返回可以恢复主要上下文。
