# UI and Interaction

Platform Web 是专业金融工作台：信息密度可以高，但层级、风险和数据状态必须一眼可辨。视觉表现服务判断与操作，不用装饰掩盖数据缺失。

## 页面骨架

```text
Application Shell
  ├─ Global navigation
  └─ Module Shell
      ├─ Page title and primary action
      ├─ Filters and summary
      ├─ Main workspace
      └─ Secondary records / details
```

- 一个页面只有一个主要纵向滚动 Owner。
- 标题、筛选、摘要和主要操作在同类页面保持稳定位置。
- 固定底栏必须为正文预留空间；Overlay 有统一层级。
- 表格和图表在窄视口优先降列、换行或局部滚动，不裁掉关键风险字段。

## 视觉语言

- 沿用各模块现有主题变量；A 股看板保持平台的浅色蓝灰底、白色卡片与蓝色操作色。强调色表达选择、涨跌、警告和危险，不强制改为深色主题。
- 盈亏颜色必须同时配合符号、文字或图标，不能只靠红绿判断。
- 标题、正文、辅助信息和表格数值具有稳定字号层级。
- 数字采用一致的小数、千分位、币种和单位规则；未知值显示 `—` 或明确状态，不显示伪造的 `0`。

## 数据状态

每个数据区块必须覆盖：loading、empty、unavailable、error、permission denied 和 stale。`sample` 数据在内部保持不可执行，用户界面使用简洁业务语言，不展示工程元数据。

## 高风险交互

- 交易、撤单、平仓、配平、权限与 Kill Switch 操作需要明确对象、方向、数量和后果。
- 主要风险提示与操作不能因响应式降级而消失。
- 提交中禁止重复操作；结果未知不能显示为失败后可直接重试。
- 所有确认弹窗只总结业务意图，不展示凭据、内部 payload 或调试信息。

## 响应式基线

- 支持约定桌面视口、浏览器缩放和系统缩放组合。
- 通过统一 Grid、Flex、最小宽度和容器规则适配，不逐页面堆分辨率补丁。
- 窄视口优先保留身份、状态、风险和主要操作，次要字段进入详情或明确的更多菜单。
