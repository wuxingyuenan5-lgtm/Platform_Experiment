# ADR-011：统一金融数值、业务时间与运行状态语义

状态：`accepted`  
日期：2026-07-18  
适用分支：`refactor/frontend-architecture-v6`

## 背景

平台即将进入 Backend、Runtime、API 和真实数据接入设计。如果未提前统一金融数值、币种、单位、时间和运行状态，将产生：

- JavaScript Number、Python float 和数据库浮点导致精度误差。
- `0.5 BTC`、`5 LOT`、`5 CONTRACT` 和名义金额无法区分。
- Funding Rate 的十进制倍率和百分数混用。
- USDT 被无条件视为 USD。
- occurredAt、receivedAt、businessDate 和 tradingDay 混用。
- MT5 Broker Time、Crypto UTC 和 CTP TradingDay 无法统一。
- Gateway `connected` 被错误解释为已同步、已恢复和可 Live 交易。
- 页面格式化字符串进入领域计算和 API。

金融平台必须在代码和数据库建设前固定这些语义。

## 决策

### 1. 正式金融值使用 Decimal

Money、Price、Quantity、Rate、Balance、Position、PnL、Risk Limit 和 EconomicEvent 不使用二进制浮点作为权威值。

跨系统传输使用十进制字符串。

### 2. 值与语义不可分离

- Money 必须具有 Currency。
- Quantity 必须具有 Unit。
- Price 必须能够结合 Instrument 和 PriceUnit 解释。
- Rate 必须具有 RateType 和周期语义，适用时。
- 外汇必须明确 baseCurrency 和 quoteCurrency。

### 3. Rate 使用十进制倍率

`0.01` 表示 `1%`。

Percentage 只作为明确的展示或传输类型，不作为默认领域计算类型。

### 4. Stablecoin 不自动等于法币

USDT、USDC 和其他稳定币不自动等于 USD。

任何 1:1 或市场折算必须具有估值政策、汇率来源、时间和质量状态。

### 5. 合约与资产数量通过 ContractSpecification 换算

LOT、CONTRACT、GRAM、TROY_OUNCE、BTC 等单位不能混用。

合约乘数、合约大小、tickSize、quantityStep 和 settlementCurrency 必须版本化。

### 6. 缺失不等于零

`null`、`0`、`unavailable`、`not_applicable` 和 `unverified` 分开。

`--`、NaN、Infinity 和格式化金额不进入领域事实。

### 7. 时间点和业务日期分开

至少区分：

- occurredAt。
- externalTime。
- receivedAt。
- processedAt。
- publishedAt。
- dataAsOf。
- generatedAt。
- businessDate。
- tradingDay。
- settlementDate。
- valuationDate。

跨系统时间点使用带偏移 ISO 8601；时区使用 IANA Time Zone ID。

### 8. Venue 和策略日历显式管理

MT5 Broker Time、Crypto Funding Interval、CTP ActionDay／TradingDay 和策略自定义日界线通过日历、时区和映射规则管理，不依赖服务器本地日期或固定 UTC 偏移。

### 9. Runtime 和 Gateway 状态多维表达

正式拆分：

- RuntimeStatus。
- WorkerStatus。
- GatewayConnectivityStatus。
- GatewayAuthenticationStatus。
- GatewaySynchronizationStatus。
- GatewayReadinessStatus。
- TradingCapabilityStatus。
- MarketDataCapabilityStatus。
- RecoveryStatus。

`connected` 不等于 `authenticated`、`in_sync`、`ready` 或 `live_enabled`。

### 10. 状态唯一来源

`domain/status-enums-and-lifecycles.md` 是状态枚举与生命周期唯一来源。

其他文档不得重新维护冲突清单。

### 11. 数值与时间唯一来源

`domain/value-currency-unit-and-time-contract.md` 是数值、币种、单位、精度、舍入和时间语义唯一来源。

## 原因

- 防止真实资金场景中的精度和单位错误。
- 支持 Crypto、MT5、CTP 和基金组合层级使用统一语义。
- 使 PnL、风险、对账和报表可重现。
- 避免前端格式和外部 SDK 类型反向定义领域。
- 避免连接恢复前错误开放交易。
- 为后续 OpenAPI、JSON Schema、数据库 Schema 和契约测试提供稳定输入。

## 影响

- API 和 Runtime Schema 的金融数值使用字符串。
- Backend 和 Runtime 需要选用 Decimal 类型或库。
- 数据库需要使用精确 Numeric／Decimal 类型。
- Instrument 和 ContractSpecification 成为订单校验与单位换算前置依赖。
- 前端负责格式化，但不决定业务精度和交易日。
- Gateway UI 必须分别显示连接、同步、就绪和交易能力。
- 状态枚举变化需要兼容策略和必要版本升级。

## 禁止事项

- 不使用 JavaScript Number 或 Python float 保存正式金额和数量。
- 不以带千分位或币种符号的字符串作为 API 领域值。
- 不把百分数值直接当 Rate。
- 不把 USDT 无条件视为 USD。
- 不用 `0` 代替缺失费用和损益。
- 不用服务器本地日期直接推导 tradingDay。
- 不把 Gateway connected 展示为“实盘可交易”。
- 不使用单一 GatewayStatus 表达全部运行能力。

## 重新讨论条件

出现以下情况时可以新增 ADR 扩展本决策：

- 某外部协议无法使用十进制字符串，但仍须在 Adapter 边界转换。
- 正式 Fund NAV 或 Finance Ledger 引入新的舍入和会计日期要求。
- 新资产类别需要新的单位或价格语义。
- 法规、交易所或 Broker 对时间和精度提出强制规则。
