# ADR-003：策略注册表作为唯一策略定义来源

状态：`accepted`  
日期：2026-07-15  
适用基线：Platform V5

## 背景

V5 中交易平台和策略管理分别维护策略列表，容易出现策略名称、ID、顺序和能力范围不一致。

同时，平台执行策略和非平台执行策略的能力不同，不能简单依赖页面内硬编码数组。

## 决策

建立统一策略注册表，作为前端策略基础定义的唯一代码来源。

当前文件：

`src/views/strategy/shared/strategyRegistry.ts`

注册表负责定义：

- 策略 ID。
- 正式名称和简称。
- 策略分类。
- 展示顺序。
- 是否进入交易平台。
- 是否进入策略管理。
- 是否具备分析、执行、损益、资金、订单能力。
- 基础腿结构和账户结构。

注册表不负责：

- 页面具体布局。
- 损益明细公式。
- Mock 业务数据。
- 后端接口地址。
- 风险阈值。

## 原因

- 避免同一策略被多处重复定义。
- 保持模块范围不同但策略身份一致。
- 为未来后端、数据和权限接入提供稳定策略 ID。
- 降低新增策略时遗漏修改点的概率。

## 影响

- 后续交易平台页签应读取 `platformStrategies`。
- 后续策略管理页签应读取 `managementStrategies`。
- Mock、路由参数、筛选条件和接口适配逐步统一使用 `StrategyId`。
- 页面不得自行创建另一份完整策略主数据列表。

## 接入方式

采用小步接入：

1. 先统一页签来源。
2. 再统一 Mock 和页面类型。
3. 最后统一路由和接口适配。

不得一次性同时重写策略页面、路由、Mock 和目录结构。

## 重新讨论条件

当策略主数据由后端统一下发时，前端注册表可以演变为静态能力声明与后端数据适配层，但稳定策略 ID 和能力边界仍应保留。
