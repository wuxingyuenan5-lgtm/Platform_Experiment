## 3. 与全项目文档的关系

交易平台专项讨论必须服从完整项目需求，但完整项目需求本身也可以根据专项研究结果调整。

正确协作方式：

```text
模块和策略需求
↔ 总体与专项架构
↔ 公共领域模型
↔ 数据、接口、安全和运维架构
```

不是简单规定“谁永远优先于谁”，而是通过用户需求、业务规则、可靠性和维护成本共同收敛。

确认后的结论需要同步至：

- 对应模块需求。
- 对应策略文档。
- 总体和专项架构。
- 公共领域对象与状态。
- 模块所有权矩阵。
- ADR。

## 5. 恢复 V1 讨论的条件

满足以下条件后再恢复本专项入口：

1. 六个一级模块和重要子板块需求完成。
2. 六份策略文档完成统一审查。
3. 全局角色、用户旅程、导航、状态和非功能要求完成。
4. 总体、后端、Runtime、数据、接口、安全和运维架构完成。
5. 公共领域对象、状态和数据权威不存在重大冲突。
6. 重大决策形成 ADR。
7. 文档一致性审计完成。

随后 V1 只负责从完整目标中选择第一批交付，不再重新定义整个项目。
