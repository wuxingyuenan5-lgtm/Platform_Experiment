# 响应式布局与跨视口验收规范

状态：`active`  
适用工程：`platform-web`
架构依据：`../architecture/frontend/responsive-layout-architecture.md`

## 1. 目标

本文档将“不同屏幕下看起来正常”转换为可复现、可记录和可阻断发布的验收标准。

本文档负责：

- 定义测试视口、视口高度和缩放组合。
- 定义页面、组件和 Overlay 的检查项。
- 定义遮挡、碰撞、滚动、溢出和视觉连续性缺陷等级。
- 定义后续人工截图和自动化视觉回归的证据格式。

本文档不定义具体 CSS 实现。

## 2. 测试前提

### 2.1 必须记录的环境

每次验收至少记录：

```text
Route:
Viewport width × height:
Browser:
Browser zoom:
OS scale:
Sidebar: expanded / collapsed
User role:
Data state: normal / loading / empty / error / long-content
Commit or PR:
```

只记录显示器物理尺寸不构成有效测试证据。

### 2.2 基础数据状态

每个核心页面至少覆盖：

1. 正常数据。
2. 加载中。
3. 空数据。
4. 错误或服务不可用。
5. 权限不足（如适用）。
6. 长标题、长 ID、大金额和长标签。
7. 表格达到真实列数和操作数量。

### 2.3 导航状态

至少覆盖：

- 侧边栏展开。
- 侧边栏折叠。
- 顶部页签接近最大数量。
- 页面滚动到顶部、中部和底部。

## 3. 验收矩阵

### 3.1 全量桌面宽度

| 编号 | 宽度 | 用途 |
|---|---:|---|
| W1 | 1280 | 最小正式支持宽度 |
| W2 | 1366 | 常见笔记本 |
| W3 | 1440 | 标准办公视口 |
| W4 | 1536 | 高 DPI／125% 系统缩放常见视口 |
| W5 | 1680 | 大型办公视口 |
| W6 | 1920 | 标准全高清 |
| W7 | 2560 | 超宽屏 |

### 3.2 视口高度

| 编号 | 高度 | 重点风险 |
|---|---:|---|
| H1 | 720 | 底栏遮挡、弹窗超高、纵向空间不足 |
| H2 | 768 | 常见低高度笔记本 |
| H3 | 864 | 常见中高度视口 |
| H4 | 900 | 标准工作区 |
| H5 | 1080 | 全高清高度 |

### 3.3 浏览器缩放

| 编号 | 缩放 | 目的 |
|---|---:|---|
| Z1 | 90% | 高密度工作区 |
| Z2 | 100% | 基准 |
| Z3 | 110% | 中间缩放稳定性 |
| Z4 | 125% | 可访问性和高缩放稳定性 |

### 3.4 核心阻断组合

每个核心页面至少通过：

| 组合 | 视口 | 缩放 | 侧边栏 |
|---|---|---:|---|
| C1 | 1280 × 720 | 100% | 展开 |
| C2 | 1366 × 768 | 100% | 展开 |
| C3 | 1440 × 900 | 100% | 展开 |
| C4 | 1536 × 864 | 100% | 展开 |
| C5 | 1920 × 1080 | 100% | 展开 |
| C6 | 2560 × 1080 | 100% | 展开 |
| C7 | 1440 × 900 | 125% | 展开 |
| C8 | 1280 × 720 | 100% | 折叠 |

核心交易和风险页面还应增加低高度、弹窗和固定操作栏组合。

## 4. 页面级通过条件

页面在每个阻断组合中必须满足：

- 页面主体不存在非预期横向滚动。
- 页面主要纵向滚动可以到达全部内容。
- 标题、筛选器、主要按钮和关键状态不重叠。
- 最后一个业务区块和最后一个操作控件不被底栏覆盖。
- 页面背景、表面和模块边界连续。
- 侧边栏展开／折叠不会造成主区覆盖或固定偏移错误。
- 页面切换正常、加载、空和错误状态时外层结构不跳变到不可用。
- 主要业务动作始终可见或可通过明确的更多操作访问。
- 焦点元素、下拉菜单和 Tooltip 不被父容器裁切。

## 5. 组件级通过条件

### 5.1 页面标题和工具栏

- 标题允许换行但不得覆盖操作区。
- 主操作保持可见。
- 次要操作折叠后有明确入口。
- 筛选器换行顺序稳定，不出现标签与控件分离。
- 控件不低于其最小可用宽度。

### 5.2 指标卡

- 数值、单位和标签不重叠。
- 长数值不会推出卡片边界。
- 降列后阅读顺序不改变。
- 不通过无限缩小字号解决空间不足。

### 5.3 图表

- 标题、图例、坐标轴、Tooltip 和工具栏可见。
- 容器宽度变化后图表完成 resize。
- 图表不覆盖相邻卡片。
- 双栏变单栏时顺序符合业务主次。
- 空数据和错误态保持合理最小高度。

### 5.4 表格

- 超宽内容只在表格容器内部横向滚动。
- 关键列和操作列可访问。
- 固定列不遮挡其他列或滚动条。
- 表格底部、分页和行操作不被固定底栏覆盖。
- 长文本截断时有完整内容入口。

### 5.5 表单和交易参数

- 多列变单列后字段顺序正确。
- 标签、输入值、单位、提示和错误信息不重叠。
- 主提交按钮和风险提示始终可访问。
- 禁用、提交中、错误和未知结果状态不改变布局到不可操作。

### 5.6 弹窗和抽屉

- 最大宽高不超过可用视口。
- 标题、正文和操作区均可访问。
- 内容超高时只在明确内容区滚动。
- 操作区不因正文滚动而消失。
- 下拉菜单和日期选择器不会被弹窗内容区裁切。

### 5.7 固定／粘性区域

- 不覆盖正文、分页、表格最后一行或表单错误。
- 滚动到页面底部时仍可访问全部内容。
- 高度变化或按钮换行后正文预留同步变化。
- 层级不覆盖 Modal 等更高层 Overlay。

## 6. 内容韧性测试

至少使用以下异常内容验证：

- 标题长度增加 30%。
- 按钮文案增加 30%。
- 账户名、策略名和标的名使用长字符串。
- 订单 ID／批次 ID 使用完整长度。
- 金额、价格和百分比包含负号、千分位和较多小数。
- 表格操作达到设计允许的最大数量。
- 中英文混排。

以下行为不算通过：

- 关键业务字段无提示省略。
- 按钮只剩无法理解的省略号。
- 单位或正负号被裁切。
- 通过将全页面字号缩小解决长内容。

## 7. 缺陷严重程度

### S0：阻断级

满足任一条件：

- 交易、确认、撤销、风险处置等关键操作不可访问。
- 正文或关键状态被永久遮挡。
- 页面无法滚动到必要内容。
- 组件重叠导致错误操作风险。
- 弹窗无法关闭或提交。

处理：禁止合并或发布。

### S1：严重

满足任一条件：

- 主要图表、表格或表单在正式支持视口内不可读。
- 页面产生明显非预期横向滚动。
- 侧边栏展开／折叠后大面积错位。
- 固定列、底栏或 Overlay 覆盖重要内容。
- 中间宽度布局断裂，但其他宽度正常。

处理：核心页面禁止发布；非核心页面必须有明确修复 Issue 和风险说明。

### S2：一般

例如：

- 间距、对齐或卡片底边不一致。
- 次要文本截断但有完整查看入口。
- 次要操作换行不理想但仍可使用。
- 超宽屏留白分配不合理。

处理：可在不影响任务时合并，但必须记录后续修复。

### S3：轻微

例如：

- 细微像素偏差。
- 不影响层级和操作的视觉差异。
- 非核心动画或装饰在部分视口表现不同。

处理：设计优化，不阻断发布。

## 8. 发布门槛

### 8.1 Application Shell 或 Page Shell 变更

必须：

- 执行全部核心阻断组合。
- 覆盖至少一个交易页面、一个研究页面、一个表格页面和一个弹窗场景。
- 不存在 S0／S1。
- 提供变更前后截图或视觉回归结果。

### 8.2 共享组件变更

必须：

- 验证所有已知使用页面。
- 覆盖组件最小宽度附近的中间状态。
- 说明 Container Query／媒体查询边界。
- 不存在新增 S0／S1。

### 8.3 单页面变更

必须：

- 至少覆盖 C1、C3、C5、C7。
- 覆盖正常、空、错误和长内容状态。
- 不通过全局选择器修复单页。

## 9. 人工证据格式

PR 中的响应式验证建议使用：

```text
Page / route:
Changed layout owner:
Tested combinations: C1, C3, C5, C7
Sidebar states: expanded, collapsed
Data states: normal, empty, error, long-content
Horizontal overflow: none / table-local only
Vertical scroll owner:
Fixed or sticky regions:
Known deviations:
Screenshots or artifact:
```

截图必须显示完整浏览器内容区或明确标注裁切范围，不能只截取已经正常的局部卡片。

## 10. 自动化建设方向

后续独立 Issue 建设：

- Playwright 核心路由导航。
- 统一视口矩阵参数。
- 页面截图基线。
- PR 视觉差异产物。
- `document.documentElement.scrollWidth > clientWidth` 等横向溢出检查。
- 关键元素边界相交检查。
- 固定底栏与正文最后元素可见性检查。

自动化截图不能替代人工判断信息层级和业务可操作性。

## 11. 当前阶段说明

Issue #85 只建立架构和验收标准，不代表现有页面已经通过本规范。

第一次正式实施应先完成缺陷与截图基线，然后治理 Application Shell 和主要滚动所有权。
