# 项目上下文交接

## 1. 项目目标
- 这是一个以“交易平台 + 策略管理 + 对冲基金看板”为主的前端项目。
- 核心目标不是做大而全的通用后台，而是围绕交易研究、执行、复盘、资金与风险管理建立稳定工作台。
- 当前重点是把策略模块和对冲基金看板的结构、样式、交互统一起来，减少重复说明和无效信息。

## 2. 当前目录结构
- `src/views/platform`：交易平台主入口。
- `src/views/strategy/management`：策略管理主入口。
- `src/views/strategy/shared`：策略模块共享组件与主题样式。
- `src/views/strategy/funding-carry`：资费套利交易工具与工作台。
- `src/views/strategy/spread-carry`：跨所价差 / 海内外价差交易工具与工作台。
- `src/views/hedgeBoard`：对冲基金看板，承接宏观、商品、加密等研究看板。
- `docs/strategy`：策略模块设计与交接文档。

## 5. 关键技术
- Vue 3 + TypeScript + `script setup`
- Vite
- Less + CSS 变量主题
- 路由驱动页面切换
- 共享页签组件 `CompactSegmentTabs`
- 本地交易工具目录映射：
  - `tradingToolBoardCatalogMap`

  - `ToolLinkCard`

## 7. 已知问题、常见坑
- `vue-tsc` 在整个仓库里有大量历史遗留错误，很多与当前任务无关，不要为了当前页面去全仓库式修复。
- 中文路径在 PowerShell 里容易显示乱码，尽量用相对路径或 Python 读写 UTF-8。
- 不要再引入无意义的说明文本、eyebrow、subtitle、source note 这类“给人看但不影响决策”的辅助文案。
- 不要把同一个功能在不同页面做成两套不同壳，后面维护成本会很高。
- 不要批量删除文件或目录；需要删文件时只能按明确单文件处理。
- 不要再把交易平台和策略模块的顶部做成不同风格的两个体系。

  - 宏观 / 商品 / 加密三类下方交易工具的排版统一。
  - 顶部壳继续完全对齐策略模块。
- 继续收口交易平台：

## 9. 不能改动 / 需要注意的约束
- 不能破坏交易平台、策略管理、对冲基金看板的现有路由结构。
- 不能一次性大规模删除旧文件或整目录。
- 不能把策略模块的统一壳拆回多个不同风格。
- 不能为了“看起来完整”而添加无意义辅助说明。
- 不能在没有确认的情况下推翻已确认的产品定位。
- 所有新增内容要优先复用已有组件、已有交易工具目录、已有主题变量。
