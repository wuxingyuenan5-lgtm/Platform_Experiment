# P1 后端最小骨架任务清单

状态：`draft`
产品基线：Platform V5
架构版本：Platform V6 Simplified
当前状态入口：`../../../docs/codex/current-state.md`
更新日期：2026-07-19

## 1. P1 目标

P1 只解决一个问题：

> 让 `platform-api` 成为策略、账户、标的、交易命令、订单、成交、持仓、PnL 和净值快照的最小业务权威。

P1 不接真实交易所 API，不做 MT5 Worker，不改造成微服务，不建设完整基金会计。

## 2. 当前起点

当前 `platform-api` 已经具备：

- FastAPI 应用入口。
- SQLite 初始化。
- 健康检查。
- 单订单提交接口。
- 双腿 `ExecutionBatch` 雏形。
- `orders`、`fills`、`positions`、`economic_events`、`pnl_results` 基础表。
- Position 和 PnL 查询接口。
- 基础测试用例。

P1 的原则是“保留并演进”，不是推倒重写。

## 3. P1 范围

### 3.1 必须实现

| 类别 | 对象 |
|---|---|
| 策略 | StrategyDefinition、StrategyVersion、StrategyInstance、StrategyAccountBinding |
| 组织归属 | LegalEntity、Fund、Portfolio、Book，允许系统自动创建默认值 |
| 账户 | Account、BalanceSnapshot |
| 标的 | Venue、Instrument、InstrumentMapping、ContractSpecification |
| 交易 | TradeCommand、ExecutionBatch、ExecutionBatchLeg、Order、Fill / Deal |
| 持仓 | PositionSnapshot |
| 收益 | EconomicEvent、PnLResult、StrategyNavSnapshot |
| 控制 | RiskDecision、AuditEvent |

### 3.2 暂不实现

- Investor、ShareClass、申购、赎回。
- 正式 Fund NAV。
- 完整 Finance Ledger。
- CTP。
- MT5 Worker。
- Crypto 真实 API。
- 复杂审批流。
- 金融 AI 分析。

## 4. 数据库任务

### P1-DB-01 默认组织层级

新增最小表：

- `legal_entities`
- `funds`
- `portfolios`
- `books`

要求：

- 系统初始化时可创建默认 LegalEntity、Fund、Portfolio、Book。
- 普通页面不要求用户管理这些对象。
- StrategyInstance 必须能归属到默认 Book。

### P1-DB-02 策略主数据

新增：

- `strategy_definitions`
- `strategy_versions`
- `strategy_instances`
- `strategy_account_bindings`

字段重点：

- 策略固定编码。
- 策略版本号。
- V1 策略类型：`funding_arbitrage`、`cross_venue_spread`、`home_abroad_spread`、`bottom_fishing`、`short_term_l`、`short_term_w`。
- TradingMode：`simulation`、`paper`、`live_locked`、`live_enabled`。
- 状态：`draft`、`active`、`paused`、`archived`。
- 绑定账户、额度、启用状态。

### P1-DB-03 账户主数据和余额快照

新增或补齐：

- `accounts`
- `balance_snapshots`

字段重点：

- accountId。
- venueId。
- accountType：`crypto`、`mt5`、`internal`。
- environment：`simulation`、`testnet`、`demo`、`live`。
- baseCurrency，V1 默认 USDT。
- credentialRef，只保存凭证引用，不保存密钥。
- balance snapshot 来源、时间、质量状态。

### P1-DB-04 标的与合约规格

新增：

- `venues`
- `instruments`
- `instrument_mappings`
- `contract_specifications`

字段重点：

- 平台统一 instrumentId。
- 外部 symbol 映射。
- venue。
- base / quote / settle currency。
- quantityUnit。
- priceTick。
- minOrderQty。
- contractMultiplier。
- 数据质量状态。

### P1-DB-05 交易命令和订单表演进

保留当前：

- `execution_batches`
- `execution_batch_legs`
- `orders`
- `fills`

新增或补齐：

- `trade_commands`
- `external_order_references`

要求：

- `TradeCommand` 是前端交易意图被后端受理后的权威入口。
- `commandId` 使用幂等键。
- `platformOrderId` 在发往 Runtime 前生成。
- 外部订单 ID 与平台订单 ID 分开。
- 支持 `result_unknown`。

### P1-DB-06 持仓、经济事件、PnL 和净值

保留并演进：

- `positions` 逐步演进为 `position_snapshots` 或保留当前表作为最新持仓投影。
- `economic_events`
- `pnl_results`

新增：

- `strategy_nav_snapshots`
- `pnl_attribution_items`

要求：

- EconomicEvent 表示经济事实，不直接等于 PnL。
- PnLResult 可版本化。
- StrategyNavSnapshot 固定时间生成。
- 公式先采用：`nav = equity / capitalBase`。
- 缺失值必须标记，不当作 0。

### P1-DB-07 风险和审计基础

新增：

- `risk_decisions`
- `audit_events`

要求：

- 记录交易命令受理前的最小风控结果。
- 关键写操作必须有 audit event。
- P1 只做轻量规则，不做复杂审批。

## 5. API 任务

### P1-API-01 系统和元数据

保留：

- `GET /health`
- `GET /api/v1/system/info`

新增：

- `GET /api/v1/system/runtime-readiness`

返回：

- backend 状态。
- database 状态。
- trading mode 默认门禁。
- runtime 是否配置，P1 可以返回未连接。

### P1-API-02 策略查询

新增：

- `GET /api/v1/strategies/definitions`
- `GET /api/v1/strategies/instances`
- `GET /api/v1/strategies/instances/{strategyInstanceId}`
- `GET /api/v1/strategies/instances/{strategyInstanceId}/accounts`

用途：

- 前端策略管理页替换核心 Mock。
- 展示 V1 六类策略状态。
- 明确哪些策略是完整闭环，哪些是占位。

### P1-API-03 账户和标的查询

新增：

- `GET /api/v1/accounts`
- `GET /api/v1/accounts/{accountId}`
- `GET /api/v1/accounts/{accountId}/balances/latest`
- `GET /api/v1/accounts/{accountId}/positions`
- `GET /api/v1/instruments`
- `GET /api/v1/instruments/{instrumentId}`

用途：

- 策略实例选择账户。
- 持仓、余额、标的规格可查询。

### P1-API-04 交易命令

当前已有：

- `POST /api/v1/trading/orders`
- `POST /api/v1/trading/execution-batches`
- `GET /api/v1/trading/execution-batches/{batchId}`

P1 调整方向：

- 保留旧接口作为兼容入口。
- 新增 `POST /api/v1/trading/commands`。
- 命令创建后产生 TradeCommand、ExecutionBatch、Order。
- Runtime 未接通时允许走 Fake/Simulation 状态。

新增：

- `GET /api/v1/trading/commands/{tradeCommandId}`
- `GET /api/v1/trading/orders`
- `GET /api/v1/trading/orders/{platformOrderId}`
- `GET /api/v1/trading/fills`

### P1-API-05 PnL 和净值

新增：

- `GET /api/v1/strategies/instances/{strategyInstanceId}/pnl`
- `GET /api/v1/strategies/instances/{strategyInstanceId}/nav-snapshots`
- `POST /api/v1/strategies/instances/{strategyInstanceId}/nav-snapshots/run`

要求：

- P1 可以先手动触发净值快照生成。
- 后续 P2/P3 再接定时任务。

## 6. 服务层任务

### P1-SVC-01 初始化种子数据

初始化：

- 默认 LegalEntity、Fund、Portfolio、Book。
- 六个 StrategyDefinition。
- 六个 StrategyVersion 初始版本。
- V1 可运行的 StrategyInstance 占位。
- Fake Venue / Simulation Account。
- 常用 Instrument 示例：BTCUSDT、ETHUSDT、XAUUSD。

要求：

- 种子数据可重复运行。
- 不覆盖用户后续修改。

### P1-SVC-02 交易命令受理

实现：

- 请求校验。
- 幂等检查。
- 策略实例状态检查。
- 账户绑定检查。
- 最小风险检查。
- 创建 TradeCommand。
- 创建 ExecutionBatch 和 Order。

P1 不要求：

- 真实外部下单。
- 复杂算法执行。

### P1-SVC-03 持仓和 PnL 投影

实现：

- Fill 更新 PositionSnapshot / 当前持仓投影。
- Fill 生成 trading EconomicEvent。
- fee/funding/swap 先支持手动或模拟写入。
- PnLResult 从 EconomicEvent 汇总。
- StrategyNavSnapshot 从余额、持仓和 PnL 快照生成。

### P1-SVC-04 审计记录

实现：

- 创建交易命令。
- 创建执行批次。
- 生成成交。
- 生成净值快照。
- 风控拒绝或警告。

## 7. 测试任务

### P1-TEST-01 数据库初始化

验证：

- 所有表可创建。
- 种子数据可重复运行。
- 默认层级存在。

### P1-TEST-02 策略查询

验证：

- 六个策略定义存在。
- 资费套利和跨所价差标记为 V1 闭环。
- 其他策略标记为占位或暂缓。

### P1-TEST-03 交易命令幂等

验证：

- 同一个 idempotencyKey 重复提交不会创建重复订单。
- 不同 idempotencyKey 可以创建新命令。

### P1-TEST-04 订单、成交和持仓

验证：

- 买入成交增加持仓。
- 卖出成交减少持仓。
- 平均价格符合 Decimal 计算。
- 缺失价格不会被当作 0。

### P1-TEST-05 PnL 和净值

验证：

- EconomicEvent 汇总为 PnLResult。
- StrategyNavSnapshot 使用 `equity / capitalBase`。
- 缺少 capitalBase 时返回数据质量异常。

### P1-TEST-06 API smoke test

验证：

- health。
- system info。
- strategies。
- accounts。
- instruments。
- commands。
- batches。
- pnl。
- nav snapshots。

## 8. 前端对接需求

P1 完成后，前端至少能拿到：

- 策略实例列表。
- 单策略实例详情。
- 绑定账户。
- 账户余额和持仓。
- 标的规格。
- 交易命令状态。
- 执行批次和腿状态。
- 订单和成交。
- PnL 汇总。
- 固定时间净值快照。
- 数据是否真实、模拟、预览或缺失。

前端仍不负责：

- 正式净值计算。
- 订单最终状态裁决。
- 持仓权威计算。

## 9. P1 完成标准

P1 完成时应满足：

- 后端可独立启动。
- 数据库初始化和种子数据可重复执行。
- 策略、账户、标的、交易命令、订单、成交、持仓、PnL 和净值快照均可查询。
- TradeCommand 具备幂等。
- `platformOrderId` 和外部订单 ID 分开。
- 金融数值使用 Decimal 字符串持久化。
- 缺失数据带质量状态。
- 关键写操作有审计记录。
- 自动测试覆盖主要链路。

## 10. 建议开发顺序

```text
1. 数据库 schema 演进和种子数据
2. 策略、账户、标的查询 API
3. TradeCommand 和幂等
4. Order / Fill / Position 投影
5. EconomicEvent / PnLResult
6. StrategyNavSnapshot
7. RiskDecision / AuditEvent
8. API smoke test 和文档同步
```

完成 P1 后，再进入：

```text
P2 Runtime + Fake Gateway
```
