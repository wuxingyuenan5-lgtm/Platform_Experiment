# Frontend Acceptance

## 自动检查

验证范围遵循[根工程规则](../../AGENTS.md)与[前端工程规则](../AGENTS.md)，这里不另设所有任务都必须执行的命令清单。局部低风险变更只运行直接相关检查；共享路由、权限、持久化和发布级变更扩大回归。

页面截图和模拟 API 响应验证展示；涉及读取、保存或恢复的业务变更，还需以真实 Platform API 与隔离数据库验证相应操作。外部行情或 Venue 可在其适配器边界替换为确定性测试实现，但不能用前端模拟成功替代本次改动的业务链路。

## 产品检查

- 直接 URL、菜单和操作按钮使用一致的 Capability 语义。
- loading、empty、unavailable、error、permission denied 和 stale 均有明确表现。
- `sample`、只读外部事实、Simulation 和 Live 不会混淆。
- Provider、Owner、内部 source、接口名和调试状态不会出现在普通业务页面。
- 刷新可以恢复路由表达的上下文，服务端业务事实重新查询。

## 金融与交易检查

- 数值、币种、单位、方向、符号和时间戳表达一致。
- ACK 不显示为 Fill，`result_unknown` 不显示为确定失败或可直接重试。
- 交易确认明确展示账户、策略、标的、方向、数量和模式。
- 窄视口和缩放状态下，风险提示与主要操作保持可见和可操作。

## 交付判断

构建通过只证明前端工程可构建，不证明外部 Provider、账户、部署或 Live Write 就绪。当前项目完成状态统一回填 [项目驾驶舱](../../docs/PROJECT.md)。

保存类操作的交付证据应覆盖服务器接受写入、重新读取、刷新恢复及对应用户权限/数据范围；“同步成功”必须对应约定的实际同步行为。已知检查失败必须保留为未解决限制。浏览器测试入口需先满足隔离要求，不复用连接真实账户的服务；具体已知阻塞见项目驾驶舱。

A 股端到端入口为 `playwright.hedge-board.config.ts`：每次使用独立 SQLite 目录及 4437/8437 测试服务，拒绝复用既有监听器，不清理旧运行目录。夹具只替换公开数据适配器；登录、权限、CSRF、生产、数据库与页面均经过正式调用链。响应式检查覆盖 1440/1024/768/390 宽度及容器裁切，不能只检查页面滚动宽度。
